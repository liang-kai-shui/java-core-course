## 一个对象中，父类部分与子类部分都在

```java
public class InheritanceRoute {
    public static void main(String[] args) {
        LabCourse course = new LabCourse("实验课", 3, 2);
        System.out.println(course.title() + "=" + course.hours());
    }
}
class CourseBase {
    private final String title;
    private final int baseHours;
    CourseBase(String title, int baseHours) {
        this.title = title;
        this.baseHours = baseHours;
        System.out.println("parent:" + title);
    }
    public String title() { return title; }
    public int hours() { return baseHours; }
}
class LabCourse extends CourseBase {
    private final int labHours;
    LabCourse(String title, int baseHours, int labHours) {
        super(title, baseHours);
        this.labHours = labHours;
        System.out.println("child:" + labHours);
    }
    @Override public int hours() { return super.hours() + labHours; }
}
```

预期`parent:实验课`、`child:2`、`实验课=5`，各占一行。本课课时用小的非负整数输入，先看结构，不拿此例当无限范围计费系统。

`class LabCourse extends CourseBase`声明继承。new只创建一个LabCourse对象，其中有父类定义的title/baseHours状态，也有子类labHours状态。父类private字段确实属于对象状态，但子类源码不能直接访问它；必须经过父类提供的入口。不要把“不能直接访问”读成“对象中不存在”。

`super(title,baseHours)`选择父类构造器，负责初始化父类定义的那部分状态。在Java 8语法中，它是子类构造器第一条语句。若不写，会隐式尝试super()；CourseBase只声明双参构造器，没有无参，所以删掉这句会编译失败。构造器不被继承；你不能因为父类有双参构造器，就默认子类也有同签名入口。

`@Override`让编译器检查“我真在覆盖父类方法”。子类hours签名与父类一致，返回int，public权限不缩小。`super.hours()`明确调用父类实现，再加实验课时。若写成`hours()+labHours`，会再次调用当前覆盖方法，一次套一次直到StackOverflowError；不是Java自动识别你想要基础值。

| 顺序 | 正在执行 | 已准备好的状态 |
|---|---|---|
| 1 | 进入LabCourse构造，转super | 字段先有默认值 |
| 2 | CourseBase正文 | title=实验课，baseHours=3 |
| 3 | LabCourse正文 | labHours=2 |
| 4 | main调用title | 继承的访问器返回实验课 |
| 5 | main调用hours | 子类→父类hours返回3→加2得5 |

super不是另一个可赋值给变量的对象引用，而是特殊语法，指明调用父类构造器或从父类实现开始的方法调用。this则代表当前接收调用的对象引用。它们不能混着当同一种变量用。

## 覆盖与重载别认错

子类写`hours(int extra)`会增加一个重载，不是覆盖无参hours。用@Override能及时发现签名拼错；去掉注解只会让误会隐藏。覆盖也不能降低访问权限，父类public而子类不写public会编译失败。父类private方法不被子类覆盖，static方法也不按实例动态覆盖。

继承可继续形成链，例如SpecialLabCourse extends LabCourse，但链越深，理解调用越费力。不是层级越长越专业。父类构造器里尽量不要调用可被覆盖的方法：此时可能先进入子类覆盖实现，而子类字段初始化还没完成，看到的是默认0/null；这是初始化与动态分派相遇的陷阱。

## 只改一处与独立任务

把main的实验课时2改为0，构造输出child:0，最终仍有基础3课时。另在副本删super(...)，预期编译失败，不运行旧class。再把@Override下的hours改名为hour，注解应暴露错误。

独立实现PrintJob与ColorJob：父类保存页数，cost返回页数乘2；子类保存一次性色彩附加费，cost返回super.cost加附加费。用页数4、附加费3得到11，0页仍按你写明的附加费规则处理。思考附加费是否应只在有页数时收取，这是业务契约问题，不是extends能替你决定的。

## 父类构造中调用子类覆盖：为什么先看到0

父类构造器像在新设备尚未完全装好时按下一个可扩展按钮，按钮却转到子类的功能。边界是这不是创建了两个对象，而是同一对象还处于初始化中；动态分派并不会等子类准备好。

```java
public class ConstructorDispatchTrap {
    public static void main(String[] args) {
        ChildProbe probe = new ChildProbe();
        System.out.println("after=" + probe.read());
    }
}
class ParentProbe {
    ParentProbe() { System.out.println("during=" + read()); }
    int read() { return -1; }
}
class ChildProbe extends ParentProbe {
    private int bonus = 7;
    @Override int read() { return bonus; }
}
```

ChildProbe的bonus声明了初值7，但初始化顺序仍是先父构造，再子字段初始化，再子构造正文。父类中的read()不是super调用，实际对象是ChildProbe，因此选择子类覆盖实现；此刻bonus仍默认0。回到main以后才读到7。

| 事件 | bonus | read选择 |
|---|---:|---|
| 对象默认状态 | 0 | 尚未调用 |
| ParentProbe构造器调用read | 0 | ChildProbe.read |
| 子字段初始化完成 | 7 | 尚未再调用 |
| main再调用 | 7 | ChildProbe.read |

只把7改9，父构造打印仍0，最后打印才变9。独立任务：把构造器里的虚调用改为只记录父类自己的有效状态，在构造完成后由main调用read；解释为什么“先打印看看”也会触发尚未安全的业务方法。不要用给子字段随便换个数字来掩盖初始化时机。
