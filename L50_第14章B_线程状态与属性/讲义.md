## 学完要能做什么

能区分六种Thread.State及其快照边界；说明优先级不是执行顺序保证；正确设置daemon时机，给线程安装局部未捕获异常处理器，不把子线程失败误当main已收到异常。

## 明明已经start，为什么说是RUNNABLE而不是“正在运行”

线程可能有资格运行却尚未分到CPU。像排队上台：已经进入候场区不代表此刻正站在台上；类比边界是Java只提供自己的状态分类，不是一张操作系统调度全过程监控图。

```java
public class StableThreadStates {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> { }); System.out.println(worker.getState());
        worker.start(); worker.join(); System.out.println(worker.getState());
    }
}
```

输出NEW、TERMINATED。未start时任务尚未执行，join成功后它已经结束；中间状态本例不强行打印成唯一答案，因为线程可能迅速执行完。getState是诊断快照，不是授权另一线程做某件事的同步协议。

| Java状态 | 当前在做什么/等什么 | 常见触发 |
|---|---|---|
| NEW | 尚未成功start | 刚new |
| RUNNABLE | 可运行，可能正在CPU上，也可能等调度 | 普通计算 |
| BLOCKED | 等进入synchronized使用的监视器 | 别人持有同一对象锁 |
| WAITING | 无时限等条件/完成/许可 | wait、join、部分park/await |
| TIMED_WAITING | 等待有时间上限 | sleep、计时wait/join等 |
| TERMINATED | run正常结束或未捕获失败结束 | join后可稳定观察 |

这里的BLOCKED不是日常“所有停下来都叫阻塞”的泛称，ReentrantLock等待常通过park表现WAITING，而不是同样都BLOCKED；具体实现快照也不能成为业务判断。isInterrupted报告取消标志，不回答是否结束；isAlive与getState承担生命周期诊断，不能拿标志true当已经清理完。

只把join移到打印第二行之后，预测第二行不再固定TERMINATED；独立任务：保留真正join以后输出“已完成”，不要用while(getState!=TERMINATED)忙等代替现成等待。

## 优先级像建议，不能当交通信号灯

传统平台线程优先级1–10，默认继承创建者，setPriority只表达调度提示并受实现/线程组等约束；不保证高优先级一定先执行或先完成。yield也只是调度提示，不承诺把CPU交给特定线程。教材p638–639 / PDF p656–657中“总先选高优先级”不宜当跨平台正确性前提；程序用join、锁、条件与队列组织依赖。当前课程使用普通平台Thread，不把JDK21虚拟线程当这几页规则的自动延伸。

## 守护线程不是不需要关闭的线程

daemon不让JVM仅为它继续存活；JVM只剩守护线程时可结束，不保证它完成写入、finally或事务。像附属照明随主场馆结束，不因还亮着就阻止关门；类比边界是它仍是执行普通代码的线程，不自动更安全、更低优先级。必须在start前setDaemon；生产程序仍设计关闭/取消与等待，不能用daemon掩盖资源泄漏。

## 观察等待的三个原因：带超时的诊断，不用状态充当通知

```java
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.TimeUnit;
public class BlockingStateSnapshots {
    static void observe(Thread thread, Thread.State expected) {
        long begin = System.nanoTime();
        while (thread.getState() != expected) {
            if (System.nanoTime() - begin > TimeUnit.SECONDS.toNanos(3)) throw new AssertionError("state not observed: " + expected);
            Thread.yield();
        }
        System.out.println(expected);
    }
    public static void main(String[] args) throws InterruptedException {
        Object monitor = new Object(); Thread blocked = new Thread(() -> { synchronized (monitor) { } });
        try { synchronized (monitor) { blocked.start(); observe(blocked, Thread.State.BLOCKED); } } finally { blocked.join(); }
        CountDownLatch gate = new CountDownLatch(1);
        Thread waiting = new Thread(() -> { try { gate.await(); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } });
        waiting.start(); try { observe(waiting, Thread.State.WAITING); } finally { gate.countDown(); waiting.join(); }
        Thread sleeping = new Thread(() -> { try { Thread.sleep(60000); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } });
        sleeping.start(); try { observe(sleeping, Thread.State.TIMED_WAITING); } finally { sleeping.interrupt(); sleeping.join(); }
    }
}
```

main先持有monitor再start，所以worker不能进入synchronized；释放后join确保它完成。第二段await门闩，第三段sleep，诊断函数最多观察3秒，超时明确失败，不一直卡住。finally中打开门闩/中断并join；即便机器太忙导致抓不到状态也能清理。本例成功输出BLOCKED、WAITING、TIMED_WAITING。

`System.nanoTime`测持续时长，不当作日历时间；yield只降低忙等对机器的干扰，不提供正确性保证。这是**诊断专用例**，不能解释成“用yield实现同步”。只把等待BLOCKED的代码挪到释放monitor之后，状态可能已错过；独立任务说明为什么实际业务应等待事件/结果，而不是赌能采样到中间状态。

## daemon只改变存活条件，正常模式仍要完成关闭

```java
import java.util.concurrent.CountDownLatch;
public class DaemonLifetime {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch ready = new CountDownLatch(1), gate = new CountDownLatch(1);
        Thread helper = new Thread(() -> {
            ready.countDown(); try { gate.await(); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        });
        helper.setDaemon(true); helper.start(); ready.await();
        if (args.length > 0 && args[0].equals("--abandon")) { System.out.println("main-return"); return; }
        System.out.println("daemon=" + helper.isDaemon()); gate.countDown(); helper.join(); System.out.println("clean-finish");
    }
}
```

默认输出daemon=true、clean-finish，说明设属性后仍显式结束任务；追加`-ProgramArgs '--abandon'`运行独立进程，只输出main-return，main返回后不再有非守护线程维持它。ready保证worker已进入流程，gate始终未开；这里没有文件、网络或重要写入，才能让“未完成就退出”成为清楚的教学实验。

只把setDaemon(true)改false再执行--abandon会等待不结束，**不要直接照做后放着不管**；若实验，用Ctrl+C结束该终端中的这次Java进程，说明它与正常关闭不同。独立任务：改成非守护线程但保持默认模式的gate.countDown与join，验证仍能正常结束，指出属性不应替代关闭协议。

在课程根目录PowerShell运行`./java.ps1 -Source './L50_第14章B_线程状态与属性/code/DaemonLifetime.java'`。
