### 怎么把讲义中的程序跑起来

带有 `public class`、完整大括号和 `main` 的 Java 代码框是完整程序。标为“片段”的短代码只替换 main 里面相应部分，不能单独当文件运行。每个完整程序另建一个文件，不能把两个 public class 或两个 main 随手拼在一起。

在 VS Code 中打开整个 `D:\Code\Java` 文件夹。在本课 `my_code` 文件夹新建 `RunSteps.java`，文件名要与 `public class` 后的名字相同；保存为 UTF-8。没有显示后缀、不会新建文件或打开终端，先看[零基础起飞](../附录/零基础起飞.md)，无需先读 PDF。

打开“终端 → 新建终端”，确认使用 **PowerShell**。以下命令从课程根目录开始输入，提示符本身不用抄：

```powershell
Set-Location 'D:\Code\Java'
.\java.ps1 -Source '.\L02_第02章_编译运行与错误\my_code\RunSteps.java'
```

这是课程提供的“编译成功才启动”工具。它每次在 `.build` 中另建输出目录，生成 class 后才运行；不要手动执行以前留下的 class。后面的完整程序同样操作，只换末尾文件名。需要键盘输入时，运行后在终端键入数据并回车；程序没有显示新提示符，可能正在等输入。出现脚本策略提示时，在同一根目录把运行一行改为：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\java.ps1 -Source '.\L02_第02章_编译运行与错误\my_code\RunSteps.java'
```

每次实验留三项记录：**预测、实际输出、解释第一次出现差异的步骤**。看到程序自己的输出才算实际启动；没有报错不等于题目做对。

## 1. 运行按钮背后也有两件工作

上一课用课程脚本直接看到了输出。现在假设按钮失败，想查出问题，需要把编译和启动分开。

先建立 `RunSteps.java`：

```java
public class RunSteps {
    public static void main(String[] args) {
        System.out.println("version A");
    }
}
```

用第 0 节的脚本方法先确认能输出 version A，再做下面的手动操作。源码仍写在 my_code；不要在 code 示例原件上试错。

## 2. 在哪一个目录，决定相对路径从哪开始

**当前目录**是终端此刻拿来解释相对路径的起点。它像站在某一栋楼，再说“去旁边那栋楼”；同一句相对位置换个起点就会变。

**绝对路径**给完整位置，例如 `D:CodeJava`。**相对路径**从当前位置出发，例如 `.my_codeRunSteps.java`。`.`表示当前文件夹，`..`表示上一层。

手动实验从本课的 my_code 开始。打开 PowerShell，逐行执行：

```powershell
Set-Location 'D:CodeJavaL02_第02章_编译运行与错误my_code'
Get-Location
Get-ChildItem
```

应看到当前位置就是这一目录，列表中有 RunSteps.java。看不到时先找保存位置，不要继续编译一个不存在的文件。

VS Code 当前编辑的文件与终端当前目录是两回事。打开了 RunSteps.java，并不会保证终端自动走到它旁边。后面写入文件也要记住这个区别。

## 3. 亲手编译一次

本机 JDK 已安装，但终端未必能靠短命令找到它。**PATH**是查找命令的目录清单，像通讯录。没登记不等于人不存在；使用完整位置仍能找到。

在刚才的 PowerShell 中设置一个变量，保存工具包目录。这个位置是本机已核对的配置；换电脑时按课程环境说明查自己的安装位置。

```powershell
$jdk = 'C:Program FilesJavagraalvm-jdk-21.0.12+7.1'
& "$jdkinjavac.exe" -version
& "$jdkinjava.exe" -version
```

`$jdk`是 PowerShell 变量，不是 Java 变量。`&`让 PowerShell 执行后面的程序路径，双引号允许路径包含空格。不要把它们写入 `.java` 文件。

为本次实验建一个新的输出目录：

```powershell
$out = Join-Path (Get-Location) ('out-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $out | Out-Null
& "$jdkinjavac.exe" --release 8 -encoding UTF-8 -d $out .RunSteps.java
```

此处那段较长的 PowerShell 只是在当前目录下造一个每次不同的文件夹名，不属于 Java 必学语法。隔离输出的目的，是让上一轮 class 不能冒充这一轮产物。

| 命令部分 | 本次含义 |
|---|---|
| javac.exe | 运行编译器 |
| --release 8 | 按 Java 8 目标语法/API 编译 |
| -encoding UTF-8 | 按 UTF-8 读取源码文本 |
| -d $out | 把 class 放进刚创建的目录 |
| .\RunSteps.java | 从当前目录找到待编译源文件 |

编译通常成功时不输出“恭喜”；先检查退出码，再看产物：

```powershell
if ($LASTEXITCODE -eq 0) {
    Get-ChildItem -LiteralPath $out
    & "$jdkinjava.exe" -cp $out RunSteps
}
```

`$LASTEXITCODE`是上一个外部程序的退出状态，通常 0 表示成功。这里的 if 属于 PowerShell，意为“成功才执行括号里的操作”。第 L07 课的 Java if 写法不同，不要混在一起。

应看到输出目录里有 RunSteps.class，之后看到 version A。若编译报错，停止，不要单独跳到启动那一行。

## 4. 启动为什么不写 RunSteps.class

**类路径**是运行工具查找类的位置。`-cp $out`告诉它到本次输出目录查找；末尾 RunSteps 是类名。

```text
java -cp 某个目录 RunSteps
         在哪里找  找哪一个类
```

本阶段不使用 package，因此类文件直接位于该目录。以后使用包，启动名还会包含包名，不能把这里的简化规则扩展为所有 Java 项目。

常见的三种名字：

| 名字 | 例子 | 用在哪里 |
|---|---|---|
| 源文件名 | RunSteps.java | javac 后面 |
| public 类名 | RunSteps | 源码外壳与启动命令 |
| 编译结果名 | RunSteps.class | 生成目录里观察 |

`java -cp $out RunSteps.class`把“.class”也当作类名的一部分，通常找不到你要的类；`java RunSteps.java`在较新 JDK 有另一种源码启动模式，本课程先不用它，避免把两步实验混掉。

大小写准确对应。Java 里的 Main、main、mian 是不同名字；Windows 文件系统的某些宽松行为不能代替 Java 标识符规则。

## 5. 为什么编译失败了，还能看见旧输出

手工流程如果先产生 version A 的 class，后来源码改坏，编译失败并不会自动把旧 class 擦掉。若仍运行旧目录，就可能再次看到 version A。

```text
第一次：正确源码 A → 编译成功 → class A → 输出 A
第二次：改坏的源码 B → 编译失败     旧 class A 仍可能存在
错误操作：忽略失败，继续启动旧目录 → 又输出 A
```

这不代表编译器忽略了错误，而是你执行了另一份旧产物。像打印失败后拿起昨天的纸张，纸上有字也不能证明今天打印成功。

安全实验：在自己的副本把文字改为 version B，并删去一处分号。使用课程根目录的 java.ps1 运行；应见编译失败，没有 version A 或 B 的程序正文。恢复分号后再运行，应见 version B。

平常优先用课程脚本；手动实验的隔离目录与“成功才启动”也必须保留。不要为了少敲一行把条件判断去掉。

## 6. 命令行参数是什么

**参数**是你交给一个操作的数据。命令行参数是在启动时交给程序的文本，例如一次传入 red、blue。

新建 `LaunchCount.java`：

```java
public class LaunchCount {
    public static void main(String[] args) {
        System.out.println("count=" + args.length);
    }
}
```

这里 String[] args 先理解成“存放启动时收到的文本的一组位置”，args.length 是收到多少项；数组的详细规则到 L10。这个程序只问数量，不访问不存在的项。

回到课程根目录运行：

```powershell
Set-Location 'D:CodeJava'
.\java.ps1 -Source '.\L02_第02章_编译运行与错误\my_code\LaunchCount.java'
.\java.ps1 -Source '.\L02_第02章_编译运行与错误\my_code\LaunchCount.java' -ProgramArgs @('red','blue')
```

分别是 count=0、count=2。`@(...)`是 PowerShell 把这两项交给脚本的写法。想传“Li Ming”作为一项，写 `@('Li Ming')`，应得到 count=1。引号用来保持这一项，不会作为姓名正文的一部分。

这与启动后停下来等待键盘输入不同：参数在启动时已经给出，后续键盘读取到 L06 才系统练习。

## 7. 五个标本，先判断失败在哪里

**诊断**是工具告诉你出了什么问题的文字。编译诊断通常包含文件、行、说明和指向位置。运行异常常有调用记录，说明程序沿着哪些方法走到出错处。

本课 error_lab 保留以下原始标本，逐个观察，先预测再按该目录说明运行，不把它们一起编译：

| 标本 | 应出现的阶段 | 这次要观察什么 |
|---|---|---|
| MissingSemicolon | 编译失败 | 第一条有效诊断指向哪里 |
| WrongFileName | 编译失败 | public 类名与文件名要求 |
| MissingMain | 编译成功，启动失败 | 有 class 不保证有当前约定入口 |
| RuntimeCrash | 启动后异常 | 运行到了哪条非法操作 |
| WrongFormula | 正常结束，结果不合题意 | 对照手算定位错误公式 |

修复放在自己的副本里。不能把预期报错的标本“修好”以后，下一次就再也找不到错误原样。

遇到多条诊断，从最早的一条有意义错误开始。一处缺括号可能让后面很多行都被误读；先改一个原因，再重新编译，不必逐条猜测每一行都独立坏了。

## 8. 按症状排查，不盲目改环境

| 现象 | 先做什么 | 为什么 |
|---|---|---|
| 找不到 java.ps1 | Get-Location，回根目录 | 先分清脚本位置与源码位置 |
| 找不到源文件 | 查看目录与文件完整后缀 | 常见是保存错地方或多了 .txt |
| 找不到主类 | 看 -cp 指向本次 class 目录吗 | 源码所在目录未必是产物目录 |
| 找不到 main | 对照完整入口拼写 | 这是启动条件，不是缺分号 |
| 少分号后仍出旧文字 | 检查是否启动旧目录 | 本次编译失败不清除旧文件 |
| 中文变乱码 | 检查 UTF-8 保存并用课程脚本 | 源文件编码与终端显示要对应 |

本课过关：能解释两步运行、产物位置、-cp 与类名；能保留错误原文，在副本修正后重新运行；能说明自己看到的是哪一轮源码的结果。IDE 是帮助编辑、编译、运行和调试的综合工具，VS Code 在本项目通过任务和脚本提供这些入口；按钮方便，但不改变这些阶段。

## 教材第2章的其余入口：工具之外还要会查资料

### 2.1：SE、发行实现与本机工具

教材先区分JDK、JRE、SE等名字。**Java SE**是标准版的平台规范范围；**OpenJDK**与具体JDK发行实现相关，不能把它理解成另一个语法完全不同的语言。EE、ME是教材介绍的平台分工背景，本课先学SE，不安装全部平台。

书里的jdk符号是安装目录的代称，不是你的电脑真的有一个叫jdk的固定路径。教材建议配置PATH，本课程用完整位置与项目脚本解决查找，保持其他项目环境不受影响；这是操作方式的适配，不改变PATH的作用。

### 2.1.3：源码、API文档、书中示例是三份材料

**库源码**展示工具内部怎样实现，例如发行包中的src.zip；**API文档**说明可以怎样调用；**教材示例源码**是作者用于说明章节的程序。三者不能混为“装了JDK就自动都有本书代码”。

像电器内部线路图、使用说明书、课堂实验样品：学会使用先看说明，想研究实现再看源码。初学不需要解压整套库才能输出一行字。

需要查一个方法时：先认类名，如String；到与学习版本对应的官方API找到该类；在方法汇总中找名字；查看参数、返回结果和失败条件。L05会用具体条目练习读法。书中的文档下载与三窗格界面属于当时版本，不要求把浏览器界面改成截图的样子。

### 2.3–2.5：IDE、图形应用与applet分别怎么处理

**IDE**把编辑、编译、运行、诊断等工作放在一个环境中。教材用Eclipse示范，并允许选其他环境；本项目使用VS Code与项目任务。它们的共同目标是把操作串起来，不是改变Java入口规则。

在VS Code打开本项目根文件夹，打开自己的独立Java文件，用Ctrl+Shift+B调用项目任务。若有问题，对照手动流程，确认任务实际编译的是哪个文件、运行的是哪一轮class。编辑器下划线是诊断入口，最终仍需保存并编译验证。

**图形化应用**会建立自己的窗口，终端应用主要通过文字输入输出。教材ImageViewer先让读者看结果，其具体窗口结构到第10–12章学习；本课认识这条后续路线，不要求提前写Swing窗口。

2.5的applet内容教材本身也允许跳过。它使用与普通java主类不同的加载方式，本课程按历史认识处理，不执行旧浏览器插件与信任设置步骤。原书工具名、当前替代方式和暂缓的知识各有来由，不把它们悄悄删成“未读过的部分”。
