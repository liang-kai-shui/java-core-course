## 我不只想知道线程结束，还要拿到它算出的答案

Runnable的run没有结果位置。**Callable<T>**把“工作完成后给出T”写进接口，call还允许受查异常；**Future<T>**是结果凭据，可等待、查询和请求取消。像提交一张取件单，单子到手不代表货已做好，查到失败也不等于有可用结果；类比边界是Future不自动启动任务，取消也不保证后台立即停止。

```java
import java.util.concurrent.*;
public class FutureResultRoutes {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        FutureTask<Integer> good = new FutureTask<>(() -> 6 * 7); Thread a = new Thread(good); a.start();
        try { System.out.println(good.get()); } finally { a.join(); }
        FutureTask<Integer> bad = new FutureTask<>(() -> { throw new IllegalArgumentException("demo"); }); Thread b = new Thread(bad); b.start();
        try { bad.get(); } catch (ExecutionException e) { System.out.println(e.getCause().getClass().getSimpleName()); } finally { b.join(); }
    }
}
```

输出42，然后IllegalArgumentException。FutureTask把Callable同时包装成Runnable和Future，所以可交Thread启动，也可get结果；坏任务的异常存在Future中，由get抛ExecutionException，getCause才是原始失败。它不走L50普通run未捕获处理器那条报告路线。

### 泛型与异常分别读

`FutureTask<Integer>`不是Thread<Integer>，类型参数描述结果；`() -> 6 * 7`是Callable，因为所在位置需要有返回值的接口。get可能等待，正常返回才有Integer；ExecutionException表示任务失败，InterruptedException表示**当前正在等待get的调用线程**被中断，不是“计算线程被中断就直接让get抛这个异常”。教材p681 / PDF p699的表述需按[Future API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/Future.html)区分。

| 结果状态 | get表现 | 能当有效答案吗 |
|---|---|---|
| 成功 | 返回T | 按业务再检查 |
| 任务失败 | ExecutionException包原因 | 不能 |
| 被取消 | CancellationException | 不能 |
| 计时等待未完成 | TimeoutException | 任务可能仍继续 |
| 等待者被中断 | InterruptedException | 处理取消，不假读旧结果 |

isDone包含成功、失败与取消，不等于成功。cancel(true)请求中断可被中断的运行机制，任务仍需合作；cancel(false)不请求中断，不能从返回true推导线程已经清理完。对FutureTask，取消状态与执行线程真正离开finally也应分开确认。

只把坏任务的throw改return -1，预测get正常给出-1而不是异常；独立任务说明“负值表示业务失败”的协议与Java异常不同，调用者应按已定义规则处理。

## 任务很多，别给每个小任务新建一个线程

执行器把提交与运行机制分开。线程池像固定几位工作人员从收件架取任务，任务完成可接下一单；类比边界是固定工作线程数不自动限制排队任务数量。newFixedThreadPool默认使用无界工作队列，newCachedThreadPool可能不断增线程；本课只提交少量已知任务，真实大量输入需有界ThreadPoolExecutor与明确拒绝策略。

submit后保存Future，在finally关闭池；shutdown拒绝新任务、继续处理已提交任务，并不等待全部结束。awaitTermination等待结束，shutdownNow尝试中断运行者并返回未启动任务列表，也**不保证自动把这些任务关联Future全部标为取消**。不能用“调用关闭方法”代替证明确实退出。

## 超时与取消：用确定的关卡区分“还没好”和“不再要”

```java
import java.util.concurrent.*;
public class FutureTimeoutAndCancellation {
    public static void main(String[] args) throws InterruptedException {
        FutureTask<Integer> pending = new FutureTask<>(() -> 7);
        try { pending.get(0, TimeUnit.MILLISECONDS); } catch (TimeoutException e) { System.out.println("timeout"); } catch (ExecutionException e) { throw new AssertionError(e); }
        System.out.println("cancelled=" + pending.isCancelled()); pending.cancel(true);
        try { pending.get(); } catch (CancellationException e) { System.out.println("cancelled"); } catch (ExecutionException e) { throw new AssertionError(e); }
        FutureTask<Integer> interruptedTask = new FutureTask<>(() -> { throw new InterruptedException("task failure"); }); Thread worker = new Thread(interruptedTask); worker.start();
        try { interruptedTask.get(); } catch (ExecutionException e) { System.out.println("task-cause=" + e.getCause().getClass().getSimpleName()); } finally { worker.join(); }
    }
}
```

FutureTask尚未被启动，get(0)必然超时，输出timeout与cancelled=false；cancel后再get抛CancellationException，输出cancelled。再创建第二个任务，任务体直接抛InterruptedException，正常start后get得到ExecutionException中的InterruptedException。这两条路线不能混同。

只把第一项cancel挪到第一次get前，预测不再超时而是取消异常；独立任务说明为什么超时并没有替你执行cancel。此例不需要睡眠或访问网络就能观察边界。

## 先收完成结果，而不是被提交顺序拖住

```java
import java.util.concurrent.*;
public class CompletionOrderGate {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ExecutorService pool = Executors.newFixedThreadPool(2); CountDownLatch gate = new CountDownLatch(1);
        try {
            CompletionService<String> completed = new ExecutorCompletionService<>(pool);
            completed.submit(() -> { gate.await(); return "slow"; }); completed.submit(() -> "fast");
            System.out.println(completed.take().get()); gate.countDown(); System.out.println(completed.take().get());
        } finally { gate.countDown(); pool.shutdownNow(); if (!pool.awaitTermination(3, TimeUnit.SECONDS)) throw new IllegalStateException("pool still active"); }
    }
}
```

慢任务等gate，快任务立即返回；完成服务第一次取到fast，然后main开gate，第二次得slow。这里的先后由门闩建立，不是靠给两个sleep写不同毫秒数。take取得已完成Future，再get取业务结果或失败，不能漏处理失败。

invokeAll返回的Future列表按输入任务顺序，方法本身等待任务组完成（或计时上限）；计时版未完成任务会被取消，**不抛TimeoutException作为正常超时返回**，教材p691 / PDF p709表需校正，见[ExecutorService API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ExecutorService.html)。invokeAny返回某个成功结果并尝试取消其余，不应要求固定是哪一个。

只在固定1线程池中先提交slow再fast，会让fast也排在慢任务后；而main等fast才开门，构成任务依赖饥饿。不要运行这个错误版本当正常例；独立任务画出唯一worker被谁占住，再把开门放到独立可运行的协调者。递归任务在有限池里等同池子任务尤其要谨慎。

## 预定执行：到时间具备资格，不保证墙钟精确

```java
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
public class ScheduledTaskSteps {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
        try {
            ScheduledFuture<Integer> once = scheduler.schedule(() -> 7, 0, TimeUnit.MILLISECONDS); System.out.println(once.get());
            CountDownLatch twice = new CountDownLatch(2); AtomicInteger count = new AtomicInteger();
            ScheduledFuture<?> repeating = scheduler.scheduleWithFixedDelay(() -> { count.incrementAndGet(); twice.countDown(); }, 0, 1, TimeUnit.MILLISECONDS);
            if (!twice.await(3, TimeUnit.SECONDS)) throw new AssertionError("not triggered"); repeating.cancel(true); System.out.println("repeated=" + (count.get() >= 2));
        } finally { scheduler.shutdownNow(); if (!scheduler.awaitTermination(3, TimeUnit.SECONDS)) throw new IllegalStateException("scheduler active"); }
    }
}
```

输出7、repeated=true。第一次schedule提交延迟0的Callable，get收结果；第二次固定延迟任务至少完成两次计数后main取消，不断言到底触发几次，避免取消与下一次启动之间的调度竞争。finally关闭并等结束。

| 方式 | 示例时间关系（任务耗时30ms、间隔100ms） |
|---|---|
| fixedRate | 理想计划开始在0/100/200ms，迟到可能追赶 |
| fixedDelay | 一次结束后再等100ms，再开始下一次 |

同一个周期任务不会因耗时超过间隔就自动重叠运行；若一次执行抛异常，后续执行可能被抑制，需明确报告和策略。ScheduledExecutorService的任务不是Swing EDT回调，更新界面仍交EventQueue或SwingWorker；Swing Timer与它不能仅按“都叫定时”互换。独立任务说明为什么每次任务中sleep(100)不等于这两种调度契约。

## ForkJoin：拆小后求结果，不是无限递归创建线程

```java
import java.util.concurrent.*;
public class ForkJoinCount {
    static class Count extends RecursiveTask<Integer> {
        private static final long serialVersionUID = 1L;
        final int[] values; final int from, to;
        Count(int[] values, int from, int to) { this.values = values; this.from = from; this.to = to; }
        protected Integer compute() {
            if (to - from <= 2) { int count = 0; for (int i = from; i < to; i++) if (values[i] >= 4) count++; return count; }
            int mid = from + (to - from) / 2; Count left = new Count(values, from, mid), right = new Count(values, mid, to);
            invokeAll(left, right); return left.join() + right.join();
        }
    }
    public static void main(String[] args) throws InterruptedException {
        ForkJoinPool pool = new ForkJoinPool(2);
        try { int[] values = {1, 4, 2, 8}; System.out.println(pool.invoke(new Count(values, 0, values.length))); System.out.println(pool.invoke(new Count(new int[0], 0, 0))); }
        finally { pool.shutdown(); if (!pool.awaitTermination(3, TimeUnit.SECONDS)) { pool.shutdownNow(); throw new IllegalStateException("fork pool active"); } }
    }
}
```

输入{1,4,2,8}，阈值2，左右各数出一个>=4，join合并得2；空数组直接得0。from含、to不含，mid用from+(to-from)/2，左右范围不重叠也不漏项。RecursiveTask<Integer>的compute返回统计数，invokeAll安排子任务，join取得各自结果；工作窃取是运行机制，不要求每个子任务独占一个新线程。

只把终止条件<=2改<0，将无法收敛，**不要运行**；独立任务先写长度0/1/2/3的递归范围树，证明每次大区间变小再改阈值。此例数组在任务期间不被其他线程修改；一般阻塞I/O不直接塞进这种计算分治框架。普通ExecutorService任务在固定池里互等，与ForkJoinTask.join的协作机制不能混为一谈。

## CompletableFuture：把“下一步”接起来，别在worker里堵住等自己

```java
import java.util.concurrent.*;
public class ComposedTaskStages {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ExecutorService pool = Executors.newSingleThreadExecutor();
        try {
            CompletableFuture<String> name = CompletableFuture.supplyAsync(() -> " 数组 ", pool);
            CompletableFuture<String> label = name.thenApply(String::trim).thenCompose(s -> CompletableFuture.supplyAsync(() -> "[" + s + "]", pool)); System.out.println(label.get());
            CompletableFuture<String> failed = new CompletableFuture<>(); failed.completeExceptionally(new IllegalArgumentException("demo"));
            System.out.println(failed.handle((value, error) -> error == null ? value : "fallback").get());
            CompletableFuture<Integer> a = CompletableFuture.completedFuture(1), b = CompletableFuture.completedFuture(2);
            System.out.println(a.thenCombine(b, Integer::sum).get()); CompletableFuture.allOf(a, b).get();
            CompletableFuture<Object> either = CompletableFuture.anyOf(CompletableFuture.completedFuture("first"), new CompletableFuture<String>()); System.out.println(either.get());
        } finally { pool.shutdownNow(); if (!pool.awaitTermination(3, TimeUnit.SECONDS)) throw new IllegalStateException("pool active"); }
    }
}
```

输出[数组]、fallback、3、first。thenApply去空白，thenCompose把异步返回标签阶段接成一层；thenCombine合两个数；anyOf读取先已完成的first。allOf返回Void只表达全部完成，若需要结果仍从各原始Future取；anyOf返回Object，教材p696 / PDF p714笼统说两者都Void且不传结果不正确，见[CompletableFuture API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/CompletableFuture.html)。

| 阶段 | 输入 | 返回类型 |
|---|---|---|
| supplyAsync | 无参数Supplier | CompletableFuture<String> |
| thenApply | String→String | CompletableFuture<String> |
| thenCompose | String→CompletableFuture<String> | CompletableFuture<String> |
| 同样函数交thenApply | String→CompletableFuture<String> | 会嵌成Future<Future<String>> |

非Async阶段可能由完成前一阶段的线程或注册阶段时的调用线程执行，不保证新线程；Async通过指定执行器安排，也不保证每一步恰好换一个不同线程。handle有结果/异常两个参数，可转换恢复值；whenComplete更适合观察，不能当同样的结果转换器。thenAccept/thenRun后续通常为Void；Either类与anyOf的异常完成选择规则有差异，不把名字当完整契约。

只把thenCompose换thenApply，先看编译器报出的类型变化，再决定是想保留嵌套还是接平。独立任务在生产阶段抛异常，由handle显示failed，不把所有异常无声换成空串。CompletableFuture.cancel的mayInterruptIfRunning在此类中不负责中断底层执行；需要取消真实任务时另保存运行任务句柄/取消协议，不沿用FutureTask的实现假设。

## 同步器：先辨认协作形状，再选现成工具

Latch像倒数到零后永久打开的门，Barrier像每轮两人集合后再出发的站点；类比边界是异常/取消需要额外处理，障栅坏掉并不等于这轮结果可用。前者等待者可以不参与计数，后者await本身就是报到。

```java
import java.util.concurrent.*;
public class LatchAndBarrierRounds {
    public static void main(String[] args) throws InterruptedException {
        int[] parts = new int[2]; CountDownLatch done = new CountDownLatch(2); Thread[] first = new Thread[2];
        for (int i = 0; i < 2; i++) { final int id = i; first[i] = new Thread(() -> { try { parts[id] = id + 1; } finally { done.countDown(); } }); first[i].start(); }
        done.await(); for (Thread t : first) t.join(); System.out.println("latch=" + (parts[0] + parts[1]));
        CyclicBarrier barrier = new CyclicBarrier(2, () -> System.out.println("round=" + (parts[0] + parts[1]))); Thread[] rounds = new Thread[2];
        for (int i = 0; i < 2; i++) { final int id = i; rounds[i] = new Thread(() -> {
            try { for (int round = 1; round <= 2; round++) { parts[id] = id + round; barrier.await(); } }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); } catch (BrokenBarrierException e) { throw new IllegalStateException(e); }
        }); rounds[i].start(); }
        for (Thread t : rounds) t.join();
    }
}
```

第一段两任务分别填1/2，在finally倒数，main await后结果3；第二段Barrier动作每轮在两人都到齐后求和，输出round=3、round=5。第一人不能在障栅动作完成前直接进入下一轮覆盖数据，因为Barrier会在动作完成后才释放本轮等待者。

只把Latch初值2改1，会让main过早读另一个槽；输出碰巧3不构成保证。独立任务记录每轮“写槽→await→动作→下一轮”四步。实际任务可能失败时，Latch倒数只表示结束到达，不代表成功；结果槽应另保存错误。Barrier支持超时/中断，其他参与者会看到BrokenBarrierException；真实应用应取消剩余参与者，不把catch空块当完成。

## 许可、交换与动态阶段：不必自己拼锁来冒充这些协议

Semaphore计数“可进入的许可”，不天然绑定取得者身份；因此只能在成功acquire后finally release，误多释放会增加可进入人数。Exchanger双向交换，SynchronousQueue单向交接且不保存缓冲元素；Phaser可注册/注销参与者。像门票、交换柜台、分阶段点名三种不同流程，不能只因都能等待就互相替代。

```java
import java.util.concurrent.*;
public class SynchronizerShapes {
    public static void main(String[] args) throws InterruptedException {
        Semaphore permits = new Semaphore(2); Thread[] workers = new Thread[2];
        for (int i = 0; i < workers.length; i++) { workers[i] = new Thread(() -> { boolean got = false; try { permits.acquire(); got = true; } catch (InterruptedException e) { Thread.currentThread().interrupt(); } finally { if (got) permits.release(); } }); workers[i].start(); }
        for (Thread t : workers) t.join(); System.out.println("permits=" + permits.availablePermits());
        Exchanger<String> exchange = new Exchanger<>(); String[] received = new String[2];
        Thread left = new Thread(() -> { try { received[0] = exchange.exchange("left"); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } });
        Thread right = new Thread(() -> { try { received[1] = exchange.exchange("right"); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } });
        left.start(); right.start(); left.join(); right.join(); System.out.println(received[0] + ":" + received[1]);
        Phaser phase = new Phaser(1); phase.register(); Thread worker = new Thread(() -> { phase.arriveAndAwaitAdvance(); phase.arriveAndDeregister(); });
        worker.start(); phase.arriveAndAwaitAdvance(); worker.join(); System.out.println("phase=" + phase.getPhase()); phase.arriveAndDeregister(); System.out.println("terminated=" + phase.isTerminated());
    }
}
```

输出permits=2、right:left、phase=1、terminated=true。Semaphore两个任务仅取得后释放，join后许可恢复；Exchanger两方收到对方文字，不是自动复制对象；Phaser初始只有main，再注册worker，两方完成第一阶段后worker注销，main最后注销令它终止。这里不演示所有调度组合，也不拿单次最大并发数当性能证据。

只把Semaphore.release移到acquire之前，许可会无依据增长；独立任务加AtomicInteger记录进入人数并验证不超过许可总数，而不是强求每次一定恰好两人同时进入。Phaser一旦参与者登记却永不到达，会阻挡阶段推进，必须在取消/失败时明确注销策略；Exchanger同样需要对方或超时/取消，不能误以为只传一个对象就立刻返回。

## SwingWorker：后台算，EDT展示，取消与清理分开

前面Callable/Future解决结果，界面还需要“谁更新控件”的规则。SwingWorker<T,V>有**两个**类型参数，T最终结果、V中间进度；doInBackground在后台，process/done在EDT。publish可能合并为一批process，不保证每publish一次就立即出现一次画面更新。见[SwingWorker API](https://docs.oracle.com/javase/8/docs/api/javax/swing/SwingWorker.html)。

```java
import java.awt.BorderLayout;
import java.awt.EventQueue;
import java.util.List;
import java.util.concurrent.*;
import javax.swing.*;
public class WorkerProgressView {
    static class View {
        final JPanel panel = new JPanel(new BorderLayout()); final JLabel status = new JLabel("ready");
        final JProgressBar progress = new JProgressBar(0, 100); final JButton start = new JButton("开始"), cancel = new JButton("取消");
        Job active;
        View() {
            JPanel buttons = new JPanel(); buttons.add(start); buttons.add(cancel); cancel.setEnabled(false);
            panel.add(status, BorderLayout.NORTH); panel.add(progress); panel.add(buttons, BorderLayout.SOUTH);
            start.addActionListener(e -> begin(new Job(this, true, null, false)));
            cancel.addActionListener(e -> { if (active != null) active.cancel(true); });
        }
        void begin(Job job) { active = job; progress.setValue(0); status.setText("working"); start.setEnabled(false); cancel.setEnabled(true); job.execute(); }
    }
    static class Job extends SwingWorker<Integer, Integer> {
        final View view; final boolean slow, fail; final CountDownLatch gate;
        final CountDownLatch entered = new CountDownLatch(1), exited = new CountDownLatch(1), finished = new CountDownLatch(1);
        boolean background, doneEdt;
        Job(View view, boolean slow, CountDownLatch gate, boolean fail) { this.view = view; this.slow = slow; this.gate = gate; this.fail = fail; }
        protected Integer doInBackground() throws InterruptedException {
            background = !EventQueue.isDispatchThread(); entered.countDown();
            try {
                if (gate != null) gate.await(); if (fail) throw new IllegalStateException("demo"); int sum = 0;
                for (int i = 1; i <= 100; i++) { if (isCancelled()) return sum; if (slow) Thread.sleep(20); sum += i; publish(i); }
                return sum;
            } finally { exited.countDown(); }
        }
        protected void process(List<Integer> batch) { if (view.active == this && !isCancelled() && !batch.isEmpty()) view.progress.setValue(batch.get(batch.size() - 1)); }
        protected void done() {
            doneEdt = EventQueue.isDispatchThread();
            try {
                if (view.active != this) return;
                try { view.status.setText("done=" + get()); view.progress.setValue(100); }
                catch (CancellationException e) { view.status.setText("cancelled"); }
                catch (ExecutionException e) { view.status.setText("failed=" + e.getCause().getClass().getSimpleName()); }
                catch (InterruptedException e) { Thread.currentThread().interrupt(); view.status.setText("interrupted"); }
                finally { view.start.setEnabled(true); view.cancel.setEnabled(false); view.active = null; }
            } finally { finished.countDown(); }
        }
    }
    static void await(CountDownLatch latch) throws InterruptedException { if (!latch.await(3, TimeUnit.SECONDS)) throw new AssertionError("worker timeout"); }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].endsWith("check")) {
            boolean cancel = args[0].equals("--cancel-check"), fail = args[0].equals("--fail-check"); Job[] holder = new Job[1];
            EventQueue.invokeAndWait(() -> { View v = new View(); Job job = new Job(v, false, cancel ? new CountDownLatch(1) : null, fail); holder[0] = job; v.begin(job); });
            Job job = holder[0]; await(job.entered); if (cancel) job.cancel(true); await(job.exited); await(job.finished);
            EventQueue.invokeAndWait(() -> { System.out.println(job.view.status.getText()); System.out.println("background=" + job.background); System.out.println("done-edt=" + job.doneEdt); });
        } else EventQueue.invokeLater(() -> {
            JFrame f = new JFrame("后台计算与取消"); f.add(new View().panel); f.setSize(420, 180); f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setVisible(true);
        });
    }
}
```

默认打开窗口，开始后逐步计算1–100的和，按钮保持响应，可取消。每步20ms暂停**只是教学慢动作**，使2秒内有机会观察进度/取消，真实计算不应为了进度条人为sleep。只有后台读取固定数字，不从后台getText或改label；计算输入应在启动前由EDT读出，再作为普通值传给任务。

| 方法 | 执行位置 | 本例责任 |
|---|---|---|
| begin | EDT | 建新worker、禁开始、启取消 |
| doInBackground | 后台 | 计算、检查取消、publish、finally清理 |
| process | EDT | 当前worker且未取消才更新进度 |
| done | EDT | get已完成结果，分别显示成功/失败/取消，恢复入口 |

一次worker只execute一次，每次开始new；active标识防止旧任务延迟到来的进度覆盖新任务。done中get此时已完成，不能在按钮处理器execute后立刻get，否则又堵EDT。后台失败由getCause显示，取消单独捕获；不是只隐藏进度条就算取消成功。

在课程根目录PowerShell，默认命令打开窗口；追加`-ProgramArgs '--check'`做无窗口成功检查，输出done=5050、background=true、done-edt=true。改参数`--cancel-check`把后台停在可中断门闩，确认进入后再cancel，且**另等后台finally退出**，输出cancelled、background=true、done-edt=true；`--fail-check`输出failed=IllegalStateException及同样线程归属。它们检查真实SwingWorker调度与组件更新，不冒称已经替你点击真实窗口取消。

只把UI更新移到doInBackground，即使一次看似正常也违反本课EDT规则；不靠等待出现随机异常才判错。独立任务修改为后台读取你明确选择的文本文件，启动前选文件、后台用UTF-8 Reader/try-with-resources、分批publish行数，取消及时退出；不要把整个PDF或任意目录扫描塞给程序。I/O不保证都可被中断，要按具体接口设计关闭策略。

invokeLater/AndWait都在已有EDT执行回调，不新建一个“UI线程”；不得在EDT里invokeAndWait，也不要让worker持业务锁等待EDT而EDT又等该锁。教材p709 / PDF p727的少数线程安全方法清单不能当绕过当前组件API契约的通行证，本课统一把控件读写放EDT，避免依赖观感/版本例外。

在课程根目录PowerShell运行`./java.ps1 -Source './L53_第14章E_Future执行器与SwingWorker/code/WorkerProgressView.java'`。
