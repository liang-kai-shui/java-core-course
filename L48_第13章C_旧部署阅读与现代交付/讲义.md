## 为什么书上让浏览器运行Java，我的浏览器却只显示一个空白

这是教材年代与当前运行环境的差别。**applet**曾由浏览器插件/查看器提供宿主，负责创建对象、调用生命周期、给参数与上下文；**Java Web Start**由JNLP描述启动外部桌面应用，通常仍有独立窗口；普通桌面应用由启动器调用main。像同一场表演曾在商场提供的舞台上演出，今天改成自带舞台，表演内容可复用，谁开门、布置、收场却必须重新安排。类比边界是运行权限与资源访问也会变化，不能只改类名就宣称迁移完成。

本课程默认JDK21：Java部署栈（浏览器插件、Java Web Start、javaws等）在JDK11移除，appletviewer也已移除；Applet API在21中仍存在但已标为待移除，**API类还能被找到不等于浏览器宿主还能运行**。参见[Oracle迁移说明](https://docs.oracle.com/en/java/javase/21/migrate/removed-tools-and-components.html)。这部分按历史设计阅读，不要求安装旧插件、降低浏览器信任或购买证书才能过关。

## 从网页参数图表，迁到独立窗口

教材p603–608 / PDF p621–626通过宿主参数传给图表。要保留的是“输入数据与绘图分开”，不是继续依赖getParameter。下面把数据显式交给普通组件，再由main在EDT创建窗口。

```java
import java.awt.*;
import java.awt.image.BufferedImage;
import javax.swing.*;
public class StandaloneStudyChart {
    static class Bars extends JPanel {
        private static final long serialVersionUID = 1L;
        final int[] values;
        Bars(int[] values) { this.values = values.clone(); for (int v : values) if (v < 0) throw new IllegalArgumentException("negative"); setBackground(Color.WHITE); }
        public Dimension getPreferredSize() { return new Dimension(320, 180); }
        protected void paintComponent(Graphics g) {
            super.paintComponent(g); if (values.length == 0) return;
            int max = 0; for (int v : values) max = Math.max(max, v); if (max == 0) return;
            int width = Math.max(0, getWidth() - 40), height = Math.max(0, getHeight() - 40); g.setColor(Color.RED);
            for (int i = 0; i < values.length; i++) {
                int cell = width / values.length, h = (int) ((long) height * values[i] / max);
                g.fillRect(20 + cell * i, getHeight() - 20 - h, Math.max(0, cell - 6), h);
            }
        }
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) EventQueue.invokeAndWait(() -> {
            Bars bars = new Bars(new int[] {20, 40}); bars.setSize(320, 180); BufferedImage image = new BufferedImage(320, 180, BufferedImage.TYPE_INT_RGB);
            Graphics2D g = image.createGraphics(); try { bars.printAll(g); } finally { g.dispose(); }
            System.out.println("bars=" + bars.values.length); System.out.println("painted=" + (image.getRGB(30, 150) == Color.RED.getRGB()));
        }); else EventQueue.invokeLater(() -> {
            JFrame f = new JFrame("独立学习图表"); f.add(new Bars(new int[] {20, 40})); f.pack(); f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setVisible(true);
        });
    }
}
```

默认窗口有两根柱，分别表示20与40分钟；改变窗口大小重新按当前区域计算，不直接获取屏幕Graphics。--check在离屏图像上绘制，输出bars=2和painted=true；它验证绘图逻辑，不证明真实窗口键盘与缩放已被人工检查。

### 为什么这次不需要init、getCodeBase

Bars构造器明确接收int[]并clone，调用者后续改原数组不会暗改图。main是启动入口，EventQueue.invokeLater把组件构造放EDT。绘制先super清背景，w/h按当前组件尺寸算；最大值为0时不除以0。x按柱号分配，y由底线减柱高；数据非负是本例明确的业务范围，不冒称实现教材含负值的完整直方图。

| 旧宿主功能 | 本课独立应用里由谁负责 | 注意边界 |
|---|---|---|
| init创建界面 | main安排EDT、构造组件 | 构造器不是浏览器自动回调 |
| HTML param | 构造参数/args/Properties | 字符串解析仍需检查缺失和格式 |
| codebase资源 | Class.getResourceAsStream | 不用终端当前位置猜包内资源 |
| start/stop激活 | 显式开始/暂停，关闭时清理 | Applet.stop与Thread.stop不同 |
| AppletContext | 明确的应用服务接口 | 没有隐藏的浏览器上下文 |

只把数据改为{0,0}，预测两柱都不填充且不除零；独立任务：改三根柱、标出标题，保持空数组与全0可运行，再考虑负数图表应如何画零线。别一开始抄全部历史图表把宿主和绘图错误混在一起。

## 生命周期仍有价值，但今天需要自己安排

历史init用于初始化，start在激活时恢复，stop在离开时暂停，destroy在销毁时清理；反复访问不等于每次重建所有东西。独立程序也需要构造、开始、暂停、关闭，但触发来自自己的按钮/窗口监听，不能只把方法命名成start就等系统来调用。Applets的stop回调含义是宿主生命周期，不是调用危险的Thread.stop杀线程；并发章使用协作取消。

## JNLP是启动描述，不是Java源代码

历史JNLP的information提供标题/供应者，resources指向JAR与运行时要求，application-desc描述应用启动；MIME类型帮助浏览器关联启动器，缓存与快捷方式由当时启动环境处理。一个XML文件不能凭空让当前JDK拥有javaws。第三方遗留兼容方案有自己的支持范围，本课不配置；当前交付采用普通JAR，或选读jpackage应用映像。

历史javax.jnlp.ServiceManager按名字取得FileOpenService等服务，与Java8标准ServiceLoader接口发现机制不是一个API。以前受限程序通过宿主提供的文件内容对象读写，普通桌面程序可直接使用JFileChooser和流，但**文件选择器不会自动建立同样沙箱**。普通应用按运行用户权限操作文件，仍要尊重选择、取消、覆盖与I/O失败。

签名用于核实签名内容完整性及相关身份链，验证成功不等于程序没有恶意或漏洞；密封、签名、加密、权限各是不同机制。旧书的sandbox/all-permissions清单是旧部署环境规则，不能在普通JAR里加一行就让当前JVM产生浏览器沙箱。现代SecurityManager状态也已变化，此处不拿历史沙箱承诺作为今天的安全隔离方案。

## 开始、暂停、关闭：先画状态，再接定时器

```java
import java.awt.EventQueue;
import javax.swing.Timer;
public class SessionLifecycle {
    static class Session {
        int count; boolean running, closed;
        final Timer timer = new Timer(1000, e -> count++);
        boolean start() { if (closed || running) return false; running = true; timer.start(); return true; }
        void pause() { timer.stop(); running = false; }
        void close() { pause(); closed = true; }
    }
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            Session s = new Session(); System.out.println(s.start()); System.out.println(s.start());
            s.pause(); System.out.println(s.start()); s.close(); System.out.println(s.start()); System.out.println(!s.timer.isRunning());
        });
    }
}
```

程序在EDT构造会话并立即验证状态，不等待Timer触发，输出true、false、true、false、true。第一次start成功，重复start拒绝；pause可再start，close以后永久拒绝。--check没有必要，本例本来就是状态检查；时间通知的真实运行已经在L42的SwingTimerTicks演示。count是将来回调改变的累计数，这里不以回调次数验证墙上时间。

只删掉start中的running判断，会怎样误报重复开始？如果改成每次new Timer，旧实例还可能继续跑。独立任务：加暂停按钮和状态标签，所有操作保留EDT约束；窗口关闭监听调用session.close，不仅隐藏窗口而留下仍在工作的计时器。

package campus.app;
import java.awt.EventQueue;
import java.io.*;
import java.util.Scanner;
import javax.swing.*;
public class DeployMain {
    public static void main(String[] args) {
        String title;

            f.setSize(360, 150); f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setVisible(true);
        });
    }
}

### 可移动JAR与选做应用映像

在课程根目录PowerShell运行`./project.ps1 -Project L48 -Mode Jar`，输出ready与资源标题；加`-ProgramArgs '--window'`显示真实窗口，手动关掉才结束。Build模式列出新建目录、classes和app.jar，List列出归档内容。把app.jar复制到课程内my_code/release，再从另一个工作目录用已解析的JDK下`java.exe -jar 完整JAR路径`启动，正文资源仍从JAR读取。

下面是**JDK21适配选做**。jpackage可把应用与运行时组成当前平台的应用映像；不是把.class翻译成所有平台通用的原生机器码，也不需要把教材PDF塞进程序。--type app-image生成目录，不安装系统软件；exe/msi安装包还有平台工具条件。本课先讲可复现操作，不把这一选做步骤计入Java8 API示例的测试结论，见[jpackage官方命令](https://docs.oracle.com/en/java/javase/21/docs/specs/man/jpackage.html)。

从课程根目录PowerShell开始，依次执行（变量与当前目录留在同一个终端）：

<!-- verify-command: package -->
```powershell
. .\_课程工具\resolve-jdk.ps1
$courseJdk = Find-CourseJdk -Root $PWD.Path
$buildLines = .\project.ps1 -Project L48 -Mode Build
$appLine = $buildLines | Where-Object { $_ -like 'Application: *' }
$appJar = $appLine.Substring('Application: '.Length)
$packageRoot = Join-Path $PWD.Path ('.build\package-' + [guid]::NewGuid().ToString('N'))
$packageInput = Join-Path $packageRoot 'input'
$packageDest = Join-Path $packageRoot 'image'
New-Item -ItemType Directory -Path $packageInput -Force | Out-Null
Copy-Item -LiteralPath $appJar -Destination (Join-Path $packageInput 'app.jar')
& (Join-Path $courseJdk 'bin\jpackage.exe') --type app-image --input $packageInput --main-jar app.jar --name CourseWindow --dest $packageDest --arguments '--window'
if ($LASTEXITCODE -ne 0) { throw 'Packaging failed; do not use an older image.' }
Write-Output (Join-Path $packageDest 'CourseWindow\CourseWindow.exe')
```

成功会打印新映像中的exe路径，双击这个exe出现窗口；交付时需要整个CourseWindow目录，不能只拷exe。每次使用唯一目录避免误认旧映像。找不到jpackage先检查本课程JDK配置，不修改全局PATH；失败保留首条诊断。这个映像在Windows制作，不能交给macOS当本地应用运行；普通JAR与平台映像应分别写清运行条件。
