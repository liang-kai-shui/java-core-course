> 前置：L11–L17；L10数组

## 学完要能做什么

能从需求识别值对象与可变业务对象；用封装维护规则；写出对象协作和独立边界验证，不把菜单、输入与状态塞进同一个类。

## 困惑：已经会写类，为什么一改需求就到处改

你要管理一项学习任务：标题、开始日期、目标分钟、已经完成分钟。若这些数据散在四个平行数组，调用者每次都要记住同一下标是一项任务，还要手工限制进度不超过目标。先把同一件事的数据和操作收拢，再讨论是否需要更多类。

类比一张学习计划卡：任务保存自己的进度；日历日期是另一张不可变值卡；启动程序扮演安排流程的人。类比边界是“名词都建类”不保证好设计。一个只转发一行代码的空壳也可能增加负担，应依据职责与变化原因划分。

## 先把需求写成可验证规则

本例约定目标至少1分钟，非正目标修正为1；记录的增量必须为正，否则返回false；到达目标后停止增加，超额只记到目标。日期是LocalDate，返回它可安全共享不可变值；标题是String。构造调用方为标题/日期提供非null值，后续L30可用异常强化这个契约。

```java
import java.time.LocalDate;
public class StudySprint {
    public static void main(String[] args) {
        StudyGoal goal = new StudyGoal("数组", LocalDate.of(2025, 3, 1), 30);
        System.out.println(goal.summary());
        System.out.println(goal.record(20));
        System.out.println(goal.record(20));
        System.out.println(goal.summary());
        System.out.println(goal.record(5));
    }
}
class StudyGoal {
    private final String title;
    private final LocalDate start;
    private final int target;
    private int done;
    StudyGoal(String title, LocalDate start, int target) {
        this.title = title;
        this.start = start;
        this.target = target > 0 ? target : 1;
    }
    boolean record(int minutes) {
        if (minutes <= 0 || done == target) return false;
        int remaining = target - done;
        done += Math.min(minutes, remaining);
        return true;
    }
    String summary() { return title + "@" + start + " " + done + "/" + target; }
}
```

输出`数组@2025-03-01 0/30`、`true`、`true`、`数组@2025-03-01 30/30`、`false`。如果你猜最后一次还能成功，需要回到“到目标后拒绝”的规则，而不是只看方法名record。

`StudyGoal`只管任务状态，不读取键盘、不调用println、不把自己保存到文件。`StudySprint.main`负责组织操作与显示。两者存在**依赖**：main使用StudyGoal；StudyGoal**拥有一个日期引用**，是has-a关系，不应为了“日期也是对象”而让任务extends LocalDate。继承表示is-a，下一章再严查适用条件。

`remaining=target-done`先算剩余，再用`Math.min(minutes,remaining)`选择本次能接纳的量。这样避免直接`done+minutes`在巨大正输入时先溢出，也使不变量`0<=done<=target`可逐条检查。访问器返回一个组合描述，不暴露可任意设置的done字段。

| 操作 | done之前 | remaining | 本次增加 | done之后 |
|---|---:|---:|---:|---:|
| record(20) | 0 | 30 | 20 | 20 |
| record(20) | 20 | 10 | 10 | 30 |
| record(5) | 30 | 0 | 拒绝 | 30 |

## 设计审查：每个字段都需要setter吗

不需要。done的公开操作是“记录一次有效学习”，不是“随意改已学分钟”。target本例构造后固定，用final表达不再重绑；未来若允许改目标，要规定低于已完成时如何处理，再设计操作。日期使用LocalDate，比三个松散整数更能表达合法日期；这是用已有值类型减少本类需要维护的规则。

私有字段允许以后更换表示，例如把分钟改为另一种内部记录，只要公开操作契约一致，调用者不一定要跟着改。描述方法也不是equals：两项同标题任务可仍是不同身份；L21会专门讨论内容相等的契约，别急着把toString当数据库键。

本阶段先让业务可独立跑通。将类拆成包项目时，对应目录可以是`src/study/model/StudyGoal.java`与`src/study/app/Main.java`，模型类和跨包使用的构造器/方法需public，Main import正确全名，classpath指编译输出根。不要仅把两个文件丢进不同文件夹却忘记package和权限。S04项目工具可以帮助你对照结构；本课独立任务仍允许单文件，避免把打包操作混成业务正确性的替代品。

## 只改一处，找出规则是否稳固

把第一次record(20)改成record(-1)，应拒绝，第二次20后仍未完成，最后5还能成功。再换一份副本把目标30改成1，第一次正输入即到1，后续拒绝。每次修改前先写四列：输入、返回、done、是否违反不变量。

独立小项目：管理“阅读”和“练习”两个目标，放进StudyGoal数组，分别执行不同增量，再用增强for统一显示。数组保存的是引用，不会把两个任务合成一个。若两个进度总一起变，检查是不是把同一个new的引用放进两个位置。

阶段审查可按三句话自测：能解释每个状态归谁；能指出所有修改状态的入口；能用零/负数/超额/完成后再记录来反驳错误实现。篇幅长或类多不是完成证据。

## 数组两项不等于两个任务：先核对对象身份，再核对业务规则

学习组合对象时，很容易把`new Goal[]{one,one}`看成复制任务。它只是复制两条引用，像同一张计划卡在目录中出现两次；边界是数组确实有两个元素，只是元素所指的业务对象相同。

```java
public class GoalAliasWalk {
    public static void main(String[] args) {
        SmallGoal one = new SmallGoal();
        SmallGoal[] shared = {one, one};
        shared[0].record(3);
        System.out.println(shared[0].done() + ":" + shared[1].done());
        SmallGoal[] independent = {new SmallGoal(), new SmallGoal()};
        independent[0].record(3);
        System.out.println(independent[0].done() + ":" + independent[1].done());
    }
}
class SmallGoal {
    private int done;
    boolean record(int amount) {
        if (amount <= 0 || done == 10) return false;
        done += Math.min(amount, 10 - done);
        return true;
    }
    int done() { return done; }
}
```

数组初始化里的one出现两次，没有执行第二次new Goal。通过shared[0]记录3以后，shared[1]读到同一done。independent则显式new两次，因此只第一项变3。增强for拿引用副本仍能调用方法改对象，和L10的int临时值自增不同。

| 数组 | 第0项操作前/后 | 第1项看到的done | 原因 |
|---|---|---:|---|
| shared | 0→3 | 3 | 同一对象 |
| independent | 0→3 | 0 | 两次new |

`record`先拒绝非正和完成后的请求，再算剩余，最多加到target；不先计算可能溢出的done+minutes。本例目标固定10，合法状态0–10。只把3改Integer.MAX_VALUE，预测两组各自状态；然后恢复。独立任务：在自己的两项目标中先列“数组位置→对象A/B”的图，再执行不同增量，证明进度不同来自独立状态，而不是恰好打印了不同标签。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L18_第04章H_类设计阶段项目/code/GoalAliasWalk.java'`。改动先复制到my_code，命令相应替换目录。
