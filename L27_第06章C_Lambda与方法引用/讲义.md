## 困惑：箭头右边的代码，到底什么时候运行

上课结束时要播放一句提醒。你先保存提醒动作，稍后再调用它。Lambda是为**函数式接口**提供单个抽象操作实现的简写，不是写到哪就立刻执行到哪的命令。像把步骤写在便条上交给工作人员，拿到便条和照便条办事是两件事。边界是Lambda不会自动开线程、自动排队或自动延迟一秒；这些时机来自接收它的API。

从完整写法开始：L26中一个类implements CompleteHook，再写completed方法。若接口只有一个抽象操作，调用者可用`title -> System.out.println(title)`提供它的实现，省去另起类名。参数类型、返回要求从目标接口推导；不是任何随意代码块都能赋给Object。

```java
import java.util.function.IntConsumer;
public class LambdaTiming {
    static void repeat(int n, IntConsumer action) {
        for (int i = 0; i < n; i++) action.accept(i);
    }
    public static void main(String[] args) {
        String message = "复习";
        Runnable action = () -> System.out.println(message);
        System.out.println("created");
        action.run();
        repeat(3, i -> System.out.println("第" + i + "次"));
    }
}
```

输出`created`、`复习`、`第0次`、`第1次`、`第2次`。action创建时没有输出“复习”；action.run()才执行。Runnable的抽象操作无参数、无返回，因此箭头前必须保留空括号`()`，箭头后println调用产生动作，不返回一个业务值。

IntConsumer接受一个int而不返回值，抽象操作名accept。`repeat(3, i -> ...)`把动作和重复次数交给repeat；循环每次调用accept(i)，i值0、1、2成为Lambda形参。这个Lambda没有自己猜轮次，也没有捕获repeat内部会变化的循环变量，i是每次调用传入的新参数。

| 代码经过哪里 | 是否执行Lambda体 | 输出 |
|---|---|---|
| Runnable action=... | 否，先建立动作 | 无 |
| println created | 不涉及 | created |
| action.run() | 是 | 复习 |
| repeat第0/1/2轮accept | 各执行一次 | 对应轮次 |

## 语法按“参数→执行体”读

两个参数写`(a,b) -> 表达式`；一个可推导类型参数可省括号；无参数必须`() -> ...`。单个表达式且接口需要返回值时，表达式结果就是返回值，例如Comparator<String>的`(a,b) -> Integer.compare(a.length(),b.length())`。有多条语句用花括号，返回值接口需要各正常分支明确return，不能只在某一分支返回。

函数式接口按有效抽象操作判断；default/static方法不增加待实现操作，Object的public方法等价声明也不计入那个单一操作。@FunctionalInterface让编译器检查这个设计承诺，但不是必须写了注解才算。Comparator虽还有默认方法，仍可接Lambda。BiFunction<String,String,Integer>参数/返回看着相近，却不是Comparator；Java按接口类型与用途约束，不仅比对“两个参数一个结果”的外形。

常用标准接口要连方法名一起记：Supplier<T>.get不接参数并产生T；Consumer<T>.accept接T做事；Function<T,R>.apply接T返回R；Predicate<T>.test接T返回boolean。IntConsumer等基本类型特化可减少装箱。先根据动作需要什么输入和输出选择接口，不要为了练箭头自造一堆重复接口。

## 捕获的是局部值，不是任意可变格子

本例message是外围main局部变量，Lambda捕获其值，要求它为final或**事实上final**：初始化后不再重新赋值。若在action.run前加message="别的"，即使你觉得“执行时再读新值也行”，Java8编译也会拒绝。普通for的循环变量持续变化，不能直接被捕获；可以在每轮定义新的局部快照，或像本例把轮次作为回调参数。

引用局部变量不重绑，不等于它指向的对象被冻结。捕获一个ArrayList引用后，列表内容仍可变；若多线程同时改还要同步，不能靠final自动解决。Lambda中的this沿用外围实例方法的this，在静态main里没有this。匿名内部类中的this则属于匿名实例，L28对照。

## 方法引用是把已有方法交出去

后文给出完整MethodReferenceForms。`对象::实例方法`绑定接收者，例如System.out::println；`类::静态方法`例如Integer::parseInt；`类::实例方法`把第一个函数参数当接收者，例如String::compareToIgnoreCase读作(a,b)->a.compareToIgnoreCase(b)。`类::new`引用构造器，`String[]::new`根据长度创建数组。双冒号本身不是立刻执行，仍要有目标函数式接口并在对应get/apply/compare等处调用。

不要直接把无参greet方法引用交给需要ActionEvent参数的ActionListener；函数签名要匹配，可用event->greet()显式忽略事件。本书p237假想例子不能省略这项类型核对。构造器引用的重载也按上下文选择，不会“任意挑一个”。

## 四种引用，逐个调用

每个变量旁先写成普通Lambda读法，再运行。Consumer<String>接一段文字不返回；Function<String,Integer>接字符串返回包装整数；Comparator<String>接两段文字返回比较结果；IntFunction<String[]>接长度返回字符串数组。尖括号说明输入/输出类型，不是调用参数。

```java
import java.util.Comparator;
import java.util.function.Consumer;
import java.util.function.Function;
import java.util.function.IntFunction;
public class MethodReferenceForms {
    public static void main(String[] args) {
        Consumer<String> printer = System.out::println;
        Function<String, Integer> parser = Integer::parseInt;
        Comparator<String> order = String::compareToIgnoreCase;
        IntFunction<String[]> factory = String[]::new;
        printer.accept("hello");
        System.out.println(parser.apply("12"));
        System.out.println(order.compare("a", "B") < 0);
        System.out.println(factory.apply(2).length);
    }
}
```

输出`hello`、`12`、`true`、`2`。数组槽位仍是null，长度2不代表两条文字已经创建；这又连接到L10数组模型。只把factory.apply(2)改0，最后行0。比较只输出是否小于0，避免把合法的任意负返回误当必须-1。方法引用的接收者映射与实际执行点，比双冒号写得短更重要。

## 谓词与组合排序：每一步各负责一件事

Predicate<String>的test返回是否符合条件。removeIf把每个元素交给谓词，true的元素删除；它在API内管理遍历，不用你在增强for中边遍历边删。Comparator.comparingInt提取整数键，thenComparing在第一键相等时比较第二键，nullsLast先处理null再交内部比较器。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.function.Predicate;
public class PredicateAndOrdering {
    public static void main(String[] args) {
        ArrayList<String> words = new ArrayList<>(Arrays.asList("bb", "", null, "aa", "b"));
        Predicate<String> empty = s -> s != null && s.isEmpty();
        words.removeIf(empty);
        Comparator<String> core = Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder());
        words.sort(Comparator.nullsLast(core));
        System.out.println(words);
    }
}
```

输出`[b, aa, bb, null]`。先去掉唯一空串，null保留；按长度排b先，同长aa先于bb，null最后。`s != null && s.isEmpty()`利用短路，不在null上调用方法。`Comparator.naturalOrder()`这里根据上下文得到String自然顺序；reversed会反转整个被调用的比较器，而不只反转你心里想到的某个键，使用前写清预期。只把nullsLast改nullsFirst，null移到最前，其余相对规则不变。

## 捕获的引用不能重绑，为什么对象内容仍能改变

把局部引用想成固定写着某个登记本编号的凭证，固定凭证不等于把登记本每页封死。边界是这仅解释可变对象共享，不意味着多线程修改就安全；本程序全在同一次main同步执行。

```java
import java.util.ArrayList;
public class CapturedReferenceState {
    public static void main(String[] args) {
        ArrayList<String> names = new ArrayList<>();
        Runnable show = () -> System.out.println(names.size());
        names.add("林");
        show.run();
        names.clear();
        show.run();
    }
}
```

names局部变量初始化后没再赋值，满足effectively final。Lambda体运行时通过捕获的同一引用读取列表当前size：创建动作时列表空，调用前add，故第一次看到1；clear之后再调用看到0。没有把创建动作时的所有对象内容做快照。

| 时刻 | names引用 | 所指列表size | 是否运行动作 |
|---|---|---:|---|
| 创建Runnable | 固定同一列表 | 0 | 否 |
| add之后 | 未重绑 | 1 | 否 |
| 第一次run | 同上 | 1 | 是，打印1 |
| clear后再run | 同上 | 0 | 是，打印0 |

只在第一次run前加入`names=new ArrayList<>();`，预计编译失败；改的是局部引用而非列表内容。独立任务：若需要保存创建动作时的“数量快照”，先取`int saved=names.size()`再捕获saved，对比它与运行时size。明确你需要的是哪一种语义，不用长度1数组偷渡计数来逃避理解捕获规则。
