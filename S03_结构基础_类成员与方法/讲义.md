## 0. 从“照着用类”走向“自己组织一个类”

S02已经画出借书卡与凭证。现在要做积分卡：每张卡有自己的持有人和积分，还要统计总共创建过几张卡。两张卡的积分不能串在一起，但发卡数量应一起累计。

如果把每个变量都加static，两人就可能误用一份积分；如果一律不加，类级统计又不好表达。**先问“这项数据属于哪一张卡，还是属于这个类的公共状态”，再选修饰词。**

分三次学：先读下面三个独立实验MemberOwnership、ConstructorDoorSteps、FieldAndLocalDefaults；再回到ObjectWorkshop综合；最后画参数副本。每次先画一份数据归属图，再运行相应阶段。

## 1. 三种位置，各自拥有数据

| 写在哪里 | 名称 | 这次怎样理解 |
|---|---|---|
| 方法内部 | 局部变量 | 本次调用中使用的临时记录 |
| 类内部、方法外，不带static | 实例字段 | 每张卡各有一份 |
| 类内部、方法外，带static | 静态字段 | 本例同一类的公共记录 |

把实例字段类比成每张积分卡上的格子，静态字段是总服务台的发卡计数，局部变量是办理一次业务时用的草稿。边界是：Java的静态字段按运行时的类归属，复杂的类加载环境可能不止一份同名类；本课在一个普通应用中观察，不把它夸成全世界唯一。

```text
PointsCard公共状态：created = 2
卡A：owner=Lin，points=2
卡B：owner=Mei，points=0
main临时记录：first→A，second→B
```

## 分步实验一：先只看字段到底归谁

不要先把构造器重载和参数重绑塞进来。这次只建两张小积分卡，给第一张加3，最后读公共创建数。状态类比为个人卡面的积分与总柜台发卡计数；边界是这里记录“创建过”，不是“当前还活着”，不随垃圾回收自动减一。

```java
public class MemberOwnership {
    public static void main(String[] args) {
        MemberState a = new MemberState("Lin", 2);
        MemberState b = new MemberState("Mei", 0);
        a.add(3);
        System.out.println(a.describe());
        System.out.println(b.describe());
        System.out.println("created=" + MemberState.created());
    }
}
class MemberState {
    private final String owner;
    private int points;
    private static int created;
    MemberState(String owner, int points) { this.owner = owner; this.points = points; created++; }
    void add(int amount) { points += amount; }
    String describe() { return owner + ":" + points; }
    static int created() { return created; }
}
```

输出Lin:5、Mei:0、created=2。MemberState.owner/points是每对象各一份；created为static，属于本例这一运行时类。main中的a/b是本次调用里的引用变量，add的amount是那次方法调用的参数，也不等于字段。

| 操作 | a.points | b.points | 公共created |
|---|---:|---:|---:|
| 建第一张 | 2 | 无对象 | 1 |
| 建第二张 | 2 | 0 | 2 |
| a.add(3) | 5 | 0 | 2 |

只把a.add(3)换成b.add(3)，输出应Lin:2、Mei:3、created=2。再在错误建模副本把points改static，两个对象就不再有独立积分，后创建的0会覆盖公共值；这不一定编译失败，因而属于模型错误，要靠状态表和运行发现。当前示例只使用小整数追踪，完整容量/失败不修改规则见原E2。

独立小任务：在表上增加第三个new，预测created与旧卡积分。新增对象与调用旧对象add是两个不同事件，不能每加一次分就把created加一。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './S03_结构基础_类成员与方法/code/MemberOwnership.java'`。改动先复制到my_code，命令相应替换目录。

## 分步实验二：两个入口，为何不产生两张卡

只填姓名的申请单把默认积分0补上，再走双参数入口。this(owner,0)委托的是同一个正在构造的对象；只有new表达式才在这次路径上要求创建新对象。类比边界是构造器不是可以给旧对象再跑一遍的普通重置方法。

```java
public class ConstructorDoorSteps {
    public static void main(String[] args) {
        new DoorCard("Lin");
        new DoorCard("Mei", 4);
        System.out.println("created=" + DoorCard.created());
    }
}
class DoorCard {
    private static int count;
    private final String owner;
    private final int points;
    DoorCard(String owner) { this(owner, 0); System.out.println("outer"); }
    DoorCard(String owner, int points) {
        this.owner = owner; this.points = points; count++;
        System.out.println("core:" + this.owner + ":" + this.points);
    }
    static int created() { return count; }
}
```

输出core:Lin:0、outer、core:Mei:4、created=2。第一张进入单参构造器，先执行双参核心入口，返回后打印outer；第二张直接双参，不打印outer。核心入口的created++各执行一次。

| new表达式 | 首选入口 | 实际调用路线 | 新对象数 |
|---|---|---|---:|
| new DoorCard("Lin") | String | 单参→双参→单参剩余 | 1 |
| new DoorCard("Mei",4) | String,int | 双参 | 1 |

this.owner=owner左侧字段、右侧参数；this(...)是构造器委托，两种this用法按括号或点区分。本课程Java8规则要求委托放第一条语句；把outer打印移到this之前会编译失败。只把0默认分改2，第一条core显示2，总数仍2；改变默认值没有改变new次数。

独立小任务：给单参入口画完整执行箭头，说明为什么把created++放在两个入口都会执行的位置可能重复统计。先确定共享的核心初始化点，不要看到两个构造器就每个都加一次数。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './S03_结构基础_类成员与方法/code/ConstructorDoorSteps.java'`。改动先复制到my_code，命令相应替换目录。

## 分步实验三：字段有默认值，局部变量不能照搬

为了观察Java规则，这个诊断小类故意不给三个字段显式初值；它不是建议业务对象总靠默认null凑合运行。新对象字段先得到0、false、null，main的局部int local只有声明时却没有可读值。

```java
public class FieldAndLocalDefaults {
    public static void main(String[] args) {
        DefaultState state = new DefaultState();
        int local;
        System.out.println(state.number);
        System.out.println(state.active);
        System.out.println(state.label);
    }
}
class DefaultState {
    int number;
    boolean active;
    String label;
}
```

正常输出0、false、null。println遇到引用null会显示文字null，不意味着有一个叫null的String对象；真正对该引用调用实例方法才会失败。局部变量local没有被读取，所以单纯声明本身可以编译。

只把System.out.println(state.number)改为System.out.println(local)，预期编译失败。再在另一正常副本把local声明改为int local=6，随后读它才能输出6。这两步要分开，不拿编译失败的程序继续跑。

还要纠正一种易混表述：本课PointsCard构造器已有形参points，若再写int points=points，会因同方法范围重复声明而先编译失败；在另一个没有同名参数的方法里写int value=value，则因读取未初始化局部变量而失败。二者都不是字段初始化的正确方法，诊断原因却不同。this.points=points才明确写字段。

独立小任务：在原构造器旁用箭头把每个等号的左右角色标出；能读到默认null不代表字段满足“名字必须非空”的业务规则，构造器仍应建立有效状态。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './S03_结构基础_类成员与方法/code/FieldAndLocalDefaults.java'`。改动先复制到my_code，命令相应替换目录。

## 2. 综合程序：分步实验完成后再合起来追踪

新建ObjectWorkshop.java，下面两个类放在同一文件。可以先在自己的副本保留main前三条输出之前的代码，等看懂后再加入参数实验；此处给出最终完整版本，方便逐段核对。

```java
public class ObjectWorkshop {
    public static void main(String[] args) {
        PointsCard first = new PointsCard("Lin", 2);
        PointsCard second = new PointsCard("Mei");
        first.add(3);
        System.out.println(first.describe());
        System.out.println(second.describe());
        System.out.println("created=" + PointsCard.getCreated());
        int number = 2;
        changeNumber(number);
        System.out.println("number=" + number);
        replaceCard(first);
        System.out.println(first.describe());
        System.out.println("created=" + PointsCard.getCreated());
    }

    private static void changeNumber(int copy) {
        copy = 99;
    }

    private static void replaceCard(PointsCard copy) {
        copy.add(1);
        copy = new PointsCard("temporary", 0);
        copy.add(10);
    }
}

class PointsCard {
    private final String owner;
    private int points;
    private static int created = 0;

    public PointsCard(String owner, int points) {
        this.owner = owner;
        this.points = points;
        created++;
    }

    public PointsCard(String owner) {
        this(owner, 0);
    }

    public void add(int amount) {
        if (amount > 0) {
            points += amount;
        }
    }

    public String describe() {
        return owner + ":" + points;
    }

    public static int getCreated() {
        return created;
    }
}
```

从课程根目录的PowerShell运行：

```powershell
.\java.ps1 -Source '.\S03_结构基础_类成员与方法\my_code\ObjectWorkshop.java'
```

预期六行是：

```text
Lin:5
Mei:0
created=2
number=2
Lin:6
created=3
```

看到结果后别急着继续。下面解释每一层怎样导致这些数字；如果某行与你预测不同，从首次不同的状态开始查。

## 3. 构造器在建立状态，不是另一种main

`new PointsCard("Lin", 2)`根据参数选择接收String和int的构造器：this.owner取右边参数，this.points同理，created再加一。**构造器名与类相同，没有返回类型。** 写成`void PointsCard(...)`会变成普通方法，不再是想要的构造器。

第二个构造器只收姓名，第一行`this(owner, 0)`调用同类的双参数构造器。像“只填姓名的表单”自动采用积分0，再走统一的初始化流程。它不创建第二个PointsCard对象；调用一次new仍建立一张卡。

这叫**重载**：同名操作接收不同参数列表，编译器按调用的参数选择。不能仅靠返回类型不同重载。`this.owner`与`this(...)`也不是同一件事：前者访问当前对象字段，后者在构造器内委托另一个构造器。本课采用Java 8规则，构造器委托写在第一条语句。

### 局部变量和字段的默认值不同

本例显式初始化字段。Java也会给新对象的字段默认值：整数0、boolean为false、引用null；局部变量使用前则必须能确认赋值。不要在这个已有points形参的构造器里再写`int points = points;`，这会在同一方法范围重复声明而编译失败；另一个无同名参数的方法里`int value = value;`则会读取尚未确定赋值的局部变量而失败。`points = points`只给参数自身赋值。正确区分this.points与参数points。

如果一个类完全没声明构造器，编译器会提供默认无参构造器；自己写过带参构造器后，不会再自动补一个可用的无参版本。把本例改成`new PointsCard()`会编译失败，先看实际有哪些参数入口。

## 4. 为什么static方法里不能直接写points

`first.add(3)`带着目标卡A，add中的points就指A的points。`PointsCard.getCreated()`不指定某张卡，只读公共统计。

| 调用 | 是否指定具体卡 | 方法怎样找到数据 |
|---|---|---|
| first.add(3) | 是，A | this是A，操作A的points |
| second.describe() | 是，B | this是B，读B的字段 |
| PointsCard.getCreated() | 否 | 直接读本类静态字段created |

如果在getCreated里直接`return points;`，究竟要哪张卡的积分？静态方法没有隐含this，因此编译拒绝这样的实例访问。**但静态方法可以拿到一个对象引用再操作它**，main中的first.add已经示范了；不能背成“static里不能用对象”。

static不表示不可修改，created就在变化；final才约束本例owner字段的再次赋值。final引用也不保证它引用的任何对象都不可变。不要把static、final、private分别解决的“归属、赋值次数、访问范围”混成一个限制。

**修改实验A**：把first.add(3)改为second.add(3)。第一张仍2，第二张变3，created仍2。只改变调用目标，不改变建卡数量。

**修改实验B**：只把add中的amount>0改为amount>=0，传入0时两种都不改变积分；这组数据不能区分返回行为，因为add是void。若业务要告诉调用者是否成功，应设计boolean返回值，练习E2会这样做。

## 5. 参数是“递给这次办理的一份副本”

main创建number=2，调用changeNumber(number)。方法的copy收到2，改成99后只改变自己的局部变量，main的number仍2。

把它类比为交一张写着2的纸复印件，工作人员改复印件，不会改你手中的原纸。引用参数同样复制值，只是纸上写的这次是“取卡凭证”。

replaceCard(first)的三个时刻：

```text
进入方法： first ──┐
                  ├──> 卡A points=5
            copy ─┘

copy.add(1)：      同一张卡A变6

copy=new ...： first ─────> 卡A points=6
               copy ─────> 新卡C points=0
copy.add(10)：              只让C变10
```

方法结束后main的first仍指A，显示Lin:6。新建C令created变3。**Java始终按值传参；能改到共享对象，不等于方法可以换掉调用方变量的引用。**

方法若想让调用者得到新卡，可以return该引用，由调用方显式接收并赋值；不要指望在方法内部重绑参数就修改外面的变量。数组引用也遵守这条规则：可通过副本改元素，但参数改指新数组不自动换掉外面的数组变量。

## 6. 从“能读懂”走到“会设计一个小类”

写类前先列三栏：**保存什么状态、允许哪些操作、哪些值必须始终合法。** 例如预约盒子保存容量和已预约数，只允许在剩余足够时预约；外部不能随手把已预约数改成999。

一个做法是private字段、构造器设初始状态、公开book方法验证并返回是否成功。不是给每个字段自动生成一套get/set：公开`setBooked(999)`可能直接绕过规则。访问器若返回内部可变数组，也可能让调用方改坏状态；必要时返回副本。

this不是当前文件、当前类名或当前线程；在实例方法里，它是本次调用的接收对象。构造器、实例方法、静态方法可以同在一个类中，**先看修饰词和参数，再找调用目标**。
