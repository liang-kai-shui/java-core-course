> 教材对应：**书本 p103–130 / PDF p121–148**（4.3–4.6；对象关系回看4.1–4.2）。本课讲解、比喻、程序与题目为课程原创。

## 0. 从“照着用类”走向“自己组织一个类”

S02已经画出借书卡与凭证。现在要做积分卡：每张卡有自己的持有人和积分，还要统计总共创建过几张卡。两张卡的积分不能串在一起，但发卡数量应一起累计。

如果把每个变量都加static，两人就可能误用一份积分；如果一律不加，类级统计又不好表达。**先问“这项数据属于哪一张卡，还是属于这个类的公共状态”，再选修饰词。**

分三次学：先字段与构造器；再实例/静态调用；最后参数副本。每次先画一份数据归属图，再运行相应阶段。

## 1. 三种位置，各自拥有数据

| 写在哪里 | 名称 | 这次怎样理解 |
|---|---|---|
| 方法内部 | 局部变量 | 本次调用中使用的临时记录 |
| 类内部、方法外，不带static | 实例字段 | 每张卡各有一份 |
| 类内部、方法外，带static | 静态字段 | 本例同一类的公共记录 |

把实例字段类比成每张积分卡上的格子，静态字段是总服务台的发卡计数，局部变量是办理一次业务时用的草稿。边界是：Java的静态字段按运行时的类归属，复杂的类加载环境可能不止一份同名类；本课在一个普通应用中观察，不把它夸成全世界唯一。

```text
PointsCard公共状态：created = 2
卡A：owner=Lin，points=2
卡B：owner=Mei，points=0
main临时记录：first→A，second→B
```

## 2. 一个完整程序，先只运行到前三行输出

新建ObjectWorkshop.java，下面两个类放在同一文件。可以先在自己的副本保留main前三条输出之前的代码，等看懂后再加入参数实验；此处给出最终完整版本，方便逐段核对。

```java
public class ObjectWorkshop {
    public static void main(String[] args) {
        PointsCard first = new PointsCard("Lin", 2);
        PointsCard second = new PointsCard("Mei");
        first.add(3);
        System.out.println(first.describe());
        System.out.println(second.describe());
        System.out.println("created=" + PointsCard.getCreated());
        int number = 2;
        changeNumber(number);
        System.out.println("number=" + number);
        replaceCard(first);
        System.out.println(first.describe());
        System.out.println("created=" + PointsCard.getCreated());
    }

    private static void changeNumber(int copy) {
        copy = 99;
    }

    private static void replaceCard(PointsCard copy) {
        copy.add(1);
        copy = new PointsCard("temporary", 0);
        copy.add(10);
    }
}

class PointsCard {
    private final String owner;
    private int points;
    private static int created = 0;

    public PointsCard(String owner, int points) {
        this.owner = owner;
        this.points = points;
        created++;
    }

    public PointsCard(String owner) {
        this(owner, 0);
    }

    public void add(int amount) {
        if (amount > 0) {
            points += amount;
        }
    }

    public String describe() {
        return owner + ":" + points;
    }

    public static int getCreated() {
        return created;
    }
}
```

从课程根目录的PowerShell运行：

```powershell
.\java.ps1 -Source '.\S03_结构基础_类成员与方法\my_code\ObjectWorkshop.java'
```

预期六行是：

```text
Lin:5
Mei:0
created=2
number=2
Lin:6
created=3
```

看到结果后别急着继续。下面解释每一层怎样导致这些数字；如果某行与你预测不同，从首次不同的状态开始查。

## 3. 构造器在建立状态，不是另一种main

`new PointsCard("Lin", 2)`根据参数选择接收String和int的构造器：this.owner取右边参数，this.points同理，created再加一。**构造器名与类相同，没有返回类型。** 写成`void PointsCard(...)`会变成普通方法，不再是想要的构造器。

第二个构造器只收姓名，第一行`this(owner, 0)`调用同类的双参数构造器。像“只填姓名的表单”自动采用积分0，再走统一的初始化流程。它不创建第二个PointsCard对象；调用一次new仍建立一张卡。

这叫**重载**：同名操作接收不同参数列表，编译器按调用的参数选择。不能仅靠返回类型不同重载。`this.owner`与`this(...)`也不是同一件事：前者访问当前对象字段，后者在构造器内委托另一个构造器。本课采用Java 8规则，构造器委托写在第一条语句。

### 局部变量和字段的默认值不同

本例显式初始化字段。Java也会给新对象的字段默认值：整数0、boolean为false、引用null；局部变量使用前则必须能确认赋值。不要在构造器内误写`int points = points;`来初始化字段，它声明的是局部变量且可能读取未赋值的自身；`points = points`则只给参数自身赋值。正确区分this.points与参数points。

如果一个类完全没声明构造器，编译器会提供默认无参构造器；自己写过带参构造器后，不会再自动补一个可用的无参版本。把本例改成`new PointsCard()`会编译失败，先看实际有哪些参数入口。

## 4. 为什么static方法里不能直接写points

`first.add(3)`带着目标卡A，add中的points就指A的points。`PointsCard.getCreated()`不指定某张卡，只读公共统计。

| 调用 | 是否指定具体卡 | 方法怎样找到数据 |
|---|---|---|
| first.add(3) | 是，A | this是A，操作A的points |
| second.describe() | 是，B | this是B，读B的字段 |
| PointsCard.getCreated() | 否 | 直接读本类静态字段created |

如果在getCreated里直接`return points;`，究竟要哪张卡的积分？静态方法没有隐含this，因此编译拒绝这样的实例访问。**但静态方法可以拿到一个对象引用再操作它**，main中的first.add已经示范了；不能背成“static里不能用对象”。

static不表示不可修改，created就在变化；final才约束本例owner字段的再次赋值。final引用也不保证它引用的任何对象都不可变。不要把static、final、private分别解决的“归属、赋值次数、访问范围”混成一个限制。

**修改实验A**：把first.add(3)改为second.add(3)。第一张仍2，第二张变3，created仍2。只改变调用目标，不改变建卡数量。

**修改实验B**：只把add中的amount>0改为amount>=0，传入0时两种都不改变积分；这组数据不能区分返回行为，因为add是void。若业务要告诉调用者是否成功，应设计boolean返回值，练习E2会这样做。

## 5. 参数是“递给这次办理的一份副本”

main创建number=2，调用changeNumber(number)。方法的copy收到2，改成99后只改变自己的局部变量，main的number仍2。

把它类比为交一张写着2的纸复印件，工作人员改复印件，不会改你手中的原纸。引用参数同样复制值，只是纸上写的这次是“取卡凭证”。

replaceCard(first)的三个时刻：

```text
进入方法： first ──┐
                  ├──> 卡A points=5
            copy ─┘

copy.add(1)：      同一张卡A变6

copy=new ...： first ─────> 卡A points=6
               copy ─────> 新卡C points=0
copy.add(10)：              只让C变10
```

方法结束后main的first仍指A，显示Lin:6。新建C令created变3。**Java始终按值传参；能改到共享对象，不等于方法可以换掉调用方变量的引用。**

方法若想让调用者得到新卡，可以return该引用，由调用方显式接收并赋值；不要指望在方法内部重绑参数就修改外面的变量。数组引用也遵守这条规则：可通过副本改元素，但参数改指新数组不自动换掉外面的数组变量。

## 6. 从“能读懂”走到“会设计一个小类”

写类前先列三栏：**保存什么状态、允许哪些操作、哪些值必须始终合法。** 例如预约盒子保存容量和已预约数，只允许在剩余足够时预约；外部不能随手把已预约数改成999。

一个做法是private字段、构造器设初始状态、公开book方法验证并返回是否成功。不是给每个字段自动生成一套get/set：公开`setBooked(999)`可能直接绕过规则。访问器若返回内部可变数组，也可能让调用方改坏状态；必要时返回副本。

this不是当前文件、当前类名或当前线程；在实例方法里，它是本次调用的接收对象。构造器、实例方法、静态方法可以同在一个类中，**先看修饰词和参数，再找调用目标**。

## 7. 本课过关检查

不看程序能解释：两张卡为何积分独立、发卡计数为何共享；两种构造器为何不意味着两个对象；参数改字段和参数改引用为何不同。能独立完成带合法性约束的小类，保留无效输入、0和恰好达到容量的边界记录。
