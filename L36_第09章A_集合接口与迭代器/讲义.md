## 都是一组对象，为什么有List、Set、Queue和Map

数组提供固定长度、下标访问；集合框架把常见组织需求做成接口与实现。**Collection<E>**约定一组元素的基本操作，List强调位置序列、允许重复，Set强调不重复，Queue强调队头处理约定。Map<K,V>保存键值关联，不继承Collection。**Collections**末尾有s，是提供静态算法与包装的工具类，不能与接口Collection混用。

像同一批资料可以按编号排队、去重登记或按ID建索引；类比边界是接口不决定具体数据结构与所有修改能力。List不承诺已经排序，Queue也不一律先进先出（优先级队列按优先级）。声明接口、构造实现，例如List<String> items=new ArrayList<>()，普通调用靠接口契约，更换实现仍须检查顺序、null与修改能力是否符合需求。

## 迭代器不是“当前元素变量”，next会同时移动

**Iterator**是逐项访问的游标对象，常画在元素之间。hasNext只问有没有下一项，next越过并返回下一项。类比读清单的手指：看是否还有项不会自动翻页；边界是Iterator不是能任意加减的指针，也不暴露真实内存布局。集合的增强for通常通过Iterable.iterator使用这种遍历；数组增强for有自己的展开规则，不必先包装成Collection。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;
import java.util.List;
public class IteratorFilterWalk {
    public static void main(String[] args) {
        List<String> steps = new ArrayList<>(Arrays.asList("读", "skip", "练"));
        Iterator<String> it = steps.iterator();
        System.out.println(it.hasNext());
        System.out.println(it.hasNext());
        while (it.hasNext()) {
            String step = it.next();
            System.out.println("visit:" + step);
            if (step.equals("skip")) it.remove();
        }
        System.out.println(steps);
    }
}
```

输出见程序顺序：两次hasNext都true，随后visit:读、visit:skip、visit:练，最终[读, 练]。重复hasNext不跳过读，remove删除的是上次next返回的skip，不是“游标后面下一项”。

| 操作 | 游标越过 | 返回 | 删除资格 |
|---|---|---|---|
| 两次hasNext | 无 | true/true | 尚不能remove |
| next | 读 | 读 | 可删读一次 |
| next | skip | skip | 可删skip一次 |
| remove | 不再next | 无 | 用掉本次删除资格 |
| next | 练 | 练 | 可删练一次 |

必须先成功next，才可remove；连续remove两次没有新next会IllegalStateException。末尾next无下一项则NoSuchElementException。某些容器迭代器不支持remove，可能UnsupportedOperationException；本课使用ArrayList明确支持。

## 为什么增强for里直接list.remove容易出问题

增强for背后有迭代器，直接对原列表做结构修改，旧游标的预期状态可能失效。ArrayList/LinkedList常以fail-fast方式尽早报ConcurrentModificationException，**同一线程也会发生**，不意味着必有另一个线程。这个检测是尽力发现bug，不能把是否抛它当作并发正确性的保证。过滤时用当前iterator.remove，或用removeIf交给API管理遍历。

只把skip改为读，过滤结果应[skip, 练]；不要同时改比较方法和列表。独立任务：删除所有空字符串，用Iterator逐项判断并删除，保留非空原顺序。若一项被漏掉，先查是不是循环体里为比较又多调用了一次next；每轮先保存返回值再使用。

## 数组列表与链表：找到位置本身也花时间

ArrayList按下标读取方便，中间增删需移动后续引用；LinkedList双向结点可以在已定位游标附近增删，但找第i项仍需走结点。不要为“删除快”每轮list.get(i)遍历长链表；那会重复定位。链表用迭代器顺走，数组列表按下标或迭代均可。RandomAccess是高效随机访问的标记，不是“随机数”或线程安全标记。

教材书本p355 / PDF p373的双向链表说明针对标准LinkedList，不表示Java语言禁止自己实现单向链表。集合大小、算法与内存访问方式都会影响实际性能，不凭一两个小输入计时下绝对结论。后面的ListIterator增加双向移动、位置插入和替换，位置与删除资格仍须分开画。

## ListIterator：插入点与上次返回项是两份状态

```java
import java.util.Arrays;
import java.util.LinkedList;
import java.util.List;
import java.util.ListIterator;
public class ListCursorGaps {
    public static void main(String[] args) {
        List<String> values = new LinkedList<>(Arrays.asList("A", "C"));
        ListIterator<String> it = values.listIterator();
        System.out.println(it.next());
        it.add("B");
        System.out.println(it.next());
        it.set("c");
        System.out.println(values);
        System.out.println(it.previous());
        it.remove();
        System.out.println(values);
        System.out.println("nextIndex=" + it.nextIndex());
    }
}
```

依次A、C、[A, B, c]、c、[A, B]、nextIndex=2。next越过A后游标在A|C；add B后在A B|C，所以下一个next仍C。set将刚返回C替换为c，不移动。previous又越过c返回它，remove此时删右侧这个刚返回项，不能机械当Backspace永远删左边。

| 步骤 | 列表与游标 | 上次返回 |
|---|---|---|
| 初始 | \| A C | 无 |
| next A | A \| C | A |
| add B | A B \| C | 删除/替换资格清除 |
| next C、set c | A B c \| | c位置 |
| previous、remove | A B \| | 资格用掉 |

表中竖线表示游标间隙，不是集合元素。只把插入B改X，结果A/X/c再A/X。独立在纸上预测连续add两个元素的顺序；它们按调用顺序插在游标之前，不会反着排。错误实验在add后立即remove应IllegalStateException，正常运行不要夹杂该失败。

在课程根目录PowerShell运行`./java.ps1 -Source './L36_第09章A_集合接口与迭代器/code/ListCursorGaps.java'`。


## 外部结构修改：错误发生在旧游标继续访问时

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;
import java.util.List;
public class IteratorInvalidation {
    public static void main(String[] args) {
        List<String> values = new ArrayList<>(Arrays.asList("A", "B"));
        Iterator<String> it = values.iterator();
        // controlled external change here
        System.out.println(it.next());
    }
}
```

正常输出A。错误副本只将注释替换为values.add("C")，ArrayList结构改变后旧it.next应报告ConcurrentModificationException。这里没有创建线程，冲突来自绕过游标的结构修改。set替换通常不改变结构，但也不意味着可任意并发使用。

独立任务：把过滤逻辑改回当前迭代器remove，或调用removeIf，不要catch CME后无条件重试当修复；它是发现bug的线索，不是正确算法的一步。
