## 学完要能做什么

能把可变参数按数组读懂并定义空输入含义；创建有字段的枚举，用有限常量表达状态而非散落字符串。

## 困惑一：参数个数没写死，方法内部究竟收到什么

你想把一次学习中的几个时长相加，有时2段、有时5段。**可变参数**是调用处的便利写法：方法最后一个形参写`int... minutes`，方法内部把它当int[]读。像把零散收据装进一个信封再交给柜台；类比边界是调用者若本来已有数组，也能直接交那个数组，此时没有保证再复制一份信封内容，修改元素会影响原数组。

## 困惑二：状态用字符串，拼错了编译器为何不提醒

任务只允许待办、进行中、完成。若用String，`"DNOE"`也能编译；**枚举**把合法选项变成一种专用类型，编译器可帮你拒绝其他名字。像三档旋钮只提供规定档位；边界是枚举不会自动规定状态转换顺序，不能只定义TODO/DOING/DONE就认为禁止了DONE回TODO，业务规则仍要写。

```java
public class PhasesAndArguments {
    static long sum(int... minutes) {
        long total = 0;
        for (int value : minutes) total += value;
        return total;
    }
    public static void main(String[] args) {
        System.out.println(sum());
        System.out.println(sum(3, 4));
        for (Phase phase : Phase.values()) System.out.println(phase.name() + ":" + phase.label());
        System.out.println(Phase.valueOf("DOING") == Phase.DOING);
    }
}
enum Phase {
    TODO("待办"), DOING("进行中"), DONE("完成");
    private final String label;
    Phase(String label) { this.label = label; }
    String label() { return label; }
}
```

输出`0`、`7`、`TODO:待办`、`DOING:进行中`、`DONE:完成`、`true`。前两个是求和，后面是枚举。它们是两种不同工具，这个程序把它们并排放好，不把“可变参数个数”和“枚举常量个数”混为同一概念。

`sum()`在本例收到长度0的int[]，从total=0开始没有迭代，返回0；空输入的意义由方法契约决定。求最大值时空输入不一定能用0，不能机械照抄。`sum(3,4)`相当于传入内容为3、4的数组；累加变量为long，可以容纳本例较大总数。...必须跟在类型后，可变参数只能一个且必须是最后一个形参。不能同时声明sum(int[])和sum(int...)，它们不是可用于区分的两个签名。

| 调用/操作 | 方法看到什么 | 结果 |
|---|---|---|
| sum() | 长度0数组 | 0 |
| sum(3,4) | [3,4] | 7 |
| Phase.values() | 按声明顺序的Phase数组 | 遍历3个常量 |
| Phase.valueOf("DOING") | 精确名字查找 | Phase.DOING |

## 枚举本身也是类与对象

`enum Phase`定义类型，TODO/DOING/DONE是规定的常量对象。常量列表后有字段/方法时以分号结束，再写private final String label和构造器。`TODO("待办")`在常量初始化时把文字传给枚举构造器，外面不能new Phase。`phase.label()`是对这个常量对象调用实例方法。

枚举同类型常量可以用==比较，因为每个枚举常量的身份固定。这个规则不能推广到String或Integer值比较。values()返回按声明次序的常量数组；name()是定义的名字，默认toString也显示该名字，但toString可被自定义，所以解析别依赖显示文本。valueOf精确匹配名字且区分大小写，`"doing"`不是`"DOING"`，会运行时IllegalArgumentException。

ordinal()给出声明位置，从0开始；compareTo依声明次序比较。它们适合理解遍历与排序，不能随便作为数据库永久编码：改常量顺序会改变ordinal。要持久化稳定编码，应自己定义稳定字段并规定解析规则。枚举隐式继承Enum，不能再extends其他类，但可以实现接口，L25介绍接口。

## 本课超前读法与常见排错

main里三元表达式/增强for已在前课使用，枚举构造器语法与普通类相似，唯一重要限制是不能提供外部public构造入口。sum中增强for不改数组，只读值；若你把它改成修改数组元素，要在契约里说明副作用。`sum((int[])null)`显式传null不是空数组，本例遍历会空指针；正常契约不接纳null数组。

## 可变参数不是防御性复制：现成数组会被怎样看见

零散实参像临时整理出的清单，现成数组则可能就是调用者交来的原清单。类比边界是Java没有统一承诺“...总复制所有元素”，不能因为语法简便就忽略副作用。

```java
import java.util.Arrays;
public class VarargsAliasWalk {
    static void raiseFirst(int... values) {
        if (values.length > 0) values[0]++;
    }
    public static void main(String[] args) {
        int[] data = {3, 4};
        raiseFirst(data);
        raiseFirst();
        raiseFirst(7, 8);
        System.out.println(Arrays.toString(data));
    }
}
```

`raiseFirst(int... values)`内部按数组处理，先检查length>0才访问第0项。传已有data直接使用同一数组引用，因此3变4；空调用得到空数组，检查为假安全返回；传7、8时形成调用所需数组，返回后没有变量继续持有它。参数变量本身仍是引用的值副本，符合L14。

| 调用 | 数组来源 | 调用者能看到什么 |
|---|---|---|
| raiseFirst(data) | 原数组 | data[0]变4 |
| raiseFirst() | 零项数组 | 不访问首项 |
| raiseFirst(7,8) | 调用打包 | 不改变data |

只把方法内自增改成`values=new int[]{99};`，预测data是否仍3；这是重绑形参而非改原元素。独立任务：设计只读sum并写明不修改传入数组，用运行前后Arrays.equals验证。若真要修改，应在方法名和契约中说明，而不是靠可变参数隐藏副作用。
