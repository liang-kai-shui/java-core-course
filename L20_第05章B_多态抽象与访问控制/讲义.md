## 困惑：变量明明写父类，为什么运行了子类方法

变量声明类型是你手中的通用操作清单；实际对象类型是具体承办者。拿着“通知”清单，你可以调用send；实际是邮件通知就走邮件实现，是站内通知就走站内实现。清单不含邮箱地址专属操作，即使承办者恰好是邮件通知，编译器也不会让你随意用它。类比边界：换一份清单（强制转换）不会把站内通知变成邮件通知，只是要求检查对象是否真具备那种身份。

## 让一个数组保存不同具体通知

```java
public class DispatchNotices {
    public static void main(String[] args) {
        NoticeBase[] notices = {new MailNotice("作业"), new SiteNotice("提醒")};
        for (NoticeBase n : notices) System.out.println(n.label());
        NoticeBase n = new MailNotice("旧题");
        if (n instanceof MailNotice) ((MailNotice) n).setSubject("提醒");
        System.out.println(n.label());
    }
}
abstract class NoticeBase {
    private String name;
    NoticeBase(String name) { this.name = name; }
    protected final String name() { return name; }
    protected final void rename(String name) { this.name = name; }
    public abstract String label();
}
class MailNotice extends NoticeBase {
    MailNotice(String name) { super(name); }
    void setSubject(String subject) { rename(subject); }
    @Override public String label() { return "mail:" + name(); }
}
final class SiteNotice extends NoticeBase {
    SiteNotice(String name) { super(name); }
    @Override public String label() { return "site:" + name(); }
}
```

输出`mail:作业`、`site:提醒`、`mail:提醒`。最后一行来自setSubject修改了第二个MailNotice的状态；通用的label方法仍能看到新状态。

`abstract class NoticeBase`声明这个类不能直接new。`public abstract String label();`只有契约、没有方法体，末尾分号；具体子类必须实现它，或者继续保持abstract。抽象类可以有字段、构造器、普通方法，本例共有name和name()，不是空壳。

编译`n.label()`时，只看NoticeBase有无可访问的label及参数是否匹配；它有，所以合法。运行时再按n引用的实际对象选择覆盖实现。这个选择叫动态分派/动态绑定。若删掉NoticeBase.label声明，即使每个子类都有label，编译器也无法允许通用变量直接调用。

| n声明类型 | 实际引用 | 编译可调用 | label运行选择 |
|---|---|---|---|
| NoticeBase | MailNotice | NoticeBase公开入口 | MailNotice.label |
| NoticeBase | SiteNotice | 同上 | SiteNotice.label |

`n.setSubject(...)`不能编译，因为NoticeBase没有它。`n instanceof MailNotice`先做运行时类型测试，真时再`(MailNotice)n`取得更具体的引用类型视角；Java 8写法分这两步。null instanceof任何引用类型为false。强转不创建对象、不复制对象、不调用构造器；若对象实际不是目标子类会在运行时抛ClassCastException。多数通用流程直接调label即可，别每次写instanceof分支来模拟已经存在的多态。

## 把重载、字段、static与final分开

重载选参数签名主要按调用处的声明类型在编译期决定；覆盖实现才按接收对象的实际类型在运行时决定。字段访问也不按覆盖分派。static方法属于类，应用类名调用，子类同名static是隐藏，不能套用实例多态规则。

final方法禁止子类覆盖；final类禁止再扩展；final字段禁止再次赋值。这三种限制分别约束不同事物，final类的可变字段并不会自动冻结。抽象方法要求子类补实现，不能同时final禁止补实现。

protected允许同包访问，也允许跨包的子类按规则访问。跨包子类通过对象引用访问继承的protected实例成员时，接收者类型必须是该子类或其子类；不能凭自己是子类就去读任意父类实例内部。优先保持字段private，给子类有限的protected方法，比公开所有内部字段更易维护。

## 数组的类型没有被变量声明洗掉

`MailNotice[]`可以赋给`NoticeBase[]`，称数组协变，但两变量引用的仍是实际MailNotice数组。往这个数组放SiteNotice，编译可能允许，运行时在存入那一步抛ArrayStoreException；不会等到调用方法时才把内存破坏。不要把父类数组变量当成能容纳任何子类的证明。想混放不同通知，一开始就new NoticeBase[]。

## 实验与独立任务

只把数组里的第二个`new SiteNotice("提醒")`改成`new MailNotice("提醒")`，第二行变mail开头，通用循环一行不改。反过来，把n实际改成SiteNotice却直接强转MailNotice，应在运行时失败；正常版本保持先测试再转。

独立设计抽象Delivery，保存名字，声明abstract int fee()；WalkDelivery费0，BikeDelivery费2。用Delivery数组统一打印，不写instanceof选费用。另写一个仅自行车有的capacity()，说明为什么通用变量不能直接调它。遇到编译错误先问清单上有没有入口，输出不对再问实际对象是哪种。

## 同一个对象，两次调用为什么先选了不同的重载

把选择拆成两层：先按手中表格选办理项目，再由真实承办者提供该项目的覆盖实现。类比边界是编译器只看可用声明和参数类型，不会偷看运行后变量到底引用什么来重新选重载。

```java
public class OverloadDispatchSteps {
    static String kind(AnimalVoice x) { return "general:" + x.voice(); }
    static String kind(CatVoice x) { return "specific:" + x.voice(); }
    public static void main(String[] args) {
        AnimalVoice a = new CatVoice();
        CatVoice b = (CatVoice) a;
        System.out.println(kind(a));
        System.out.println(kind(b));
    }
}
class AnimalVoice { String voice() { return "animal"; } }
class CatVoice extends AnimalVoice { @Override String voice() { return "cat"; } }
```

Animal视角a实际是Cat。`kind(a)`的实参声明类型Animal，编译选Animal版本；`kind(b)`选Cat版本。二者进入方法后都调用voice，这一层才按实际Cat选择覆盖实现。输出general:cat与specific:cat，不能只记成“Java总按实际类型”。

| 调用 | 编译选重载 | 运行voice实现 |
|---|---|---|
| kind(a) | kind(AnimalVoice) | CatVoice.voice |
| kind(b) | kind(CatVoice) | CatVoice.voice |

只将第二次参数写成`(AnimalVoice)b`，两次都选通用版本，但voice仍cat；强转不创建新对象。独立任务：在纸上加一个DogVoice覆盖voice，不增加kind重载，说明通用kind能否服务它。若不得不为每种子类写instanceof，先查共同动作是否已能直接多态调用。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L20_第05章B_多态抽象与访问控制/code/OverloadDispatchSteps.java'`。改动先复制到my_code，命令相应替换目录。

## 数组协变：哪个瞬间检查“能不能装”

通用变量像把外箱贴成“动物”，不会把内部专为猫准备的槽位改造成任意动物槽。类比边界是数组在运行时记住组件类型，失败发生在写入，Java不让不兼容值悄悄进入。

```java
public class ArrayStoreCheckpoint {
    public static void main(String[] args) {
        Integer[] numbers = new Integer[1];
        Object[] view = numbers;
        System.out.println("before");
        view[0] = Integer.valueOf(1);
        System.out.println("stored=" + numbers[0]);
    }
}
```

这份正常程序只放猫，输出1。`Object[] view=cats`仅换引用的声明视角，没有复制数组。只把`view[0]="dog"`当错误变体，编译允许Object元素，运行存入时却会ArrayStoreException；应在before后失败，不会打印stored。独立任务：若真的需要混放不同类型，一开始new Object[]；若只需要共同Animal行为，选共同父类型数组。不要靠强转把真实数组组件类型洗掉。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L20_第05章B_多态抽象与访问控制/code/ArrayStoreCheckpoint.java'`。改动先复制到my_code，命令相应替换目录。
