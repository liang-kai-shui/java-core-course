## 知道学号，怎样直接找到学习记录

列表的下标表示位置，Map的键表示你选择的标识。**映射**保存键→值关联，同一个键最多对应一个值；值可以重复，多个学号都可关联相同分数。像按学号查登记卡，类比边界是Map不自动证明学号来自真实世界、也不按“看起来一样”判断键；HashMap靠equals/hashCode，TreeMap靠比较顺序。

`Map<String,Integer>`两个类型参数分别管键和值，不是允许交两个任意值；put建立或替换，get查值，remove删关联。HashMap无迭代顺序保证，TreeMap按键排序；本课为便于逐步核对用LinkedHashMap保留插入序，不能从输出稳定推断普通HashMap也承诺这顺序。

```java
import java.util.LinkedHashMap;
import java.util.Map;
public class MapAssociationSteps {
    public static void main(String[] args) {
        Map<String, Integer> scores = new LinkedHashMap<>();
        System.out.println(scores.put("Lin", 10));
        System.out.println(scores.put("Lin", 20));
        System.out.println(scores.size());
        System.out.println(scores.get("Lin"));
        System.out.println(scores.getOrDefault("missing", 0));
        scores.put("empty", null);
        System.out.println(scores.get("empty"));
        System.out.println(scores.containsKey("empty"));
    }
}
```

依次null、10、1、20、0、null、true。第一次put前无旧值返回null；第二次同键返回旧10并替换20，size仍1。missing缺键时getOrDefault给0。empty明确映射null，get得null但containsKey为true，因此get返回null不总能说明键不存在。

| 操作 | 关联 | 返回/观察 |
|---|---|---|
| put Lin10 | Lin→10 | 旧值null |
| put Lin20 | Lin→20 | 旧10，数量不加 |
| get缺键 | 无关联 | get为null或默认值 |
| put empty null | 新关联存在 | containsKey true |

如果直接把get结果拆箱成int，缺键或null值会NullPointerException。getOrDefault只在缺键时给默认，不把现存null映射自动当0。对计数器本课直接规定不存null值，可以使用下一实验的merge；若业务允许null，必须明确其含义。

## 更换键规则或容器，要一并检查契约

键用于equals/hash/排序的状态在入表期间应稳定；否则查找位置与当前状态不一致，行为没有你期待的保证。用String或不可变值键更简单。复制Map只新建外层关联结构，若值是可变业务对象，两个Map仍可能共享它，不是自动深复制。

HashMap允许一个null键和null值；TreeMap自然顺序通常不接null键；ConcurrentHashMap键值都不接null。书本p374 / PDF p392的“键可以null而值不能null”不能当Map统一规定，已核对[HashMap API](https://docs.oracle.com/javase/8/docs/api/java/util/HashMap.html)。本课主要键为非null字符串，null值仅用于辨析，不把特殊值混进词频任务。

只把第二次put的键Lin改Mei，旧值将null，size变2，原Lin仍10。独立任务：画“同键替换”和“新键增加”两张状态图，再给每张写put返回值。不要把键唯一误说成所有值也不能重复。

## 首次出现的键，不能先把null加1

计数时`counts.get(word)+1`会在第一次拆箱null失败。可先getOrDefault(word,0)，或putIfAbsent初始0，或merge(word,1,Integer::sum)。merge对缺键/映射null直接放1，有非null旧值才调用合并函数。合并返回null表示移除关联，输入合并值本身不能null。

compute把键和旧值交函数；computeIfAbsent仅在无非null值时计算；computeIfPresent只在有非null值时计算。它们的null规则不同，不靠“方法名都含compute”猜。Map.replaceAll对每项替换值，支持null值的实现可保留null关联，**不是返回null就都删除**。书本p375–376 / PDF p393–394的putIfAbsent中文写反、computeIfAbsent和replaceAll删除描述不准确，后面用状态程序核对，依据[Map API](https://docs.oracle.com/javase/8/docs/api/java/util/Map.html)。这些普通Map复合操作不自动成为多线程原子事务，L52专讲并发容器。

## 三种视图是窗口，不是搬一份新数据

keySet给键集、values给值的Collection（值可重复）、entrySet给键值条目集。它们关联原Map：通过视图remove会删原关联；通常不能add，因为单加键或值不足以定义一对关联。Map.Entry.getKey/getValue读该条目，支持时setValue改原值。窗口类比边界是它仍是一个Java对象，但行为转到原Map，不能当独立快照。需要快照时显式new ArrayList<>(map.values())等，元素引用仍是浅复制。

## 计数与null：看关联是否存在，不能只看返回null

```java
import java.util.LinkedHashMap;
import java.util.Map;
public class MapNullUpdateRoutes {
    public static void main(String[] args) {
        Map<String, Integer> counts = new LinkedHashMap<>();
        for (String word : new String[]{"read", "code", "read"}) counts.merge(word, 1, Integer::sum);
        System.out.println(counts);
        counts.computeIfAbsent("missing", key -> null);
        System.out.println(counts.containsKey("missing"));
        counts.put("nullable", null);
        counts.computeIfAbsent("nullable", key -> null);
        System.out.println(counts.containsKey("nullable"));
        counts.replaceAll((key, value) -> null);
        System.out.println(counts.containsKey("read"));
    }
}
```

输出{read=2, code=1}、false、true、true。merge按逐词更新：read首次1，code首次1，再read合并2。computeIfAbsent对缺键返回null不新增；对已有nullable→null也不删除原来的null关联。replaceAll返回null把原read值改null而保留键。merge等另有返回null删除规则，不能混为同一口诀。

| 更新方法 | 旧值 | 函数结果 | 关联结果 |
|---|---|---|---|
| computeIfAbsent missing | 无键 | null | 不新增 |
| computeIfAbsent nullable | 现有null | null | 原关联仍在 |
| replaceAll read | 2 | null | read仍在，值null |

只把missing的函数结果改7，应新增并containsKey true。独立用containsKey和get同时记录，解释哪种业务需要区分缺值与显式空值。词频部分不接null，因此不让这份诊断样本的特殊值进入正常统计契约。

## 视图删除与快照：两扇窗不等于两张表

```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Set;
public class MapWindowAndSnapshot {
    public static void main(String[] args) {
        Map<String, Integer> map = new LinkedHashMap<>();
        map.put("A", 1); map.put("B", 2);
        Set<String> keys = map.keySet();
        List<String> snapshot = new ArrayList<>(keys);
        keys.remove("A");
        System.out.println(map);
        System.out.println(snapshot);
    }
}
```

输出{B=2}与[A, B]。keys直接关联map，remove A同时删关联；snapshot只是把当时键引用复制进新列表，不跟踪后续增删。这里只String不可变，快照内容稳定；可变对象元素另需决定复制深度。

状态：map{A1,B2}→keys[A,B]与snapshot[A,B]→keys.remove A→map{B2}，snapshot不变。错误副本把remove换add C，应UnsupportedOperationException：视图没收到新值，不能建立完整关联。独立先从map put C3，再观察已有keys视图包含C，证明视图不是一次性抓取。

## 插入序与访问序：读一项也可能改变次序

默认LinkedHashMap保持插入序；三参数构造器最后true才启用访问序。像一份按首次登记排的名单，与把最近查阅卡放到末尾的工作台；类比边界是访问序不自动设置缓存上限，更不把次数当频率排序。

```java
import java.util.LinkedHashMap;
import java.util.Map;
public class MapAccessOrder {
    public static void main(String[] args) {
        Map<String, Integer> insertion = new LinkedHashMap<>();
        Map<String, Integer> access = new LinkedHashMap<>(16, 0.75f, true);
        insertion.put("A", 1); insertion.put("B", 2);
        access.put("A", 1); access.put("B", 2);
        insertion.get("A"); access.get("A");
        System.out.println(insertion.keySet());
        System.out.println(access.keySet());
    }
}
```

输出[A, B]与[B, A]。两表相同put顺序，随后get A；默认表不动，访问序表将A移末尾。只把true改false，两行相同。独立解释removeEldestEntry返回true是在新插入后允许移除最老项，不是“返回true再添加新项”；若实现上限2，放第三项后最老项应退出。缓存仍需考虑线程、失效与值资源关闭，本课不凭此宣称完整缓存服务。

## 身份映射、枚举映射与弱键：先说为何选择

HashMap按值相等找键；IdentityHashMap按==区分对象，适合追踪对象图中的具体实例。它不是“更快的通用HashMap”，也不满足普通按equals的Map期望。EnumMap只接受指定枚举键，按声明次序处理，像固定的状态栏目；类比边界是未put的状态仍没有值，不会自动生成所有计数。

```java
import java.util.EnumMap;
import java.util.HashMap;
import java.util.IdentityHashMap;
import java.util.Map;
public class SpecializedMapKeys {
    enum Stage { TODO, DONE }
    public static void main(String[] args) {
        String a = new String("same");
        String b = new String("same");
        Map<String, Integer> values = new HashMap<>();
        Map<String, Integer> identities = new IdentityHashMap<>();
        values.put(a, 1); values.put(b, 2);
        identities.put(a, 1); identities.put(b, 2);
        System.out.println(values.size()); System.out.println(identities.size());
        Map<Stage, Integer> counts = new EnumMap<>(Stage.class);
        counts.put(Stage.DONE, 1); counts.put(Stage.TODO, 2);
        System.out.println(counts);
    }
}
```

两个显式new String内容一样但身份不同，普通表size1，身份表size2。EnumMap先放DONE再TODO，仍按声明序显示{TODO=2, DONE=1}。identityHashCode并不保证是地址或唯一编号，书本p380–381的地址说法不作API承诺。

只把b=a，身份表也只1项；独立解释两个Map浅复制值引用是否会克隆业务对象。WeakHashMap则以弱引用保存键：当键不再被其他强引用维持，垃圾回收可能清理关联；没有确定的回收时刻，不用System.gc+sleep断言“几秒后必空”。值仍强引用，若值反向强引用键还可能阻止预期清理。它不是可预测的过期缓存，基础任务不要求用它代替显式remove。
