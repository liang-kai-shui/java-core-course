## 学完要能做什么

能用add/get/set/remove操作可变列表；分清size与容量；解释装箱、拆箱、null和remove重载。

## 困惑：明明准备了100个位置，set(0,...)为什么还越界

数组长度创建后固定；ArrayList会管理内部存储，随添加自动扩容。**容量**是内部可容纳的潜力，**size**是当前实际元素个数。像预订100个座位的活动，目前可能还没有任何报名者；set是替换第几位已报名者，不是凭空登记一个人。边界是容量不是Java数组length的别名，内部扩容倍率与时机也不是你应依赖的业务契约。

```java
import java.util.ArrayList;
public class ListAndBoxing {
    public static void main(String[] args) {
        ArrayList<Integer> scores = new ArrayList<>(100);
        System.out.println(scores.size());
        scores.add(10);
        scores.add(20);
        scores.add(1, 15);
        scores.set(0, 12);
        System.out.println(scores);
        scores.remove(Integer.valueOf(15));
        System.out.println(scores);
        int sum = 0;
        for (int score : scores) sum += score;
        System.out.println("sum=" + sum);
        System.out.println(Integer.valueOf(1000).equals(Integer.valueOf(1000)));
    }
}
```

输出`0`、`[12, 15, 20]`、`[12, 20]`、`sum=32`、`true`。先用三个空格画列表，再逐步增加元素，不要画100个已经存在的成绩。

`ArrayList<Integer>`中的尖括号说明元素按Integer对象使用。泛型参数需要引用类型，不能写ArrayList<int>；Integer是int对应的不可变包装类。右侧`<>`由左侧推断元素类型，叫菱形语法。此时只需会用现成泛型，L33再定义自己的。

`scores.add(10)`把int10自动装箱为Integer，尾部添加；`add(1,15)`在下标1插入，原1及后面元素向后移。`set(0,12)`替换已有元素不改size；`get(0)`读取。`remove(Integer.valueOf(15))`按内容删除第一个15；若写remove(1)，参数是int，会按下标删第二项。两个remove是重载，不是库随机猜你的意思。

| 操作后 | 元素 | size |
|---|---|---:|
| 构造容量100 | [] | 0 |
| add10、add20 | [10,20] | 2 |
| add(1,15) | [10,15,20] | 3 |
| set(0,12) | [12,15,20] | 3 |
| remove值15 | [12,20] | 2 |

get/set/remove下标必须`0<=i<size`；按位置add可以`0<=i<=size`，等于size表示尾插。教材书本p180的set警告中“小于或等于”不准确，p183的add边界又漏了尾插；按实际API和实验区分两者。[ArrayList API](https://docs.oracle.com/javase/8/docs/api/java/util/ArrayList.html)。

## 装箱不是把基本值变成可变对象

`for(int score:scores)`每次取出Integer并自动拆箱为int，再求和。`Integer.valueOf(1000)`取得表示1000的对象，不承诺每次都新建，缓存是可能的；比较内容用equals，不能根据==对某个数碰巧成功就推断所有数字都行。`Integer n=3; n++;`是拆箱、加1、重新装箱并重绑n，不是修改原Integer对象。

Integer变量可以为null；若拆箱为int会NullPointerException。容器允许null不意味着算术支持null，应在添加时拒绝或在处理时写清策略。`Integer.parseInt("12")`返回基本int，是静态解析方法，不是创建对象构造器；字符串非法会运行时NumberFormatException，L30处理。

Integer不是引用传参的变通法：方法里`x=x+1`还是只重绑形参，L14结论不变。教材建议的旧CORBA holder不用于本课程JDK21环境；需要更新数值就返回新值并由调用者接住，或设计有明确操作的自定义对象。

## 列表复制与成本要看清

`other=scores`只复制列表引用，两变量指同一个容器；`new ArrayList<>(scores)`建立独立容器，元素引用仍共享，叫浅复制。Integer不可变，适合当前例子；装可变业务对象时修改元素内部状态仍会被两个容器看到。

ensureCapacity只为未来添加准备空间，trimToSize尝试缩小内部存储到当前数量；它们都不改变size。不要为了“省空间”每加一项就trim。按下标get通常快，中间插入/删除需要移动后续元素；链表也有查找位置的成本，不能只看“删除不用搬”就断言一定更快。原始ArrayList不写类型参数会放弃一部分编译检查，强转也不能神奇证明内部元素类型，L34再分析擦除。

## 实验与独立任务

只把构造后的第一条输出改为`scores.set(0,5)`，预期在运行时越界，因为size为0；不能拿容量100证明已有第0项。另在正常副本把删除15改为remove(1)，本例恰好也是删15，再改为remove(15)会按下标越界，这样才能暴露重载差别。

## 同样写1，删除的是位置还是数值

重载先看参数类型，不能靠列表里“看起来正好有1”判断。把remove(int)想成拿号找座位，remove(Object)想成按登记内容找人；边界是后者按equals删首个匹配，不是删全部，也不是按对象地址。

```java
import java.util.ArrayList;
import java.util.Arrays;
public class RemoveAndUnboxRoutes {
    public static void main(String[] args) {
        ArrayList<Integer> byIndex = new ArrayList<>(Arrays.asList(9, 1, 7));
        ArrayList<Integer> byValue = new ArrayList<>(Arrays.asList(9, 1, 7));
        byIndex.remove(1);
        byValue.remove(Integer.valueOf(1));
        System.out.println(byIndex);
        System.out.println(byValue);
        Integer boxed = 3;
        int plain = boxed;
        System.out.println(plain);
    }
}
```

两份列表独立建好，从相同[9,1,7]出发。remove(1)按位置删掉值1，结果碰巧一样，很容易掩盖概念；所以实验改为remove(0)与remove(Integer.valueOf(0))，一个删9，一个找不到0而不改表。看行为差异要用能区分规则的数据。

| 参数类型 | 含义 | 找不到/越界 |
|---|---|---|
| int | 下标 | 不在0到size-1则异常 |
| Integer传给Object重载 | 值 | 无匹配返回false，表不变 |

末尾boxed=3再自动拆箱，正常打印3。只把boxed改null，编译仍允许Integer引用为空，但取int那步运行失败；不要把null当数值0。独立任务：在自己的平均数方法明确不接纳null的前提，再处理空列表；空容器与容器含null是两种不同情况。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L22_第05章D_数组列表与包装类型/code/RemoveAndUnboxRoutes.java'`。改动先复制到my_code，命令相应替换目录。
