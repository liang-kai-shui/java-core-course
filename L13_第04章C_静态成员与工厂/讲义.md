## 学完要能做什么

能说明每个实例的编号与整类编号计数器的区别；选择实例方法或静态方法；读懂私有构造器与命名工厂。

## 困惑：每张卡都有一个号，发号机应该放在哪里

两张卡各自保存编号id；下一张要用哪个号，却不能各自从1重新计算。**实例字段**每个对象一份，**静态字段**归类的这一份状态。可以把它想成柜台公共发号机与个人卡面：发号机往前走，已经印在旧卡上的号码不跟着变。边界是Java的“整类”更准确地说与定义这个类的类加载器相关，不是跨进程的全球数据库；重启程序计数会从初始值重新开始。

static不等于常量：可变的静态计数器仍会变；`static final`才常用于不可重赋的类常量。它若引用可变对象，对象仍可改变。也不要为了让main方便调用就把所有字段变static，那样所有读者会意外共享个人状态。

## 让两个工厂入口说出用途

```java
public class TicketOffice {
    public static void main(String[] args) {
        Ticket a = Ticket.regular();
        Ticket b = Ticket.guest();
        System.out.println(a.summary());
        System.out.println(b.summary());
        System.out.println("issued=" + Ticket.issued());
    }
}
class Ticket {
    private static int nextId = 1;
    private final int id;
    private final String kind;
    private Ticket(String kind) {
        id = nextId;
        nextId++;
        this.kind = kind;
    }
    static Ticket regular() { return new Ticket("普通"); }
    static Ticket guest() { return new Ticket("访客"); }
    static int issued() { return nextId - 1; }
    String summary() { return id + ":" + kind; }
}
```

输出依次是`1:普通`、`2:访客`、`issued=2`。程序启动的这一轮先把nextId初始化为1；每次new只给新对象领一个号。

`private Ticket(String kind)`令外部不能直接new Ticket；类自己的静态工厂可以调用它。`regular()`与`guest()`是有名字的入口，返回类型Ticket，`return new Ticket(...)`把引用交给调用者。工厂不是Java关键字，是一种API设计方式。与构造器相比，它可以取清楚的名字，也可以缓存/复用实例或返回子类型，所以不能一见工厂就断言“每次一定新建”；本例明确每次new。

`id = nextId; nextId++;`先把当前号复制到当前对象，再推进公共发号机。写成id=nextId++也能得到相同效果，但分两步更容易看清顺序。`Ticket.issued()`以类名调用静态方法；不要借某个实例来调用它，否则读者会误以为结果属于那张卡。

| 动作 | 公共nextId | a.id | b.id |
|---|---:|---:|---:|
| 类初始化后 | 1 | 无对象 | 无对象 |
| regular构造完 | 2 | 1 | 无对象 |
| guest构造完 | 3 | 1 | 2 |

`summary()`需要某一张卡的id和kind，所以是实例方法，有隐含this。`issued()`只读类计数器，没有this，不能直接读取某一张卡的kind；若真要处理一张卡，应接收Ticket参数或把操作放回实例方法。main本身也是static：JVM无需先创建启动类对象就可进入它，但main中仍可以new业务对象。

## 静态常量、静态导入和测试入口

数学常量`Math.PI`是静态成员；`Math.max(2,3)`是静态操作。`import static java.lang.Math.max;`允许写max(2,3)，它只简化名称，没有复制代码、没有改变方法归属。多个来源同名时可读性会下降，初学时保留Math.更清楚。业务类可以另有main作为小型测试入口；启动哪个类就进入哪个main，其他main不会自动轮流执行。

这里的发号器只用于单线程讲解。多线程同时读取再递增会有竞态，L51再解决；不能把此例当作生产环境唯一ID服务。编号也不是统计已存活对象的数量：对象不再使用时nextId不会自动回退。

## 一处实验与独立小任务

把`nextId = 1`改成`nextId = 100`，两张卡会是100、101；但`issued()`中的`nextId-1`已经不再表达已发数量。这个实验暴露了原公式依赖起点1。修法是另外维护issuedCount，构造时加1，别把“号码”和“数量”混成一个概念。

独立任务：实现MemberCard.student()与MemberCard.teacher()，前者类别“学生”、后者“教师”，编号从100起，并提供count()准确返回发出的数量。先创建三张卡，再输出数量3。若每张卡都100，检查nextId是否误成实例字段；若旧卡显示新号，检查summary是否错误地读nextId而非id。

## 两次调用工厂，为什么可能还是同一个对象

工厂是“怎样取得一个对象”的公开入口，不是“必须新建”的语言指令。一个固定只读标志可以复用，像多次查询都指向同一份公共告示；边界是可变业务对象不一定适合共享，否则一个调用者会影响另一个。

```java
public class FactoryReuseWalk {
    public static void main(String[] args) {
        Notice a = Notice.shared();
        Notice b = Notice.shared();
        Notice c = Notice.fresh();
        System.out.println(a == b);
        System.out.println(a == c);
        System.out.println(c.text());
    }
}
class Notice {
    private static final Notice SHARED = new Notice("Java");
    private final String label;
    private Notice(String label) { this.label = label; }
    static Notice shared() { return SHARED; }
    static Notice fresh() { return new Notice("Java"); }
    String text() { return label; }
}
```

`private static final`先创建一个整类持有的引用，final固定这条引用，label又是不可变String；本例没有任何改状态操作。shared返回原引用，fresh每次执行new。变量类型仍是Notice，不因为从不同方法返回而改变。

| 操作 | 新建对象吗 | 接收的引用 |
|---|---|---|
| 第一次shared | 此方法不new | a→公共实例 |
| 第二次shared | 此方法不new | b→同一公共实例 |
| fresh | 明确new | c→另一实例 |

所以前三行分别true、false、Java。只把第二次shared改fresh，预测第一行；再恢复。独立任务：解释Ticket的发号器为什么不能照搬shared实现，否则两张“新票”可能根本不是两个身份。使用工厂时先读契约；比较日期/文字内容仍使用各自的equals，不用本实验的身份比较替代。
