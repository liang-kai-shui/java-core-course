## 困惑：把对象交给工具，为何工具反过来调用它

你安排一次学习流程，希望工具在准备完成后通知你记录。**回调**就是调用者提供一个满足接口的对象，工具在约定时机调用它的方法。像把联系电话留给柜台，办理到某个步骤时柜台联系你；边界是回调不等于后台线程、不保证“过一会儿”，也可能就在当前调用内部同步执行。

```java
public class CallbackRoute {
    public static void main(String[] args) {
        Flow.run("阅读", new PrintingHook());
    }
}
interface CompleteHook { void completed(String title); }
class PrintingHook implements CompleteHook {
    @Override public void completed(String title) { System.out.println("record:" + title); }
}
class Flow {
    static void run(String title, CompleteHook hook) {
        System.out.println("prepare:" + title);
        hook.completed(title);
        System.out.println("finish:" + title);
    }
}
```

输出`prepare:阅读`、`record:阅读`、`finish:阅读`。把对象new出来时并没有打印record，真正执行在Flow.run的hook.completed(title)。点左边hook是回调对象，title只是这次传入的事件信息。

`CompleteHook`接口给出方法契约；`PrintingHook`实现它。Flow只知道CompleteHook，不必知道PrintingHook具体类。以后传入“保存记录”的实现，流程代码也能保持相同。它先准备、调用回调、再完成；回调在本例是同步方法，若回调抛失败，finish不自动执行。异常课再设计是否兜底。

| 正在执行 | 调用者 | 接收者 | 下一步 |
|---|---|---|---|
| main发起Flow.run | main | Flow静态方法 | 打印prepare |
| hook.completed | Flow | PrintingHook实例 | 打印record |
| 回调返回 | PrintingHook | 回到Flow | 打印finish |
| run返回 | Flow | 回到main | 程序结束 |

教材用javax.swing.Timer定时回调。interval单位毫秒，start注册并启动，之后由Swing事件线程触发ActionListener.actionPerformed，stop停止后续通知。它不是java.util.Timer，后者是另一种后台调度工具；本书p222处出现的java.swing应读成javax.swing。我们先用同步流程看清控制权，窗口与事件线程在L40–L42再真正运行，不能把这里只测试同步回调说成已经测试定时器计时精度。

## Comparator：把“怎样比较”交给排序工具

Comparable把一种自然顺序放在元素类里；Comparator是另一个策略对象，可为同一组String提供按长度、字典等不同顺序，不必修改String。后面的LengthOrder样本调用`Arrays.sort(words,new ByLength())`，工具需要比较时回调compare(first,second)。接口参数是Comparator<String>，返回负/零/正；使用Integer.compare(length1,length2)表达，不需要把策略写成static，因为接口要求实例方法。

对象数组排序是稳定的：本例等长度的bb与cc保留输入相对次序，不是每次随机排列。比较器必须有一致的排序契约，不能每次随机返回符号；也不要在compare中修改正在排序的数据。先实现正确规则，再考虑性能，不用猜sort究竟调用多少次比较。

## 复制：有两个变量，不代表有两个业务对象

`copy=original`只增加别名，两者还是同一个对象。`super.clone()`建立一个字段级浅复制：基本字段复制值，引用字段复制引用，因此可变子对象仍可能共享。像复印目录卡时只抄了同一个抽屉号码，两张目录仍指向同一抽屉。边界是深复制需要按对象图和业务规则决定，可能存在循环、共享关系、不可复制资源，不是“遇到引用就无限递归new”。

后面的CloneLedger完整程序为Notes保留int[] marks。clone先复制外层对象，再`copy.marks=marks.clone()`复制可变数组，之后改副本元素不会改原件。String/LocalDate不可变值常可共享，没必要为了“深”再复制。数组clone只复制数组这一层；若元素还是可变对象，仍共享元素对象。

Cloneable是标记接口，自己没有clone方法；Object.clone为protected，类要向使用者公开clone，还需覆盖成public。未实现标记却调用Object.clone会CloneNotSupportedException。`throws CloneNotSupportedException`先读为“本方法声明可能把这个受检查失败继续交给调用者”；main也声明时，未处理的失败将报告并结束，不是无视异常。L30会系统讲。clone不调用普通构造器重新初始化同一套流程，不能依靠构造器副作用来统计克隆。

在自己的简单值类中，显式复制构造器或命名copy方法常更容易说明意图，但它们一样要决定哪些可变子对象需要复制。公开clone还需考虑未来子类的可变字段，本课用final Notes减少扩展风险；不会把所有类都要求可克隆。

## 独立运行比较策略

先预测输入{bb,a,cc,ddd}的结果。ByLength没有自己的状态，但仍需new一个实例，才能作为Comparator传入。compare返回0的bb和cc保持原相对次序；如果在比较中再按字典打破同长关系，则是另一条明确规则。

```java
import java.util.Arrays;
import java.util.Comparator;
public class LengthOrder {
    public static void main(String[] args) {
        String[] words = {"bb", "a", "cc", "ddd"};
        Arrays.sort(words, new ByLength());
        System.out.println(Arrays.toString(words));
    }
}
class ByLength implements Comparator<String> {
    @Override public int compare(String first, String second) {
        return Integer.compare(first.length(), second.length());
    }
}
```

输出`[a, bb, cc, ddd]`。只把Integer.compare的左右长度交换，改为降序，预期`[ddd, bb, cc, a]`；同长次序仍保持。独立增加空串，验证长度0排到最前。空数组可排序；null元素需要另定策略，当前不接纳。

在课程根目录PowerShell运行`./java.ps1 -Source './L26_第06章B_回调比较器与克隆/code/LengthOrder.java'`。


## 独立运行克隆：复制到哪一层

下面的外层对象与数组各自画一个框：original→Notes A→数组X；copy→Notes B→数组Y。先super.clone复制Notes，再复制marks生成Y，否则A、B都指X。构造器也复制输入数组，避免调用者保留的原数组绕过封装。

```java
import java.util.Arrays;
public class CloneLedger {
    public static void main(String[] args) throws CloneNotSupportedException {
        Notes original = new Notes(new int[] {1, 2});
        Notes copy = original.clone();
        copy.setFirst(9);
        System.out.println(original);
        System.out.println(copy);
    }
}
final class Notes implements Cloneable {
    private int[] marks;
    Notes(int[] marks) { this.marks = marks.clone(); }
    void setFirst(int value) { marks[0] = value; }
    @Override public Notes clone() throws CloneNotSupportedException {
        Notes copy = (Notes) super.clone();
        copy.marks = marks.clone();
        return copy;
    }
    @Override public String toString() { return Arrays.toString(marks); }
}
```

输出`[1, 2]`与`[9, 2]`。`copy.marks=marks.clone()`右侧从当前原对象复制数组，左侧只把副本字段改指向新数组。只删这一行就变两行[9,2]。throws的读法见正文；正常类已实现Cloneable，本例预期不抛该失败。零长度数组可克隆，但不能再setFirst，本方法契约要求非空；不要把越界问题错归因到克隆机制。

在课程根目录PowerShell运行`./java.ps1 -Source './L26_第06章B_回调比较器与克隆/code/CloneLedger.java'`。

## 回调的状态归谁：换动作不需要改流程

前面回调直接打印。现在工具通知两次，由回调对象累计次数；像同一联系人接到两通通知后更新自己的登记本。类比边界是调用仍同步，不是留电话就自动启动线程。

```java
public class CallbackStateOwner {
    public static void main(String[] args) {
        CounterHook hook = new CounterHook();
        System.out.println("before=" + hook.count());
        TwiceFlow.run(hook);
        System.out.println("after=" + hook.count());
    }
}
interface CountHook { void done(); }
class CounterHook implements CountHook {
    private int count;
    public void done() { count++; }
    int count() { return count; }
}
class TwiceFlow {
    static void run(CountHook hook) { hook.done(); hook.done(); }
}
```

CounterHook只有自己的count；TwiceFlow只接CountHook约定并调用done，根本不读取count。main持有具体对象，流程返回后读取次数。new hook本身没有调用done，开始0；run里面两次才变2。

| 执行点 | 谁操作 | hook.count |
|---|---|---:|
| 创建后 | 构造默认字段 | 0 |
| 第一次done | 流程调用，回调自增 | 1 |
| 第二次done | 同上 | 2 |
| 返回main | 读取，无额外通知 | 2 |

只删一次hook.done调用，末值1；再独立创建第二个CounterHook而不运行，说明它还是0。独立任务：实现一个收集标题的Hook，把一次通知的标题放进自己的ArrayList，再由main显示。流程依赖接口，策略状态留给实现对象，不能为了省传参把所有计数放static。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L26_第06章B_回调比较器与克隆/code/CallbackStateOwner.java'`。改动先复制到my_code，命令相应替换目录。
