## 困惑：拿到类名字符串，怎么知道它能做什么

普通调用在源码中写死类型和方法；工具若要检查运行时才知道的类型，需要**反射**：把类型的结构信息当成对象来查询。类比设备目录：设备是业务对象，目录卡描述它有哪些接口、部件和装配入口。边界是Class不是源码文本，也不是磁盘的.class文件路径；描述信息存在于运行时，与文件路径不是一回事。

得到Class常用三条路：`obj.getClass()`看实际对象的类型；`ReadingNote.class`按源码已知类型取描述；`Class.forName("ReadingNote")`按全名查找，可能失败。`Class<?>`先读作“描述某个尚未指定类型的Class对象”，不是要立刻学会通配符证明，L35再深化。int.class也存在，说明Class能描述基本类型，不代表int值本身成为对象。

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;
public class ReflectionWorkshop {
    public static void main(String[] args) {
        try {
            Class<?> type = Class.forName("ReadingNote");
            System.out.println(type == ReadingNote.class);
            Constructor<?> constructor = type.getConstructor(String.class);
            Object note = constructor.newInstance("初读");
            System.out.println(note.getClass().getSimpleName());
            Field field = type.getDeclaredField("title");
            System.out.println(Modifier.toString(field.getModifiers()));
            field.setAccessible(true);
            field.set(note, "复习");
            Method method = type.getMethod("label", String.class);
            System.out.println(method.invoke(note, "!"));
        } catch (ReflectiveOperationException ex) {
            System.out.println("reflection-failed:" + ex.getClass().getSimpleName());
        }
    }
}
class ReadingNote {
    private String title;
    public ReadingNote(String title) { this.title = title; }
    public String label(String suffix) { return title + suffix; }
}
```

输出`true`、`ReadingNote`、`private`、`复习!`。只操作本课程自己的类，不去探测JDK内部私有字段。

`type.getConstructor(String.class)`找到public、形参为String的构造器描述；`newInstance("初读")`才真正创建业务对象。这里用Constructor.newInstance，避免旧Class.newInstance接口的局限与当前弃用问题。得到Object变量note后，反射仍记得它实际为ReadingNote。构造器不被继承，所以getConstructors不会把父类构造器当成当前类构造器返回。

`getDeclaredField("title")`找此类自己声明的字段，private也能找见；找见不等于有权读取。`Modifier.toString(field.getModifiers())`解释访问修饰信息。`setAccessible(true)`在当前允许的应用类环境中请求跳过语言访问检查，然后field.set修改指定对象字段。没有它，本例不同顶层类对private字段写入会IllegalAccessException。不能说“任何JDK任何类都能这样打开”：Java 9后的模块封装还有限制，JDK21内部类并不任你访问；[AccessibleObject API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/AccessibleObject.html)。

| 步骤 | 对象角色 | 是否执行业务逻辑 |
|---|---|---|
| 取Class | 类型描述 | 不创建ReadingNote |
| 取Constructor | 构造入口描述 | 尚未构造 |
| newInstance | 产生业务实例note | 执行构造器 |
| 取Field | 字段描述 | 尚未改title |
| field.set(note,...) | 指定实例及新值 | title改变 |
| Method.invoke | 指定接收者和实参 | 执行label并返回结果 |

getFields/getMethods查询public成员，包含继承来的公开字段/方法；getDeclaredFields/getDeclaredMethods查询此类型自己声明的各权限成员，不自动包含父类声明。枚举出来的成员顺序不应假定稳定，若要可重复报告先排序。Method保存方法描述，`invoke(note,"!")`的第一个实参是接收对象，后面才是传给label的显式参数。静态方法没有接收者，可传null；基本返回值会包装成对象。

## 这次先会读异常路线

反射可能找不到类、找不到成员、没有权限、构造或调用失败。`try { ... } catch (ReflectiveOperationException ex) { ... }`读作：正常时顺序执行try，若出现这类反射失败，跳过try剩余语句进入catch，ex保存失败对象，最后继续后面流程。不是让失败那一行自动重试，也不是所有异常都被这个catch捕获。L30–L31会完整介绍层次和恢复策略。这里把错误类型打印出来，让错误实验可核对。

若被反射调用的方法自己抛异常，invoke以InvocationTargetException包裹，原因可由getCause查看；参数个数/类型不对也可能运行时失败。普通直接调用能在编译期发现很多这类错误，所以业务代码明知方法时优先直接调用。L25的接口回调和L27的Lambda通常比反射式回调更清楚。

## 继承设计回看：比工具更重要的是契约

把共同职责放父类，字段仍尽量private，避免子类遍地依赖内部表示。只有is-a且全部继承操作保持有意义时才用extends；否则用组合。覆盖不能悄悄改变原承诺，编译器只能检查语法和类型，不能理解“这个费用是否符合政策”。有统一动作时用多态，不要串联很多类型判断。

教材书本p209拿扩展LocalDate作假设比较；LocalDate实际是final，源码不能extends它。要表示假日，设计一个拥有LocalDate的Holiday值类。不可变也不自动让不合法的继承变合法。教材的通用对象分析器递归遍历全部私有字段、用visited防循环，是深化算法思路；本课不把它宣称为可对JDK21任意对象直接运行的万能工具，也不以暴露所有私有状态作为业务默认toString。

## 保持数组实际类型：Object不是Object[]

问题：通用工具要调整任何数组长度，不能每次都写一个int版、String版。所有数组能赋给Object，但int[]不能赋给Object[]；数组元素是基本值，不是逐个对象引用。

```java
import java.lang.reflect.Array;
import java.util.Arrays;
public class TypedArrayResize {
    static Object resize(Object source, int newLength) {
        Class<?> type = source.getClass();
        if (!type.isArray() || newLength < 0) throw new IllegalArgumentException("array and nonnegative length required");
        Object result = Array.newInstance(type.getComponentType(), newLength);
        System.arraycopy(source, 0, result, 0, Math.min(Array.getLength(source), newLength));
        return result;
    }
    public static void main(String[] args) {
        int[] numbers = {2, 4};
        String[] words = {"A"};
        System.out.println(Arrays.toString((int[]) resize(numbers, 4)));
        String[] expanded = (String[]) resize(words, 2);
        System.out.println(Arrays.toString(expanded));
        System.out.println(Arrays.toString((String[]) resize(expanded, 0)));
    }
}
```

输出是`[2, 4, 0, 0]`、`[A, null]`、`[]`。resize契约接收非null数组和非负新长度。`if`中的检查拒绝非数组或负长度；`throw new IllegalArgumentException(...)`读作“创建参数不合约的失败对象并立即抛出”，本次方法不再向下执行，调用者未捕获则会结束程序并报告。正式异常处理见L30，正常实验先使用满足契约的输入。`source.getClass().getComponentType()`取得组件类型，`Array.newInstance`按这个类型创建新数组，返回Object。`Array.getLength`统一读取任何数组长度；arraycopy只搬迁两边都装得下的那一段，不会把剩余部分填成旧末元素。组件为引用时复制引用，不深复制对象。

| 源数组 | 新长度 | 复制个数min | 剩余槽位 |
|---|---:|---:|---|
| int[2] | 4 | 2 | 0、0 |
| String[1] | 2 | 1 | null |
| String[2] | 0 | 0 | 无 |

只改新长度4为1，第一行变[2]；原numbers仍是[2,4]，resize返回新数组。若写new Object[newLength]，内容看着像字符串也不能转String[]，运行时仍识别实际Object数组。本例在日常代码中优先使用Arrays.copyOf，反射实现用于理解库怎样保留组件类型，不要求为了“通用”重写标准库。

## 找不到方法与方法执行失败，为什么不是同一种异常

反射有“找到操作说明”和“实际执行操作”两步。像先找到窗口，再由窗口处理业务，业务拒绝不等于窗口不存在；边界是invoke用InvocationTargetException包装目标抛出的异常，不能只看最外层名字猜原因。

```java
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Method;
public class InvocationFailureRoute {
    public static void main(String[] args) {
        try {
            Method method = CheckedLabel.class.getMethod("load", String.class);
            System.out.println(method.invoke(new CheckedLabel(), ""));
        } catch (InvocationTargetException ex) {
            System.out.println("cause=" + ex.getCause().getClass().getSimpleName());
        } catch (ReflectiveOperationException ex) {
            System.out.println("lookup=" + ex.getClass().getSimpleName());
        }
    }
}
class CheckedLabel {
    public String load(String text) {
        if (text.isEmpty()) throw new IllegalArgumentException("empty");
        return "book:" + text;
    }
}
```

getMethod成功取得load(String)描述；invoke才运行load，传空串时业务抛IllegalArgumentException。catch InvocationTargetException取getCause得到实际原因。另一个catch处理查找/访问等反射失败，放在后面，因为前者也是ReflectiveOperationException子类。

| 只改什么 | 失败点 | 本例观察 |
|---|---|---|
| 保持空串 | 目标业务执行 | cause=IllegalArgumentException |
| 方法名load改missing | 查找 | lookup=NoSuchMethodException |
| 参数空串改Java | 正常业务 | book:Java |

这次getCause的返回值是Throwable，调用getClass().getSimpleName只取失败类型，不是重新抛出或重试。独立任务：在CardReflection里将“找错名字”和“目标拒绝非法名字”分两份实验，写出是否已经进入业务方法。普通代码知道类型时仍优先直接调用，反射不会让错误自动更容易处理。
