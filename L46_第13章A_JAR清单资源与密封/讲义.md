## 我的电脑能运行，拷给别人为什么少了一段文字

开发目录能找到文件，不代表交付包里有它。把程序看成一只旅行箱：class是可执行零件，资源是随箱携带的说明资料，Manifest是箱上的启动/依赖说明；类比边界是JAR不是自带整台电脑，普通JAR仍需要兼容的Java运行时，清单也不会自动下载所有依赖。

S05已经验证入口，S06验证库与资源；本课沿教材13.1把它们整理成交付检查。JAR采用ZIP容器，扩展名改zip只改变名称不会改格式；创建归档本身不会编译.java。`jar cf`创建、`tf`列目录、`xf`解压、`uf`更新，`-C 目录 .`把该目录**内部**作为条目根；若把classes目录本身封进去，条目多一层可能找不到包全名。

## 清单是一种有规则的文本，不是Java代码

```java
import java.io.ByteArrayInputStream;
import java.nio.charset.StandardCharsets;
import java.util.jar.Manifest;
public class ManifestSections {
    public static void main(String[] args) throws Exception {
        String text = "Manifest-Version: 1.0\nMain-Class: campus.app.Main\nClass-Path: lib/text.jar\n\nName: campus/model/\nSealed: true\n\n";
        Manifest manifest = new Manifest(new ByteArrayInputStream(text.getBytes(StandardCharsets.UTF_8)));
        System.out.println(manifest.getMainAttributes().getValue("Main-Class"));
        System.out.println(manifest.getMainAttributes().getValue("Class-Path"));
        System.out.println(manifest.getAttributes("campus/model/").getValue("Sealed"));
    }
}
```

这个最小程序只在内存解析自建清单，输出campus.app.Main、lib/text.jar和true，不创建或修改任何JAR。它先把字符串UTF-8编码成字节，再让Manifest读取；getMainAttributes读主节，getAttributes按`campus/model/`读取命名节。Attributes值仍是文字，不会自动加载类或开启安全机制。

| 字段 | 谁读取、用于什么 | 常见误解 |
|---|---|---|
| Main-Class | java -jar选择入口 | 填源码路径或带.class |
| Class-Path | 归档启动时解析依赖URL | 以当前PowerShell目录为基准 |
| Name: campus/model/ | 后续属性的命名节范围 | Java的package语句 |
| Sealed: true | 类加载时的包来源约束 | 加密或防反编译 |

字段冒号后留空格，各节之间空行，文本末尾要有行结束；长行有续行规则，手工拼装时不随意折断。`Class-Path: lib/text.jar`相对应用JAR所在位置解释，多个项以空格分隔，不是Windows命令行类路径的分号。`java -jar`与`java -cp ... 包.主类`是两种启动方式，不把后者的-cp想当然叠加到前者。详细规则见[JAR规范](https://docs.oracle.com/javase/8/docs/technotes/guides/jar/jar.html)。

只改Main-Class值为campus.app.Other，解析仍成功，因为“读到文本”不等于“类存在且可启动”。独立任务：分别描述清单语法错、主类不存在、依赖缺失会在什么阶段暴露，回S05/S06运行对应失败实验。

## 资源查找不从当前终端目录起步

`Main.class.getResourceAsStream("about.txt")`相对Main的包；`getResourceAsStream("/campus/about.txt")`相对类路径根；路径分隔用`/`，开头的斜杠不是D盘根。ClassLoader的getResourceAsStream规则与Class不同：通常用不带开头斜杠的类路径根名字，别机械替换调用者。

找不到返回null，先明确报告缺哪个资源，别直接new Scanner(null)让错误跑到别处；找到流后仍需解码/解析并关闭。资源URL可能是jar:，不能一律new File(url.getPath())当普通磁盘文件。打包只读文字用流读取；用户要改的笔记、配置写在包外可写路径，不试图把JAR内部条目当普通文件覆盖。

## 密封包：限制同一加载器中的包来源

密封要求同一密封包的类来自同一JAR来源；主节Sealed设置默认，命名包节可覆盖。像给一套零件登记同一出厂批次，混入另一个箱子的同包零件会在加载时被拒绝；类比边界是它不是数字签名、权限沙箱、加密，也不保证改过整个JAR的人无法替换内容。包名相同还不足以说明运行时就是同一个包，类加载器身份也参与，详见上面的JAR规范。

本课清单解析程序只证明字段读法；实际密封验证见后面的独立程序，它在临时目录中自建两个小归档并加载类，不假称内存解析已经证明安全边界。现代JDK没有书中老rt.jar目录布局，Pack200也已移除，不要求按旧工具打包；普通jar创建/列目录/入口机制仍可用于本课程。

package campus.app;
import java.io.InputStream;
import java.util.Scanner;
public class ResourceMain {
    public static void main(String[] args) {

}

## 真实密封实验：同名包的两个来源在加载时冲突

下面是独立JDK实验，单文件由java.ps1运行；它用本地编译器临时生成两个辅助类，再放入两个JAR，实验结束关闭加载器并删除自己的临时目录。源码中的类只是固定教学文本，不编译用户输入。ToolProvider属于javax.tools，getSystemJavaCompiler在缺编译器环境返回null，因此本例额外需要完整JDK，不把一般JAR运行说成一律需要javac。

```java
import java.io.*;
import java.net.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.*;
import java.util.jar.*;
import java.util.stream.Stream;
import javax.tools.*;
public class SealingOriginCheck {
    static void jar(Path output, Path cls, String entry, boolean sealed) throws IOException {
        Manifest mf = new Manifest(); mf.getMainAttributes().putValue("Manifest-Version", "1.0");
        if (sealed) mf.getMainAttributes().putValue("Sealed", "true");
        try (JarOutputStream out = new JarOutputStream(Files.newOutputStream(output), mf)) {
            out.putNextEntry(new JarEntry(entry)); Files.copy(cls, out); out.closeEntry();
        }
    }
    static void deleteTree(Path root) throws IOException {
        List<Path> all = new ArrayList<>(); try (Stream<Path> paths = Files.walk(root)) { paths.forEach(all::add); }
        all.sort(Comparator.reverseOrder()); for (Path p : all) Files.delete(p);
    }
    public static void main(String[] args) throws Exception {
        JavaCompiler compiler = ToolProvider.getSystemJavaCompiler(); if (compiler == null) throw new IllegalStateException("need JDK");
        Path root = Files.createTempDirectory("course-seal-");
        try {
            Path a = root.resolve("A.java"), b = root.resolve("B.java"), classes = root.resolve("classes"); Files.createDirectory(classes);
            Files.write(a, "package tiny; public class A {}".getBytes(StandardCharsets.UTF_8));
            Files.write(b, "package tiny; public class B {}".getBytes(StandardCharsets.UTF_8));
            int result = compiler.run(null, null, null, "--release", "8", "-encoding", "UTF-8", "-d", classes.toString(), a.toString(), b.toString());
            if (result != 0) throw new IllegalStateException("compile failed");
            Path first = root.resolve("first.jar"), second = root.resolve("second.jar");
            jar(first, classes.resolve("tiny/A.class"), "tiny/A.class", true); jar(second, classes.resolve("tiny/B.class"), "tiny/B.class", false);
            try (URLClassLoader loader = new URLClassLoader(new URL[] {first.toUri().toURL(), second.toUri().toURL()}, null)) {
                Class<?> type = Class.forName("tiny.A", true, loader); System.out.println("sealed=" + type.getPackage().isSealed());
                try { Class.forName("tiny.B", true, loader); throw new AssertionError("mixed origin accepted"); }
                catch (SecurityException expected) { System.out.println("mixed-origin=rejected"); }
            }
        } finally { deleteTree(root); }
    }
}
```

先加载tiny.A，包已密封，输出sealed=true；随后tiny.B试图来自另一JAR，输出mixed-origin=rejected。deleteTree在finally清理，倒序删除确保子项先删；Stream<Path>是可关闭的目录遍历流，此处只用它排序删除当前实验明确创建的根内文件，后续API语法不要求背诵。方法没有走访课程文件夹。

只把第一个manifest中的Sealed从true改false，预测第二次加载将不再触发密封冲突（程序故意抛AssertionError指出预期已改变），再将输出检查改为确认B正常加载。独立任务：用自己的话说明密封是加载规则，为什么仅在ManifestSections里读到true还不构成行为证据。

在课程根目录PowerShell运行`./java.ps1 -Source './L46_第13章A_JAR清单资源与密封/code/SealingOriginCheck.java'`。
