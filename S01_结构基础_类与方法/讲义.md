# S01 讲义 · 文件里为什么要套class和main

> 前置：L01–L02：会保存文本并启动一个程序；不要求会变量、对象或C++。
> 教材对应：**书本 p28–31 / PDF p46–49**（3.1；4.4.5（书本 p115–116 / PDF p133–134））。本课讲解、比喻、程序与题目为课程原创。

## 0. 先把问题说清楚

你只想显示一句话，却被要求写两层大括号、`class`、`public static void main`。如果只记“固定外壳”，以后看到另一个方法、另一个类或一个JAR，就又不知道从哪读起。

这课只解决三件事：**文件保存文字；类组织成员；方法组织一次可以调用的操作。** `main`是本课程所用普通应用的入口方法。先不创建自己的对象，S02会把对象单独讲清。

建议分两次：第一次看层级和调用路线；第二次拆入口、比较别的语言并做错误实验。不要为了读本课先去背整个面向对象术语表。

## 1. 文档、办事部件的设计、操作流程，是三个层次

想象为校园借书系统写一份工作设计：文档保存文字；设计中列出某个部件能做的操作；每项操作再列步骤。

| Java里的东西 | 类比 | 它真正负责什么 |
|---|---|---|
| `CorridorRoute.java` | 保存设计文字的文档 | 磁盘上的源码文件 |
| `class CorridorRoute` | 一个部件的设计定义 | 声明一种类型并组织它的成员 |
| 方法 `main`、`greet` | 有名字的操作流程 | 接到调用后执行方法体 |
| `println(...)`语句 | 流程中的一步 | 这一步请求输出 |

**类比边界**：Java的类不是磁盘文件夹，也不是电脑里的一名员工。一个文件可以写多个非public顶层类；一个类可以有多个方法。类的定义本身不会让所有方法自动执行。

先观察下面这一棵树，竖线表示“写在谁的内部”，不表示执行先后：

```text
源码文件 CorridorRoute.java
└─ 类 CorridorRoute
   ├─ 方法 main
   │  ├─ 输出1
   │  ├─ 调用greet
   │  └─ 输出3
   └─ 方法 greet
      └─ 输出2
```

你以后读代码，先找所属层级，再找执行路线。看到一段代码写在页面下方，不能据此认定它最后才执行。

## 2. 亲手让程序“走进另一个方法，再回来”

在本课`my_code`新建`CorridorRoute.java`，保存下面的完整程序：

```java
public class CorridorRoute {
    public static void main(String[] args) {
        System.out.println("1. open");
        greet();
        System.out.println("3. close");
    }

    public static void greet() {
        System.out.println("2. hello");
    }
}
```

在VS Code打开课程根文件夹，选择“终端→新建终端”，用PowerShell。从根目录输入：

```powershell
.\java.ps1 -Source '.\S01_结构基础_类与方法\my_code\CorridorRoute.java'
```

运行脚本会隔离编译输出，编译失败就停止。成功应依次显示`1. open`、`2. hello`、`3. close`。若策略阻止脚本，在同一根目录用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\java.ps1 -Source '.\S01_结构基础_类与方法\my_code\CorridorRoute.java'
```

跟着一次调用走：

| 走到哪里 | 此时做什么 | 下一步到哪里 |
|---|---|---|
| 启动器选择CorridorRoute | 调用约定的main | main第一条语句 |
| main第一条输出 | 显示1 | `greet();` |
| `greet();` | 暂停main后续步骤，进入greet | greet里的输出 |
| greet的右花括号 | 本次greet结束 | 回main，继续调用之后的语句 |
| main最后输出 | 显示3 | main结束 |

类比按“办理欢迎事项”的工作单去执行一次子流程，办完回到调用位置。类比只说明控制流，不表示每个方法会启动新进程或新线程。

## 3. 定义方法和调用方法，为什么写法不同

看两行局部写法，**它们是片段，不是独立程序**：

```text
public static void greet() { ... }   定义：这项操作怎样做
greet();                             调用：现在做一次
```

定义带方法体，调用只交出方法名及括号中的输入。此例没有输入，仍保留`()`。花括号表示方法体；调用后面的分号结束调用语句。不能把整个方法定义塞进main；Java普通方法不能直接定义在另一个方法内部。

`greet`写在main后面，编译器仍知道它属于同一个类，因此本例不需要先写一份C++函数原型。Java普通方法定义写在类里；此处没有`.h`头文件，也没有`CorridorRoute::greet`式类外定义。

**预测实验A**：只删掉`greet();`这一行，第二行输出还出现吗？不会。定义仍在，但没有调用它。

**预测实验B**：恢复后，把调用复制一次。预计`1、2、2、3`。增加调用次数不会增加类的定义数量。

**预测实验C**：把整个greet定义移到main定义之前，保持两者在同一对类花括号内。输出仍是`1、2、3`，因为启动仍从main开始。

## 4. 把入口那一行拆开，而不是一次背六个词

```text
public   static   void   main   (String[] args)
可访问   类的方法  无返回值 入口名   接收启动文本的参数
```

- **public**：此方法是公开可访问的。它不表示“所有本地变量都公开”，访问范围由各处声明分别决定。
- **static**：调用此方法不需要先创建这个类的一个实例。像先到总服务台发出开馆指令，再由流程建立所需具体部件；不是说“运行中不能有对象”或“数值不能变化”。
- **void**：这次方法调用不交回结果值。它仍可以输出文字；“没有返回值”与“没有任何效果”不同。
- **main**：在本课`java 类名`启动方式中，启动器按约定找这个名字。我们取名`greet`不会让它自动变入口。
- **String[] args**：接收启动时的一组文本。`String`是文本类型，`[]`表示数组，`args`是程序员取的参数名。暂不使用也要保持入口形状；数组在L10详细学习。

本课程固定以Java 8语法/API学习，并用JDK 21编译运行这个入口。其他版本或启动模式可能有其他规则，不从本课模板推导所有Java系统都只能如此启动。

## 5. `System.out.println`为什么有两个点

不要把它当成一个不可拆的咒语，也不要把点两边都叫“函数”。

```text
System       .out                    .println("hello")
标准库的类    找到它提供的标准输出字段    对这个输出对象调用打印方法
```

`System`是类名，`out`是其静态字段，通常引用标准输出对象；`println`是这个对象的方法。JDK替你提供了这项输出能力，不需要自己先`new System`。

像找到总服务台上标为“输出”的设备，再按设备的“打印并换行”操作。边界是：字段不是实际硬件按钮，`out`也可以被程序安排成其他输出目标。现在只使用默认终端输出。

括号里的`"hello"`是交给打印方法的文本；引号属于源码的表示法，正常不打印引号。两个点都涉及成员访问，但`out`与`println`的成员种类不同。

## 6. 和C++、Python比较时，只比较这一次普通启动

| 问题 | 本课程的Java | 常见C++程序 | 常见Python脚本 |
|---|---|---|---|
| 普通操作写在哪里 | 类的方法内部 | 可写在自由函数main中，也可使用类 | 可以写在模块顶层，也可定义函数/类 |
| 启动点 | 指定类的约定main | 程序入口main函数 | 执行模块的顶层代码 |
| 类是Java独有的吗 | 不是，Java强调按类组织普通代码 | 也支持类和对象 | 也支持类和对象 |
| 这是否等于文件里必须只有一个类 | 不等于 | 不等于 | 不等于 |

这张表只帮助你看见结构差异，不要求你先会另外两门语言。Java也有基本类型，不能把“普通代码围绕类组织”夸成“Java里一切都是对象”。

## 7. 一次只破坏一个地方，先判断失败阶段

先复制正确文件到自己的新实验目录，保留原件。每项改完先预测，再编译；失败时不继续启动旧class。

| 只改这一处 | 应观察到什么 | 先查什么 |
|---|---|---|
| 文件改名Wrong.java，public类名不变 | javac编译失败 | 文件名与public顶层类名匹配 |
| main改为mian | 编译可以成功，普通启动失败 | 入口方法的精确名字 |
| 删除main前的static | 实例方法本身可合法定义，但本课启动找不到约定入口 | 是否满足本课入口形状 |
| 把greet定义放进main内部 | 编译失败 | 花括号层级，方法应与main并列 |

不是每个类都需要main。以后`Student`只表示学生资料，启动类`App`使用它即可；也允许多个类各有main，启动命令只选择其中一个，不会把所有main轮流执行。

## 分步实验：调用里再调用，究竟回到哪里

前面的greet只有一层，现在加一层，但仍不使用变量或对象。具体困惑是：main进入prepare，prepare又进入showCourse，showCourse结束后会直接结束整个程序吗？不会，每次方法调用都有自己的“回来后继续的位置”。像办事单把一项小任务交给子流程，子流程办完只返回给刚才委托它的那一步；类比边界是本例全在同一线程执行，不是三个工作人员同时办理。

```java
public class NestedCallSteps {
    public static void showCourse() { System.out.println("3.course"); }
    public static void prepare() {
        System.out.println("2.prepare");
        showCourse();
        System.out.println("4.prepare");
    }
    public static void main(String[] args) {
        System.out.println("1.main");
        prepare();
        System.out.println("5.main");
    }
}
```

预期1.main、2.prepare、3.course、4.prepare、5.main。先在纸上用手指停在调用后的那一行，再走进被调用方法；从其右花括号回来时找到刚才停的位置。

| 当前方法 | 遇到什么 | 保存的继续位置 | 下一步 |
|---|---|---|---|
| main | prepare() | main的最后一条println | 进入prepare |
| prepare | showCourse() | prepare的最后一条println | 进入showCourse |
| showCourse | 到达结束花括号 | 使用刚才保存的位置 | 回prepare打印4 |
| prepare | 到达结束花括号 | 使用main的位置 | 回main打印5 |

只把showCourse();删掉，输出应1、2、4、5，showCourse定义仍在却没有执行。再在另一副本仅把main的prepare调用复制一遍，预期1、2、3、4、2、3、4、5。源码中只定义一次prepare，仍能被调用两次；每次返回各自的调用位置。

独立小任务：让main调用welcome，welcome调用showGoal，分别打印进入/返回的可识别文字。先画包含树（定义写在哪里），再画执行箭头（本次先去哪），不能用一张树同时冒充两种关系。原CampusGreeting作业仍按原要求提交，这个随堂任务不临时增加旧课必交项。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './S01_结构基础_类与方法/code/NestedCallSteps.java'`。改动先复制到my_code，命令相应替换目录。

## 分步实验：点号不等于“又调用了一个函数”

这次只看输出请求。System.out先取得JDK提供的输出对象，再在这个对象上调用print或println。print写内容不主动补本次末尾换行，println写后补换行。方法名不同，操作契约不同；两个点不代表System、out、println三个函数从里到外执行。

```java
public class OutputRequestSteps {
    public static void main(String[] args) {
        System.out.print("A");
        System.out.println("B");
        System.out.println("C");
    }
}
```

输出两行AB与C。第一条没有换行，所以第二条B接在A后面；第二条末尾换行，第三条C从下一行开始。双引号是源码表示文本的界限，输出中不带它们。这里的分号结束Java语句，不自动决定终端是否换行。

只把第一条print改println，预期三行A、B、C。再单独把第二条println改print，预期一行ABC，第三条末尾才换行。这种一处修改能把语句分隔与显示换行分开。

独立小任务：用三条输出语句组成两行“Java course”和“one step”；哪些调用要带ln，由你先写预期现象再选。若全部挤一行，先查用的是print还是println，不要先改类名或大括号。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './S01_结构基础_类与方法/code/OutputRequestSteps.java'`。改动先复制到my_code，命令相应替换目录。
