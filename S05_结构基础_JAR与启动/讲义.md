# S05 讲义 · JAR是什么：把程序装箱，再找到入口

> 前置：S04：会从classpath根与完整类名找到class，能把多份源码一起编译。
> 教材对应：**书本 p580–583 / PDF p598–601**（13.1.1–13.1.3；作为课程结构基础提前学习，不包含本章全部部署主题）。本课讲解、比喻、程序与题目为课程原创。

## 0. 发给别人一堆class，还是一个保持结构的箱子

S04的程序运行需要两份class。项目扩大后，逐个发送文件很容易漏掉一份或打乱包目录。**JAR（Java Archive）是按ZIP格式组织的归档文件，可以装类文件和资源。** 它在分发层面把许多文件放进一个容器，仍保留内部条目的名字。

可以把JAR想成运送部件的箱子：包目录是箱内分类，class是编译后的部件说明，清单文件像随箱标签。边界是：箱子不是发动机；JAR本身不会代替JVM，也不是把字节码变成CPU原生机器码的.exe。

**类、包、JAR分别处在不同层次。** 类组织数据与操作，包为类型提供命名和访问范围，JAR组织分发的文件集合。同一个JAR可以包含许多包，同一个包也可能由不同JAR提供不同类；它们不是一一对应关系。

## 1. 用两份很小的源码，追踪一次完整分发

把本课code/project复制到my_code/project，已有个人副本不覆盖。目录沿用S04的src约定：

```text
project/
└─ src/campus/
   ├─ app/JarMain.java
   └─ text/JarGreeting.java
```

<!-- source: code/project/src/campus/text/JarGreeting.java -->
```java-source
package campus.text;

public class JarGreeting {
    public static String forName(String name) {
        return "packed: " + name;
    }
}
```

<!-- source: code/project/src/campus/app/JarMain.java -->
```java-source
package campus.app;

import campus.text.JarGreeting;

public class JarMain {
    public static void main(String[] args) {
        String name = args.length == 0 ? "Lin" : args[0];
        System.out.println(JarGreeting.forName(name));
    }
}
```

先在课程根目录的PowerShell用项目工具执行正常路径：

```powershell
.\project.ps1 -Project S05 -SourceRoot '.\S05_结构基础_JAR与启动\my_code\project' -Mode Run
.\project.ps1 -Project S05 -SourceRoot '.\S05_结构基础_JAR与启动\my_code\project' -Mode Jar
```

两次应都显示packed: Lin。第二次由工具先编译、打包，再以`java -jar`启动这一次的新JAR；不是因为有个.jar文件就省略了编译。每次输出隔离，失败不接着执行旧文件。策略阻止时沿用S04的单次Bypass写法。

## 2. 四步链路，逐一指出输入和产物

```text
两份 .java 源码
  │ javac：检查语法与类型，编译
  ▼
classes/campus/.../*.class
  │ jar：保持目录，把class与清单归档
  ▼
campus.jar
  │ java -jar：读清单选入口，让JVM执行字节码
  ▼
运行中的进程 → main → 其他方法 → 程序输出
```

注意jar是**工具名**，.jar是**文件后缀**；类似javac是工具，而.java是源码文件后缀。大小写JAR常指格式概念，不是另一种编程语言。

## 3. 手动编译打包：别把源码直接压成“可执行程序”

在课程根目录的PowerShell输入下面一段。$projectPath指自己已经复制的项目，生成目录是本次新建的，不覆盖旧学习记录。

```powershell
. .\_课程工具\resolve-jdk.ps1
$jdk = Find-CourseJdk -Root (Get-Location).Path
$projectPath = (Resolve-Path '.\S05_结构基础_JAR与启动\my_code\project').Path
$build = Join-Path $projectPath ('build-' + [guid]::NewGuid().ToString('N'))
$out = Join-Path $build 'classes'
New-Item -ItemType Directory -Path $out -Force | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 -d $out "$projectPath\src\campus\text\JarGreeting.java" "$projectPath\src\campus\app\JarMain.java"
if ($LASTEXITCODE -ne 0) { throw '编译失败，停止。' }
$jarPath = Join-Path $build 'campus.jar'
& "$jdk\bin\jar.exe" cfe $jarPath campus.app.JarMain -C $out .
if ($LASTEXITCODE -ne 0) { throw '打包失败，停止。' }
& "$jdk\bin\jar.exe" tf $jarPath
```

这套jar短选项与教材Java 8时期的写法一致，在本机JDK 21也可用。

| 命令部分 | 具体作用 |
|---|---|
| c | 创建归档 |
| f与后面的$jarPath | 输出到指定JAR文件 |
| e与后面的类全名 | 指定应用入口，写入清单 |
| -C $out . | 让归档工具从$out内部取内容；不把classes本身当外层目录装进去 |
| tf | 列出归档条目，f后给要查看的文件 |

`-C`只影响jar取文件的起点，不是PowerShell的Set-Location，也不改变Java的工作目录。**这里的点表示所选目录的内容**，不能机械换成源码目录。

## 4. 打开箱子，看看里面到底是什么

内容表应包含这些关键条目，文件夹条目或创建顺序可以不同：

```text
META-INF/MANIFEST.MF
campus/app/JarMain.class
campus/text/JarGreeting.class
```

不应该是`classes/campus/app/JarMain.class`，因为类路径根位于JAR内部的顶层。也不应该只装了JarMain.java：运行这份普通字节码JAR所需的class没有因此自动产生。

**清单（manifest）**是JAR里的说明文件，标准位置是META-INF/MANIFEST.MF。它不是另一份Java源码。本例关键内容类似：

```text
Manifest-Version: 1.0
Main-Class: campus.app.JarMain
```

Main-Class填**类全名**，不填文件路径、`.class`或方法名。清单文本按规范需要行结束；本例由jar的e选项生成，避免手工漏换行。普通JAR可以没有入口；库JAR没有main通常很正常。

## 5. 两种启动方式，入口由谁决定

编译打包完成后，在同一个PowerShell依次尝试：

```powershell
& "$jdk\bin\java.exe" -cp $jarPath campus.app.JarMain
& "$jdk\bin\java.exe" -jar $jarPath
```

| 写法 | 在哪里找应用类 | 主类由谁给 |
|---|---|---|
| -cp 某.jar 类全名 | 把JAR当一个classpath入口 | 命令行给类名 |
| -jar 某.jar | 以该归档作为应用启动入口 | 清单Main-Class |

两种都执行字节码，没有哪一种把程序自动转成机器码文件。`-jar`是选启动方式，不是“这里还要再加一个主类参数”；JAR文件名后面的普通参数会交给main的args。

例如`java -jar campus.jar Mei`在本例把Mei当启动参数，输出packed: Mei。命令行前面的java需要可用运行环境，是否能在别人电脑运行还取决于版本、依赖和所需数据。

## 6. 无入口JAR不是坏掉的JAR

在同一个手动实验中，另建不指定e选项的归档：

```powershell
$plainJar = Join-Path $build 'no-entry.jar'
& "$jdk\bin\jar.exe" cf $plainJar -C $out .
if ($LASTEXITCODE -ne 0) { throw '打包失败，停止。' }
& "$jdk\bin\java.exe" -cp $plainJar campus.app.JarMain
```

这仍可输出packed: Lin，因为命令行明确给了主类。再单独运行`java -jar`指向no-entry.jar，预期启动失败：清单没有Main-Class。这不是语法错误，也不意味着里面没有可用的类。

就像箱中部件齐全，却没有标“从哪一个操作开始”的发货标签；指定主类的-cp启动方式另外提供了这条信息。类比只说明缺的是什么，不替代实际清单规则。

## 7. 为什么双击JAR有时毫无反应

双击依赖操作系统文件关联；还可能使用不显示控制台的启动方式。终端程序即使执行完，也未必留下可见窗口。因此本课用明确的终端命令验证：看退出状态与自己的输出。

“能否双击”不是判断JAR内容正确的唯一标准；JAR也不自动包含JVM。给别人分发时要说明启动命令、兼容运行环境，以及是否还需要外部库。下一课会让“另一个库JAR”和资源也各归其位。

## 8. 过关时应能独立回答

不用看图，说出源码、class、JAR、运行进程四者的产生顺序。能打开内容表，判断包树是否装对；能解释-cp启动与-jar启动的入口来源；制作有入口与无入口两份归档，区分预期成功和预期失败。
