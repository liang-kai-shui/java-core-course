# L41 参考答案与解析

先独立完成，再比较推演。窗口位置、字体实际字形与你机器上的像素值可能不同，判断看规则而不是看某台机器的截图。

## Q1

四层分工：

| 名词 | 保存什么 | 不保存什么 |
|---|---|---|
| 形状对象（Rectangle2D 等） | 坐标、宽高、几何类型 | 颜色、字体、屏幕像素 |
| Graphics2D | 这次绘制的颜色、字体、裁剪等状态 | 业务数据；不等于画布 |
| 组件坐标 | 以内容区左上为原点的位置 | 屏幕绝对坐标 |
| 画面像素 | 真正被涂上的颜色 | 形状的“意图” |

`setColor`/`setPaint` 只改 Graphics2D 的状态，`fill`/`draw` 才把形状变成像素。已经画好的红矩形是一批像素，后面把笔改成蓝色不会回头重涂它们；要变蓝，只能清屏后按新顺序重画。所以答案是“颜色只作用于后续绘制”，不是“颜色绑定在形状上”。

常见错法：把 Graphics2D 说成图片；说 `setColor` 会“刷新”已有图形；把坐标原点说成屏幕左上。

## Q2

| 问题 | 参考回答 |
|---|---|
| 矩形参数 | 左上角 x、左上角 y、宽、高；宽高是长度，不是右下角坐标 |
| 线段参数 | 起点 x、起点 y、终点 x、终点 y；没有宽高 |
| 椭圆外接框 | 左上角 + 宽高围出的框；中心 = 左上 + 宽高的一半，半径 = 宽高的一半 |
| 文字 y | 基线；`getStringBounds` 的 y 为负，等于 −上坡度 |
| deriveFont | int 重载改风格，float 重载改字号；JDK 21 实测 `deriveFont(14)` 得 `PLAIN`、字号 12，教材“斜体”说法不能照抄 |
| 图像非 null | 不能证明有效；宽高可能 ≤ 0，必须检查正尺寸 |

椭圆那句“没有宽高、只有半径”不准确：`Ellipse2D` 用外接框描述，宽高就是外接框的宽高；圆只是宽高相等的特例。

## E1

参考记录：

```text
无参数：窗口标题“形状与坐标”，左红矩形、右蓝椭圆、下方黑线与 Java 2D；
        关闭后终端返回。
--check：rectangle=true / ellipse=true；不创建窗口。
```

两者证明的范围不同：窗口证明“看得见、能交互”，`--check` 只证明“这条离屏路径上两个内部像素是红/蓝”。`--check` 不证明字体、缩放、装饰和整体布局。

平移实验：把 `new Rectangle2D.Double(20, 20, 120, 70)` 的 x 改成 60，新矩形覆盖 x=60..179；原来 (30,30) 已在图形外，检测点应改成 (70,30) 之类。先算范围再改点，不能为了让测试通过而改预期值。

字体样本：把 `24.0f` 改 `36.0f`，`inside` 可能仍为 true，但文字明显变大，位置需按新 bounds 重算。图像样本：画布 20 改 16，8×8 图在横纵各铺 2 块，正好整除。

## E2

参考实现见 [StudyBadge.java](StudyBadge.java)。结构：

```text
Badge extends JPanel：白底、首选 220×140
paintComponent：super → create → 绿色 fillRect(20,20,80,50) → 黑色 drawString("Study",20,100) → dispose
main：--check 离屏验证；否则 JFrame + add + pack + setVisible
```

`--check` 输出 `fill=true`、`background=true`：(30,30) 在绿块内部，(5,5) 是背景白。文字基线在 y=100，字框顶部大约在 100−上坡度，所以文字落在矩形下方而不是矩形里面。

常见错法：把 y=100 当字框顶部；在 `paintComponent` 里改计数器导致每次重绘都变化；忘记 `dispose` 副本或误释放原 `g`。

## E3

`--check` 的判定点要按操作选：填充看内部，描边看边线。PNG 输出必须是调用者显式给出的新路径，程序不能默认覆盖某个固定文件；写失败要抛出并说明，不能打印“已保存”。

图像三种输入的结果：

| 输入 | 结果 | 失败阶段 |
|---|---|---|
| 合法 PNG | `size=宽:高` | — |
| 三个普通字节 | `unsupported`（read 返回 null） | 解码/加载 |
| 不存在的路径 | `io-error`（IOException） | 打开文件 |

三者都在进入平铺循环前被拒绝；平铺步长必须为正，否则循环不前进或方向错误。

## E4

参考实现见 [CenteredTitle.java](CenteredTitle.java)。三个位置：

```text
x     = (320 - bounds.getWidth()) / 2
top   = (120 - bounds.getHeight()) / 2
baseY = top - bounds.getY()        // getY 为负，等价于 top + 上坡度
```

`--check` 输出 `inside=true`，表示度量框完整落在 320×120 内。基线用灰色画在 `baseY`，能看到字母 g 的下降部分在基线以下、大写字母在基线以上。

常见错法：把 `baseY` 直接写成 `top`（文字整体偏上）；用字符数×字号估宽度；换字号后不重算位置。
