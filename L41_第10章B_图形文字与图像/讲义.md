## 1. 形状对象不是画面：draw、fill与画笔状态

`Rectangle2D` 对象里只有坐标和宽高，它不包含颜色，也不等于屏幕上的那块红色。真正把形状变成像素的，是 `Graphics2D` 的 `draw`（描边）或 `fill`（填内部）。教材 p420 的说法是：先创建一个实现了 `Shape` 接口的对象，再调用 `Graphics2D.draw`。

像手里有一张画好尺寸的图纸：图纸本身不显示，得拿笔在展示板上描出来。类比边界是：`Graphics2D` 不只是“笔”，它还保存颜色、字体、裁剪区等一组状态；这些状态不会跟着形状对象走。

```java
import java.awt.Color;
import java.awt.Dimension;
import java.awt.EventQueue;
import java.awt.Graphics;
import java.awt.Graphics2D;
import java.awt.geom.Ellipse2D;
import java.awt.geom.Rectangle2D;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import java.io.UncheckedIOException;
import javax.imageio.ImageIO;
import javax.swing.JFrame;
import javax.swing.JPanel;
public class ShapePaintLab {
    static class Scene extends JPanel {
        private static final long serialVersionUID = 1L;
        Scene() { setBackground(Color.WHITE); }
        @Override public Dimension getPreferredSize() { return new Dimension(360, 220); }
        @Override protected void paintComponent(Graphics g) {
            super.paintComponent(g);
            Graphics2D copy = (Graphics2D) g.create();
            try {
                copy.setColor(Color.RED); copy.fill(new Rectangle2D.Double(20, 20, 120, 70));
                copy.setColor(Color.BLUE); copy.fill(new Ellipse2D.Double(180, 20, 120, 70));
                copy.setColor(Color.BLACK); copy.drawLine(20, 130, 300, 130); copy.drawString("Java 2D", 20, 180);
            } finally { copy.dispose(); }
        }
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) {
            EventQueue.invokeAndWait(() -> {
                Scene panel = new Scene(); panel.setSize(360, 220);
                BufferedImage image = new BufferedImage(360, 220, BufferedImage.TYPE_INT_RGB);
                Graphics2D g = image.createGraphics(); try { panel.printAll(g); } finally { g.dispose(); }
                System.out.println("rectangle=" + (image.getRGB(30, 30) == Color.RED.getRGB()));
                System.out.println("ellipse=" + (image.getRGB(240, 55) == Color.BLUE.getRGB()));
                if (args.length > 1) {
                    try { ImageIO.write(image, "png", new File(args[1])); }
                    catch (IOException ex) { throw new UncheckedIOException(ex); }
                }
            });
        } else EventQueue.invokeLater(() -> {
            JFrame frame = new JFrame("形状与坐标"); frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.add(new Scene()); frame.pack(); frame.setLocationByPlatform(true); frame.setVisible(true);
        });
    }
}
```

无参数运行会打开窗口：左边红矩形，右边蓝椭圆，下方一条黑线和“Java 2D”文字。在课程根目录 PowerShell 运行：

```powershell
.\java.ps1 -Source './L41_第10章B_图形文字与图像/code/ShapePaintLab.java'
```

`--check` 不建窗口，只在 EDT 里把面板画到内存图片上，检查两个内部像素：`rectangle=true`、`ellipse=true`。像素点选在图形内部，不选抗锯齿的边缘，因为边缘是混合色，不能拿来做固定值断言。

| 时刻 | 画笔颜色 | 动作 | 结果 |
|---|---|---|---|
| 进入paintComponent | 默认 | `super.paintComponent` 用背景铺底 | 整块白 |
| 第一次setColor | RED | `fill` 左上(20,20)宽120高70 | 左红块 |
| 第二次setColor | BLUE | `fill` 椭圆外接框(180,20,120,70) | 右蓝椭圆 |
| 第三次setColor | BLACK | 画线、画字 | 前两块仍是原色 |

第三行最能说明问题：把颜色改成黑色，并不会把已经画好的红矩形“重涂”成黑色；`setColor` 只改这支笔之后的行为。要换色重画，必须重绘整个区域并重新按顺序执行。

`g.create()` 复制一份当前绘制环境，`finally` 里 `dispose()` 释放副本；Swing 传进来的原 `g` 不能随手释放。这不是仪式：`create` 出来的副本带有独立的颜色、字体、裁剪状态，释放它不会破坏外面的绘制。

只改一处的实验：把红矩形 `fill` 换成 `draw`，再看窗口——矩形只剩边框。再把检查点 (30,30) 换成边框上的 (20,20)，体会“内部点”和“边线点”不是一回事。

独立小任务：在同一个面板里画第三个图形（例如一条从左上到右下的对角线），要求它在黑线之后仍保持自己的颜色；说明你的代码顺序为什么能得到这个结果。

## 2. 四个参数与外接矩形：Float和Double到底差在哪

`new Rectangle2D.Double(x, y, w, h)` 的四个参数是：左上角 x、左上角 y、宽、高。**不是**左上角和右下角。教材 p421–423 反复强调这一点，因为一旦把右下角当参数传进去，宽高就变成负数，图形直接为空。

```java
import java.awt.geom.Rectangle2D;

public class RectParamsProbe {
    public static void main(String[] args) {
        Rectangle2D.Double rect = new Rectangle2D.Double(100, 50, 80, 40);
        System.out.println("x=" + rect.getX() + " y=" + rect.getY());
        System.out.println("w=" + rect.getWidth() + " h=" + rect.getHeight());
        System.out.println("maxX=" + rect.getMaxX() + " maxY=" + rect.getMaxY());
        System.out.println("center=" + rect.getCenterX() + "," + rect.getCenterY());
        Rectangle2D upcast = new Rectangle2D.Float(100F, 50F, 80F, 40F);
        System.out.println("float-width=" + upcast.getWidth());
        rect.setRect(0, 0, -80, -40);
        System.out.println("empty=" + rect.isEmpty());
    }
}
```

输出：

```text
x=100.0 y=50.0
w=80.0 h=40.0
maxX=180.0 maxY=90.0
center=140.0,70.0
float-width=80.0
empty=true
```

`maxX` 是 `x + w = 180`，它表示“右边界坐标”，不是“最后一个被填充的像素列”；第 4 节会看到 `fill` 实际只填到 179。`getCenterX` 是 `x + w/2`。

最后两行是这节的重点：`upcast` 是 `Rectangle2D.Float` 对象，但声明成 `Rectangle2D`，`getWidth()` 仍返回 `double` 的 `80.0`。教材 p421 说得很清楚：`Rectangle2D` 的方法参数和返回值都是 `double`，即使对象内部用 `float` 存坐标。这就是为什么 `float f = rect.getWidth();` 编译不过，必须写 `(float) rect.getWidth()`。

| 写法 | 内部存储 | 构造参数 | 方法返回 |
|---|---|---|---|
| `new Rectangle2D.Double(...)` | double | double | double |
| `new Rectangle2D.Float(...)` | float | float | double |
| 变量声明 `Rectangle2D r` | 看实际对象 | — | double |

`Float`/`Double` 是 `Rectangle2D` 的**静态嵌套子类**，不是 `java.lang.Double` 那个包装类；它们存在的理由只是让“省空间的 float 坐标”和“省事的 double 坐标”共用一个父类型。教材 p421 还提到：`Rectangle2D.Float` 有一个自己的 `setRect(float...)`，一旦用父类型变量接收就调不到它，但父类的 `setRect(double...)` 仍然可用。

图 10-11 的继承关系值得记一眼：`Rectangle2D`、`Ellipse2D` 都继承 `RectangularShape`（都有外接矩形），`Line2D` 直接实现 `Shape`；`Point2D` 只是坐标点，**不是** `Shape`，不能直接交给 `draw`。教材里从 Java 1.0 留下的 `Rectangle`、`Point` 用整数坐标，属于历史类，新代码不必优先使用。

只改一处的实验：把 `new Rectangle2D.Double(100, 50, 80, 40)` 改成 `(100, 50, 180, 90)`，先预测 `maxX` 和 `center` 再运行。你会发现宽高不是“右下角”，而是长度。

独立小任务：用 `Ellipse2D.Double` 画一个外接框为 `(150, 200, 100, 50)` 的椭圆，写出它的中心、左边界、右边界；再说明“椭圆没有宽高、只有半径”这句话哪里不准确。

## 3. 只知道对角或中心时：先规范化，再画

实际画图时，你手里往往不是左上角加宽高，而是两个对角点，或者“圆心加一个角”。直接拿这两个点相减，顺序一反就得到负宽高。

```java
import java.awt.geom.Rectangle2D;
public class DiagonalRectangle {
    public static void main(String[] args) {
        Rectangle2D rect = new Rectangle2D.Double();
        rect.setFrameFromDiagonal(100, 60, 20, 10);
        System.out.println(rect.getX() + ":" + rect.getY() + ":" + rect.getWidth() + ":" + rect.getHeight());
        System.out.println(rect.getCenterX() + ":" + rect.getCenterY());
    }
}
```

输出 `20.0:10.0:80.0:50.0` 和 `60.0:35.0`。输入先给右下 (100,60)、再给左上 (20,10)，`setFrameFromDiagonal` 自动取两个方向的最小值作起点，宽高取距离。你把两个点的顺序换过来，结果应当完全相同。

```java
import java.awt.geom.Ellipse2D;
import java.awt.geom.Rectangle2D;

public class CircleFromCenter {
    public static void main(String[] args) {
        Ellipse2D circle = new Ellipse2D.Double();
        circle.setFrameFromCenter(100, 80, 130, 110);
        System.out.println("x=" + circle.getX() + " y=" + circle.getY() + " w=" + circle.getWidth() + " h=" + circle.getHeight());
        Rectangle2D naive = new Rectangle2D.Double(100, 60, 20 - 100, 10 - 60);
        System.out.println("naive-empty=" + naive.isEmpty());
        System.out.println("naive-w=" + naive.getWidth());
    }
}
```

输出：

```text
x=70.0 y=50.0 w=60.0 h=60.0
naive-empty=true
naive-w=-80.0
```

`setFrameFromCenter(cx, cy, cornerX, cornerY)` 接收中心和“外接框上的一个角”，宽 = 2×|cornerX−cx| = 60，高 = 2×|cornerY−cy| = 60，于是左上角是 (100−30, 80−30) = (70,50)。这也说明：给中心和一个角，就能唯一确定一个以该中心对称的外接框；如果你给的点不在对角方向，算出来的框会和你想象的不同。

`naive` 那两行是反例：把右下角当宽高传，宽变成 −80，`isEmpty()` 为 `true`。空几何不是 `null`：对象存在，只是没有面积，`draw` 不会帮你补出一个可见正方形。

| 已知条件 | 正确入口 | 常见错法 |
|---|---|---|
| 左上角 + 宽高 | `new Rectangle2D.Double(x, y, w, h)` | 把右下角当宽高 |
| 任意两个对角 | `setFrameFromDiagonal(...)` | 直接相减，顺序反了 |
| 中心 + 宽高 | `(cx-w/2, cy-h/2, w, h)` | 把中心当左上角 |
| 中心 + 一个角 | `setFrameFromCenter(...)` | 把角当成宽高 |

只改一处的实验：把 `setFrameFromCenter(100, 80, 130, 110)` 的最后一个点改成 `(130, 80)`，预测高度是多少、图形是否还可见。这个实验能暴露“角点必须在两个方向都偏离中心”。

独立小任务：用 `setFrameFromCenter` 画一个外接框 120×80 的椭圆，写出它的左上角和两个对角点；再用 `setFrameFromDiagonal` 用这两个对角点重建，验证两次得到同一个框。

## 4. 颜色只作用于后续绘制：fill与draw还差一像素

`setColor` 与 `setPaint` 都是改“这支笔”的状态，不影响已经画好的像素。教材 p426 还给了一个很容易被忽略的细节：`fill` 在右侧和下方会少画一个像素。

```java
import java.awt.Color;
import java.awt.Graphics2D;
import java.awt.geom.Rectangle2D;
import java.awt.image.BufferedImage;

public class FillVersusDrawPixels {
    static BufferedImage blank() {
        BufferedImage image = new BufferedImage(32, 32, BufferedImage.TYPE_INT_RGB);
        Graphics2D paint = image.createGraphics();
        try {
            paint.setColor(Color.WHITE);
            paint.fillRect(0, 0, 32, 32);
        } finally {
            paint.dispose();
        }
        return image;
    }

    public static void main(String[] args) {
        Rectangle2D rect = new Rectangle2D.Double(0, 0, 10, 20);
        BufferedImage filled = blank();
        Graphics2D fillPen = filled.createGraphics();
        try {
            fillPen.setColor(Color.RED);
            fillPen.fill(rect);
        } finally {
            fillPen.dispose();
        }
        BufferedImage drawn = blank();
        Graphics2D drawPen = drawn.createGraphics();
        try {
            drawPen.setColor(Color.RED);
            drawPen.draw(rect);
        } finally {
            drawPen.dispose();
        }
        System.out.println("fill-inside=" + (filled.getRGB(9, 19) == Color.RED.getRGB()));
        System.out.println("fill-right-edge=" + (filled.getRGB(10, 20) == Color.RED.getRGB()));
        System.out.println("draw-edge=" + (drawn.getRGB(10, 20) == Color.RED.getRGB()));
        System.out.println("draw-inside=" + (drawn.getRGB(9, 19) == Color.RED.getRGB()));
    }
}
```

输出四行：

```text
fill-inside=true
fill-right-edge=false
draw-edge=true
draw-inside=false
```

矩形是 `(0,0,10,20)`，`fill` 填的是 x=0..9、y=0..19，所以 (9,19) 是红的，(10,20) 不是——右边界和下边界那一条被让出去了。`draw` 正好相反：它画的是边界线，(10,20) 在线上所以是红的，而 (9,19) 在内部、不在 1 像素宽的边线上，所以不是红的。

这也解释了为什么不能用“图形内部点”去检查 `draw` 的结果，也不能用“边线上一点”去检查 `fill`。本课后面的检查点都按这个规则选。

| 操作 | 覆盖范围 | 适合检查的点 |
|---|---|---|
| `fill(rect)` | 内部，右/下边界让出一像素 | 内部，如 (9,19) |
| `draw(rect)` | 1 像素宽的边界线 | 边界，如 (10,20) |

颜色的来源有三种常见写法：`Color.RED` 这类 13 个预定义常量、`new Color(r, g, b)`（0–255）、以及 `SystemColor.window` 这类跟系统主题走的颜色。改组件底色用 `setBackground`，它影响 `super.paintComponent` 铺的那层；`setForeground` 只是组件的默认前景色，不会自动改你已经画上去的像素。`brighter()`/`darker()` 返回新颜色对象，不是原地修改。

只改一处的实验：把 `fill` 的矩形宽从 10 改成 11，预测 (10,20) 是否变红（x 方向多了一列），再预测 y 方向；分开验证，别一次改两个方向。

独立小任务：画一个 3 像素宽的红色边框（提示：`draw` 的线宽由 `BasicStroke` 控制，属于本课“选读”，你也可以画两个嵌套矩形来模拟），并说明你的检查点为什么选在边框上。

## 5. 文字放在基线上：Font、deriveFont与居中

`drawString(text, x, y)` 的 y 是**基线**，不是文字框顶部。字母 g、p 的下降部分在基线以下，大写字母在基线以上；`getStringBounds` 返回的矩形正是以基线为参照，顶部 y 是负数。教材 p431 的图 10-13 把基线、上坡度、下坡度、行间距、字高画在一起，值得对照。

```java
import java.awt.Font;

public class FontOverloadTrap {
    public static void main(String[] args) {
        Font base = new Font("SansSerif", Font.PLAIN, 12);
        Font byStyle = base.deriveFont(14);
        Font bySize = base.deriveFont(14.0f);
        System.out.println("style-arg: style=" + byStyle.getStyle() + " size=" + byStyle.getSize2D());
        System.out.println("size-arg: style=" + bySize.getStyle() + " size=" + bySize.getSize2D());
        Font italic = base.deriveFont(Font.ITALIC);
        System.out.println("italic=" + italic.isItalic() + " size=" + italic.getSize2D());
    }
}
```

输出：

```text
style-arg: style=0 size=12.0
size-arg: style=0 size=14.0
italic=true size=12.0
```

`deriveFont(14.0f)` 走 float 重载，改的是字号；`deriveFont(Font.ITALIC)` 走 int 重载，改的是风格。这两行说明重载选择由**参数类型**决定，不是由数字看起来像什么决定。

教材 p430 的警告说：`deriveFont(14)` 会把 14 当风格位，结果是斜体。在本机 JDK 21 上实测，14 不是一个合法的风格组合，JDK 把它规整成了 `PLAIN`（`style=0`、`isItalic()=false`），字号保持 12。所以“int 重载改的是风格而不是字号”这个结论仍然成立，但“结果一定是斜体”这句具体描述不能照抄；不同 JDK 版本对非法风格位的处理可能不同，写代码时应当传 `Font.BOLD` 这类有名字的常量，而不是裸数字。

字体名也有两类：`SansSerif`、`Serif`、`Monospaced`、`Dialog`、`DialogInput` 是逻辑名，由系统映射到本机实际字体；`Arial` 这类是物理名，换一台机器不一定存在。教材 p429 的程序用 `GraphicsEnvironment.getAvailableFontFamilyNames()` 列出本机字体，这个方法的结果随机器变化，不能把某台机器的清单当成标准答案。

```java
import java.awt.Color;
import java.awt.Font;
import java.awt.Graphics2D;
import java.awt.geom.Rectangle2D;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;
public class TextBaselineMeasure {
    public static void main(String[] args) throws IOException {
        BufferedImage image = new BufferedImage(320, 120, BufferedImage.TYPE_INT_RGB); Graphics2D g = image.createGraphics();
        try {
            g.setColor(Color.WHITE); g.fillRect(0, 0, 320, 120);
            Font font = new Font("SansSerif", Font.BOLD, 12).deriveFont(24.0f); g.setFont(font);
            String text = "Java pg"; Rectangle2D bounds = font.getStringBounds(text, g.getFontRenderContext());
            double x = (320 - bounds.getWidth()) / 2; double top = (120 - bounds.getHeight()) / 2; double baseY = top - bounds.getY();
            g.setColor(Color.BLACK); g.drawString(text, (float) x, (float) baseY);
            g.setColor(Color.GRAY); g.drawLine(0, (int) baseY, 319, (int) baseY);
            g.setColor(Color.BLUE); g.draw(new Rectangle2D.Double(x, top, bounds.getWidth(), bounds.getHeight()));
            System.out.println("inside=" + (x >= 0 && top >= 0 && x + bounds.getWidth() <= 320 && top + bounds.getHeight() <= 120));
        } finally { g.dispose(); }
        if (args.length > 1) ImageIO.write(image, "png", new File(args[1]));
    }
}
```

输出 `inside=true`。这段代码把三件事放在一张图上：黑色文字、灰色基线、蓝色度量框。`bounds.getY()` 是负数（基线到度量框顶部的距离取负），`baseY = top - bounds.getY()` 等于 `top + 上坡度`，正好把文字框顶对齐到 `top`。

居中公式可以拆成三步，别背成一串：

| 步骤 | 式子 | 含义 |
|---|---|---|
| 水平位置 | `x = (画布宽 - bounds宽) / 2` | 两侧留白相等 |
| 框顶位置 | `top = (画布高 - bounds高) / 2` | 上下留白相等 |
| 基线位置 | `baseY = top - bounds.getY()` | 从框顶下移上坡度 |

只改一处的实验：把字号从 `24.0f` 改成 `36.0f`，先预测文字是否还完整落在画布里，再运行。字号变大后宽高都变，`x` 和 `baseY` 必须重新算；只把原来的 y 加 12 是错的。

独立小任务：把文字改成含中文的“学习 Java”，用 `inside` 检查它是否仍在画布内；再说明为什么换字体后同一串文字的宽度可能变化，而你的公式不需要改。

## 6. 图像：先证明读进来了，再谈平铺

教材 p435 用 `new ImageIcon(filename).getImage()` 取图，p436 的平铺程序只判断 `image == null`。这在“文件不存在”时不保险：`ImageIcon` 可能给你一个引用不为 `null`、但宽高为 −1 的图像，后面拿它做步长就会出问题。

课程用 `ImageIO.read` 走一条能明确报告失败的路线：文件打不开抛 `IOException`，内容没有可用解码器返回 `null`，两种都要在进入绘制循环前处理。

```java
import java.awt.Color;
import java.awt.Graphics2D;
import java.awt.image.BufferedImage;
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import javax.imageio.ImageIO;
public class PositiveTileImage {
    public static void main(String[] args) throws IOException {
        BufferedImage tile = new BufferedImage(8, 8, BufferedImage.TYPE_INT_RGB); Graphics2D pen = tile.createGraphics();
        try { pen.setColor(Color.ORANGE); pen.fillRect(0, 0, 8, 8); } finally { pen.dispose(); }
        ByteArrayOutputStream bytes = new ByteArrayOutputStream(); ImageIO.write(tile, "png", bytes);
        BufferedImage loaded = ImageIO.read(new ByteArrayInputStream(bytes.toByteArray()));
        if (loaded == null || loaded.getWidth() <= 0 || loaded.getHeight() <= 0) throw new IOException("invalid image");
        BufferedImage output = new BufferedImage(20, 20, BufferedImage.TYPE_INT_RGB); Graphics2D g = output.createGraphics();
        try { for (int y = 0; y < 20; y += loaded.getHeight()) for (int x = 0; x < 20; x += loaded.getWidth()) g.drawImage(loaded, x, y, null); }
        finally { g.dispose(); }
        System.out.println("size=" + loaded.getWidth() + "x" + loaded.getHeight());
        System.out.println("tiled=" + (output.getRGB(19, 19) == Color.ORANGE.getRGB()));
    }
}
```

输出 `size=8x8` 和 `tiled=true`。这里没有外部图片文件：先造一张 8×8 的橙色图，编码成 PNG 字节再解码回来，模拟“从文件读入”的完整路径。`ByteArrayOutputStream` 暂存字节，`ByteArrayInputStream` 当作读取来源；换成真实文件时，把读取来源换成 `new File(路径)` 即可。

平铺循环的关键是**步长必须为正**：`x += loaded.getWidth()`，宽高已经检查过大于 0，循环才会前进。画布 20 不能被 8 整除，最后一块超出边界的部分由绘图裁剪，不需要循环恰好停在 20。

```java
import java.awt.image.BufferedImage;
import java.io.ByteArrayInputStream;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;
public class ImageLoadBoundary {
    public static void main(String[] args) {
        try {
            BufferedImage image = args.length == 0 ? ImageIO.read(new ByteArrayInputStream(new byte[] {1, 2, 3})) : ImageIO.read(new File(args[0]));
            if (image == null) System.out.println("unsupported");
            else if (image.getWidth() <= 0 || image.getHeight() <= 0) System.out.println("bad-size");
            else System.out.println("size=" + image.getWidth() + ":" + image.getHeight());
        } catch (IOException e) { System.out.println("io-error"); }
    }
}
```

默认把三个普通字节当图像解码，`ImageIO.read` 返回 `null`，输出 `unsupported`；传入一个不存在的路径则走 `catch`，输出 `io-error`。这两条路都必须处理：`null` 不代表“文件没问题”，`IOException` 也不代表“格式不支持”。

| 输入 | 结果 | 下一步 |
|---|---|---|
| 合法 PNG | `size=宽:高` | 可以绘制 |
| 字节不是图像 | `unsupported`（null） | 报告格式问题，别继续 |
| 路径不存在/无权限 | `io-error`（IOException） | 报告文件问题，别继续 |
| 宽或高 ≤ 0 | `bad-size` | 不能拿来做步长 |

`drawImage(image, x, y, null)` 的最后一个参数是 `ImageObserver`，普通内存图像传 `null` 即可；教材 p437 提醒这个调用可能在图像还没画完时就返回，但 `ImageIO.read` 返回的 `BufferedImage` 已经完整解码，不存在“画一半”的问题。要缩放就传目标宽高：`drawImage(img, x, y, w, h, null)`，它会拉伸，保持比例需要自己先算统一比例。

只改一处的实验：把平铺画布从 20 改成 16，预测横向、纵向各铺几块；再把 `ImageIO.read` 的来源换成一个纯文本文件，确认输出是 `unsupported` 而不是崩溃。

独立小任务：把自己 `my_code` 里的一张图片读进来，打印宽高，再按原尺寸平铺到 200×150 的画布；如果读取失败，分别记录是 `null` 还是异常，不要用扩展名判断成功。

## 7. 运行与排错

所有命令都在课程根目录 PowerShell 输入，单文件用 `java.ps1`；复制到 `my_code/` 后把命令里的 `code` 换成 `my_code`。`--check` 只做离屏像素检查，真实窗口、字体观感、缩放效果必须无参数运行观察。源码文件名与 public 类名一致。

| 现象 | 先查哪里 |
|---|---|
| 屏幕上什么都没有 | 形状是否只 `new` 没 `draw/fill`；`paintComponent` 是否被调用；窗口是否 `pack` |
| 图形位置不对 | 四个参数是否把右下角当宽高；坐标原点在内容区左上，y 向下 |
| 图形不可见但坐标没错 | 宽或高是否为负/零；是否画在可视区外 |
| 矩形边框一像素差异 | `fill` 与 `draw` 的覆盖范围不同，检查点要按操作选 |
| 文字位置偏上/偏下 | y 是基线；居中要减 `bounds.getY()`，不是直接减高度 |
| 文字超出画布 | 字号变了但位置没重算；字体换过宽度也变 |
| `ImageIcon` 图显示不出来 | 文件路径相对工作目录；先打印 `getWidth(null)` 是否为 −1 |
| 平铺死循环/卡住 | 图像宽高是否为 0 或负；步长是否为正 |
| 中文变方框 | 逻辑字体未必包含全部汉字；换 `Dialog` 或指定字体，先查本机字体清单 |

最后用一句完整的话回答本课：Java 2D 里，形状对象只描述几何，`Graphics2D` 保存这支笔的颜色、字体等状态，`draw` 描边、`fill` 填内部，颜色只影响后续绘制；文字按基线定位，居中要靠字体度量反推；图像先确认读入且尺寸为正，再进入绘制或平铺循环。
