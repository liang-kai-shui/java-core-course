这一课要解决什么问题

让程序接收你输入的数据，打印清楚的结果，并把文本写入文件。

1. Scanner像一位读入助手

输入流可以先理解为按顺序到来的数据通道，System.in通常连接键盘输入。Scanner是帮助从通道里读数或文本的工具；new Scanner(System.in)建立这位读入助手，import java.util.Scanner让你能写短类名。new的对象构造机制第4章讲，此处只掌握使用方式。

nextInt()读一个整数，nextDouble()读一个浮点数；next()读一个空白分隔的片段，nextLine()读当前行剩余内容并跨过行分隔符。输入Li Ming，next不能一次读到完整姓名。

int age = in.nextInt();
in.nextLine(); // 消耗数字后这一行剩余的内容
String name = in.nextLine();

为什么要中间这一行？数字读取通常把数字后面的换行留在通道里；紧接着nextLine会先读到数字所在行的剩余部分。如果那部分只有换行，结果就是空串。注意：这一行不一定只剩换行，若同一行还有别的数据，也会一起被读走；本课约定年龄和姓名分别各占一行。

Locale.US在数值输入示例里明确使用点作小数分隔，避免系统地区设置改变实验。这里只把Locale看成“地区格式规则”，不要求先学国际化框架。

2. 格式化输出

格式化是把数值按约定排成文字。printf("%.2f%n", price)中的%.2f用两位小数显示浮点数，%d显示整数，%s显示文本，%n换行。显示两位不等于底层值变成精确的两位小数。格式说明符与参数类型必须匹配。

3. 文件有路径，也有编码

Paths.get("note.txt")表示相对当前工作目录的路径，不一定是源码所在目录。课程脚本不替你切换到源码文件夹；从根目录启动时相对文件就落在根目录。

编码是文字变成字节的规则，读写双方一致才能避免乱码。FileUtf8Demo用UTF-8明确写入、读回一个文件；路径由命令行参数指定。资源指打开后需要管理的文件通道等，try (...) { ... }会在结束时关闭本例的文件工具；第7章再系统讲异常与资源管理。示例的throws IOException表示本方法可能把此类文件错误交给调用方；不是“自动修好错误”。

示例将内容写到你给出的目标路径，会覆盖同名文件；请只在自己新建的实验目录里使用不同文件名。不要把教材PDF路径交给它。

动手实验

运行InputDemo，依次输入年龄、完整姓名、单价、数量，按练习的顺序每项一行；先预测账单。FileUtf8Demo使用课程给出的.build/file-lab/note.txt路径，运行后打开文件确认内容，再换一个新名字测试。使用参数或代码中明确的路径定位文件，别靠搜索猜。
