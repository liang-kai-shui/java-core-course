0. 这课分几步学

分三次：第 1–4 节只处理键盘和换行；第 5 节输出格式；第 6–8 节再读写文件。基础键盘任务与文件体验分开，不要求一次学会异常体系。

怎么把讲义中的程序跑起来

带有 public class、完整大括号和 main 的 Java 代码框是完整程序。标为“片段”的短代码只替换 main 里面相应部分，不能单独当文件运行。每个完整程序另建一个文件，不能把两个 public class 或两个 main 随手拼在一起。

在 VS Code 中打开整个 D:\Code\Java 文件夹。在本课 my_code 文件夹新建 ReadOneAge.java，文件名要与 public class 后的名字相同；保存为 UTF-8。没有显示后缀、不会新建文件或打开终端，先看零基础起飞，无需先读 PDF。

打开“终端 → 新建终端”，确认使用 PowerShell。以下命令从课程根目录开始输入，提示符本身不用抄：

Set-Location 'D:\Code\Java'
.\java.ps1 -Source '.\L06_第03章D_输入输出\my_code\ReadOneAge.java'

这是课程提供的“编译成功才启动”工具。它每次在 .build 中另建输出目录，生成 class 后才运行；不要手动执行以前留下的 class。后面的完整程序同样操作，只换末尾文件名。需要键盘输入时，运行后在终端键入数据并回车；程序没有显示新提示符，可能正在等输入。出现脚本策略提示时，在同一根目录把运行一行改为：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\java.ps1 -Source '.\L06_第03章D_输入输出\my_code\ReadOneAge.java'

每次实验留三项记录：预测、实际输出、解释第一次出现差异的步骤。看到程序自己的输出才算实际启动；没有报错不等于题目做对。

1. 程序为什么停着不动

前面把数据写在源码里，换一个年龄就得改程序。现在让同一程序运行时接收不同输入。

输入是数据进入程序，输出是结果离开程序。流可以先理解为按顺序传送数据的通道；System.in 通常接收终端键盘输入，System.out 通常向终端输出。通道类比强调顺序，不代表每读一次电脑就自动给你一整行。

Scanner是从文本来源中识别数字或片段的标准库工具。import 让程序知道我们使用哪一个现成类，new 建立一个本次读入工具；第 4 章再学习自己设计类和对象。

import java.util.Scanner;

public class ReadOneAge {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.println("请输入年龄，然后回车：");
        int age = in.nextInt();
        System.out.println("age=" + age);
    }
}

运行后先看到提示；此时没有 PowerShell 新提示符，程序正在等待输入。在同一个终端输入 18 并回车，才看到 age=18。不要把 18 写到源码窗口，也不要把“等待”当成编译卡住。

行为 程序状态
建立 Scanner 准备读取标准输入
打印提示 尚未有年龄数据
执行 nextInt 等待或读取下一份整数文本，得到 int
赋给 age 保存读取结果
打印 age 使用这次输入

如果输入 hello，nextInt 不能把它变成整数，会出现输入不匹配异常。本课先约定有效输入，不要求设计自动纠错菜单；但要知道这不是 Java 无法显示中文。

2. 读一个片段，还是读整行

分隔符是用来区分片段的边界。Scanner 默认的片段分隔通常是空格、制表、换行等空白。

方法 尝试得到什么 输入 Li Ming 时
next() 下一个空白分隔片段 首次得到 Li
nextInt() 把下个片段读成 int 不是整数，不能成功
nextDouble() 按地区规则读成 double 不是数值，不能成功
nextLine() 当前位置到本行末的正文，并跨过行分隔符 若在行首，得到 Li Ming

新建第二个完整程序，先只读整行：

import java.util.Scanner;

public class ReadFullName {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.println("请输入姓名：");
        String name = in.nextLine();
        System.out.println("name=[" + name + "]");
    }
}

输入 Li Ming，输出 name=[Li Ming]。再输入空行，会得到 name=[]；空串是本次实际读到的正文，不等于没有调用成功。把 nextLine 改成 next，仅改这一处，预测带空格姓名的结果，再运行。

3. 读完整数后，姓名为什么突然变成空串

关键是“接着上次位置继续读”，不是每个读取都重置到新一行。假设你依次输入年龄和姓名：

18↵
Li Ming↵

先把输入想成等待读取的队伍：

[1][8][本行结束][L][i][空格][M][i][n][g][本行结束]

nextInt 解析并取走 18 后，当前位置尚在数字所在行末的分隔位置。紧接着 nextLine 读“这一行剩余的正文”，这里剩余正文为空，于是立刻得到空串，并越过行结束。

第一次 nextInt  → 18
第一次 nextLine → ""       读取数字这一行剩余的内容
第二次 nextLine → "Li Ming" 真正读下一行

这是解释读取位置的简化队列，不是声称 Scanner 或终端内部恰好使用这幅内存布局。

4. 先约定输入布局，再写对应读取

本题明确约定“年龄一行，姓名下一行”：

import java.util.Scanner;

public class AgeThenName {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int age = in.nextInt();
        in.nextLine();
        String name = in.nextLine();
        System.out.println(name + ":" + age);
    }
}

输入上面的两行，输出 Li Ming:18。中间那次 nextLine 的结果故意不保存，因为本题不需要数字所在行的剩余正文。

先预测：如果用户把 18 Li Ming写在同一行，中间那次 nextLine 会拿走什么？会拿走数字之后包括姓名的剩余正文，所以这个方案不能无条件套在所有输入布局上。

随堂实验顺序：正确输入两行 → 删除中间读取，看空串 → 恢复 → 输入同一行并观察为何需要另一个协议。不要背成“nextInt 后永远加一个 nextLine 就对”。

5. 账单：数值计算与显示格式分开

格式化是把一个值按要求排成文字，例如保留两位小数。格式化不会把 double 内部的二进制近似数变成精确十进制金额。

import java.util.Locale;
import java.util.Scanner;

public class BillWalk {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        in.useLocale(Locale.US);
        String name = in.nextLine();
        double price = in.nextDouble();
        int count = in.nextInt();
        double total = price * count;
        System.out.println("name=" + name);
        System.out.printf(Locale.US, "total=%.2f%n", total);
    }
}

输入三行 Li Ming、12.5、3，得到：

name=Li Ming
total=37.50

这里先读整行姓名，再读数字，没有“数字后立即读姓名”的衔接问题。Locale 表示地区格式规则；本例用 US 明确小数点为点号，避免运行环境差异改变练习。

拆开 printf 的参数：

部分 作用
Locale.US 按这一地区规则格式化
"total=%.2f%n" 模板：标签、浮点数两位小数、换行
total 填进模板中 %f 位置的数值

常用 %d放整数，%s放文本，%f放浮点数，%.2f指定小数位，%n换行。想输出百分号本身用 %%。说明符与值类型要匹配；把整数交给 %f 不是自动变成浮点数的万能写法。

测试数量 0：总额 0.00；价格 0.1、数量 3：显示 0.30。显示正常不证明内部值完全精确，L09 会引入十进制运算工具。

6. 文件在哪里：源码目录与工作目录分开

文件路径说明要读写哪个文件。相对路径从运行进程的工作目录开始计算，不自动从 .java 所在文件夹开始。

从课程根目录运行，note.txt指根目录的文件；从本课 my_code 运行，同一个相对名字会指向那里。课程脚本不替你切到源码目录。

文本编码规定字符怎样对应字节。像发信双方使用同一套编号字典；写入按 UTF-8、读取按另一种规则，可能错解。类比说明约定一致，不表示每个字母一定只占一个字节。

文件体验放在自己的实验目录，使用新文件名。下面程序将覆盖固定实验路径同名文件，先确认这个路径不存放你的重要内容。

7. 用PrintWriter写文本，再用Scanner读回（教材3.7.3）

PrintWriter是把文本写到指定目标的工具，可以像System.out一样使用print、println、printf。路径只表示位置，打开写入工具后才真正进行文件操作。

import java.io.IOException;
import java.io.PrintWriter;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Scanner;

public class FileRoundTrip {
    public static void main(String[] args) throws IOException {
        Path folder = Paths.get(".build", "lecture-file-lab");
        Files.createDirectories(folder);
        Path file = folder.resolve("note.txt");
        PrintWriter writer = new PrintWriter(file.toString(), "UTF-8");
        writer.println("你好，Java！");
        writer.close();
        Scanner reader = new Scanner(file, "UTF-8");
        String text = reader.nextLine();
        reader.close();
        System.out.println("text=" + text);
        System.out.println("file=" + file.toAbsolutePath());
    }
}

从课程根目录运行，输出text=你好，Java！，以及.build\lecture-file-lab\note.txt的绝对位置。打开该路径应看到同样正文。本程序会覆盖同名实验文件，只用于新建的练习目标。

部分 本次读法
Paths.get、resolve 指定目录和文件位置
Files.createDirectories 确保实验目录存在；这是课程补的准备动作
new PrintWriter(文件名,编码) 建立按UTF-8写文本的工具
println 写正文并换行
close 完成并关闭；写入关闭也让缓冲内容送到目标
new Scanner(file,编码) 从这个文件读取，而非从键盘读取
reader.nextLine 按前面学过的整行规则取得正文
throws IOException 允许把本方法的文件操作错误向上报告

本例先写完关闭，再打开读取，保证读取的不是尚未完整写出的内容。简单正常路径中明确调用close；若中途出错，关闭还需要更完整的管理，下一节原示例展示try资源语法，异常体系第7章再学。

特别注意构造参数的类型：new Scanner("note.txt")把这几个字母当输入正文，不会打开文件。要读文件，使用本例的Path入口。工作目录可通过System.getProperty("user.dir")观察，但它也不应被误当源码目录。

教材还展示shell重定向。本课程使用PowerShell，它不能直接照搬cmd的<输入重定向语法；先用以上文件工具完成本课，不把不同shell的命令混写。

格式化与密码输入的阅读层次

教材3.7.2的宽度与标志也有具体用处：[%8.2f]中8是最小显示宽度，.2是小数位，方括号让补空格可见；%,.2f在Locale.US下加入分组逗号；String.format返回格式化文本但不立即输出。比如给12.5用8位两小数格式，正文12.50长5，前面会有3个空格。宽度太小不会自动把数字砍短。

原书日期时间格式表用于认识旧代码；普通数值与文本格式要会用，其余查表，不背全部字母。

3.7.1的Console用于无回显密码输入，与Scanner的可见文本不同。在某些IDE或非交互环境下System.console()会是null；不能直接对它调用方法。密码工具与char[]清理留作选读，不在此要求提前设计登录系统。

8. 看懂原有 FileUtf8Demo，再做 E3

code 中的 FileUtf8Demo 与上例目的类似，但路径来自启动参数，并使用 PrintWriter 和 Scanner。

其中 try (...) { ... }建立一次资源使用范围，结束时自动关闭放在括号里的文件工具；资源是打开后需要管理的文件通道等。像用完水龙头要关上，实际规则是自动调用相应关闭操作，而不是修复文件内容。

它还使用 if 判断参数数量、return 提前结束。先把它们读成“参数不足则说明用法并结束”，L07 再系统学分支。不要因为这份体验程序提前使用了一些语法，就要求自己现在独立写出每一行。

从根目录运行原例：

.\java.ps1 -Source '.\L06_第03章D_输入输出\code\FileUtf8Demo.java' -ProgramArgs @('.build/file-lab/my-note.txt')

E3 的交付是目标路径、输出、文件正文及编码解释。普通键盘输入例在 main 结束时整段程序结束；不要为了模仿文件的关闭操作，在还要继续读取 System.in 的流程中提前关闭标准输入。

9. 症状检查与过关

现象 首先核对
程序像停住 是否正等 nextInt 或 nextLine，输入后是否回车
姓名只有 Li 用的是 next 还是 nextLine
姓名突然空白 前一次读数后，当前位置是否仍在本行末
12.5 读取失败 输入格式与 Locale 约定是否一致
文件找不到 实际工作目录与打印的绝对位置
文件中文乱码 写入、读取、编辑器是否使用一致编码

过关时应能独立读多词姓名、计算并格式化账单，解释两次不同的 nextLine 各读走什么；文件体验能说明数据落在哪里。复杂异常恢复不列作本课隐藏要求。方法细节可按需查 Scanner 官方说明。
