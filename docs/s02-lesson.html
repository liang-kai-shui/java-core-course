0. 同一句“学生”，可能指四种东西

你见过String name、Scanner in = new Scanner(...)，也会遇到Student student = new Student(...)。这里的Student出现两次，student又出现一次，它们不是同一个角色。

我们用校园借书卡做贯穿例子：类定义像借书卡的设计规则，对象像按规则建立的一张实际卡，引用变量保存能找到卡的凭证。 一个规则可创建许多卡；复制凭证不会自动再印一张卡。

这只是关系比喻：Java引用不是你能读写的实际门牌数字，不能做地址加减；对象也不是磁盘上的.java文件。先分清角色，再看语法。

1. 先把一个表达式拆成两步

以下是读法片段，完整程序在下一节：

ReaderCard first = new ReaderCard("Lin");
└─类型─┘  变量名   └────创建对象并取得引用────┘
  1. 右边new ReaderCard("Lin")创建一个新的ReaderCard对象，执行初始化流程，得到可找到它的引用。
  2. 左边声明变量first，把这个引用保存进去。

ReaderCard是类名，同时也是这类变量可以使用的类型名；first是程序员起的变量名。变量叫first并不表示它只能指向第一个对象。

为什么要声明新类型？int可以表示整数，但单个int不能同时表达“这张卡的姓名以及允许的操作”。类让我们把相关状态和操作组织在一起。使用类不是为了让每一行数字都绕一次new。

2. 两个new与一次赋值：结果为什么不同

在本课my_code新建CardBoard.java。下面是一个源文件，包含两个顶层类：

public class CardBoard {
    public static void main(String[] args) {
        ReaderCard first = new ReaderCard("Lin");
        ReaderCard alias = first;
        ReaderCard other = new ReaderCard("Lin");
        alias.rename("Mei");
        System.out.println(first.getName());
        System.out.println(other.getName());
        System.out.println(first == alias);
        System.out.println(first == other);
    }
}

class ReaderCard {
    private String name;

    public ReaderCard(String name) {
        this.name = name;
    }

    public void rename(String newName) {
        name = newName;
    }

    public String getName() {
        return name;
    }
}

从课程根目录的PowerShell运行：

.\java.ps1 -Source '.\S02_结构基础_对象与引用\my_code\CardBoard.java'

应依次显示Mei、Lin、true、false。只有CardBoard是public顶层类，所以文件叫CardBoard.java；ReaderCard没有public，不要求另放一个文件。编译这个文件会得到CardBoard.class和ReaderCard.class，创建几张对象不会决定产生几个class文件。

3. 先画关系，再逐行解释输出

前三行执行完：

first ──┐
        ├──> 卡A：name="Lin"
alias ──┘
other ─────> 卡B：name="Lin"
语句 新建卡了吗 改变哪一项
第一个new 是，卡A first保存它的引用
alias = first 否 复制引用，两变量找到卡A
第二个new 是，卡B other保存它的引用
alias.rename("Mei") 否 通过alias找到卡A，改变卡A的name字段

于是first.getName()读到Mei，other.getName()读到Lin。first == alias问引用是否指向同一个对象，所以true；first == other为false，即使两卡曾有相同姓名。

姓名字符串在这里是卡的一个字段。rename让这个字段引用另一段文本，不是在原String对象内部改字。L05会用这张图继续解释字符串不可变。

修改实验A：只把ReaderCard alias = first;改为ReaderCard alias = new ReaderCard("Lin");。现在有三张卡，first的输出恢复Lin，两个引用比较均false。先画三张卡再运行。

修改实验B：恢复原程序，只把alias.rename("Mei")改为other.rename("Mei")。这次先显示Lin、再显示Mei，其余比较不变。

4. 类里面这些声明为什么放在不同位置

ReaderCard类
├─ 字段name：每张卡各有一份状态
├─ 构造器ReaderCard：创建卡时怎样设初始状态
├─ 实例方法rename：改变调用目标卡的状态
└─ 实例方法getName：读调用目标卡的状态

字段是声明在类内部、方法外部的变量，也叫域。name没有static，因此每个ReaderCard实例都有自己的name字段。它不像main里的first那样是局部变量。

构造器负责初始化新对象，名字与类相同，没有返回类型，连void也不写。public ReaderCard(String name)表示初始化时接收一个文本参数。new不是调用一个叫ReaderCard的普通方法；构造器不能当作card.ReaderCard(...)去给旧对象重新命名。

构造器中的name参数与字段同名。this表示本次正在初始化或调用的那个对象，所以this.name = name读成“把右边参数收到的姓名，存入当前卡的name字段”。如果误写name = name，只是给参数自身赋值，没有设置字段。

构造器也可以不接收输入，例如灯初始为关闭时，可写片段public Lamp() { on = false; }，再用new Lamp()创建。括号空着表示这次没有参数，不是省掉初始化角色；练习可以显式写这个无参构造器，不需要猜编译器会替你补什么。

实例方法对一个具体对象执行。alias.rename("Mei")中的alias决定对哪张卡操作，括号给出这次交入的姓名。方法里的name = newName等价于本例的this.name = newName。

getName前面的String是返回类型。return name;把当前字段的值交给调用方并结束这次方法调用；println再打印收到的文本。它不会自动改变卡的名字。void方法则不返回这样的值。

5. private是保护状态，public是提供操作

为什么不让所有代码直接改first.name？因为卡可能要求姓名不能空、借书数不能负。若任何地方都能随手改字段，规则就散落在整个项目中。

封装把状态及相关操作放在一起，并控制外部能怎样访问它。像卡片由办理窗口按规则更新，使用者调用rename或getName。类比边界是：private是语言访问规则，不是加密；不能保护你已经主动返回给外部的可变对象。

此例字段是private，外部CardBoard不能直接访问。两个方法是public，可以请求它们办理读写。不是每个private字段都必须配一个set方法；将来账户余额可能只允许通过deposit、withdraw改变。

S03会加入合法范围检查；这课先观察“通过方法改变哪一个对象”。不要为了使用private而引入尚未解释的完整设计模式。

6. 没有对象、没有值，和对象内容为空不是一件事

ReaderCard a;        只声明局部变量，尚未赋值；读取它会编译失败
ReaderCard b = null; 已赋值，但没有指向对象；调用b.getName()会运行失败
new ReaderCard("")  确实创建了卡，只是name指向空文本

未使用的局部变量声明本身合法；失败发生在还未确定赋值就读取。null可以赋给引用变量，表示当前无对象，不是一个名字叫null的卡。

若main里写alias = null，只改了alias保存的引用，first仍能找到卡A。丢掉一张凭证不会销毁其他凭证，也不等于立即销毁对象。 JVM可以回收以后不再可达的对象占用的内存，回收时机不由一行null保证。文件、连接等资源仍需明确关闭，不能用垃圾回收代替close。

在副本中，让alias为null后仍调用rename，预测为编译成功、运行时NullPointerException；删除这次调用后first仍可用。失败实验别覆盖正确原件。

7. 对照别的语言，避免把一种赋值规则套给所有类型

Java的int second = firstNumber复制整数值；ReaderCard alias = first也复制变量中的值，只是这次值是对象引用，故两者找到同一对象。这两条并不矛盾。

C++普通对象变量赋值常有对象复制语义，C++引用和指针也各有自己的规则；Python变量绑定对象的模型又有其规则。这里不要求会这些语言，只记住Java的引用赋值不自动克隆对象。深复制、equals、构造器重载会各自有专题，不靠一句“和某语言一样”带过。

分步实验：.java文件、.class文件、类描述和实际对象分开

原练习出现ReaderCard.class，必须补一个很容易漏掉的区别：在文件管理器里，它可能是编译产物文件名；写在Java表达式里，ReaderCard.class却是类字面量，取得运行时描述ReaderCard这种类型的Class对象，不是打开磁盘文件，也不是new一张ReaderCard卡。

像磁盘上保存的设计文档、运行时可查询的类型说明卡、按设计建立的两张借阅卡，三者各有职责。类比边界：类型说明不等于完整源码文本；Java类加载器还参与区分运行时类型，当前只在普通单一应用中观察。

public class ClassLiteralCards {
    public static void main(String[] args) {
        TypeCard first = new TypeCard("Lin");
        TypeCard second = new TypeCard("Lin");
        System.out.println("two-objects=" + (first != second));
        System.out.println("same-type=" + (first.getClass() == second.getClass()));
        System.out.println("same-description=" + (first.getClass() == TypeCard.class));
    }
}
class TypeCard {
    private final String name;
    TypeCard(String name) { this.name = name; }
    String getName() { return name; }
}

预期two-objects=true、same-type=true、same-description=true。first与second分别new，所以身份不同；first.getClass()读作“取得此对象实际类型的描述”，不是返回另一个借阅卡；TypeCard.class按已知类型取得同一个描述。此处仅用==比较这些描述是否同一份，不要求先背Class泛型声明。

写法/位置 此处代表什么 数量由什么决定
ClassLiteralCards.java文件 源码文字 保存了哪些源文件
TypeCard.class磁盘文件 TypeCard的字节码 编译了哪些类型定义
Java表达式TypeCard.class 运行时类型描述对象 本次运行时的类型身份
new TypeCard(...) 业务实例及其引用 运行时实际执行了几次创建

只把second= new TypeCard("Lin")改second=first，第一行变false，后两行仍true。再单独改变second的姓名，身份与类型比较结果不变：字段内容、对象身份、所属类型不是同一个测试。

分步实验：没有对象与对象里有空姓名，不再只靠术语区分

“只声明”“赋null”“存空文本”会在不同阶段产生不同现象。先运行合法程序，再在副本只改一处制造预期失败；不把三种情况一开始都塞进失败程序，导致第一处失败遮住后面观察。

public class ReferenceAbsence {
    public static void main(String[] args) {
        ProfileCard card = new ProfileCard("");
        ProfileCard alias = card;
        alias = null;
        System.out.println(alias == null);
        System.out.println("length=" + card.getName().length());
        ProfileCard missing = null;
        if (missing != null) System.out.println(missing.getName());
        else System.out.println("no-card");
    }
}
class ProfileCard {
    private final String name;
    ProfileCard(String name) { this.name = name; }
    String getName() { return name; }
}

输出true、length=0、no-card。alias=null只改alias的引用，card仍指实际ProfileCard；卡中姓名是空字符串，因此调用getName后再求length得到0。这里length()是String提供的文本长度方法，括号不能省，返回int；空字符串有对象值，null没有可调用的字符串对象。

语句 变量是否有值 是否有业务对象 可做的下一步
ProfileCard missing; 尚未确定赋值 不能据此断定 不可先读取missing
missing=null 有引用值null 此变量没指目标 可与null比较，不可直接调实例方法
new ProfileCard("") 得到非null引用 有实际卡 可读取长度0的姓名

only-null的分支先用missing!=null判有无目标；为false就执行else报告无卡，没有调用getName。只把if条件改为true，编译仍能过，但运行会NullPointerException，这就是调用无目标的阶段。恢复后另只删missing声明的=null，if读取时会编译失败，因为局部变量未确定赋值。两处故障分不同副本，不能声称运行看到了根本没编译通过的情况。
