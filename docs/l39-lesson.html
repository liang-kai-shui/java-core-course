学完要能做什么

能区分固定长度视图、不可修改视图和快照；正确使用排序/二分/批处理；完成类型安全数组转换，读懂遗留Enumeration与BitSet。

接口写着List，为什么add会抛异常

List约定方法名字，但很多修改是API标注的可选操作：实现可以按契约拒绝。Arrays.asList(array)提供数组支持的固定长度视图，可以get/set，却不能增删；Collections.unmodifiableList(list)禁止通过这个视图修改，但原列表仍能改。像隔着窗口看登记本，窗口可以允许换某栏、禁止加页，或完全只读；类比边界是这些不是同一个限制，不能统一叫“不可变对象”。

import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;
public class FixedViewAndSnapshot {
    public static void main(String[] args) {
        String[] array = {"A", "B"};
        List<String> fixed = Arrays.asList(array);
        List<String> readonly = Collections.unmodifiableList(fixed);
        fixed.set(0, "X");
        List<String> snapshot = new ArrayList<>(fixed);
        System.out.println(Arrays.toString(array));
        array[1] = "Y";
        System.out.println(readonly);
        System.out.println(snapshot);
    }
}

输出[X, B]、[X, Y]、[X, B]。fixed.set改底层数组，因此array首项变X；readonly关联同一底层，array第二项改Y后也看得到。snapshot是明确new ArrayList复制出的独立容器，仍是修改之前的X/B。String元素不可变，当前复制引用足够；可变元素的内部状态还可能共享。

对象 支持set 支持增删 会看到底层变化
Arrays.asList视图 是 否 是
unmodifiableList视图 否 否 是
new ArrayList复制 是 是 外层不跟随

readonly不是“任何地方都不能改”。若要稳定快照并不让调用者改外层，可先new复制，再unmodifiable包装；元素是否也必须不可变另作决定。nCopies(n,obj)重复的是同一对象引用，不是new了n份业务对象；singleton/emptyList等也有明确不可修改约定。

只把fixed.set的X改Z，应影响array与readonly的首项，snapshot取决于它在何时复制。独立任务：在纸上将“先复制再改”和“先改再复制”交换，分别画快照内容，别把快照想成随时间倒流保存的原始数据。

子范围窗口会改原表，结构变化后不能继续盲用

subList(from,to)含起点、不含终点。对视图clear删除的是原列表这段，不是清空一份副本。父表在视图之外发生结构性修改后，继续使用旧子视图的语义通常不再有保证，ArrayList会常见CME；不要把旧视图长期当快照保存。TreeSet/TreeMap的subSet/subMap按排序值范围，不是按位置；导航版本可用boolean指定端点包含。

算法输入不只看类型，也看顺序与修改能力

Collections.sort/List.sort要求支持替换元素，但不一定要求能改变size，所以Arrays.asList通常可排序；不可修改视图不能拿去排序。对象排序稳定，等序元素保留原相对顺序，不等于算法永远不移动它们。具体实现可变，不能拿教材旧算法比较断言所有JDK性能。

binarySearch前提是按相同顺序排序；未找到返回负编码-(插入点)-1，所以插入点为-result-1，不是单纯取负。重复值找到哪个不保证。大非RandomAccess列表仍可能用迭代器二分，链路走访O(n)、比较O(log n)，不能把教材p392简写成“所有链表直接普通线性查找”；见Collections API。

shuffle用于混排，可传Random固定种子做可复现实验，但“固定种子”不是安全随机的承诺。max/min空集合会失败；copy(to,from)替换已有位置，目标size必须足够，只有容量够不行。fill同样替换每个位置为同一引用；reverse反转、rotate旋转，frequency按相等统计，disjoint检查无共同值。先读契约，算法不会统一替你扩容。

removeAll删除另一集合出现项，retainAll保留交集；若需保留源，先复制。List.replaceAll接单元素转换函数，Collections.replaceAll接列表、旧值、新值，不能漏第一个列表参数，教材p392示例漏了它。每个操作可能改源数据，下面分开实验观察。

安全包装与遗留入口的界限

checkedList(list,String.class)能在通过该视图错误添加时尽早查类型，不能修复已有坏数据或验证嵌套List全部实参。旧代码raw变量要声明List，不把返回视图硬转ArrayList。synchronizedList/Map给单个操作同步，遍历和“先检查再修改”的复合动作仍需按约定外部同步，L51–L52实践，不能只包一层便宣称整段流程线程安全。

Vector/Hashtable是历史同步容器，单方法同步不等于复合算法原子；Enumeration.hasMoreElements/nextElement是旧遍历入口，可用Collections.enumeration/list连接新集合。Stack继承Vector暴露多余操作，普通栈可用Deque。Properties用于文本配置，在L47完整实践，不用它保存任意对象。BitSet保存一组开关位，后面实际区分length、cardinality与初始容量。教材的素数性能表是当时环境案例，不证明今天任意Java/C++程序谁更快。

子列表clear：明确删的是原表哪一段

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
public class SubListDeletion {
    public static void main(String[] args) {
        List<String> source = new ArrayList<>(Arrays.asList("A", "B", "C", "D"));
        List<String> window = source.subList(1, 3);
        System.out.println(window);
        window.clear();
        System.out.println(source);
        System.out.println(window);
    }
}

输出[B, C]、[A, D]、[]。范围1含到3不含选B/C，clear后它们从原表消失，window长度为0。像在同一表上圈出两行再删除，类比边界是视图对象不复制两行，后续父表外部结构修改还可能使旧视图无效。

只把to端3改2，窗口只有B，clear后[A,C,D]。独立任务：需要保留原表时先new ArrayList<>(subList)，再clear副本并观察原表不变。若from==to是合法空窗口，不等于null；端点越界仍运行失败。

算法copy替换已有位置，不替你登记新元素

import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;
public class CollectionAlgorithmSteps {
    public static void main(String[] args) {
        List<String> target = new ArrayList<>(Collections.nCopies(3, "?"));
        Collections.copy(target, Arrays.asList("A", "B"));
        System.out.println(target);
        Collections.reverse(target);
        System.out.println(target);
        int found = Collections.binarySearch(Arrays.asList(10, 20, 30), 25);
        System.out.println(-found - 1);
    }
}

输出[A, B, ?]、[?, B, A]、2。目标先用nCopies创建三个?的列表，再new ArrayList使其可改；copy从位置0替换两项，第三项保留，reverse只反序。binarySearch在已排序的10/20/30查25返回-3，故插入点为-(-3)-1，即2。

目标若改为只有容量3但size0的ArrayList，copy运行时IndexOutOfBoundsException。只改容量不改变size正是L22已讲模型。独立先画目标三项，再读copy(to,from)的参数顺序；写反可能破坏来源，不能把copy看成赋值新列表。

数组转换：实际类型和尾部标记都要观察

import java.util.Arrays;
import java.util.List;
public class TypedArrayConversion {
    public static void main(String[] args) {
        List<String> words = Arrays.asList("A", "B");
        String[] typed = words.toArray(new String[0]);
        System.out.println(Arrays.toString(typed));
        String[] large = {"old", "old", "old", "old"};
        String[] returned = words.toArray(large);
        System.out.println(Arrays.toString(large));
        System.out.println(returned == large);
    }
}

输出[A, B]、[A, B, null, old]、true。typed实际String[]；large足够长就被返回，紧接末项的下标2被置null，下标3仍old，不保证全清空。教材p351 / PDF p369的简略说法按Collection.toArray API修正。

只把typed取得方式改为(String[]) words.toArray()，编译允许强转，运行实际Object[]不能变String[]，应ClassCastException。独立用Integer列表转换并检查数组length，不把“元素内容是String”误当作“数组实际类型一定String[]”。

BitSet：最高点在哪里，与有多少点不同

import java.util.Arrays;
import java.util.BitSet;
import java.util.Collections;
import java.util.Enumeration;
public class BitFlagsAndEnumeration {
    public static void main(String[] args) {
        BitSet done = new BitSet(128);
        done.set(2); done.set(9);
        System.out.println("length=" + done.length()); System.out.println("count=" + done.cardinality());
        done.clear(9);
        System.out.println("length=" + done.length()); System.out.println("count=" + done.cardinality());
        Enumeration<String> oldAccess = Collections.enumeration(Arrays.asList("A", "B"));
        System.out.println(Collections.list(oldAccess));
    }
}

输出length=10、count=2、length=3、count=1、[A, B]。初始128只准备存储容量；置下标2/9后，最高9所以逻辑length10，只有两项true。清9后最高2，length3，true数量1。不要把length当固定总槽数，或当true计数。

BitSet的and/or/xor/andNot会修改接收者，若保留原位集先clone；本课按“已完成任务编号”理解位开关，不声称它等同一个普通Set所有操作。只把9改5，length随最高位变而count仍2。独立表示任务1/3完成并清1，写出length与cardinality；再用Collections.enumeration旧接口遍历两项，说明它只换访问协议，不会把列表元素变成Java的enum常量。

在课程根目录PowerShell运行./java.ps1 -Source './L39_第09章D_视图算法与转换/code/BitFlagsAndEnumeration.java'。
