1. 电脑到底在干什么

1.1 先把电脑想成一间厨房

你做一顿饭，不能把所有事情都交给同一个东西：柜子负责存原料，台面负责摊开正在处理的东西，厨师负责照步骤操作。

电脑也有分工。

厨房里的角色 电脑里的东西 它主要负责什么
厨师 CPU，中央处理器 执行指令，进行运算和控制
料理台面 内存，也叫RAM 临时放正在使用的程序和数据
储物柜 硬盘、固态硬盘等存储设备 保存程序、照片、文档等文件

这三个词为什么要现在认识？因为以后你会碰到三种不同的问题：

  • “我写的源码存在哪里？”——主要是在找硬盘上的文件。
  • “这个程序运行时用了多少空间？”——可能是在问它占用了多少内存。
  • “它是不是一直在计算？”——可能要观察CPU使用情况。

先分清自己在问哪件事，才不会把“硬盘快满了”和“内存不够用”当成同一个问题。

这个厨房比方只帮助理解分工。真实电脑还有寄存器、缓存、GPU等部件，CPU也不是完全不能暂存数据；现在不用把这些细节一口气学完。

1.2 内存和硬盘最大的区别

问题 内存：台面 硬盘：柜子
主要放什么 当前运行、处理中的东西 要保存的文件
普通电脑断电后呢 原来的运行状态通常不能保留 已经正确保存的文件通常仍在
“16GB内存”说的是谁 这里 不是这里
“硬盘还剩100GB”说的是谁 不是这里 这里
学Java时的例子 正在执行的程序、运行时的数据 .java源码、教材PDF、保存的练习

所以，保存不是“我已经在屏幕上看到字了”，而是让软件把修改写入对应文件。

你在编辑器里改了三行代码，还没保存，编译器从硬盘读取的可能仍是旧内容。这就是为什么课程总让你先按 Ctrl+S。

有些软件会自动保存、恢复未保存的内容。这是软件提供的额外帮助，不能据此认为“所有修改都会自动保存”。本课程先养成自己确认保存的习惯。

动手①：看见“保存前”和“保存后”的区别

  1. 打开记事本，输入一句“这是我的学习记录”。
  2. 按 Ctrl+S。如果是新文档，会让你选文件名和保存位置。
  3. 保存到一个你找得到的文件夹，名字例如 观察.txt。
  4. 关闭记事本，再从资源管理器找到这个文件，重新打开。

应该看到什么：刚才保存的那句话还在。

如果找不到：先回忆刚才选了哪个文件夹，不要马上重写一份。下一节开始讲“怎样确定文件的位置”。

2. 什么是文件

2.1 为什么要有文件

假设你写了一段文字，希望明天继续看。电脑需要知道三件事：

  1. 你要保存哪些内容。
  2. 这份内容叫什么名字。
  3. 它放在什么地方。

文件就是电脑把一份数据组织起来、让你能按名字保存和读取的一种方式。可以先把它想成贴了标签的资料袋。

观察.txt、教材.pdf、照片.jpg、FlightHello.java，都属于文件。

资料袋是比方，不代表一个文件在硬盘内部必须占连续的一整块空间。现在关心的是：它作为一份有名字的内容，可以被找到、打开、修改和保存。

2.2 文件里到底装了什么

照片看起来是画面，歌曲听起来是声音，源码看起来是文字；保存和传输时，它们都会用数字数据表示。

电脑最基本的数据单位叫位，英文bit，可以取0或1。字节英文byte，通常按8位计算。你在“属性”里看到的文件大小，往往会用字节、KB、MB等表示。

不用现在学习二进制计算，只要先知道：文件的内容要由合适的规则和软件解释。

文件 合适的打开方式 为什么
观察.txt 记事本、VS Code 里面是文本
教材PDF PDF阅读器 按PDF的格式组织页面
照片 看图软件 按图片格式解释数据
Java源码 VS Code等文本编辑器 查看、修改代码文字

拿记事本打开图片或.class文件，可能看到怪符号。这不一定说明文件坏了，也可能只是用错了查看内容的方式。

2.3 文件“打开了”和程序“运行了”不同

你双击教材PDF，启动的是PDF阅读器，阅读器把教材显示出来。教材里的示例代码不会因为你打开这一页就自动执行。

同样，你在浏览器里看到这篇讲义，只是打开了网页。网页中的Java代码展示在屏幕上，不等于它已经在你的电脑里编译运行。

你做的事 实际发生了什么
打开教材PDF 阅读器显示教材
打开网页中的讲义 浏览器显示课程内容
在VS Code打开.java 编辑器显示源码文字
按课程命令编译并启动Java类 工具开始处理、执行这个程序

动手②：查看文件的类型、位置和大小

  1. 按 Win+E 打开文件资源管理器，就是平时浏览“此电脑”“下载”的那个窗口。
  2. 找到刚保存的 观察.txt，右键选择“属性”。
  3. 找到“文件类型”“位置”“大小”这几项。
  4. 再对教材PDF做同样的观察。

应该发现：它们的类型、大小可以不同，位置也可以不同，但都是文件。

观察问题：你能把“它叫什么”和“它放哪里”分别说出来吗？说不清位置就接着看第4节。

3. 文件名和扩展名：先把后缀显示出来

3.1 FlightHello.java分成哪两部分

部分 在这个名字里是什么 有什么用
主名 FlightHello 帮人和工具区分这份文件
扩展名，也叫后缀 .java 提示文件的类型；影响工具识别和默认打开方式

文件名中可以有多个点。对 FlightHello.java.txt 来说，最后的扩展名是 .txt，不是 .java。

扩展名像标签，不是转换器。 把照片从.jpg改名为.java，不会把照片变成Java代码；把源码从.java改成.exe，也不会变成能直接启动的Windows程序。

3.2 这门课会遇到哪些后缀

后缀 先理解成什么 本课程里怎样用
.txt 普通文本 观察记录、练习数据
.md 按Markdown标记排版的文本 讲义、练习；在编辑器里能直接写答案
.pdf 固定页面的文档 你的教材
.java Java源代码文本 你亲手编写、修改的程序
.class 编译后的Java类文件，包含字节码等信息 交给Java运行环境加载执行，不手改其中内容
.jar 将Java类和资源等装在一起的一种归档文件 后续学习打包；不是每个JAR都能直接启动
.ps1 PowerShell脚本 项目的java.ps1会帮你编译和运行
.exe Windows可执行文件 java.exe、javac.exe就是已有工具
.zip 压缩包 下载课程后先完整解压，再学习和写作业

不要把 .java、.class 和 java.exe当成一个东西。 第7节会把它们串起来。

3.3 Windows 11：怎样显示文件扩展名

如果系统把后缀藏起来，你可能只看到 FlightHello，却不知道它实际叫 FlightHello.java还是FlightHello.java.txt。

按下面做：

  1. 按 Win+E，打开文件资源管理器。
  2. 在窗口上方找到 “查看”。
  3. 点开 “显示”。
  4. 勾选 “文件扩展名”。
  5. 回到文件列表，观察文件名的末尾。

Windows 10常见的界面是在顶部“查看”选项卡里直接勾选“文件扩展名”；部分界面也可在“文件夹选项→查看”中取消“隐藏已知文件类型的扩展名”。找不到时按实际系统界面查看，资源管理器的右键“查看”菜单不一定包含这个开关。

这个操作只改变显示方式，不会改动文件内容。它与“显示隐藏的项目”也不是同一个开关。

3.4 最常见的坑：源码其实多了一个.txt

你在记事本中保存了 FlightHello.java，但保存类型仍是“文本文档”。实际文件名可能变成：

FlightHello.java.txt

如果扩展名被隐藏，看起来很像已经起对名字了。

检查办法：先显示扩展名，再看完整名字；也可以右键属性查看文件类型。

用记事本新存Java源码时，留意“保存类型”是否选为“所有文件”，名字是否确实以.java结束，编码是否为UTF-8。用VS Code新建并保存为FlightHello.java通常更直观，第8节会带你做。

动手③：确认你看见的是真名

  1. 显示扩展名。
  2. 在课程目录找一个 .md、一个 .java和教材 .pdf。
  3. 分别读出它们的完整文件名。
  4. 在VS Code中打开一个.md，按 Ctrl+Shift+V查看排版后的预览，再回到编辑标签。

应该看到什么：编辑区里有#、**等文本标记，预览区会把它们显示成标题或加粗。它们来自同一份.md文件。

和交作业有什么关系：答案直接写在本地 练习.md 的编辑区并保存。浏览器里的课程网页用于阅读，不会因为你在浏览器里看过题目就自动生成作答文件。

4. 文件夹、路径，以及“我现在在哪”

4.1 为什么还要有文件夹

如果把照片、教材、示例、作业全堆在一起，你会很难找到想要的东西。

文件夹用来组织文件，也可以继续包含其他文件夹。它又叫目录；这两个词在本篇可以当作同义词。

可以把硬盘想成柜子，文件夹是抽屉，抽屉里还可以有小抽屉。几层文件夹形成的组织结构，常叫目录树。

这门课的一小部分可以画成：

Java/                         ← 课程根目录
├── README.md                 ← 总入口
├── java.ps1                  ← 运行工具
├── 附录/
│   └── 零基础起飞.md
├── L01_第01章_认识Java/
│   ├── 讲义.md
│   ├── 练习.md                ← 在这里直接写本课文字答案
│   ├── code/                 ← 课程原始示例
│   └── my_code/              ← 你自己的本课代码
└── my_code/                  ← 第8节会新建，用于这篇入门实验
    └── flight_lab/
        └── FlightHello.java

根目录在这里指这套课程最外层的文件夹，不是特指C盘根目录。判断自己有没有打开对：应该能在这一层同时看到 README.md、java.ps1和各课文件夹。

根目录的入门实验my_code/flight_lab与L01里面的my_code是两个不同位置。这篇用新文件FlightHello.java练操作，不改你已经写过的L01答案和HelloJava.java。

4.2 路径就是地址

路径是告诉人和工具“到哪一层找哪个文件”的地址。

以这台电脑的课程位置为例：

D:\Code\Java\my_code\flight_lab\FlightHello.java
这一段 读法
D: D盘这个位置标识
\Code 进入Code文件夹
\Java 再进入Java文件夹
\my_code 再进入my_code
\flight_lab 再进入入门实验文件夹
\FlightHello.java 最后找到这个文件

\叫反斜杠，这里用来分隔层级。网上也经常看到/，叫正斜杠。Windows的许多工具能接受部分正斜杠写法，但并非所有位置都可随意互换；本篇的PowerShell示例统一按给出的写法输入。

盘符不是物理硬盘数量的证明。 一块硬盘可能划分出C盘、D盘；你的电脑也可能根本没有D盘。

如果你从GitHub下载到“下载”文件夹，课程地址可能完全不同。D:\Code\Java是本机示例，不是每个人都必须拥有的固定地址。

4.3 绝对路径和相对路径

别人问你“去图书馆怎么走”，你可以说完整街道门牌，也可以说“从这里出去右转”。

  • 绝对路径类似完整门牌：写清确定的起点，例如D:\Code\Java\README.md。
  • 相对路径类似“从这里走”：从当前所在目录算起，例如README.md。

相对路径依赖一个前提：你现在站在哪里。

假设终端当前目录是D:\Code\Java：

写法 指向哪里
README.md 课程根目录里的README
.\README.md 同上；.表示当前位置
.\附录\零基础起飞.md 进入附录找这篇文章
..\ 回到上一层D:\Code

如果当前目录已经变成D:\Code\Java\附录，同样写README.md就会在“附录”里面找它，不再指向根目录的README。

两个点 .. 是上一层，一个点 . 是当前位置。 点后面跟哪个分隔符、后面还有哪些名字，也要一起读，不能只看某个词眼熟就认为地址相同。

4.4 三个“位置”容易被混在一起

位置 它是谁的状态
资源管理器地址栏 这个浏览窗口正查看哪个文件夹
VS Code打开的工作区文件夹 编辑器把哪个文件夹当作项目入口
终端当前目录 这一个终端中的相对路径从哪里算

它们可能相同，也可能不同。 你在编辑器里点开一个深层源码，不代表终端自动跟着进入那个目录；新开另一个终端，也不保证继承你刚才所有操作。

碰到“找不到文件”，先核对这三者，不要第一反应就重装软件。

4.5 空格、引号与复制路径

例如JDK安装在：

C:\Program Files\Java\graalvm-jdk-21.0.12+7.1

Program Files中间有空格。命令行需要知道“这是一个完整地址”，所以常把路径放进英文引号里：

cd 'D:\Code\Java'

中文文件夹和带空格的路径并非一律不能用。本项目本来就有中文课次目录。先掌握引号和准确路径，不要为了学编程把课程目录全部改名。

Java源文件主名先用英文，例如FlightHello.java，并与程序中的public class FlightHello对应，能减少起步时的拼写困扰。

5. 什么是程序：为什么打开源码不等于运行

5.1 先区分“指令”与“数据”

程序是为完成任务而组织的一系列指令。它可以显示文字、计算总价、处理图片，也可以启动和管理别的程序。

记事本是一个程序，教材PDF通常是它交给阅读器处理的数据，Java源码则是开发工具要读取和处理的文本。

现实中的一个软件可能由多个文件、库和资源组成，不能简单认定“一个软件永远就是一个.exe”。起步先分清：你在编辑什么，你正在让哪个工具执行任务。

5.2 用菜谱把几个角色分开

想象你把做饭步骤写在纸上：

厨房里的动作 编程中相似的动作
写、修改菜谱 编写、修改源代码
检查并转换为厨房能使用的操作单 编译
执行员按照操作单工作 启动运行环境执行程序
端出结果 程序产生输出或完成其他任务

读一眼菜谱，不会自动做出饭。打开源文件，也不等于已经运行其中的程序。

这个比方不能用来理解所有底层细节，尤其别把字节码当成“已经执行过的结果”。字节码仍是待执行的指令表示，不是最终屏幕输出。

5.3 Java初学者最容易混淆的三个东西

东西 它是什么 你通常怎样处理
FlightHello.java 你编写的源码文本 用编辑器打开、修改、保存
FlightHello.class 编译产生的类文件 让Java运行环境加载执行
java.exe 已安装JDK中的启动工具 在终端通过命令启动它

双击.java具体会怎样，取决于电脑的文件关联，也就是系统约定“这种文件默认交给谁打开”。常见情况是打开编辑器，或询问用什么程序打开。这本身不说明Java坏了。

双击.class也不等于系统自动知道“请替我选好运行环境、类路径和入口”。本课程用明确的命令启动，方便你看清每一步。

如果你以后看到新版Java用java 文件.java直接启动源文件，那是JDK提供的源文件启动模式；其中仍有编译与执行过程。我们先学两步形式，便于观察文件和报错，不把“先编译再执行”误解成“所有工具都必须让人手工点两次”。

动手⑤：看懂“打开”发生在哪里

  1. 在VS Code里打开课程的一个.java示例，只观察内容，先不点击运行。
  2. 找到程序里System.out.println(...)那一行。
  3. 想一想：现在只是显示了这行代码，终端里是否已经出现它要输出的文字？

应该区分：编辑器中显示代码，与程序在终端里实际输出，是两种不同的现象。第8节会真的运行一遍，再回来对照。

6. 什么是进程：用任务管理器看见正在运行的东西

6.1 程序和进程不是同一个角度

源码和程序文件保存在硬盘上；当你启动程序，操作系统会为这次运行安排内存、执行等资源。

这次运行中的实例，叫进程。可以类比“保存的菜谱”与“这一次正在进行的做饭活动”。

问题 程序及其文件 进程
关注什么 保存的指令、软件内容 一次运行活动
不运行时还在吗 已保存的文件仍可以在 这次活动已经结束
为什么会占内存 文件被使用、运行时需要装入相关内容 运行中要维护自己的数据和资源
能和窗口一一对应吗 不能这样推断 也不能；一个窗口可能关联多个进程，进程也可以没窗口

浏览器经常有多个进程；新版记事本可能用标签页组织文档。因此，“打开三个窗口就必定是三个独立进程”不能当成通用规则。

Java程序运行时，任务管理器里可能看到java.exe、Java相关名称，或被归在某个应用分组里。具体显示随工具和启动方式不同，不要求大家的截图完全一致。

6.2 任务管理器是观察工具

任务管理器是Windows自带的工具，用来查看正在运行的应用、进程和资源使用情况。

它像厨房监控台，可以帮助回答：“谁还在运行”“谁正忙”“谁占了较多内存”。

打开方法：同时按 Ctrl+Shift+Esc。

如果界面是精简的，先找“详细信息”或“更多详细信息”；如果已经有“进程”“性能”等页面，就直接进入“进程”。Windows不同版本的位置有差异，以文字标签为准。

常见列 先怎样理解
名称 这一项是哪一个应用或进程
CPU 一段时间内使用了多少CPU处理能力
内存 正占用多少内存
磁盘 近期存储读写活动
网络 近期网络传输活动

点“内存”或“CPU”的列标题，通常可以按这一列排序；再点可能改变排序方向。

占得多不等于有错。 浏览器打开很多页面、编译器正在工作，都可能正常地使用资源。暂时等待键盘输入的程序，CPU占用也可能很低，但仍然活着。

6.3 程序卡住时先做什么

对你在终端里启动的练习程序：先点到那个终端，再按 Ctrl+C，请求中断当前运行。

如果按键被终端当作复制，先取消文字选择、确认焦点在正在运行程序的终端，再试一次。中断是否成功也要看程序是否停止、提示符是否重新出现。

确实无法停止时，才在任务管理器里识别自己刚启动的程序，使用“结束任务”。这是强制停止，不会替你保存尚未保存的内容；不要为了练习随便结束不认识的系统进程、编辑器或其他人的任务。

死循环是本来想重复有限次，却写成一直无法结束的循环。它可能持续消耗CPU；也有程序只是等输入，看起来没动但并非死循环。先看题目要求和终端提示，不要只凭“还没结束”判断。

动手⑥：看见进程，再正常关闭

  1. 打开任务管理器，进入“进程”。
  2. 按内存列排序，找出自己的浏览器；只观察，不结束它。
  3. 打开一个记事本文档，观察列表中是否出现或更新对应项。
  4. 从记事本菜单或窗口按钮正常关闭它，留意任务管理器的变化。

应该学会的事：能找到应用并观察资源，而不是要求列表必须恰好增加一行。

后面自己的Java程序运行不结束时，你至少知道有“中断当前运行”和“确认进程再结束任务”这两种处理办法。

7. 代码、编译器，以及Java多出来的那一层

7.1 人为什么不直接给CPU写指令

CPU执行的是对应硬件能识别的机器指令，不是直接读懂中文作文。让人长期用一串机器指令编写复杂程序，很难阅读、修改和检查。

所以有了编程语言：规定一些严格的写法，让人能够描述操作，再由工具处理这些描述。

代码就是你按编程语言规则写下来的内容；开发时原始的那份，叫源代码，简称源码。

编程语言不像日常聊天那样能大量依靠猜测。少一个引号、拼错一个名字，可能就变成另一种意思，或者根本不符合规则。

Java是这样一种语言。它的代码不要求你先学过C、C++或Python。

7.2 编译器为什么像翻译员

编译器是一种程序：读取源码，检查相应规则，再转换为后续工具可以使用的形式。

像把你写的菜谱整理成统一的操作单。整理时能发现漏了符号、名字用错、某些类型不合要求等问题，但不一定知道你原本想做什么菜。

例如你本来想算长方形面积，却写成周长，程序完全可能编译成功。“工具接受了代码”和“结果符合题意”要分别判断。

7.3 Java这条链要分两段看

本课程先采用下面的形式：

你手写并保存                    编译得到                    启动执行
FlightHello.java   --javac-->   FlightHello.class   --java / JVM-->   屏幕输出
   源代码文本                  类文件，包含字节码等信息

字节码是一种供Java虚拟机使用的指令表示。它与直接交给某一款CPU的机器码不是同一个层次。

JVM是Java Virtual Machine的缩写，中文叫Java虚拟机。它负责加载、执行相应Java程序；实际实现可能解释字节码，也可能把部分代码编译成本机机器码执行。初学不需要拆开它内部的所有步骤。

这个“虚拟机”不是要求你先装一台完整的虚拟Windows电脑。先把它理解成Java程序的执行环境中的核心执行部分。

7.4 同一张角色表，消除五个名字的混淆

名字 它是什么 类比与作用
Java 一门编程语言；日常也用来指相关平台 你学习的规则，以及围绕它提供的工具与库
JDK Java Development Kit，开发工具包 工具箱，里面有编译、启动等开发工具
javac JDK提供的Java编译命令 翻译员，把源码编译成类文件
java 启动Java程序的命令 请运行环境开始执行指定程序的入口
JVM Java虚拟机 运行环境中负责执行Java程序的核心部分
JRE Java Runtime Environment，Java运行环境的概念 JVM及运行所需库等；现代发行方式与旧教材截图不必完全相同

特别看清最后一个字母：java和javac是两个不同的命令。它们不是“一个词的两种随便写法”。

在Windows的JDK安装目录中，你能找到java.exe、javac.exe。这些工具本身已经是可运行的软件，不是你要从零编写的课堂作业。

我们选用JDK 21来学习。书中的Java8写法与“电脑安装的JDK版本”也不是同一个概念；课程会尽量先按教材基础语法编写，再单独补新版本内容。

7.5 “跨平台”到底承诺了什么

可以先把字节码想成统一的操作单：不同系统上有适配的执行环境，就不必每次重新手写一份同样的业务逻辑。

但前提仍然存在：运行环境要兼容程序要求的版本，程序需要的库、文件和系统功能也得满足。

说法 怎样修正
Java程序任何电脑都能直接跑 要有适配、兼容的运行环境及所需依赖
Windows上的java.exe可以原样拿到所有系统执行 启动工具和JVM实现也要适配系统、硬件
有JDK就保证我写的程序完全正确 工具不能替代题意检查和测试

这不是让你现在研究全部兼容性问题，而是避免把“跨平台”误解为“没有任何条件”。

8. 终端和命令行：从打开窗口到亲手运行

8.1 为什么要用打字下命令

你也许习惯点“开始”“打开”。命令行只是另一种交代任务的方式：把“启动哪个工具、处理哪个文件、用什么选项”写成一行。

学编程需要它，是因为：

  • 工具的一些功能通过命令使用最直接。
  • 同一条命令可以重复执行，也能原样交给别人复现。
  • 编译、运行产生的结果和诊断，可以保留成完整文字。

它不是“必须很懂电脑才能打开的黑客模式”。我们先学几条只负责查看、换位置和运行自己文件的命令。

8.2 终端、PowerShell、cmd分别是什么

终端先理解为容纳命令输入、输出的窗口或面板。

PowerShell是理解并执行你输入的命令的一种程序。cmd也是一种，但具体语法不同。Windows Terminal又可以提供标签页，让这些命令解释程序在里面运行。

名字 在这篇里怎样理解
命令行 用文字输入命令这种操作方式
终端 输入命令、看输出的界面
PowerShell 本文统一使用的命令解释程序
cmd/命令提示符 另一种命令解释程序；不要混抄两边的语法
VS Code终端面板 编辑器内提供的终端界面，里面仍要选具体使用哪个解释程序

下面所有标为powershell的命令，都在PowerShell里输入，不是写进.java代码里。

8.3 两种打开方法

方法A：从Windows打开。

  1. 按一下 Win 键，打开开始菜单。
  2. 输入 PowerShell。
  3. 打开“Windows PowerShell”或已安装的“PowerShell”。普通权限即可。
  4. 应该出现一个可以输入文字的窗口；窗口颜色不是判断依据。

方法B：从VS Code打开。

  1. 菜单“文件→打开文件夹”，选择课程最外层目录。
  2. 菜单“终端→新建终端”。
  3. 看终端标签或下拉菜单，确认选择的是PowerShell。
  4. 如果当前是cmd、Git Bash等，使用终端旁的下拉菜单新建PowerShell终端。

你可能看到：

PS D:\Code\Java>

这叫提示符，意思大致是“我当前在这个目录，正在等你的命令”。

不要把提示符一起输入。 如果材料写PS D:\Code\Java>只是举例说明位置；真正需要输入的命令放在单独的命令块中。

8.4 先会“我在哪、这里有什么、走到哪里”

先输入下面这一条，按回车：

Get-Location

它会显示当前目录，例如：

Path
----
D:\Code\Java

然后输入：

Get-ChildItem

它会列出当前目录的文件与子目录。显示项目可能包括名称、修改时间、长度等；文件夹的长度列不一定像普通文件那样有数值。

输出不是让你继续输入的命令。 等新的提示符出现，再输入下一条。

8.8 再揭开脚本：它大致帮你做了什么

课程脚本不是另一门神秘语言。对本阶段无package的单文件程序，它主要做：

  1. 找到已经安装的JDK。
  2. 找到你指定的源码，建立一份新的编译输出目录。
  3. 调用javac编译。
  4. 只有编译成功才调用java启动，避免错跑上次的旧class。
  5. 帮本机终端与程序输出约定UTF-8，减少中文乱码。

package是Java用于组织类名字的一种机制，后面才讲。此处只知道我们的入门文件暂时不写它，不能把这份单文件脚本当成所有复杂Java工程的通用启动器。

8.9 看见两步形式：先编译，再启动

已经完成8.7后，再读这一段。它帮助你理解javac和java的区别，不要求第一次就记住每个选项。

下面使用本机已检查的JDK位置。其他读者应采用自己的安装位置；先前check-java.ps1输出的Course JDK可帮助定位。

在课程根目录执行：

$jdk = 'C:\Program Files\Java\graalvm-jdk-21.0.12+7.1'
New-Item -ItemType Directory -Path '.\my_code\flight_lab\out' -Force | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 '-Xlint:all,-options' -d '.\my_code\flight_lab\out' '.\my_code\flight_lab\FlightHello.java'

这几行中，$jdk只是给一段路径起个临时名字；New-Item创建输出文件夹，-Force允许文件夹已存在；| Out-Null是不把创建目录的普通结果打印出来。它们属于PowerShell操作，不是Java源码。

最后一行开头的&表示“启动后面这个地址的程序”。引号把带空格的安装路径视作整体。

编译选项 这里的作用
--release 8 在当前编译器支持范围内约束为Java8的语法与标准API
-encoding UTF-8 按UTF-8读取源文件文字
-Xlint:all,-options 启用代码警告，仅关闭旧目标版本本身的选项提示
-d '...\out' 把编译产物放进指定输出目录
最后一个.java路径 本次要编译的源码

编译成功时javac可能一句话都不输出。 不要因为没有“恭喜成功”就以为它没工作。

紧接着执行下面这一整段：

if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -cp '.\my_code\flight_lab\out' FlightHello
}

$LASTEXITCODE在这里保存刚才外部程序的退出码，0通常表示正常完成；if这段是PowerShell判断，意思是“上一次编译成功才继续”。不要在编译和这个判断之间再启动别的外部程序，否则读到的可能不是编译器的状态。

-cp告诉启动工具去哪个位置寻找类，简称类路径。这里启动的是类名FlightHello，不写.class扩展名；它也不等于把源码路径原样再抄一遍。

现在应再次看到Hello, Java!。再执行：

Get-ChildItem '.\my_code\flight_lab\out'

应该找到：FlightHello.class。先不拿编辑器修改它：它是编译产物，源码才是你要编辑的内容。

手动例子先用英文输出，是为了专注编译和启动；下面中文实验优先走课程脚本。不同终端的中文配置需要另核对，不能用“英文正常”证明所有编码环节都已经相同。

动手⑨：走完“新建→保存→运行→找到产物”

  1. 编辑器里有你自己的FlightHello.java，源码中的类名一致。
  2. 源文件已经保存。

9. 中文、编码和乱码：不是一见方块就重装Java

9.1 同样的文件，为什么会读出怪文字

电脑保存的是字节数据。要把字变成字节，以及把字节还原成字，需要双方约定规则。

这类约定叫字符编码。类比一套“文字怎样写成数字、数字怎样读回文字”的规则本。

你用一套规则保存，对方用另一套不匹配的规则读取，就可能出现乱码。

这个比方不能理解成所有字符都固定占一个字节。不同编码使用的表示方法和长度可能不同。

9.2 先区分Unicode、UTF-8和字体

名字 先理解什么
Unicode 为字符等规定编号和相关规则的标准体系
UTF-8 将Unicode文本编码成字节的一种方式
GBK 中文环境里仍可能遇到的另一种字符编码
ASCII 早期常见的字符编码，覆盖基本英文等字符，不包含汉字
字体 决定字符用什么字形画到屏幕上

例如英文字母A在UTF-8里用一个字节表示；汉字中用三个字节表示。“一个汉字就是一个字节”不能作为通用结论。 这与Java中String.length()的计数规则也不是同一个问题，后面字符串课会分开讲。

如果字符成了别的乱字，先怀疑编码环节；如果部分符号只显示为方框，也可能是字体缺少对应字形。不要认为所有显示异常只有一个原因。

9.3 Java输出中文要经过几站

可以把这次输出当成一封经过几个站点的信：

你在编辑器里写中文
    ↓ 按某种编码保存
.java源文件
    ↓ 编译器按约定读取
程序中的文字
    ↓ 运行时写出字节
终端按自己的规则读取、显示
环节 本课程先采用的做法
源文件保存 UTF-8
javac读取源码 显式指定-encoding UTF-8
本机程序输出与控制台 优先由课程java.ps1配合UTF-8处理
文本文件的读写 输入输出课再明确指定读写编码

源码是UTF-8，不自动保证终端也按UTF-8显示。 JDK版本、命令解释程序、终端和启动方式都有可能影响实际表现。

9.4 chcp能说明什么，不能说明什么

在Windows终端里输入：

chcp

它会显示当前活动控制台代码页，常见结果有936或65001；65001对应UTF-8。不要假设所有中文Windows、所有终端的默认结果都相同。

修改控制台代码页也不等于把硬盘上的源文件转换成了UTF-8。对Windows PowerShell5.1等环境，仅改chcp也未必同时改变所有.NET控制台、管道和程序的编码处理。

初学时不必为了这一篇反复改系统区域设置。先使用已提供的脚本；确实遇到问题时，报告编辑器保存编码、实际启动命令和终端类型。

在你自己的FlightHello.java中，把那一行改成：

System.out.println("我在学习Java");

如果乱码：先保留现象，核对是不是仍在用刚才手动启动的旧class，或换成了另一种运行按钮。编辑器打开文件就已乱码时，先保留原文件副本、检查读取编码，不要一边看着乱码一边反复覆盖保存。

10. 改了代码，为什么还是旧结果

10.1 先记住这三个动作

修改 → 保存 → 重新编译并运行。

你改的是源码，不会因此把之前生成的每一个.class都同步改好。编译器要重新处理保存后的源码，启动时也要找到这次产生的类文件。

有些IDE会帮你自动编译，这是工具替你完成步骤；不能据此推断任意终端命令、任意目录也都会自动更新。

10.2 用一个小实验看见“旧”在哪里

假设你已经完成第8节的手动编译，out目录里有输出Hello, Java!的类文件。

如果你现在只修改源码中的文本，按 Ctrl+S，却只运行旧out目录里的类：

& "$jdk\bin\java.exe" -cp '.\my_code\flight_lab\out' FlightHello

它仍可能输出旧文字。这不是源码修改没生效，而是你根本还没把这个修改编译到正在运行的那份class里。

这里的$jdk沿用8.9节在同一个PowerShell会话中的设置。换了新终端，这个临时名字可能已经不存在，需要重新设置；不要把变量不存在误判成Java类文件损坏。

10.3 编译失败，也可能还留着上次的class

在自己实验文件里暂时删掉println语句后的分号：

System.out.println("我在学习Java")

重新编译应当失败。失败不会保证替你删除所有旧产物。 如果忽略错误，另外运行上次的class，就可能又看到旧输出。

课程java.ps1每次使用新的隔离输出目录，编译失败立即停下，就是为了减少这个误会。

动手⑪：故意错一次，再验证恢复

  1. 确保你改的是入门实验FlightHello.java，不是教材示例或已经交过的L01源码。
  2. 删掉一处分号并保存。
  3. 用课程脚本运行，记录第一条有效编译诊断，以及是否出现程序自己的输出。
  4. 恢复分号，保存，再运行。
  5. 看到正确中文输出后，才把“这次已恢复”记下来。

编译诊断里的路径、行号和措辞可能随环境变化；关注它是否指出你故意制造的错误。不要求和老师的英文/中文提示逐字相同。
