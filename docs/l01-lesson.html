0. 这课分几步学

分两次也可以：第一次学第 1–4 节，自己输出一行文字；第二次学第 5–8 节，解释工具分工并做错误小实验。结束时要能自己改输出、再运行，而不只是认识几个英文缩写。

怎么把讲义中的程序跑起来

带有 public class、完整大括号和 main 的 Java 代码框是完整程序。标为“片段”的短代码只替换 main 里面相应部分，不能单独当文件运行。每个完整程序另建一个文件，不能把两个 public class 或两个 main 随手拼在一起。

在 VS Code 中打开整个 D:\Code\Java 文件夹。在本课 my_code 文件夹新建 FirstGreeting.java，文件名要与 public class 后的名字相同；保存为 UTF-8。没有显示后缀、不会新建文件或打开终端，先看零基础起飞，无需先读 PDF。

打开“终端 → 新建终端”，确认使用 PowerShell。以下命令从课程根目录开始输入，提示符本身不用抄：

Set-Location 'D:\Code\Java'
.\java.ps1 -Source '.\L01_第01章_认识Java\my_code\FirstGreeting.java'

这是课程提供的“编译成功才启动”工具。它每次在 .build 中另建输出目录，生成 class 后才运行；不要手动执行以前留下的 class。后面的完整程序同样操作，只换末尾文件名。需要键盘输入时，运行后在终端键入数据并回车；程序没有显示新提示符，可能正在等输入。出现脚本策略提示时，在同一根目录把运行一行改为：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\java.ps1 -Source '.\L01_第01章_认识Java\my_code\FirstGreeting.java'

每次实验留三项记录：预测、实际输出、解释第一次出现差异的步骤。看到程序自己的输出才算实际启动；没有报错不等于题目做对。

1. Java 为什么是一整套平台（教材 1.1）

编程语言是表达程序操作的规则；库是可以调用的现成能力；执行环境负责把程序实际运行起来。Java 将这些组成一套平台，是本章的起点。

可以把它类比成制作舞台演出：剧本语言表达安排，现成灯光与音响工具提供能力，场地与执行系统让安排真正发生。只拿到剧本写法，不等于已经拥有完整剧场。类比只说明职责，不表示电脑能够猜测人没写清的安排。

为什么不能只学几句语法？你写 System.out.println 时，语言规则告诉工具怎样读这个调用；库提供输出功能；运行环境让这次输出发生。以后联网、读文件也会同时依赖这些部分。

本课先建立平台地图与术语含义。末尾用一个最小程序观察“它真的执行了”，手动拆分命令到 L02 讲；不把第1章偷偷换成完整安装教程。

2. 白皮书的11个术语，在回答哪些问题（教材 1.2）

白皮书在这里是介绍设计目标与思路的说明材料。教材列这些词以后，还讨论目标与实际使用体验的差距。学习时要能说明含义与边界，不需要背宣传口号。

2.1 写程序时：简单性、面向对象

简单性指语言在设计时舍去某些复杂机制，例如不给程序员做指针算术的语法。像减少机器上容易误用的旋钮；旋钮少了，不代表所有任务都简单。真实项目还有库、数据、错误和设计问题，所以“写问候容易”不能推出“几天掌握整个Java”。

面向对象把一项事物的数据与对它的操作联系起来。比如学生记录不仅有姓名、成绩，还能提供显示资料等操作。像一份带办事入口的登记卡，而不是把数据与所有动作散得到处都是。这里先理解组织思路，不能把“任何文件有一个class外壳”就当作已经学会面向对象设计；第4章会亲手建类。

2.2 运行时：健壮性、安全性

健壮性关心程序面对错误或不合规则的操作时怎样表现。编译阶段做类型等检查，运行阶段也会检测某些非法动作，例如数组越界。像在施工前和使用时都设检查点；它能早发现一部分问题，不能保证公式、需求都正确。

安全性关心代码可以访问什么、系统怎样限制某些行为，与“能否计算正确”是不同问题。可以把权限理解成门禁，但门禁设计与实现仍可能有缺陷。教材也回顾了早期浏览器沙箱遇到的问题；不能从“Java有安全机制”推断任意来源的程序都值得运行。

2.3 换机器运行：体系结构中立、可移植性

体系结构在这里指CPU等机器的组织与指令背景。体系结构中立强调编译出来的字节码不直接绑定某一种CPU的机器指令。

可移植性还包括基本类型规则、库接口等在不同系统上的一致约定。两者相关但不完全一样：一种标准工作单能被各地执行系统读懂，不代表各地文件位置、字体、外部工具都相同。

例如Java的int值范围有明确规定；程序如果写死某台电脑的文件绝对路径，移到别人机器仍可能失败。教材以跨平台界面等讨论边界，不是在承诺所有外观和外部依赖完全一致。

2.4 执行方式：解释型、高性能

解释执行可先理解为运行系统读懂中间指令并完成操作。即时编译是在运行过程中，将某些字节码转换为本机机器码的技术。像先按标准单执行，反复做的工作再整理为当地更直接的动作方案；真实机制不靠人重新抄写。

教材“解释型”与“高性能”不矛盾：JVM不必永远采用单一执行方式。不能用“先生成class”断言它已经是CPU机器码，也不能用“有解释执行”断言任何Java程序都必然慢。性能最终受程序、数据与执行环境影响。

2.5 与其他工作配合：分布式、多线程、动态性

分布式在本章强调库可以帮助通过网络交换数据。像向另一办事处取资料，需要协议与连接；不是“程序自动分散到所有电脑”。本课不提前配置服务器。

多线程让一个进程里能有多条执行活动，例如界面响应与后台工作协调进行。像同一部门分几条工作线，不等于一定同时用上多个CPU，也不表示可以任意同时修改数据；并发的正确性后面专门学习。

动态性涉及运行时加载、连接类及获知类型信息等能力。像系统运行期间按规则接入新的工作部件，不表示Java变量可以无条件变成任意类型，也不是必须从网页下载程序。

2.6 随堂检查：别只复述名词

把“换CPU仍能执行兼容字节码”“越界时报告问题”“后台活动与界面工作协调”“运行时加载类”分别对应到上述术语；再各说一条它没有保证的事情。能说出作用和边界，比背11个词更重要。

3. 源码、字节码、JVM怎样连接

源代码是保存下来的程序文本；javac是编译它的工具。普通编译生成class字节码，java启动工具找到类，让JVM执行。JVM是Java虚拟机，负责字节码执行相关工作，不是整台电脑模拟器。

你保存的 .java ── javac检查并转换 ──> .class字节码
                                       │
                              java启动兼容JVM执行
                                       ↓
                                   程序产生效果

JDK是供开发使用的工具包，包括编译与运行工具；JRE是运行环境的概念，不等于编译器。下一课按教材第2章把这些工具和本机配置对应起来。

字节码可移植仍有前提：目标环境兼容其版本、所需库与数据存在、程序没有无条件依赖另一系统特有功能。

4. applet 与 Internet：理解它当时想解决什么（教材 1.3）

Internet是互联网络；浏览器是获取和展示网页的应用。applet是教材讨论的一种旧式Java网页嵌入程序：浏览器配合相应运行支持，加载字节码，在指定区域呈现交互内容。

它曾用来让静态页面出现复杂计算与交互，例如转动物体模型。程序在哪里执行很重要：在服务器上生成网页，与把字节码交给客户端浏览器执行，是不同的安排。

教材同时描述了浏览器版本、兼容和安全问题。它是理解Java早期发展的历史材料；本课程不把旧插件安装当作现代基础实验，也不要求用applet写网页。Java程序可以在浏览器之外的终端、桌面或服务器环境运行。

5. 发展简史：记设计需求怎样变化（教材 1.4）

这段历史的主线是：早期消费设备对体积、可移植代码的需求，转向网络时代的展示与应用，再发展为更广泛的运行平台。名称曾从Oak变为Java，版本号与标准库也长期演变。

只抓三个阅读支点：

  • 为什么需要不直接绑定某一种CPU的中间代码。
  • 为什么浏览器applet的热度变化，不等于整个平台失去用途。
  • 为什么教材基于Java 8，而我们的运行工具可以是JDK 21。

Java 8加入了lambda等语言变化，也扩展了流、日期时间等库；这些词现在只作后续目录预告，不要求提前会用。教材的发展表停留在本版写作时，不能当作今天所有版本的清单。

6. 常见误解：把“语言、数据、工具、环境”分开（教材 1.5）

容易混淆的说法 本课建立的区分
Java是HTML的一部分 HTML描述网页结构，Java表达程序操作
有XML就不需要Java XML描述数据，处理数据仍需程序或工具
写几行简单，就表示全平台好学 小实验与真实项目的知识量不同
一门语言包办所有应用场景 语言选择还受平台、库、任务约束
Java只是语法 标准库、运行环境、工具也是平台的重要部分
读到旧版许可介绍就能判断今天所有发行包 许可说明属于具体时期与发行物，不能用历史叙述作现行结论
有解释执行所以关键程序一定慢 JVM还可即时编译，性能要看实际任务
Java程序都在网页里 普通应用也可以在浏览器之外运行
有安全设计就等于任何代码都安全 机制、实现、代码行为与权限都需要分别考虑
JavaScript是Java的简化版 是不同语言，名字相似不等于从属关系
一种新设备会自动替代所有现有电脑 设备能力、使用方式与软件生态会影响选择

表格是对本章问题的原创归纳，不要求背诵原文。JavaScript的运行生态也在发展，这里只澄清它与Java是不同语言。

7. 用最小程序观察一次实际执行

现在按第0节创建FirstGreeting.java。类在这里先当作组织程序的外壳，main方法是本阶段普通应用的启动入口。println将括号中的文字输出并换行，英文分号结束输出语句。

public class FirstGreeting {
    public static void main(String[] args) {
        System.out.println("你好，Java！");
        System.out.println("这是我自己运行的程序。");
    }
}

应依次看到“你好，Java！”和“这是我自己运行的程序。”。双引号框住源码中的文字，本身不显示。花括号分别围住类和方法；这些结构到L03逐项拆解，不要求现在设计自己的对象体系。

先交换两条输出的位置，再把第一行改成昵称。每次保存后重新运行。若仍出现旧文字，先查有没有保存、命令指向哪一个文件，不先怀疑所有Java安装都坏了。

8. 健壮性不等于程序一定符合题意

本例希望求长2、宽3的长方形面积，却写成加法：

public class RectangleCheck {
    public static void main(String[] args) {
        System.out.println(2 + 3);
    }
}

输出5，但期望面积是6。编译器接受合法加法，却不知道你的题意，这叫逻辑错误。把+改*后保存重跑，应得6。

编译错误是在产生本次编译结果前被拒绝，例如缺必需分号；运行时异常是在启动后执行某条非法操作时报告问题。类找不到或入口不对还需区分为启动问题，L02会逐个观察。

E3错误实验先复制正确问候程序，同时让副本文件名与public类名对应，再只删一处分号；记录第一条有效诊断，补回并重新运行。原标本保留，避免失去比较依据。

9. 观察自己所处的运行环境

public class EnvironmentPeek {
    public static void main(String[] args) {
        System.out.println("java.version=" + System.getProperty("java.version"));
        System.out.println("os.name=" + System.getProperty("os.name"));
    }
}

System.getProperty请求环境信息，返回文本；+把标签与结果接在一起。你记录自己的java.version和os.name，不照抄他人。不同版本或系统输出不同，正好说明“统一运行规则”不表示“所有环境属性相同”。

本课基础过关：能讲平台各部分的分工，自己运行并修改输出，区分编译成功与逻辑正确，说明兼容运行的前提。白皮书11个词要有含义与边界的认识，不逐条背书；历史年代、插件操作不作为卡关条件。
