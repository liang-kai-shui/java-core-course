0. 这课分几步学

建议分三次：第 1–3 节追踪 while；第 4–6 节比较 do/for、边界与变量位置；第 7–9 节再做嵌套和独立练习。每次先手算一小轮，不必一次读完。

怎么把讲义中的程序跑起来

带有 public class、完整大括号和 main 的 Java 代码框是完整程序。标为“片段”的短代码只替换 main 里面相应部分，不能单独当文件运行。每个完整程序另建一个文件，不能把两个 public class 或两个 main 随手拼在一起。

在 VS Code 中打开整个 D:\Code\Java 文件夹。在本课 my_code 文件夹新建 WhileTrace.java，文件名要与 public class 后的名字相同；保存为 UTF-8。没有显示后缀、不会新建文件或打开终端，先看零基础起飞，无需先读 PDF。

打开“终端 → 新建终端”，确认使用 PowerShell。以下命令从课程根目录开始输入，提示符本身不用抄：

Set-Location 'D:\Code\Java'
.\java.ps1 -Source '.\L08_第03章F_循环\my_code\WhileTrace.java'

这是课程提供的“编译成功才启动”工具。它每次在 .build 中另建输出目录，生成 class 后才运行；不要手动执行以前留下的 class。后面的完整程序同样操作，只换末尾文件名。需要键盘输入时，运行后在终端键入数据并回车；程序没有显示新提示符，可能正在等输入。出现脚本策略提示时，在同一根目录把运行一行改为：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\java.ps1 -Source '.\L08_第03章F_循环\my_code\WhileTrace.java'

每次实验留三项记录：预测、实际输出、解释第一次出现差异的步骤。看到程序自己的输出才算实际启动；没有报错不等于题目做对。

1. 重复三遍可以复制，重复几遍由输入决定呢

若要输出三次 Hello，可以写三条语句；若要一千次，要改一千处吗？若次数来自用户输入，写源码时甚至不知道要复制多少次。

循环用一套条件与操作表达重复。循环体是每轮要执行的代码，迭代是其中一轮。像按清单逐件处理，但程序不会自己知道“都处理完了”，终止规则必须写清。

每个循环先问三个问题：从什么状态开始；什么条件下继续；每轮如何向结束前进。条件只是这次能否进入，不是电脑替你保存的总次数。

2. while：先问，再做，再回去问

public class WhileTrace {
    public static void main(String[] args) {
        int i = 1;
        int sum = 0;
        while (i <= 3) {
            sum = sum + i;
            System.out.println("i=" + i + ", sum=" + sum);
            i = i + 1;
        }
        System.out.println("after: i=" + i + ", sum=" + sum);
    }
}

累加器是保存“到目前为止总和”的变量，这里是 sum。可以类比同一个篮子不断放入新东西；每轮换空篮子就不能保留总量。

先逐行看第一次：i 建为 1，sum 建为 0；条件 1<=3 真；右边 0+1 得 1，写回 sum；打印；i 由 1 变为 2；回到条件，不回到最初声明。

条件检查前 i 条件结果 进入前 sum 累加后 sum 更新后 i
1 true 0 1 2
2 true 1 3 3
3 true 3 6 4
4 false 6 不再执行 仍是 4 
建立 i=1、sum=0
        ↓
   检查 i<=3 ── false ──> 输出 after，继续后文
        │ true
        ↓
   累加 → 打印 → i 加 1
        └────────────────> 再检查条件

应看到：

i=1, sum=1
i=2, sum=3
i=3, sum=6
after: i=4, sum=6

循环体三次，条件四次。最后一次检查虽然失败，也真实发生；只是循环体没再执行。退出值 i=4 不代表循环体曾用 4 累加。

只改一处的三个实验

  1. 把条件上界 3 改 1：循环体一次，退出 i=2，sum=1。
  2. 改 0，起点仍 1：第一次就失败，sum 仍 0。
  3. 恢复上界 3，把 <= 改 <：只累计 1、2，sum=3。

先填预测，再运行。若预测错，沿表找到第一次不同的条件检查，不要只修改最终输出文本。

3. 更新、初值与变量位置，决定累计能否保留

若删去 i=i+1，i 始终为 1，条件反复为真。while 不会自动增加计数器；若运行了已知无限的副本，在终端 Ctrl+C 停止，保留原程序。

若把 int sum=0;放进循环体，每轮都会重新建立零初值。下面片段替换原循环相关部分：

int i = 1;
while (i <= 3) {
    int sum = 0;
    sum += i;
    System.out.println(sum);
    i++;
}

输出变成 1、2、3。不是加法坏了，而是前一轮的累计没有带入下一轮。

本轮 i 外部初始化：sum 进入→离开 每轮重新初始化：进入→离开
1 0→1 0→1
2 1→3 0→2
3 3→6 0→3

累加通常从 0 开始，因为还没处理数据，总和为 0。累乘通常从 1 开始，否则每次乘都还是零。找最大值则不能无脑从 0 开始：全负数据会被一个不存在的 0 压住，数组课再处理。

while 后也不能随手加分号。while(i<=3);的空语句成了循环体，更新在后面的块中永远轮不到。不要为了试它让程序长时间空转，先纸上分析即可。

4. do-while：先做一次，之后再问

public class CheckTiming {
    public static void main(String[] args) {
        int first = 0;
        while (first > 0) {
            System.out.println("while body");
            first--;
        }
        int second = 0;
        do {
            System.out.println("do body");
            second--;
        } while (second > 0);
        System.out.println("second=" + second);
    }
}

只输出 do body、second=-1。while 首次检查 0>0 假；do 先输出、减一，再检查 −1>0 假。

形式 第一次动作之前检查吗 正常流程可能零次吗
while 是 可以
do-while 否 不可以，先进入一次

do 的结尾 while(...);有必需分号，与 while 后误写空体的分号位置不同。像先尝试一次操作再决定是否继续；如果任务规定没有数据就不能处理，先做一次未必合适。

5. for：把计数的三项规则摆在一起

public class ForTrace {
    public static void main(String[] args) {
        for (int round = 0; round < 3; round++) {
            System.out.println("round=" + round);
        }
        System.out.println("finished");
    }
}

输出 round=0、round=1、round=2，最后 finished。分成四块：

for (int round = 0;   round < 3;   round++) {
     初始化一次         每次问       每轮体后更新
    循环体
}

顺序不是从左到右扫一遍就结束，而是：初始化一次 → 检查 → 体 → 更新 → 检查 → …… → 条件假后离开。

次序 round 执行什么
初始化 0 只做一次
第一次检查真 0 输出 0，再更新成 1
第二次检查真 1 输出 1，再更新成 2
第三次检查真 2 输出 2，再更新成 3
第四次检查假 3 不进体，也不再做本轮更新

变量名 round 不会自动让它成为计数器。换成 i 或 times 也一样，规则来自你的初始化、条件与更新。

round 在 for 初始化处声明，作用域限于这个 for 的条件、更新和循环体。结束后输出 round 会编译失败；若确实需要退出值，可事先在外层声明，再把初始化部分留空，但两个分号仍保留。

6. 从 0 开始与从 1 开始，分别在数什么

任务 起点 继续条件 进入时看到的数
重复三次，用零起编号 i=0 i<3 0、1、2
求 1 到 3 的和 i=1 i<=3 1、2、3

两者次数相同，但用于计算的数据不同。不能机械规定“循环一定从 0”或“<= 一定错”。数组从 0 编号，到 L10 才把长度与访问位置连起来。

步长是每轮计数改变多少，例如 i+=2 每次跨两格。片段 for(int n=2;n<=10;n+=2)会经过 2、4、6、8、10；更新到 12 后失败，不要求恰好停在上界。

若步长 3、起点 0，条件写 n!=10 会跳过 10；选择上界判断通常写 n<10 更符合任务。终止要靠推演，不能想当然“迟早走到”。

本课先用普通上界、单独更新，下一课再讲 break 与 continue。复杂金融或组合数背景不是理解循环的先决知识。

7. 嵌套：每到一行，都完整走一遍列

嵌套循环是在一个循环体里再放循环。像外层选教室，内层逐个点这个教室的座位。每换教室，座位从头点起；类比强调内层重启，不保证每个嵌套任务执行次数都相乘成某个固定平方。

public class RectangleRows {
    public static void main(String[] args) {
        for (int row = 1; row <= 2; row++) {
            for (int column = 1; column <= 3; column++) {
                System.out.print("*");
            }
            System.out.println();
        }
    }
}

print只输出内容，不自动换行；不带参数的 println 输出一次换行。所以结果是两行，每行三个星号：

***
***
外层 row 内层 column 依次取值 完成本行后
1 1、2、3；到4时结束内层 换行
2 重新从1开始，再到2、3 换行
3 外层条件假 不再创建内层

星号输出 2×3=6 次，换行只有 2 次。把 println() 移到内层，每个星就占一行；把它移到所有循环之后，会把六个星挤在同一行。

每次只移动这条换行语句，先预测三种布局。此时可以靠输出直接看见“某条语句属于哪层循环”。

8. 从矩形走到三角形，不先抄答案

练习 E2 要求三行：

*
**
***

先列每行的配方：

当前行 row 本行星号数 内层需要循环几次
1 1 1
2 2 2
3 3 3

外层仍从第 1 行走到第 3 行，内层的上界不再是固定 3，而是“当前行数”。换行仍应在本行所有星号之后。

起步时先让程序只输出每行 row，确认 1、2、3；再在每行里输出相应数量的星；最后去掉调试数字。若输出是正方形，检查内层上界是否还固定为 3；若只有一长行，检查换行位置。

9. 独立求和，先做最小可检查的版本

E1 要读 n，分别写 for 版与 while 版。先固定 n=3，让循环里额外打印“当前数、累计值”，手算到 6；确认后再接入 Scanner，并去掉调试输出。

题目 n=0 表示没有任何整数要加，总和应为 0。不要为了“至少进一次”改用 do-while。n=1 验证恰好一次，n=5 验证普通多次，n=10000 验证允许上界；本题总和 50005000 能装进 int，不需无根据换更复杂工具。

for 与 while 两个版本是两份独立程序，类名也不同，不能在同一文件粘上两个 public class。正式提交仍按原题名，讲义新建的追踪程序只是随堂实验。

10. 看症状，回到第一处状态差异

现象 优先查什么
一次不进 首次检查是否已 false
少一项或多一项 起点、< 与 <= 是否配套
不停输出 更新是否存在、方向是否正确、是否被跳过
只剩最后一项 累加器是否每轮被清零
循环后变量找不到 变量是否只在 for 或块内声明
图形只成一列 换行是否放进最内层

过关需能完整填写状态表、解释末次失败检查、选择正确初值与更新、独立写两种求和和三角形。学会“会读→会改→会写”三层后，再用教材的投资、组合数案例拓展应用。

回到教材案例：循环规则不只负责数1、2、3

3.8.3：达到目标才停，次数事先未知

教材Retirement的变量包括目标、每轮存入量、利率、余额和年份。重点是状态如何更新，不要求先有金融知识：先增加本轮投入，再按更新后的余额计算该轮增长，随后年份加一；达到目标才停止。

在简化的教学数字中，目标250、每轮加入100、增长率10%，初始余额0。第一轮先到100再增10，余额110；第二轮先到210再增21，余额231；第三轮到331再增33.1，余额364.1，随后条件失败。

这个表能解释while为什么不是“预先知道要做三次”，以及交换“加投入”和“计算增长”会改变结果。原书也说明其模型省略现实因素，本课只把它当状态更新案例，不据此制定实际理财安排。

教材Retirement2先执行更新并显示，再询问用户是否继续，回答N才再来一次。它用do-while的原因是用户先看到本轮状态，才有信息作下一步选择；不是为了“所有循环都至少跑一次”。

3.8.4：同一个for也能计算递推结果

教材用组合数示范“计数器变化，同时累计一个计算结果”。换一个原创场景：5人选2人，不分顺序。初值result=1，第1轮乘5除1得到5，第2轮乘4除2得到10。

这里累乘初值1，与求和初值0的理由不同；k=0时零轮，保留1表示一种什么都不选的方式。n、k大时普通int可能溢出，L09再用BigInteger把同类步骤接起来。

教材还提醒不要靠double每次加0.1，等于10才停止：0.1的表示误差可能使它跳过精确的10。用整数计数器控制次数更清楚。本课不实际长时间运行这种错误循环。
