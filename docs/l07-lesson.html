一对大括号不能只叫“外壳”

Java程序里类、方法、if分支都可能使用花括号，但各自控制的内容不同。S01讲类组织方法，本课在一个方法里面选择某组语句。if不会新建一个类，也不会新开一个程序进程。

类PassChoice
└─ main方法
   ├─ 输入score
   ├─ if/else选择块  ← 只选择其中一条执行路线
   └─ 输出finished  ← 选择之后汇合继续

像办事窗口按材料条件选择“受理”或“补交”，办理结束再共同打印收条。边界是：现实工作人员可以猜意图，程序只按你写出的boolean条件执行；缩进也不会代替花括号决定控制范围。

学习段 重点问题 先测什么
一次选择 哪段执行、之后去哪 59与60
多档规则 是多标签还是只选一档 95，检查顺序与互斥
作用域与任务 名字在哪可用、每条路径有值吗 票价所有接缝及非法范围

变量声明放在分支中只在相应范围可用，不能因为屏幕上看见它就认为外面也能读。先画包含关系，再追踪实际走过的那条路。

动手入口：先保存，再验证当前文件

在VS Code打开解压后的课程根目录（能看见java.ps1的那一层），在本课my_code新建PassChoice.java，复制或手敲下面同名完整程序并保存为UTF-8。选择“终端→新建终端”，确认使用PowerShell，从课程根目录输入：

.\java.ps1 -Source '.\L07_第03章E_条件分支\my_code\PassChoice.java'

看到程序自己的输出才证明实际执行。编译失败就停止；脚本为每次运行隔离class输出，不执行旧文件。策略阻止时使用课程首页的单次运行写法。完整Java代码框可单独建文件；标为片段的代码只放进相应位置。一个文件可有多个非public顶层类，但public顶层类名需与文件名匹配，不把多个独立main样本拼成一个文件。

每次只改一处，记录“预测→实际→第一次差异发生在哪一步”。不会文件、后缀或路径操作，回本课程零基础起飞，不以阅读PDF替代操作解释。

1. 为什么输出不能每次都执行

同一个程序，分数 75 要显示通过，分数 50 要显示再练习。如果顺着写两条 println，它们都会执行，程序没有替你选择。

分支是根据条件选择执行哪些代码。像遇到岔路按路牌选择，但路牌必须是程序能判断的真假问题；它不会自动理解“分数不错”这样的模糊描述。

先写中文规则：

如果 score 至少 60：显示 pass
否则：显示 retry
选择完成后：总是显示 finished

if表示“如果”，else表示“否则”。它们是语言关键字，不是我们取的名字。括号内放 boolean 条件，花括号内放对应操作。

2. 完整程序与执行路线

import java.util.Scanner;

public class PassChoice {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int score = in.nextInt();
        if (score >= 60) {
            System.out.println("pass");
        } else {
            System.out.println("retry");
        }
        System.out.println("finished");
    }
}

输入 75 时，条件真，输出 pass，跳过 else，再输出 finished。输入 50 时，条件假，跳过 if 块，输出 retry，再输出 finished。

读取 score
    |
检查 score>=60
    ├─ true  → pass  ─┐
    └─ false → retry ─┤
                      ↓
                  finished

选一条分支不等于结束程序。 走完选择后会继续后面的语句，除非某条分支明确用了 return 等控制动作。这里两个输出位置的 finished 都相同，是为了让这件事可见。

输入 条件 哪个分支执行 哪个跳过 最后还会输出
59 false else if finished
60 true if else finished
75 true if else finished

先测试 59、60，观察边界；再把 >= 改成 >，只有正好 60 的结果应变化。不能只凭 75 通过就判断比较号正确。

3. 没有 else，以及多出来的分号

有些动作只在满足条件时发生，其他时候什么也不做。片段放到 main 读入 score 之后：

if (score == 100) {
    System.out.println("perfect");
}
System.out.println("thank you");

score=100 输出两行，其他分数只输出 thank you。没有 else 不是语法缺陷，而是没有安排另一条动作。

花括号围住的代码块控制操作范围；缩进只是帮助人看。课程先统一加花括号，避免把第二条语句写到块外却误以为仍受条件控制。

这个错误实验用不带else的独立片段：if(score>=60) { System.out.println("pass"); }。在它的条件后加分号，再接原输出块。不要在保留else的完整程序里照做：那会因else失去配对而编译失败，是另一种现象。分号自身构成空语句，if 控制的是“什么也不做”；后面的块变成独立执行。于是 50 分也打印 pass。

这通常能编译并正常结束，却不合题意，是逻辑错误。编译器不需要知道你不想这样写。

4. 多个 if 与 else-if 链，先看同一份数据

互斥指结果只允许选择一项，例如一个分数只给一个等级；如果允许“通过”和“优秀”两个标签一起出现，就不一定互斥。

public class IndependentOrChain {
    public static void main(String[] args) {
        int score = 95;
        System.out.println("independent:");
        if (score >= 60) {
            System.out.println("passed");
        }
        if (score >= 90) {
            System.out.println("excellent");
        }
        System.out.println("chain:");
        if (score >= 90) {
            System.out.println("excellent");
        } else if (score >= 60) {
            System.out.println("passed");
        } else {
            System.out.println("retry");
        }
    }
}

independent 部分会显示两个标签，chain 部分只有 excellent。不是较短写法更高级，而是两种写法在表达不同任务。

链按顺序检查，遇到第一个 true 就执行那一块，不再检查后续链项。若先问 >=60，95 就已经被选为 passed，不会再获得 excellent。

5. 先写区间，避免遗漏接缝

给 0–100 的分数评档。有效范围是业务题目规定的规则，能读成 int 不代表分数合理。150 能读进 int，仍是非法分数。

import java.util.Scanner;

public class GradeBoundary {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int score = in.nextInt();
        if (score < 0 || score > 100) {
            System.out.println("invalid");
        } else if (score >= 90) {
            System.out.println("excellent");
        } else if (score >= 60) {
            System.out.println("pass");
        } else {
            System.out.println("retry");
        }
    }
}
实际区间 应得结果 要测试的接缝
小于 0 或大于 100 invalid −1、101
0–59 retry 0、59
60–89 pass 60、89
90–100 excellent 90、100

走到 >=60 那一项时，前面的非法与 >=90 已经失败，因此范围已经隐含是 60–89。不必再堆一遍全部上界，但必须知道这是由前面的检查保证的。

边界测试是在规则切换的位置验证，不是挑一个看起来随机的数。75 只能证明一条中间路径，不能证明 59/60 没有缝隙。

6. 花括号内的名字，外面不一定能用

块作用域说明名字在代码的哪些区域可见。像一份局部工作表只供该工作段使用；类比不表示离开块后一定立刻发生某种内存清除动作。

预期编译失败片段：

if (score >= 60) {
    int messageCount = 1;
    System.out.println(messageCount);
}
System.out.println(messageCount); // 这里已经不能使用这个局部名字

若后面确实需要结果，可以在外层先建立并赋初值，然后各分支更新它；不能在分支中偶然声明一次，就认为所有路径都创建过变量。

还有一个 Java 规则：在仍可见的局部变量或参数范围内，不允许随意在内层再次声明同名局部变量。先用不同且有意义的名字，避免把“暂时更新原变量”误写为“重新声明”。

else与最近尚未匹配的 if 配对，不能靠缩进猜。统一写花括号最直接，复杂的嵌套应先画规则再编码。

7. 独立完成票价，不照着分数变量名硬替换

练习 Ticket 的输入是年龄，输出是一个词。先把题目变成区间表：非法、0–5、6–17、18–59、60–120。

起步顺序：

  1. 只读年龄并输出，确认 Scanner 工作。
  2. 加非法判断，把 −1、121 挡在正常规则之外。
  3. 再加免费档，用 5、6 检查接缝。
  4. 继续增加半价、全价、老年档，每次只打印一项。
  5. 对照原题的十个边界输入，逐个记期望与实际。

不知道顺序时，可以从低向高或高向低设计，但要证明区间完整且互斥。不要为了一次命中让多个独立 if 各自重复输出。

8. 自查与过关

不看资料解释四件事：if/else 选完后会到哪里；两个独立 if 为什么可能都执行；阈值顺序如何影响 95；if 后多分号为何常不是编译错误。

Java if 条件必须是 boolean，if(1)不能使用；而 boolean 变量之间的赋值有时也能出现在条件中，因此不要笼统认为“赋值写进 if 一定编译失败”。本课清楚地区分赋值 = 与比较 ==，让意图直接可读。

本课通过要有票价正确运行和边界证据，并能解释作用域与两种分支结构；选做的更复杂规则不作为卡关条件。

从教材图3-7到图3-9：跟踪的不只是一条打印

教材用业绩与奖金说明一条分支可以更新不止一个结果。我们的分数、票价例子换了场景，控制结构仍对应：先判断，执行整个块，再汇合继续。

可以把PassChoice的真分支临时加两条不同输出，验证都受同一条件控制；再将第二条移到块外，比较50与75的输出。这正是在观察“块把多条动作组织为一个受控制单位”，不是只学习某条println的特殊行为。

3.8.1先介绍块，再介绍if。读代码时，先圈出每对花括号的区域，再追踪当前路径中已声明且已赋值的局部变量。后续更复杂的分支仍使用这套方法。
