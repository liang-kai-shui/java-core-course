1. 三张图，回答三种问题

源码怎样组织：

项目根目录
└─ src/                     源码根（本项目约定）
   └─ campus/app/Main.java  保存源码文字的文件
      └─ 类Main的定义
         ├─ 字段            保存实例或类的状态
         ├─ 构造器          初始化新对象
         └─ 方法            定义可调用的操作
            └─ 语句/代码块   本次执行的步骤

这张图表示包含关系。src不是Java关键字；类也不是磁盘文件夹。文件可以有多个非public顶层类，一个类可以有许多方法。

运行时的数据关系：

类的定义：ReaderCard规定状态与操作
运行中的对象：卡A{name=Lin}，卡B{name=Mei}
局部变量：first → 卡A，alias → 卡A，other → 卡B
静态字段：例如这一运行时类的发卡数量

新建对象、复制引用、修改对象字段是三种动作。图中的箭头是引用关系，不是能由你做加减的地址，也不是磁盘快捷方式。

文件怎样变成一次运行：

.java源码 ──javac──> .class字节码 ──jar归档──> app.jar
                                                    │
                            java选择入口、启动JVM执行│
                                                    ↓
                     main → 方法调用 → 返回 → 程序输出

普通JAR只是类与资源的归档，不自动包含JVM、不自动合并依赖，也不等于原生exe。一个运行中的进程可以加载许多类并创建许多对象，不能按文件数量猜对象或进程数量。

3. 五个名字，别拿同一个点号混为一谈

写法 这次是什么
campus.app.Main 类的完整名字，含包名
campus/app/Main.class 归档或类路径根下的字节码条目
Main.class出现在Java源码中 类字面量，得到表示类型的Class对象
System.out 读System类提供的out字段
name.length() 对String对象调用方法

Java并不是唯一有类、包、库的语言。需要学的是它们在Java中的组合与查找规则；不能拿另一个语言的一句结论直接套用。

4. 真实工程里的src/main/java又是哪一层

常见Maven项目把源码与测试进一步分开。按官方目录约定，可以先这样读：

项目根/
├─ pom.xml                          项目与构建配置
├─ src/
│  ├─ main/
│  │  ├─ java/campus/app/Main.java   应用源码
│  │  └─ resources/...              随应用处理的资源
│  └─ test/
│     ├─ java/...                   测试源码
│     └─ resources/...              测试资源
└─ target/                          构建生成的输出

此时源码根是src/main/java，下面才按包排目录；类全名仍可为campus.app.Main。main/java不加入包名。pom.xml像构建工作单，描述项目、依赖及构建安排；实际Java语句仍在类的方法中。生成目录内的具体文件以项目配置为准。

这张图把常见工程映射回S04–S06已经学过的角色。当前课程用JDK命令与项目脚本完成实验；学会读这棵树后，再按后续工具课实际配置Maven或Gradle。
