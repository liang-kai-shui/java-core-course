维护与打包

本页目录
  • 修改课程后
  • 分发范围
  • GitHub 发布

学习只需要JDK和编辑器。以下工具供课程维护者验证和更新网页，不是学生开课前的安装要求。

修改课程后

  1. 同步讲义、练习与参考答案；保持双页码。公开练习题源为 _课程工具/exercises.json，用户直接在本地各课 练习.md 中作答，不能清空或用发布模板覆盖它。新增课次先看教材正文，再修改 _课程工具/course.json、公开题目模板和路线图。
  2. 新增或修改Java源码时，在 _课程工具/checks.json 登记正常输出、输入、边界和错误实验的预期阶段。
  3. 运行 python _课程工具/verify_course.py，实测原始课程源码。报告写入 outputs/验证报告.json，不代表学生成绩。
  4. 用已安装Markdown模块的Python运行 python _课程工具/build_release.py，生成离线网页和ZIP。缺模块时才用 python -m pip install -r _课程工具/requirements.txt；不要求每次重新安装。

网页导航改动后，运行 node _课程工具/check_navigation.cjs。该检查需要开发环境安装Playwright及浏览器；可用COURSE_BROWSER指定现有浏览器可执行文件，NODE_PATH指向已有Node包目录。不属于普通学习者的安装要求。检查包含独立页面、当前项、历史前进后退、课内页签、连续阅读深链接与滚动、手机宽度；报告在outputs中。

源码验证使用标准库和JDK。网页构建使用Python Markdown；pypdf仅供抽取教材书签。当前电脑系统Python已安装Markdown，Codex自带Python与系统Python的软件包互不相同，不要把“某个解释器没有包”当成电脑完全没有包。

分发范围

构建器按白名单收集课程文档、示例、错误标本、参考答案和工具。每课练习使用 exercises.json 中的空白模板，不读取本地练习中的个人答案。排除教材PDF、扫描图、个人进度、作答、my_code源码、批改记录、缓存、编译产物及本机JDK绝对配置。公开包用学习进度模板替代个人记录，重新使用时按实际情况建立进度追踪.md。

docs/是可双击的纯本地阅读器，不加载网络资源。完整课程源码与网页打入 outputs/Java入门课程-第1-3章.zip；附SHA-256与内部链接/ZIP完整性校验报告。

构建只更新生成物；不得覆盖学生作答或个人进度。不要把一次性种子脚本当作日常维护工具反复运行。

GitHub 发布

公开仓库：liang-kai-shui/java-core-course。在线阅读：GitHub Pages。沿用C++课程的代码MIT、文档CC BY-NC-SA 4.0协议。

构建时同步生成根目录 可分发版/，这是独立的公开Git仓库；已存在的 .git/ 不会被构建器覆盖。本地个人学习目录与教材不加入该仓库。维护者在本地课程根目录修改并验证，再构建公开版本；推送前检查可分发版的Git差异。

python _课程工具/verify_course.py
python _课程工具/build_release.py
git -C 可分发版 status --short

GitHub Pages以main分支的 /docs 为发布源，.nojekyll 保证原样提供HTML与带下划线的文件。压缩包可本地分发；仓库直接保留课程源文件与网页，下载仓库ZIP也能离线阅读。
