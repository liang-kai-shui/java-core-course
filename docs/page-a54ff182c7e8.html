Java 陪读课程工作约定

本项目配合用户自备的《Java核心技术 卷Ⅰ：基础知识（原书第10版）》中文版。先读 README.md、学习路线图.md、进度追踪.md 和 给其他LLM的批改指南.md，再处理当前课。

  • 不假设用户会 C++ 或已经学会 Java。根据实际作答判断；已有 C++ 项目不是 Java 掌握证据。
  • 教材按章推进，密集章节拆课。每个新术语先解释是什么、为什么需要、给出类比，再解释类比边界。
  • 用户明确要求对齐C++课程的零基础教学深度：零基础起飞必须完整解释电脑/文件/后缀/路径/进程/终端，再串起Java运行。每个主题按具体困惑→原因与类比→逐步操作→预期现象→排错展开，不压缩成术语速记。命令须说明在哪里输入、从哪一目录开始、生成什么、成功如何判断；区分PowerShell与cmd，保留Java与C++运行链路的差别。
  • 网页默认按C++课程的多页结构组织：课程首页、课程说明、附录，以及分组的讲义/练习/参考答案/示例入口。每课提供独立页面、课内切换和真实上下页链接；全一册仅为可选连续阅读。侧栏当前项必须与实际页面或连续阅读位置一致，不能写死课程说明。改导航后运行_课程工具/check_navigation.cjs，用浏览器验证跳页、刷新、前进后退、深链接和全一册滚动。
  • 每课要有目标、前置知识、双页码阅读表、白话讲解、独立可运行示例、预测/修改实验、必做练习、边界样例和过关标准。题目为本课程原创，不冒称教材原题。
  • 讲义页码必须同时写“书本 pX”和“PDF pY”。阅读规则见 页码对应说明.md；首批第1–3章正文边界已看图核对，后续编写前继续看正文，不凭书签就声称逐页核对。
  • 不复制教材正文或扫描图进入可分发包。PDF 保留原文件名，不自动改名、不打包、不提交。
  • 默认先提示，再给局部修法；不得未经用户要求重写其提交。完整参考答案单独存放。
  • 用户直接在每课练习.md里作答，不要求复制到作答.md。批改以练习.md中实际答案为主，兼容已有作答文件；不得为恢复空白题目而覆盖个人练习。
  • 公开题目源在_课程工具/exercises.json。网页、ZIP与可分发版均从该模板构建练习，不从个人练习复制答案。新增或改题时显式同步模板，保留原有学生作答。
  • 每次批改读旧进度、核对上轮订正、按题记录证据、追加日志，并保存进度追踪.md。材料已生成、助手测试通过都不等于学生通过。
  • 不凭空填写“未开始”“阅读完成”“已经掌握”。无证据填“未确认”；只有明确必做项、核心概念和所需验证均有依据，才判整课通过。
  • 编译使用本地 JDK，普通示例保持 Java 8 语法/API；默认在 JDK 21 上用 --release 8。不能将此写成“已在 Java 8 JVM 测试”。新版本补充单独注明。
  • 每个独立 main 程序隔离编译输出，编译失败立即停止，不得执行旧 class。错误实验必须标明预期失败阶段；验证脚本不能把所有源码都要求编译成功。
  • 本机 JDK 配置见 环境说明.md 和 .java-course.json。优先用 java.ps1，不修改全局 PATH、JAVA_HOME 或其他项目编辑器设置。
  • 更新内容后运行 python _课程工具/verify_course.py，再运行 python _课程工具/build_release.py。后者需 Markdown 包；普通学习不需要 Python。
  • 对外发布前排除个人进度、作答、批改、构建产物、工具临时目录及教材。发布仓库位于可分发版，个人学习目录不整体提交；用户已授权创建并推送liang-kai-shui/java-core-course。
