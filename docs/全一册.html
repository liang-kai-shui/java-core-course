零基础起飞 · 在电脑上跑一个程序

电脑里的文件是一份有名字的数据，例如讲义、PDF、源代码；文件夹用来组织这些文件。类比书页与书架，但电脑可以让文件夹一层层包含。

路径是找到文件的位置。例如 D:\Code\Java\README.md 是从盘符出发的完整地址；code\HelloJava.java 是相对当前目录的地址。命令里出现空格或中文时，用引号把路径包起来。Windows资源管理器的“查看→显示→文件扩展名”能帮你分清.java、.txt和.pdf；不要把代码保存成HelloJava.java.txt。

CPU负责执行计算，内存暂存运行中的数据，硬盘长期存文件。像厨师、案板和储物柜：关机后源码仍在硬盘，程序运行时的临时数据通常不会自动保存。类比只帮助理解分工，不代表CPU只有一个任务或内存只能存一种东西。

程序是按规则组织的一系列指令。源代码是人写的文字；Java编译器先把它转换成字节码文件，JVM再执行。进程是程序运行起来的一次活动；同一程序可以运行多次。需要查看进程时按Ctrl+Shift+Esc打开任务管理器；不要看到陌生进程就结束它。

终端是输入命令并观察输出的窗口；PowerShell是理解这些命令的一种程序。它们不等于Java。你写javac时，是请求PowerShell启动Java编译器；出现“不是可识别的命令”，说明找程序这一步就没成功，还没有开始检查Java语法。

在VS Code里选择“文件→打开文件夹”，打开整个Java课程目录；菜单“终端→新建终端”会出现命令输入窗口。输入Get-Location查看当前目录，Get-ChildItem查看里面的文件。不要把提示符里的PS D:\Code\Java>也复制进命令。

首个任务：确认你能找到教材PDF、README和L01文件夹，打开讲义，然后按README运行HelloJava。暂时记住“保存→编译→运行”三步；看不懂代码时不急，L02和L03会逐项拆开。

术语先说清楚

  • JDK：开发Java的工具包，里面有编译器和运行工具。像做菜的一套厨具，不只是拿到成品。
  • JVM：执行Java字节码的虚拟机。可以理解成各个平台提供的“字节码执行员”；它不是完整的电脑模拟器。
  • JRE：Java运行环境这个概念，包括JVM及运行所需的库等。现代JDK的发行形式和书中旧版界面不同，本课程不另找一个“JRE下载”安装。
  • PATH：系统寻找命令的目录清单。命令找不到只表明搜索失败，不证明软件没安装。

先会两步运行

在某个示例目录的PowerShell中，手动执行（例：HelloJava.java）：

$jdk = 'C:\Program Files\Java\graalvm-jdk-21.0.12+7.1'
New-Item -ItemType Directory -Path .\out -Force | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 '-Xlint:all,-options' -d .\out .\HelloJava.java
if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -cp .\out HelloJava
}

javac把源文件变成.class；java按类名启动程序。-d指定编译产物目录；-cp指定从哪里找类；运行时写HelloJava，不带.class。--release 8在当前JDK允许的范围内约束Java8语法与标准API；它不会把JDK21变成JDK8。-Xlint:all,-options启用代码警告，仅关闭旧目标版本的选项提示。

正常学习优先用根目录的 java.ps1：它每次新建隔离输出目录，失败立即停，避免错跑旧class。示例无package且各有独立main，不要把所有课次一次编译到同一个目录。

需要程序参数时：.\java.ps1 -Source '路径\ArgsDemo.java' -ProgramArgs @('red','blue')。-CompileOnly只编译，不声称运行成功。脚本适用Windows PowerShell5.1或PowerShell7；其他系统可用上面同等的javac/java命令，路径按系统修改。

中文输入与输出

源码统一保存UTF-8；编译显式-encoding UTF-8。本机JDK21运行时可设置-Dstdout.encoding=UTF-8和-Dstderr.encoding=UTF-8；项目脚本同时临时设置控制台编码并在退出前恢复。输入示例使用键盘交互，不靠旧PowerShell默认编码的管道传中文。出现乱码时先记录终端、源文件编码和实际命令，别随意重装JDK。

报错时如何判断

编译失败看javac诊断；运行失败看异常类型、第一条指向自己源码的堆栈行和输入；结果错误则列出输入→期望→实际。看到Compilation succeeded只代表编译过了，看到程序自己的输出才说明它实际运行。

编译有错时不要手动继续运行旧class。脚本生成的 .build/ 都是可再生文件，不含你的源码；本项目不自动删除其中内容。

一份.java文字为什么能变成屏幕上的输出？先建立“谁负责哪一步”的地图，后面报错才知道找谁。

1. Java不只是语法

编程语言是人给电脑描述操作的一套规则。像约定好的工作指令，规则统一才能被工具理解。平台还包括执行环境和可以调用的现成库；库可以类比常用工具集合。你不是每次输出文字都从控制硬件开始写。

本课只要求理解1.1、1.2和1.5的主旨：Java提供语言、类库和运行环境，移植性有前提。1.3、1.4作历史阅读；不要背年代，也不用实现浏览器applet。

2. 源码→编译→执行

你手写的HelloJava.java叫源代码，就是保存下来的程序文本。编译器javac先检查它是否符合规则，再生成常见后缀为.class的字节码。JVM执行字节码，完成输出等动作。类比同一份菜谱先整理成统一的操作单，再由不同厨房里的执行员完成；厨房仍需要合适的工具和原料。

HelloJava.java --javac--> HelloJava.class --java/JVM--> 屏幕输出

编译成功只说明通过了一部分规则检查，不能证明程序算对了。把2+3错写成2-3仍可能编译成功。

JDK是开发工具包，包含javac和运行工具；JRE是运行环境的概念。我们已有JDK21，不再找旧JRE安装包。java是启动工具，不等于整个Java平台。

3. 先跑一个最小程序

示例code/HelloJava.java中，class先理解为装程序的外壳，main先理解为启动入口。System.out.println把括号中的内容输出并换行。每个词的详细规则L03继续讲，不要求现在背“面向对象”定义。

4. 三类现象，三种判断

编译错误：工具不能把源码编译成功，例如少分号。运行时异常：已经启动，执行到不合法操作时报告问题，例如数组越界。逻辑错误：程序跑完，但不符合题意，例如长方形面积写成周长。这只是入门分类；程序也可能同时有多类问题。

跨平台是指兼容的字节码可以由各系统上的适配JVM执行，不是任意电脑不用安装东西就能跑，也不是依赖特定系统文件的程序必然通用。System.getProperty示例先当作“向运行环境查询信息”的现成工具，之后再讲对象和方法。

2. 编译命令逐项拆开

在某个源码目录中，按环境说明设置$jdk，再执行：

& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 -d .\out .\HelloJava.java
if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -cp .\out HelloJava
}

&让PowerShell启动引号中的程序；不是Java语法。-d是放编译产物的目录，-cp是运行时查找类的目录。类名在这里是HelloJava，运行时不写扩展名。$LASTEXITCODE记录上个外部程序的退出状态；这里等于0才继续，防止编译失败仍执行旧文件。

当前目录是相对路径的起点。Get-Location看位置，Get-ChildItem看文件。教材命令中的示例路径不能原样当成你电脑的真实地址。

3. 程序的名字要对应

先采用一文件一个public class的约定：HelloJava.java里面是public class HelloJava。大小写也要对应。main必须按当前模板准确写为public static void main(String[] args)；写成Main是不同名字。

命令行参数是在启动类名后给程序的数据，像把待办事项随启动请求一起交进去。ArgsDemo先只显示参数个数，不访问不存在的第一个参数；数组细节L10讲。

这一课要解决什么问题

程序要记住人数、价格、姓名和真假条件。如何给数据起名，又避免把不合适的数据混用？

1. 先看程序外壳

public class VariableDemo {
    public static void main(String[] args) {
        int count = 3;
        System.out.println(count);
    }
}

class声明类；类可以组织程序，后面还会用来描述对象。方法是一段有名字、可被调用的操作；这里main是启动方法。先把public static void main(String[] args)当作完整模板使用：public表示可访问，static使启动时无需先创建该类对象，void表示不返回结果；第4章会用真正的调用解释它们。

花括号包住代码范围，分号结束语句。//到行末是注释，/* ... */是块注释，注释不会被执行，也不能随意嵌套。引号中的//属于文本，不会变成注释。

2. 变量与赋值

变量给运行中要用的数据起名，像贴着标签的格子。int count = 3声明类型、名字并给初值。count = count + 1是先取右边旧值计算，再把结果放回左边；不是数学里声称两侧永远相等。

类型规定可以存什么值及允许哪些操作。类比容器标签只是入门帮助；Java的引用变量并不直接把整个对象装进格子。

局部变量用之前必须确定已赋值：int count;本身合法，但直接输出尚未赋值的count会编译失败。不要把“局部变量未初始化”与“数组元素有默认值”混为一谈。

3. 常用类型先抓住用途

类型 适合的值 重点
byte/short/int/long 一定范围内的整数 首选int；很大的整数字面量加L
float/double 浮点数 首选double；float字面量常需f；许多小数不能精确表示
char 一个UTF-16代码单元 如'A'、'中'；不是任意一个完整Unicode字符
boolean true或false 不能拿0/1自动替代
String 一段文本 引用类型，不属于8种基本类型

字面量是直接写在源码里的值，例如42、3.5、'A'和"Java"。常量在本课用final int DAYS = 7表示赋值后不能再改的量，避免把固定意义散落成神秘数字。普通变量名用studentCount这类有意义的写法，常量名可用MAX_COUNT。

4. 范围、初始化与作用域

int范围是-2147483648到2147483647；存不下的计算不会自动变成long。运行VariableDemo观察最大值加1，它会绕回负数。不要套用C++有符号整数溢出的规则。

作用域指代码哪些位置可以使用一个名字。花括号内声明的局部变量通常只在相应范围可用；它不是对“这块数据在内存里什么时候消失”的完整描述。

这一课要解决什么问题

相同数字，为什么换个类型或括号就得到不同答案？先确定表达式怎样算，再给结果起名。

1. 整数除法发生在赋值之前

表达式是会计算出结果的组合，像一张小算式。7 / 2两侧是整数，结果是3；double x = 7 / 2只是把已经得到的3再转成3.0。要得到3.5，让运算本身含double：7 / 2.0。%是余数，不是百分比。

负整数除法向0截断，例如-7/2是-3，-7%2是-1。乘法和除法优先于加减，但涉及业务含义时主动加括号比硬背复杂优先级更清楚。

教材3.5.1还会用到Math这个数学工具类：Math.sqrt(9.0)得到平方根3.0，Math.pow(2.0, 3.0)得到8.0。这里的点表示调用该类提供的方法，不是小数点。Java中的^是按位异或，不是乘方；想算平方也可直接写x * x。本阶段只需按API说明调用，第4章再展开静态方法。

2. 类型转换不能修复已经算坏的结果

转换是把值用另一种类型表示。强制转换写成(int)3.9，结果是3，丢掉小数部分，不是四舍五入。

int count = 1_000_000;
long wrong = count * count;
long right = (long) count * count;

第一种先按int相乘并溢出，装进long也救不回来；第二种在乘之前就让计算使用long。即使int转double通常能表示，long转double仍可能丢精度，不能认为“目标容量大就什么都不丢”。

+=等组合赋值有隐式转换规则，例如short s=1; s+=1可行，直接s=s+1不一定可行。本课优先写清楚表达式，不靠隐式转换省字。i++先给出旧值再加1，++i先加1再给出值；在独立一行作为更新时相同，避免堆在一个复杂算式里。

3. 比较与短路

==比较是否相等，=赋值；!=不等。&&表示同时成立，||表示至少一个成立，!取反。它们处理boolean，不把整数自动当真假。

短路是已经知道结果时不再执行右边，像两道门中第一道明确不通就不必检查第二道。divisor != 0 && 10 / divisor > 1在除数为0时不会计算除法。&和|用于boolean时会计算两边，也可用于整数位运算；与&&、||不要混用。

三目表达式score >= 60 ? "pass" : "retry"根据条件选一个值。位运算的& | ^ ~ << >> >>>先知道作用在二进制位；本课扩展阅读，不要求用它写业务题。3.5.9枚举先理解“给有限选项起名字”，详细设计在第5章。

1. String与不变性

字符串是一段文本，例如"Java"；Java用String类表示它。方法调用是请求某个对象或类完成一个操作，写法先读成“对象.操作(参数)”。参数是交给操作的数据，返回值是操作得到的结果。

String name = "  Java  ";
name.trim();
System.out.println(name);
name = name.trim();

不可变表示已经建立的String对象内容不会被这些操作改写。trim()返回去掉首尾相应空白的新结果；不接住结果，name还是原来的引用。这里的引用可类比找到对象的凭证，但不是能自己做地址算术的指针。重新给变量赋值与修改原对象不是一回事。

2. 内容比较用equals

a.equals(b)比较字符串内容；引用上的==比较是否指向同一对象。一些字面量可能共享对象，导致==偶尔看似能比内容，不能因此拿它判断用户输入的文本。

空字符串""是存在但没有内容的String；null是没有指向对象。null.length()会报异常，不是0。已知常量时可写"yes".equals(answer)，answer为null也不会因为调用者为null而报错；不要因此认为所有null操作都安全。

3. 下标从0，终点不包含

"Java".charAt(0)得到'J'。substring(1,3)取下标1、2，得到"av"；结束下标不包含，像从起点格子走到终点前停下。length()是代码单元个数，合法charAt下标从0到length()-1。空串没有可取的第0个元素。

"score="+80+5会先拼接成文本再继续拼接，得到score=805；要先求和写"score="+(80+5)。

4. Unicode与StringBuilder

String内部使用UTF-16代码单元语义；emoji等补充字符可能占两个代码单元。运行UnicodeDemo，比较length和codePointCount。码点是Unicode给字符分配的编号；它与“视觉上一个字形”也不总是一对一。先知道边界，本课不要求实现通用字素切分。

反复拼很多片段时，可以用StringBuilder这个可变文本构建工具，像先在草稿板上逐段追加，最后toString()交出String。append会改变构建器，区别于String上的不可变操作。先运行示例，不要求在还没学循环时优化所有字符串。

为什么要中间这一行？数字读取通常把数字后面的换行留在通道里；紧接着nextLine会先读到数字所在行的剩余部分。如果那部分只有换行，结果就是空串。注意：这一行不一定只剩换行，若同一行还有别的数据，也会一起被读走；本课约定年龄和姓名分别各占一行。

Locale.US在数值输入示例里明确使用点作小数分隔，避免系统地区设置改变实验。这里只把Locale看成“地区格式规则”，不要求先学国际化框架。

2. 格式化输出

格式化是把数值按约定排成文字。printf("%.2f%n", price)中的%.2f用两位小数显示浮点数，%d显示整数，%s显示文本，%n换行。显示两位不等于底层值变成精确的两位小数。格式说明符与参数类型必须匹配。

Paths.get("note.txt")表示相对当前工作目录的路径，不一定是源码所在目录。课程脚本不替你切换到源码文件夹；从根目录启动时相对文件就落在根目录。

这一课要解决什么问题

同样的程序，需要按年龄或分数选择不同操作。怎样写出互斥又没有漏掉临界值的规则？

1. if是按条件选择执行

条件是计算结果为boolean的表达式，像一道决定往哪走的路口。if (score >= 60) { ... } else { ... }只选一个分支。条件不是任意整数；if(1)不能照搬到Java。

if (score < 0 || score > 100) {
    System.out.println("invalid");
} else if (score >= 90) {
    System.out.println("excellent");
} else if (score >= 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}

这是一条互斥的条件链：前一项成立就不再测试后面的项。顺序是规则的一部分；先测>=60再测>=90，90分也会先进入pass。多个独立if不是同一回事，可能重复打印。

2. 先写范围表再写代码

把分数切成：小于0、0–59、60–89、90–100、大于100。分界处用-1、0、59、60、89、90、100、101验证。边界测试就是专门在这些接缝检查，像检查两块拼图之间有没有缝或重叠；只测75分无法证明60分正确。

判断“18至25岁，包含两端”，写age >= 18 && age <= 25，不能写数学式18 <= age <= 25。同类条件先用括号表达清楚，不要依靠缩进猜关联。

3. 代码块与作用域

代码块是花括号包围的一组语句。局部变量通常从声明后到所属块结束可用，块里的同名声明还有限制。写入块内不等于声明了一个到处可用的名字。

if (ready) {
    int count = 3;
    System.out.println(count);
}

块外用count会编译失败。初学时总给分支加花括号，避免只控制一条语句时误读。不在if括号后随手加分号：if(condition);可能让后面的语句无条件执行。

输出100行、累加一组数或反复读取输入，不应该复制粘贴100份代码。循环用一段规则表达重复。

1. while的三个要素

循环是在条件满足时重复执行代码，像按清单逐件检查货物。务必找出：初始状态、继续条件、如何前进。

int i = 1;
int sum = 0;
while (i <= 5) {
    sum += i;
    i++;
}

逐轮写表：进入时i=1，sum变成1，i变成2；下一轮sum变成3。退出时i=6，sum=15。遗漏i++可能永远满足条件。迭代就是循环的一轮，不是某个新的Java关键字。

do { ... } while(condition);至少执行一次，while可能一次不执行。读教材投资示例时先看状态怎么变化，不急于套金融背景；double只用于教学计算，不据此推出财务金额都适合浮点数。

2. for把计数规则放在一起

for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

顺序是初始化一次→检查条件→循环体→更新→再检查。这里i的作用域限于for及其循环体。需要恰好n次且从0编号，常用i=0; i<n; i++；需要1到n的值，常用i=1; i<=n; i++，不要不看目的机械替换符号。

3. 初值与空情况

累加从0开始，是因为没有任何数时总和为0。求最大值不能总从0开始：若输入全负数，会得到不存在的0；数组课将处理这一点。n=0时循环可能不进入，程序仍需给出题目规定结果。

嵌套循环像钟表的时针与分针：外层每前进一次，内层完成一整轮。NestedDemo的两行三列共执行6次输出。不要只把两个上限相加；同时也别把一切嵌套循环都不加条件地说成固定平方复杂度。

这一课要解决什么问题

有限的几个选项怎样分派？循环中想提前结束怎么办？整数或小数超出基本类型能力时用什么？

1. switch按一个值选择分支

多重选择是按同一个值匹配若干选项。传统Java8写法中，case标出选项，default处理未匹配情况，break结束当前switch。没有break时可能继续执行后面的语句，叫贯穿；它有时是有意合并分支，但初学要明确标注。

switch (day) {
    case 6:
    case 7:
        System.out.println("weekend");
        break;
    default:
        System.out.println("weekday");
}

示例假定day在1–7内；若任务要求验证范围，必须先处理0、8等非法值。switch适合离散选项，不直接写case score >= 60。新版箭头语法另行补充，首批练习采用教材风格。

2. break和continue

循环里的break结束最内层对应循环；continue跳过本轮剩余部分，转入下一轮。for中的continue会先走更新部分；while里若把更新放在continue之后，可能永远跳过更新导致死循环。

不要说continue“退出循环”；它只退出这一轮。多层嵌套和带标签跳转先会读，本课选做，不要求靠标签重写普通题。

3. BigInteger与BigDecimal

大整数BigInteger用于超出long范围的整数，仍受可用内存与资源限制；不是无限大。new BigInteger("...")从十进制文本建立值。相加写a.add(b)，不能写a+b。

十进制数BigDecimal适合明确控制十进制表示与舍入。需要精确表示0.1时用new BigDecimal("0.1")，避免先把0.1变成近似double再交给构造器。BigDecimal.valueOf(0.1)也是常见选择，但必须分清它与new BigDecimal(0.1)。

这些数值对象的运算返回结果，a.add(b)不改原a，需要保存结果。除法不一定有有限小数，1/3要指定保留位数和舍入规则，如divide(three,2,RoundingMode.HALF_UP)；本课用它观察“保留2位按规则取舍”，不泛称所有金额都采用同一规则。equals还比较scale等表示细节，数值比较用compareTo并检查是否为0。

保存一组成绩并统计，而不是为每个人写一个变量。本课结束做一个有明确输入输出的成绩统计器。

1. 数组是编号的一排同类型元素

数组按编号组织一组固定长度元素，像编号从0开始的储物格。int[] scores = new int[3]建立3个int元素，默认各为0；变量scores保存数组引用。合法下标是0、1、2，scores.length是3，数组length不是方法，没有括号。

引用共享：int[] b = scores复制引用，像两张凭证找到同一排格子，改b[0]会影响从scores看到的内容。Arrays.copyOf建立另一份数组。对引用数组做浅拷贝时元素仍可能共享对象；当前先对int数组验证。

for (int i = 0; i < scores.length; i++) {
    scores[i] += 1;
}
for (int score : scores) {
    System.out.println(score);
}

增强for适合依次读取元素；for(int score:scores){score++;}只改本轮局部变量，不会把int数组元素改掉。需要下标更新时用普通for。

2. 不存在的位置不是“随便一个值”

访问length位置会产生越界异常。空数组new int[0]合法，但没有第0项；它与null不同。统计平均值先确认数量大于0；最大值对非空数组可从第一项初始化，避免把全负数误判为0。

3. 排序与查找有前提

Arrays.sort会改变原数组顺序；想保留原始录入顺序先复制。Arrays.binarySearch要求相应区间按同样规则有序；未找到时返回负数编码，不能把所有负结果都解释成固定-1，也不能把返回值直接当成绩。

4. 二维数组是数组的数组

int[][] grid={{1,2},{3,4,5}}两行长度不同。外层grid.length是行数，内层每次读grid[row].length；不能假设每行都等于第0行长度。不规则数组就是这种不等长情况。NestedArrayDemo演示遍历；不要求现在写高维算法。

命令行参数String[] args也属于数组；访问args[0]前检查长度。它与Scanner读键盘是不同的数据入口。

5. 阶段项目的边界

成绩统计器先读数量n，约定0–100；n=0打印no data并结束。n>0再读n个0–100的整数成绩，保留录入顺序，输出总分、两位小数平均分、最大值、最小值、及格人数，再另行打印排序副本。题目规定有效的成绩输入，不把字母恢复或文件保存作为本阶段卡关项。

编译成功、运行成功、结果符合题意是不同结论。正常题核对普通值和题目明确要求的边界；固定输入输出按题意比较。故意错误实验按目标阶段判断：编译失败、运行时异常、逻辑错误不能混为一谈。编译诊断随语言环境可能不同，不能只凭一条英文错误文本判对错。

字符串内容比较检查equals；数组检查下标、空数组、引用共享；输入检查nextInt/nextLine衔接；整数除法、溢出、精度和整型表达式中间结果都要根据真实代码判断。选用少量能证实问题的测试，不机械堆测试。

明确区分“助手实测”“学生自测记录”“仅静态检查”。没有工具时必须写“未实际编译运行”，不能编造输出、零警告或通过用例。JDK21上--release8编译不等于在JDK8虚拟机实测。

public class RaggedSum {
    public static void main(String[] args) {
        int[][] values = {{1, 2}, {3, 4, 5}, {}};
        int sum = 0;
        for (int row = 0; row < values.length; row++) {
            for (int column = 0; column < values[row].length; column++) {
                sum += values[row][column];
            }
        }
        System.out.println("sum=" + sum);
    }
}
ScoreStats.java
import java.util.Arrays;
import java.util.Locale;
import java.util.Scanner;
public class ScoreStats {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        if (n < 0 || n > 100) {
            System.out.println("invalid count");
            return;
        }
        if (n == 0) {
            System.out.println("no data");
            return;
        }
        int[] scores = new int[n];
        for (int i = 0; i < n; i++) {
            scores[i] = in.nextInt();
        }
        int sum = 0;
        int maximum = scores[0];
        int minimum = scores[0];
        int passed = 0;
        for (int score : scores) {
            sum += score;
            if (score > maximum) { maximum = score; }
            if (score < minimum) { minimum = score; }
            if (score >= 60) { passed++; }
        }
        int[] sorted = Arrays.copyOf(scores, scores.length);
        Arrays.sort(sorted);
        System.out.println("original=" + Arrays.toString(scores));
        System.out.println("sum=" + sum);
        System.out.printf(Locale.US, "average=%.2f%n", sum / (double) n);
        System.out.println("max=" + maximum);
        System.out.println("min=" + minimum);
        System.out.println("passed=" + passed);
        System.out.println("sorted=" + Arrays.toString(sorted));
    }
}
