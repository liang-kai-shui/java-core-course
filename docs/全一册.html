1. 电脑到底在干什么

1.1 先把电脑想成一间厨房

你做一顿饭，不能把所有事情都交给同一个东西：柜子负责存原料，台面负责摊开正在处理的东西，厨师负责照步骤操作。

电脑也有分工。

厨房里的角色 电脑里的东西 它主要负责什么
厨师 CPU，中央处理器 执行指令，进行运算和控制
料理台面 内存，也叫RAM 临时放正在使用的程序和数据
储物柜 硬盘、固态硬盘等存储设备 保存程序、照片、文档等文件

这三个词为什么要现在认识？因为以后你会碰到三种不同的问题：

  • “我写的源码存在哪里？”——主要是在找硬盘上的文件。
  • “这个程序运行时用了多少空间？”——可能是在问它占用了多少内存。
  • “它是不是一直在计算？”——可能要观察CPU使用情况。

先分清自己在问哪件事，才不会把“硬盘快满了”和“内存不够用”当成同一个问题。

这个厨房比方只帮助理解分工。真实电脑还有寄存器、缓存、GPU等部件，CPU也不是完全不能暂存数据；现在不用把这些细节一口气学完。

1.2 内存和硬盘最大的区别

问题 内存：台面 硬盘：柜子
主要放什么 当前运行、处理中的东西 要保存的文件
普通电脑断电后呢 原来的运行状态通常不能保留 已经正确保存的文件通常仍在
“16GB内存”说的是谁 这里 不是这里
“硬盘还剩100GB”说的是谁 不是这里 这里
学Java时的例子 正在执行的程序、运行时的数据 .java源码、教材PDF、保存的练习

所以，保存不是“我已经在屏幕上看到字了”，而是让软件把修改写入对应文件。

你在编辑器里改了三行代码，还没保存，编译器从硬盘读取的可能仍是旧内容。这就是为什么课程总让你先按 Ctrl+S。

有些软件会自动保存、恢复未保存的内容。这是软件提供的额外帮助，不能据此认为“所有修改都会自动保存”。本课程先养成自己确认保存的习惯。

动手①：看见“保存前”和“保存后”的区别

  1. 打开记事本，输入一句“这是我的学习记录”。
  2. 按 Ctrl+S。如果是新文档，会让你选文件名和保存位置。
  3. 保存到一个你找得到的文件夹，名字例如 观察.txt。
  4. 关闭记事本，再从资源管理器找到这个文件，重新打开。

应该看到什么：刚才保存的那句话还在。

如果找不到：先回忆刚才选了哪个文件夹，不要马上重写一份。下一节开始讲“怎样确定文件的位置”。

2. 什么是文件

2.1 为什么要有文件

假设你写了一段文字，希望明天继续看。电脑需要知道三件事：

  1. 你要保存哪些内容。
  2. 这份内容叫什么名字。
  3. 它放在什么地方。

文件就是电脑把一份数据组织起来、让你能按名字保存和读取的一种方式。可以先把它想成贴了标签的资料袋。

观察.txt、教材.pdf、照片.jpg、FlightHello.java，都属于文件。

资料袋是比方，不代表一个文件在硬盘内部必须占连续的一整块空间。现在关心的是：它作为一份有名字的内容，可以被找到、打开、修改和保存。

2.2 文件里到底装了什么

照片看起来是画面，歌曲听起来是声音，源码看起来是文字；保存和传输时，它们都会用数字数据表示。

电脑最基本的数据单位叫位，英文bit，可以取0或1。字节英文byte，通常按8位计算。你在“属性”里看到的文件大小，往往会用字节、KB、MB等表示。

不用现在学习二进制计算，只要先知道：文件的内容要由合适的规则和软件解释。

文件 合适的打开方式 为什么
观察.txt 记事本、VS Code 里面是文本
教材PDF PDF阅读器 按PDF的格式组织页面
照片 看图软件 按图片格式解释数据
Java源码 VS Code等文本编辑器 查看、修改代码文字

拿记事本打开图片或.class文件，可能看到怪符号。这不一定说明文件坏了，也可能只是用错了查看内容的方式。

2.3 文件“打开了”和程序“运行了”不同

你双击教材PDF，启动的是PDF阅读器，阅读器把教材显示出来。教材里的示例代码不会因为你打开这一页就自动执行。

同样，你在浏览器里看到这篇讲义，只是打开了网页。网页中的Java代码展示在屏幕上，不等于它已经在你的电脑里编译运行。

你做的事 实际发生了什么
打开教材PDF 阅读器显示教材
打开网页中的讲义 浏览器显示课程内容
在VS Code打开.java 编辑器显示源码文字
按课程命令编译并启动Java类 工具开始处理、执行这个程序

动手②：查看文件的类型、位置和大小

  1. 按 Win+E 打开文件资源管理器，就是平时浏览“此电脑”“下载”的那个窗口。
  2. 找到刚保存的 观察.txt，右键选择“属性”。
  3. 找到“文件类型”“位置”“大小”这几项。
  4. 再对教材PDF做同样的观察。

应该发现：它们的类型、大小可以不同，位置也可以不同，但都是文件。

观察问题：你能把“它叫什么”和“它放哪里”分别说出来吗？说不清位置就接着看第4节。

3. 文件名和扩展名：先把后缀显示出来

3.1 FlightHello.java分成哪两部分

部分 在这个名字里是什么 有什么用
主名 FlightHello 帮人和工具区分这份文件
扩展名，也叫后缀 .java 提示文件的类型；影响工具识别和默认打开方式

文件名中可以有多个点。对 FlightHello.java.txt 来说，最后的扩展名是 .txt，不是 .java。

扩展名像标签，不是转换器。 把照片从.jpg改名为.java，不会把照片变成Java代码；把源码从.java改成.exe，也不会变成能直接启动的Windows程序。

3.2 这门课会遇到哪些后缀

后缀 先理解成什么 本课程里怎样用
.txt 普通文本 观察记录、练习数据
.md 按Markdown标记排版的文本 讲义、练习；在编辑器里能直接写答案
.pdf 固定页面的文档 你的教材
.java Java源代码文本 你亲手编写、修改的程序
.class 编译后的Java类文件，包含字节码等信息 交给Java运行环境加载执行，不手改其中内容
.jar 将Java类和资源等装在一起的一种归档文件 后续学习打包；不是每个JAR都能直接启动
.ps1 PowerShell脚本 项目的java.ps1会帮你编译和运行
.exe Windows可执行文件 java.exe、javac.exe就是已有工具
.zip 压缩包 下载课程后先完整解压，再学习和写作业

不要把 .java、.class 和 java.exe当成一个东西。 第7节会把它们串起来。

3.3 Windows 11：怎样显示文件扩展名

如果系统把后缀藏起来，你可能只看到 FlightHello，却不知道它实际叫 FlightHello.java还是FlightHello.java.txt。

按下面做：

  1. 按 Win+E，打开文件资源管理器。
  2. 在窗口上方找到 “查看”。
  3. 点开 “显示”。
  4. 勾选 “文件扩展名”。
  5. 回到文件列表，观察文件名的末尾。

Windows 10常见的界面是在顶部“查看”选项卡里直接勾选“文件扩展名”；部分界面也可在“文件夹选项→查看”中取消“隐藏已知文件类型的扩展名”。找不到时按实际系统界面查看，资源管理器的右键“查看”菜单不一定包含这个开关。

这个操作只改变显示方式，不会改动文件内容。它与“显示隐藏的项目”也不是同一个开关。

3.4 最常见的坑：源码其实多了一个.txt

你在记事本中保存了 FlightHello.java，但保存类型仍是“文本文档”。实际文件名可能变成：

FlightHello.java.txt

如果扩展名被隐藏，看起来很像已经起对名字了。

检查办法：先显示扩展名，再看完整名字；也可以右键属性查看文件类型。

用记事本新存Java源码时，留意“保存类型”是否选为“所有文件”，名字是否确实以.java结束，编码是否为UTF-8。用VS Code新建并保存为FlightHello.java通常更直观，第8节会带你做。

动手③：确认你看见的是真名

  1. 显示扩展名。
  2. 在课程目录找一个 .md、一个 .java和教材 .pdf。
  3. 分别读出它们的完整文件名。
  4. 在VS Code中打开一个.md，按 Ctrl+Shift+V查看排版后的预览，再回到编辑标签。

应该看到什么：编辑区里有#、**等文本标记，预览区会把它们显示成标题或加粗。它们来自同一份.md文件。

和交作业有什么关系：答案直接写在本地 练习.md 的编辑区并保存。浏览器里的课程网页用于阅读，不会因为你在浏览器里看过题目就自动生成作答文件。

4. 文件夹、路径，以及“我现在在哪”

4.1 为什么还要有文件夹

如果把照片、教材、示例、作业全堆在一起，你会很难找到想要的东西。

文件夹用来组织文件，也可以继续包含其他文件夹。它又叫目录；这两个词在本篇可以当作同义词。

可以把硬盘想成柜子，文件夹是抽屉，抽屉里还可以有小抽屉。几层文件夹形成的组织结构，常叫目录树。

这门课的一小部分可以画成：

Java/                         ← 课程根目录
├── README.md                 ← 总入口
├── java.ps1                  ← 运行工具
├── 附录/
│   └── 零基础起飞.md
├── L01_第01章_认识Java/
│   ├── 讲义.md
│   ├── 练习.md                ← 在这里直接写本课文字答案
│   ├── code/                 ← 课程原始示例
│   └── my_code/              ← 你自己的本课代码
└── my_code/                  ← 第8节会新建，用于这篇入门实验
    └── flight_lab/
        └── FlightHello.java

根目录在这里指这套课程最外层的文件夹，不是特指C盘根目录。判断自己有没有打开对：应该能在这一层同时看到 README.md、java.ps1和各课文件夹。

根目录的入门实验my_code/flight_lab与L01里面的my_code是两个不同位置。这篇用新文件FlightHello.java练操作，不改你已经写过的L01答案和HelloJava.java。

4.2 路径就是地址

路径是告诉人和工具“到哪一层找哪个文件”的地址。

以这台电脑的课程位置为例：

D:\Code\Java\my_code\flight_lab\FlightHello.java
这一段 读法
D: D盘这个位置标识
\Code 进入Code文件夹
\Java 再进入Java文件夹
\my_code 再进入my_code
\flight_lab 再进入入门实验文件夹
\FlightHello.java 最后找到这个文件

\叫反斜杠，这里用来分隔层级。网上也经常看到/，叫正斜杠。Windows的许多工具能接受部分正斜杠写法，但并非所有位置都可随意互换；本篇的PowerShell示例统一按给出的写法输入。

盘符不是物理硬盘数量的证明。 一块硬盘可能划分出C盘、D盘；你的电脑也可能根本没有D盘。

如果你从GitHub下载到“下载”文件夹，课程地址可能完全不同。D:\Code\Java是本机示例，不是每个人都必须拥有的固定地址。

4.3 绝对路径和相对路径

别人问你“去图书馆怎么走”，你可以说完整街道门牌，也可以说“从这里出去右转”。

  • 绝对路径类似完整门牌：写清确定的起点，例如D:\Code\Java\README.md。
  • 相对路径类似“从这里走”：从当前所在目录算起，例如README.md。

相对路径依赖一个前提：你现在站在哪里。

假设终端当前目录是D:\Code\Java：

写法 指向哪里
README.md 课程根目录里的README
.\README.md 同上；.表示当前位置
.\附录\零基础起飞.md 进入附录找这篇文章
..\ 回到上一层D:\Code

如果当前目录已经变成D:\Code\Java\附录，同样写README.md就会在“附录”里面找它，不再指向根目录的README。

两个点 .. 是上一层，一个点 . 是当前位置。 点后面跟哪个分隔符、后面还有哪些名字，也要一起读，不能只看某个词眼熟就认为地址相同。

4.4 三个“位置”容易被混在一起

位置 它是谁的状态
资源管理器地址栏 这个浏览窗口正查看哪个文件夹
VS Code打开的工作区文件夹 编辑器把哪个文件夹当作项目入口
终端当前目录 这一个终端中的相对路径从哪里算

它们可能相同，也可能不同。 你在编辑器里点开一个深层源码，不代表终端自动跟着进入那个目录；新开另一个终端，也不保证继承你刚才所有操作。

碰到“找不到文件”，先核对这三者，不要第一反应就重装软件。

4.5 空格、引号与复制路径

例如JDK安装在：

C:\Program Files\Java\graalvm-jdk-21.0.12+7.1

Program Files中间有空格。命令行需要知道“这是一个完整地址”，所以常把路径放进英文引号里：

cd 'D:\Code\Java'

中文文件夹和带空格的路径并非一律不能用。本项目本来就有中文课次目录。先掌握引号和准确路径，不要为了学编程把课程目录全部改名。

Java源文件主名先用英文，例如FlightHello.java，并与程序中的public class FlightHello对应，能减少起步时的拼写困扰。

动手④：复制一份真实地址

  1. 在资源管理器里进入课程最外层，确认看到README和java.ps1。
  2. 按 Ctrl+L选中地址栏，再按 Ctrl+C复制当前文件夹地址。
  3. 粘贴到记事本里，看清它从哪个盘或位置开始。
  4. 再进入“附录”，比较地址末尾多了哪一段。

应该发现：文件夹地址和文件的完整地址不同，后者还要加文件名。

如果看到的是压缩包内部：先回到ZIP所在位置，右键选择“全部解压”，进入解压后的普通文件夹再操作。不要只从压缩包中拖出一个Java文件；课程还需要根目录里的运行工具和其他材料。

5. 什么是程序：为什么打开源码不等于运行

5.1 先区分“指令”与“数据”

程序是为完成任务而组织的一系列指令。它可以显示文字、计算总价、处理图片，也可以启动和管理别的程序。

记事本是一个程序，教材PDF通常是它交给阅读器处理的数据，Java源码则是开发工具要读取和处理的文本。

现实中的一个软件可能由多个文件、库和资源组成，不能简单认定“一个软件永远就是一个.exe”。起步先分清：你在编辑什么，你正在让哪个工具执行任务。

5.2 用菜谱把几个角色分开

想象你把做饭步骤写在纸上：

厨房里的动作 编程中相似的动作
写、修改菜谱 编写、修改源代码
检查并转换为厨房能使用的操作单 编译
执行员按照操作单工作 启动运行环境执行程序
端出结果 程序产生输出或完成其他任务

读一眼菜谱，不会自动做出饭。打开源文件，也不等于已经运行其中的程序。

这个比方不能用来理解所有底层细节，尤其别把字节码当成“已经执行过的结果”。字节码仍是待执行的指令表示，不是最终屏幕输出。

5.3 Java初学者最容易混淆的三个东西

东西 它是什么 你通常怎样处理
FlightHello.java 你编写的源码文本 用编辑器打开、修改、保存
FlightHello.class 编译产生的类文件 让Java运行环境加载执行
java.exe 已安装JDK中的启动工具 在终端通过命令启动它

双击.java具体会怎样，取决于电脑的文件关联，也就是系统约定“这种文件默认交给谁打开”。常见情况是打开编辑器，或询问用什么程序打开。这本身不说明Java坏了。

双击.class也不等于系统自动知道“请替我选好运行环境、类路径和入口”。本课程用明确的命令启动，方便你看清每一步。

如果你以后看到新版Java用java 文件.java直接启动源文件，那是JDK提供的源文件启动模式；其中仍有编译与执行过程。我们先学两步形式，便于观察文件和报错，不把“先编译再执行”误解成“所有工具都必须让人手工点两次”。

动手⑤：看懂“打开”发生在哪里

  1. 在VS Code里打开课程的一个.java示例，只观察内容，先不点击运行。
  2. 找到程序里System.out.println(...)那一行。
  3. 想一想：现在只是显示了这行代码，终端里是否已经出现它要输出的文字？

应该区分：编辑器中显示代码，与程序在终端里实际输出，是两种不同的现象。第8节会真的运行一遍，再回来对照。

6. 什么是进程：用任务管理器看见正在运行的东西

6.1 程序和进程不是同一个角度

源码和程序文件保存在硬盘上；当你启动程序，操作系统会为这次运行安排内存、执行等资源。

这次运行中的实例，叫进程。可以类比“保存的菜谱”与“这一次正在进行的做饭活动”。

问题 程序及其文件 进程
关注什么 保存的指令、软件内容 一次运行活动
不运行时还在吗 已保存的文件仍可以在 这次活动已经结束
为什么会占内存 文件被使用、运行时需要装入相关内容 运行中要维护自己的数据和资源
能和窗口一一对应吗 不能这样推断 也不能；一个窗口可能关联多个进程，进程也可以没窗口

浏览器经常有多个进程；新版记事本可能用标签页组织文档。因此，“打开三个窗口就必定是三个独立进程”不能当成通用规则。

Java程序运行时，任务管理器里可能看到java.exe、Java相关名称，或被归在某个应用分组里。具体显示随工具和启动方式不同，不要求大家的截图完全一致。

6.2 任务管理器是观察工具

任务管理器是Windows自带的工具，用来查看正在运行的应用、进程和资源使用情况。

它像厨房监控台，可以帮助回答：“谁还在运行”“谁正忙”“谁占了较多内存”。

打开方法：同时按 Ctrl+Shift+Esc。

如果界面是精简的，先找“详细信息”或“更多详细信息”；如果已经有“进程”“性能”等页面，就直接进入“进程”。Windows不同版本的位置有差异，以文字标签为准。

常见列 先怎样理解
名称 这一项是哪一个应用或进程
CPU 一段时间内使用了多少CPU处理能力
内存 正占用多少内存
磁盘 近期存储读写活动
网络 近期网络传输活动

点“内存”或“CPU”的列标题，通常可以按这一列排序；再点可能改变排序方向。

占得多不等于有错。 浏览器打开很多页面、编译器正在工作，都可能正常地使用资源。暂时等待键盘输入的程序，CPU占用也可能很低，但仍然活着。

6.3 程序卡住时先做什么

对你在终端里启动的练习程序：先点到那个终端，再按 Ctrl+C，请求中断当前运行。

如果按键被终端当作复制，先取消文字选择、确认焦点在正在运行程序的终端，再试一次。中断是否成功也要看程序是否停止、提示符是否重新出现。

确实无法停止时，才在任务管理器里识别自己刚启动的程序，使用“结束任务”。这是强制停止，不会替你保存尚未保存的内容；不要为了练习随便结束不认识的系统进程、编辑器或其他人的任务。

死循环是本来想重复有限次，却写成一直无法结束的循环。它可能持续消耗CPU；也有程序只是等输入，看起来没动但并非死循环。先看题目要求和终端提示，不要只凭“还没结束”判断。

动手⑥：看见进程，再正常关闭

  1. 打开任务管理器，进入“进程”。
  2. 按内存列排序，找出自己的浏览器；只观察，不结束它。
  3. 打开一个记事本文档，观察列表中是否出现或更新对应项。
  4. 从记事本菜单或窗口按钮正常关闭它，留意任务管理器的变化。

应该学会的事：能找到应用并观察资源，而不是要求列表必须恰好增加一行。

后面自己的Java程序运行不结束时，你至少知道有“中断当前运行”和“确认进程再结束任务”这两种处理办法。

7. 代码、编译器，以及Java多出来的那一层

7.1 人为什么不直接给CPU写指令

CPU执行的是对应硬件能识别的机器指令，不是直接读懂中文作文。让人长期用一串机器指令编写复杂程序，很难阅读、修改和检查。

所以有了编程语言：规定一些严格的写法，让人能够描述操作，再由工具处理这些描述。

代码就是你按编程语言规则写下来的内容；开发时原始的那份，叫源代码，简称源码。

编程语言不像日常聊天那样能大量依靠猜测。少一个引号、拼错一个名字，可能就变成另一种意思，或者根本不符合规则。

Java是这样一种语言。它的代码不要求你先学过C、C++或Python。

7.2 编译器为什么像翻译员

编译器是一种程序：读取源码，检查相应规则，再转换为后续工具可以使用的形式。

像把你写的菜谱整理成统一的操作单。整理时能发现漏了符号、名字用错、某些类型不合要求等问题，但不一定知道你原本想做什么菜。

例如你本来想算长方形面积，却写成周长，程序完全可能编译成功。“工具接受了代码”和“结果符合题意”要分别判断。

7.3 Java这条链要分两段看

本课程先采用下面的形式：

你手写并保存                    编译得到                    启动执行
FlightHello.java   --javac-->   FlightHello.class   --java / JVM-->   屏幕输出
   源代码文本                  类文件，包含字节码等信息

字节码是一种供Java虚拟机使用的指令表示。它与直接交给某一款CPU的机器码不是同一个层次。

JVM是Java Virtual Machine的缩写，中文叫Java虚拟机。它负责加载、执行相应Java程序；实际实现可能解释字节码，也可能把部分代码编译成本机机器码执行。初学不需要拆开它内部的所有步骤。

这个“虚拟机”不是要求你先装一台完整的虚拟Windows电脑。先把它理解成Java程序的执行环境中的核心执行部分。

7.4 同一张角色表，消除五个名字的混淆

名字 它是什么 类比与作用
Java 一门编程语言；日常也用来指相关平台 你学习的规则，以及围绕它提供的工具与库
JDK Java Development Kit，开发工具包 工具箱，里面有编译、启动等开发工具
javac JDK提供的Java编译命令 翻译员，把源码编译成类文件
java 启动Java程序的命令 请运行环境开始执行指定程序的入口
JVM Java虚拟机 运行环境中负责执行Java程序的核心部分
JRE Java Runtime Environment，Java运行环境的概念 JVM及运行所需库等；现代发行方式与旧教材截图不必完全相同

特别看清最后一个字母：java和javac是两个不同的命令。它们不是“一个词的两种随便写法”。

在Windows的JDK安装目录中，你能找到java.exe、javac.exe。这些工具本身已经是可运行的软件，不是你要从零编写的课堂作业。

我们选用JDK 21来学习。书中的Java8写法与“电脑安装的JDK版本”也不是同一个概念；课程会尽量先按教材基础语法编写，再单独补新版本内容。

7.5 “跨平台”到底承诺了什么

可以先把字节码想成统一的操作单：不同系统上有适配的执行环境，就不必每次重新手写一份同样的业务逻辑。

但前提仍然存在：运行环境要兼容程序要求的版本，程序需要的库、文件和系统功能也得满足。

说法 怎样修正
Java程序任何电脑都能直接跑 要有适配、兼容的运行环境及所需依赖
Windows上的java.exe可以原样拿到所有系统执行 启动工具和JVM实现也要适配系统、硬件
有JDK就保证我写的程序完全正确 工具不能替代题意检查和测试

这不是让你现在研究全部兼容性问题，而是避免把“跨平台”误解为“没有任何条件”。

7.6 我到底要不要重新安装

这台电脑已经有可用的JDK21。 直接接着第8节检查，不用为了截图或教材版本相同而卸载重装。

其他读者如果确实还没有JDK，可以按下面的顺序准备：

  1. 打开Windows“设置→系统→关于/系统信息”，查看“系统类型”。普通x64电脑选x64；ARM电脑按实际架构选择，不根据“都是64位”就随意混选。
  2. 到Eclipse Temurin官方发布页选择JDK21、Windows和相应架构。选择 JDK，不要只找能运行但不含开发工具的包。
  3. 下载安装程序，记住安装位置。安装选项若提供添加PATH，可按安装器说明处理；已有环境的读者不用为了这一篇更改全局配置。
  4. 安装后重新打开终端，再检查java -version和javac -version。
  5. 能运行java但找不到javac时，先核对JDK是否完整安装、两个工具是否来自同一安装目录。

PATH是系统寻找命令时使用的一份目录清单，像“去哪几个地方找工具”的通讯录。java找不到，可能只是工具没被列进这份清单，不证明电脑完全没装Java。

本课程根目录的check-java.ps1会优先读取项目配置，再尝试已有环境与常见安装目录。所以本机即使直接输入java找不到，也可以先通过课程工具使用已经安装的JDK。具体配置查环境说明。

动手⑦：说清“谁写、谁编译、谁执行”

看一眼上面的运行链，试着用自己的话补完整：

我写的是_文件；_工具把它编译成类文件；启动时通过_命令，让_负责执行。

不需要说得和本文一模一样，但不要把.class说成屏幕输出，也不要把JDK、javac、JVM都叫作“那个Java”。

下一节会真正走一遍，不止停留在记名字。

8. 终端和命令行：从打开窗口到亲手运行

8.1 为什么要用打字下命令

你也许习惯点“开始”“打开”。命令行只是另一种交代任务的方式：把“启动哪个工具、处理哪个文件、用什么选项”写成一行。

学编程需要它，是因为：

  • 工具的一些功能通过命令使用最直接。
  • 同一条命令可以重复执行，也能原样交给别人复现。
  • 编译、运行产生的结果和诊断，可以保留成完整文字。

8.2 终端、PowerShell、cmd分别是什么

终端先理解为容纳命令输入、输出的窗口或面板。

cmd/命令提示符 另一种命令解释程序；不要混抄两边的语法
VS Code终端面板 编辑器内提供的终端界面，里面仍要选具体使用哪个解释程序

8.8 再揭开脚本：它大致帮你做了什么

课程脚本不是另一门神秘语言。对本阶段无package的单文件程序，它主要做：

  1. 找到已经安装的JDK。
  2. 找到你指定的源码，建立一份新的编译输出目录。
  3. 调用javac编译。
  4. 只有编译成功才调用java启动，避免错跑上次的旧class。
  5. 帮本机终端与程序输出约定UTF-8，减少中文乱码。

package是Java用于组织类名字的一种机制，后面才讲。此处只知道我们的入门文件暂时不写它，不能把这份单文件脚本当成所有复杂Java工程的通用启动器。

8.9 看见两步形式：先编译，再启动

已经完成8.7后，再读这一段。它帮助你理解javac和java的区别，不要求第一次就记住每个选项。

下面使用本机已检查的JDK位置。其他读者应采用自己的安装位置；先前check-java.ps1输出的Course JDK可帮助定位。

在课程根目录执行：

$jdk = 'C:\Program Files\Java\graalvm-jdk-21.0.12+7.1'
New-Item -ItemType Directory -Path '.\my_code\flight_lab\out' -Force | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 '-Xlint:all,-options' -d '.\my_code\flight_lab\out' '.\my_code\flight_lab\FlightHello.java'

这几行中，$jdk只是给一段路径起个临时名字；New-Item创建输出文件夹，-Force允许文件夹已存在；| Out-Null是不把创建目录的普通结果打印出来。它们属于PowerShell操作，不是Java源码。

最后一行开头的&表示“启动后面这个地址的程序”。引号把带空格的安装路径视作整体。

编译选项 这里的作用
--release 8 在当前编译器支持范围内约束为Java8的语法与标准API
-encoding UTF-8 按UTF-8读取源文件文字
-Xlint:all,-options 启用代码警告，仅关闭旧目标版本本身的选项提示
-d '...\out' 把编译产物放进指定输出目录
最后一个.java路径 本次要编译的源码

编译成功时javac可能一句话都不输出。 不要因为没有“恭喜成功”就以为它没工作。

紧接着执行下面这一整段：

if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -cp '.\my_code\flight_lab\out' FlightHello
}

$LASTEXITCODE在这里保存刚才外部程序的退出码，0通常表示正常完成；if这段是PowerShell判断，意思是“上一次编译成功才继续”。不要在编译和这个判断之间再启动别的外部程序，否则读到的可能不是编译器的状态。

-cp告诉启动工具去哪个位置寻找类，简称类路径。这里启动的是类名FlightHello，不写.class扩展名；它也不等于把源码路径原样再抄一遍。

现在应再次看到Hello, Java!。再执行：

Get-ChildItem '.\my_code\flight_lab\out'

应该找到：FlightHello.class。先不拿编辑器修改它：它是编译产物，源码才是你要编辑的内容。

手动例子先用英文输出，是为了专注编译和启动；下面中文实验优先走课程脚本。不同终端的中文配置需要另核对，不能用“英文正常”证明所有编码环节都已经相同。

动手⑨：走完“新建→保存→运行→找到产物”

完成8.6–8.9，观察下列四个事实：

  1. 编辑器里有你自己的FlightHello.java，源码中的类名一致。
  2. 源文件已经保存。
  3. 终端确实输出Hello, Java!。
  4. 手动编译的out目录里确实有FlightHello.class。

9. 中文、编码和乱码：不是一见方块就重装Java

9.1 同样的文件，为什么会读出怪文字

电脑保存的是字节数据。要把字变成字节，以及把字节还原成字，需要双方约定规则。

这类约定叫字符编码。类比一套“文字怎样写成数字、数字怎样读回文字”的规则本。

你用一套规则保存，对方用另一套不匹配的规则读取，就可能出现乱码。

这个比方不能理解成所有字符都固定占一个字节。不同编码使用的表示方法和长度可能不同。

9.2 先区分Unicode、UTF-8和字体

名字 先理解什么
Unicode 为字符等规定编号和相关规则的标准体系
UTF-8 将Unicode文本编码成字节的一种方式
GBK 中文环境里仍可能遇到的另一种字符编码
ASCII 早期常见的字符编码，覆盖基本英文等字符，不包含汉字
字体 决定字符用什么字形画到屏幕上

例如英文字母A在UTF-8里用一个字节表示；汉字中用三个字节表示。“一个汉字就是一个字节”不能作为通用结论。 这与Java中String.length()的计数规则也不是同一个问题，后面字符串课会分开讲。

如果字符成了别的乱字，先怀疑编码环节；如果部分符号只显示为方框，也可能是字体缺少对应字形。不要认为所有显示异常只有一个原因。

9.3 Java输出中文要经过几站

可以把这次输出当成一封经过几个站点的信：

你在编辑器里写中文
    ↓ 按某种编码保存
.java源文件
    ↓ 编译器按约定读取
程序中的文字
    ↓ 运行时写出字节
终端按自己的规则读取、显示
环节 本课程先采用的做法
源文件保存 UTF-8
javac读取源码 显式指定-encoding UTF-8
本机程序输出与控制台 优先由课程java.ps1配合UTF-8处理
文本文件的读写 输入输出课再明确指定读写编码

源码是UTF-8，不自动保证终端也按UTF-8显示。 JDK版本、命令解释程序、终端和启动方式都有可能影响实际表现。

9.4 chcp能说明什么，不能说明什么

在Windows终端里输入：

chcp

它会显示当前活动控制台代码页，常见结果有936或65001；65001对应UTF-8。不要假设所有中文Windows、所有终端的默认结果都相同。

修改控制台代码页也不等于把硬盘上的源文件转换成了UTF-8。对Windows PowerShell5.1等环境，仅改chcp也未必同时改变所有.NET控制台、管道和程序的编码处理。

初学时不必为了这一篇反复改系统区域设置。先使用已提供的脚本；确实遇到问题时，报告编辑器保存编码、实际启动命令和终端类型。

10. 改了代码，为什么还是旧结果

10.1 先记住这三个动作

修改 → 保存 → 重新编译并运行。

你改的是源码，不会因此把之前生成的每一个.class都同步改好。编译器要重新处理保存后的源码，启动时也要找到这次产生的类文件。

有些IDE会帮你自动编译，这是工具替你完成步骤；不能据此推断任意终端命令、任意目录也都会自动更新。

10.2 用一个小实验看见“旧”在哪里

假设你已经完成第8节的手动编译，out目录里有输出Hello, Java!的类文件。

如果你现在只修改源码中的文本，按 Ctrl+S，却只运行旧out目录里的类：

& "$jdk\bin\java.exe" -cp '.\my_code\flight_lab\out' FlightHello

它仍可能输出旧文字。这不是源码修改没生效，而是你根本还没把这个修改编译到正在运行的那份class里。

这里的$jdk沿用8.9节在同一个PowerShell会话中的设置。换了新终端，这个临时名字可能已经不存在，需要重新设置；不要把变量不存在误判成Java类文件损坏。

10.3 编译失败，也可能还留着上次的class

在自己实验文件里暂时删掉println语句后的分号：

System.out.println("我在学习Java")

重新编译应当失败。失败不会保证替你删除所有旧产物。 如果忽略错误，另外运行上次的class，就可能又看到旧输出。

课程java.ps1每次使用新的隔离输出目录，编译失败立即停下，就是为了减少这个误会。

动手⑪：故意错一次，再验证恢复

  1. 确保你改的是入门实验FlightHello.java，不是教材示例或已经交过的L01源码。
  2. 删掉一处分号并保存。
  3. 用课程脚本运行，记录第一条有效编译诊断，以及是否出现程序自己的输出。
  4. 恢复分号，保存，再运行。
  5. 看到正确中文输出后，才把“这次已恢复”记下来。

编译诊断里的路径、行号和措辞可能随环境变化；关注它是否指出你故意制造的错误。不要求和老师的英文/中文提示逐字相同。

10.4 遇到这些现象，先查哪一步

现象 优先核对 下一步
java不是可识别的命令 工具位置和PATH 用check-java.ps1检查，不直接断言没装JDK

术语先说清楚

  • JDK：开发Java的工具包，里面有编译器和运行工具。像做菜的一套厨具，不只是拿到成品。
  • JVM：执行Java字节码的虚拟机。可以理解成各个平台提供的“字节码执行员”；它不是完整的电脑模拟器。
  • JRE：Java运行环境这个概念，包括JVM及运行所需的库等。现代JDK的发行形式和书中旧版界面不同，本课程不另找一个“JRE下载”安装。
  • PATH：系统寻找命令的目录清单。命令找不到只表明搜索失败，不证明软件没安装。

先会两步运行

在某个示例目录的PowerShell中，手动执行（例：HelloJava.java）：

$jdk = 'C:\Program Files\Java\graalvm-jdk-21.0.12+7.1'
New-Item -ItemType Directory -Path .\out -Force | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 '-Xlint:all,-options' -d .\out .\HelloJava.java
if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -cp .\out HelloJava
}

javac把源文件变成.class；java按类名启动程序。-d指定编译产物目录；-cp指定从哪里找类；运行时写HelloJava，不带.class。--release 8在当前JDK允许的范围内约束Java8语法与标准API；它不会把JDK21变成JDK8。-Xlint:all,-options启用代码警告，仅关闭旧目标版本的选项提示。

正常学习优先用根目录的 java.ps1：它每次新建隔离输出目录，失败立即停，避免错跑旧class。示例无package且各有独立main，不要把所有课次一次编译到同一个目录。

需要程序参数时：.\java.ps1 -Source '路径\ArgsDemo.java' -ProgramArgs @('red','blue')。-CompileOnly只编译，不声称运行成功。脚本适用Windows PowerShell5.1或PowerShell7；其他系统可用上面同等的javac/java命令，路径按系统修改。

中文输入与输出

源码统一保存UTF-8；编译显式-encoding UTF-8。本机JDK21运行时可设置-Dstdout.encoding=UTF-8和-Dstderr.encoding=UTF-8；项目脚本同时临时设置控制台编码并在退出前恢复。输入示例使用键盘交互，不靠旧PowerShell默认编码的管道传中文。出现乱码时先记录终端、源文件编码和实际命令，别随意重装JDK。

2. 源码→编译→执行

你手写的HelloJava.java叫源代码，就是保存下来的程序文本。编译器javac先检查它是否符合规则，再生成常见后缀为.class的字节码。JVM执行字节码，完成输出等动作。类比同一份菜谱先整理成统一的操作单，再由不同厨房里的执行员完成；厨房仍需要合适的工具和原料。

HelloJava.java --javac--> HelloJava.class --java/JVM--> 屏幕输出

编译成功只说明通过了一部分规则检查，不能证明程序算对了。把2+3错写成2-3仍可能编译成功。

JDK是开发工具包，包含javac和运行工具；JRE是运行环境的概念。我们已有JDK21，不再找旧JRE安装包。java是启动工具，不等于整个Java平台。

4. 三类现象，三种判断

编译错误：工具不能把源码编译成功，例如少分号。运行时异常：已经启动，执行到不合法操作时报告问题，例如数组越界。逻辑错误：程序跑完，但不符合题意，例如长方形面积写成周长。这只是入门分类；程序也可能同时有多类问题。

跨平台是指兼容的字节码可以由各系统上的适配JVM执行，不是任意电脑不用安装东西就能跑，也不是依赖特定系统文件的程序必然通用。System.getProperty示例先当作“向运行环境查询信息”的现成工具，之后再讲对象和方法。

2. 编译命令逐项拆开

在某个源码目录中，按环境说明设置$jdk，再执行：

& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 -d .\out .\HelloJava.java
if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -cp .\out HelloJava
}

&让PowerShell启动引号中的程序；不是Java语法。-d是放编译产物的目录，-cp是运行时查找类的目录。类名在这里是HelloJava，运行时不写扩展名。$LASTEXITCODE记录上个外部程序的退出状态；这里等于0才继续，防止编译失败仍执行旧文件。

当前目录是相对路径的起点。Get-Location看位置，Get-ChildItem看文件。教材命令中的示例路径不能原样当成你电脑的真实地址。

3. 程序的名字要对应

命令行参数是在启动类名后给程序的数据，像把待办事项随启动请求一起交进去。ArgsDemo先只显示参数个数，不访问不存在的第一个参数；数组细节L10讲。

4. 读报错不要只看最后一行

这一课要解决什么问题

程序要记住人数、价格、姓名和真假条件。如何给数据起名，又避免把不合适的数据混用？

1. 先看程序外壳

public class VariableDemo {
    public static void main(String[] args) {
        int count = 3;
        System.out.println(count);
    }
}

class声明类；类可以组织程序，后面还会用来描述对象。方法是一段有名字、可被调用的操作；这里main是启动方法。先把public static void main(String[] args)当作完整模板使用：public表示可访问，static使启动时无需先创建该类对象，void表示不返回结果；第4章会用真正的调用解释它们。

花括号包住代码范围，分号结束语句。//到行末是注释，/* ... */是块注释，注释不会被执行，也不能随意嵌套。引号中的//属于文本，不会变成注释。

2. 变量与赋值

变量给运行中要用的数据起名，像贴着标签的格子。int count = 3声明类型、名字并给初值。count = count + 1是先取右边旧值计算，再把结果放回左边；不是数学里声称两侧永远相等。

类型规定可以存什么值及允许哪些操作。类比容器标签只是入门帮助；Java的引用变量并不直接把整个对象装进格子。

局部变量用之前必须确定已赋值：int count;本身合法，但直接输出尚未赋值的count会编译失败。不要把“局部变量未初始化”与“数组元素有默认值”混为一谈。

3. 常用类型先抓住用途

类型 适合的值 重点
byte/short/int/long 一定范围内的整数 首选int；很大的整数字面量加L
float/double 浮点数 首选double；float字面量常需f；许多小数不能精确表示
char 一个UTF-16代码单元 如'A'、'中'；不是任意一个完整Unicode字符
boolean true或false 不能拿0/1自动替代
String 一段文本 引用类型，不属于8种基本类型

字面量是直接写在源码里的值，例如42、3.5、'A'和"Java"。常量在本课用final int DAYS = 7表示赋值后不能再改的量，避免把固定意义散落成神秘数字。普通变量名用studentCount这类有意义的写法，常量名可用MAX_COUNT。

4. 范围、初始化与作用域

int范围是-2147483648到2147483647；存不下的计算不会自动变成long。运行VariableDemo观察最大值加1，它会绕回负数。不要套用C++有符号整数溢出的规则。

作用域指代码哪些位置可以使用一个名字。花括号内声明的局部变量通常只在相应范围可用；它不是对“这块数据在内存里什么时候消失”的完整描述。

这一课要解决什么问题

相同数字，为什么换个类型或括号就得到不同答案？先确定表达式怎样算，再给结果起名。

1. 整数除法发生在赋值之前

表达式是会计算出结果的组合，像一张小算式。7 / 2两侧是整数，结果是3；double x = 7 / 2只是把已经得到的3再转成3.0。要得到3.5，让运算本身含double：7 / 2.0。%是余数，不是百分比。

负整数除法向0截断，例如-7/2是-3，-7%2是-1。乘法和除法优先于加减，但涉及业务含义时主动加括号比硬背复杂优先级更清楚。

教材3.5.1还会用到Math这个数学工具类：Math.sqrt(9.0)得到平方根3.0，Math.pow(2.0, 3.0)得到8.0。这里的点表示调用该类提供的方法，不是小数点。Java中的^是按位异或，不是乘方；想算平方也可直接写x * x。本阶段只需按API说明调用，第4章再展开静态方法。

2. 类型转换不能修复已经算坏的结果

转换是把值用另一种类型表示。强制转换写成(int)3.9，结果是3，丢掉小数部分，不是四舍五入。

int count = 1_000_000;
long wrong = count * count;
long right = (long) count * count;

第一种先按int相乘并溢出，装进long也救不回来；第二种在乘之前就让计算使用long。即使int转double通常能表示，long转double仍可能丢精度，不能认为“目标容量大就什么都不丢”。

+=等组合赋值有隐式转换规则，例如short s=1; s+=1可行，直接s=s+1不一定可行。本课优先写清楚表达式，不靠隐式转换省字。i++先给出旧值再加1，++i先加1再给出值；在独立一行作为更新时相同，避免堆在一个复杂算式里。

3. 比较与短路

==比较是否相等，=赋值；!=不等。&&表示同时成立，||表示至少一个成立，!取反。它们处理boolean，不把整数自动当真假。

短路是已经知道结果时不再执行右边，像两道门中第一道明确不通就不必检查第二道。divisor != 0 && 10 / divisor > 1在除数为0时不会计算除法。&和|用于boolean时会计算两边，也可用于整数位运算；与&&、||不要混用。

三目表达式score >= 60 ? "pass" : "retry"根据条件选一个值。位运算的& | ^ ~ << >> >>>先知道作用在二进制位；本课扩展阅读，不要求用它写业务题。3.5.9枚举先理解“给有限选项起名字”，详细设计在第5章。

1. String与不变性

字符串是一段文本，例如"Java"；Java用String类表示它。方法调用是请求某个对象或类完成一个操作，写法先读成“对象.操作(参数)”。参数是交给操作的数据，返回值是操作得到的结果。

String name = "  Java  ";
name.trim();
System.out.println(name);
name = name.trim();

不可变表示已经建立的String对象内容不会被这些操作改写。trim()返回去掉首尾相应空白的新结果；不接住结果，name还是原来的引用。这里的引用可类比找到对象的凭证，但不是能自己做地址算术的指针。重新给变量赋值与修改原对象不是一回事。

2. 内容比较用equals

a.equals(b)比较字符串内容；引用上的==比较是否指向同一对象。一些字面量可能共享对象，导致==偶尔看似能比内容，不能因此拿它判断用户输入的文本。

空字符串""是存在但没有内容的String；null是没有指向对象。null.length()会报异常，不是0。已知常量时可写"yes".equals(answer)，answer为null也不会因为调用者为null而报错；不要因此认为所有null操作都安全。

3. 下标从0，终点不包含

"Java".charAt(0)得到'J'。substring(1,3)取下标1、2，得到"av"；结束下标不包含，像从起点格子走到终点前停下。length()是代码单元个数，合法charAt下标从0到length()-1。空串没有可取的第0个元素。

"score="+80+5会先拼接成文本再继续拼接，得到score=805；要先求和写"score="+(80+5)。

4. Unicode与StringBuilder

String内部使用UTF-16代码单元语义；emoji等补充字符可能占两个代码单元。运行UnicodeDemo，比较length和codePointCount。码点是Unicode给字符分配的编号；它与“视觉上一个字形”也不总是一对一。先知道边界，本课不要求实现通用字素切分。

反复拼很多片段时，可以用StringBuilder这个可变文本构建工具，像先在草稿板上逐段追加，最后toString()交出String。append会改变构建器，区别于String上的不可变操作。先运行示例，不要求在还没学循环时优化所有字符串。

这一课要解决什么问题

同样的程序，需要按年龄或分数选择不同操作。怎样写出互斥又没有漏掉临界值的规则？

1. if是按条件选择执行

条件是计算结果为boolean的表达式，像一道决定往哪走的路口。if (score >= 60) { ... } else { ... }只选一个分支。条件不是任意整数；if(1)不能照搬到Java。

if (score < 0 || score > 100) {
    System.out.println("invalid");
} else if (score >= 90) {
    System.out.println("excellent");
} else if (score >= 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}

这是一条互斥的条件链：前一项成立就不再测试后面的项。顺序是规则的一部分；先测>=60再测>=90，90分也会先进入pass。多个独立if不是同一回事，可能重复打印。

2. 先写范围表再写代码

把分数切成：小于0、0–59、60–89、90–100、大于100。分界处用-1、0、59、60、89、90、100、101验证。边界测试就是专门在这些接缝检查，像检查两块拼图之间有没有缝或重叠；只测75分无法证明60分正确。

判断“18至25岁，包含两端”，写age >= 18 && age <= 25，不能写数学式18 <= age <= 25。同类条件先用括号表达清楚，不要依靠缩进猜关联。

3. 代码块与作用域

代码块是花括号包围的一组语句。局部变量通常从声明后到所属块结束可用，块里的同名声明还有限制。写入块内不等于声明了一个到处可用的名字。

if (ready) {
    int count = 3;
    System.out.println(count);
}

块外用count会编译失败。初学时总给分支加花括号，避免只控制一条语句时误读。不在if括号后随手加分号：if(condition);可能让后面的语句无条件执行。

这一课要解决什么问题

输出100行、累加一组数或反复读取输入，不应该复制粘贴100份代码。循环用一段规则表达重复。

1. while的三个要素

循环是在条件满足时重复执行代码，像按清单逐件检查货物。务必找出：初始状态、继续条件、如何前进。

int i = 1;
int sum = 0;
while (i <= 5) {
    sum += i;
    i++;
}

逐轮写表：进入时i=1，sum变成1，i变成2；下一轮sum变成3。退出时i=6，sum=15。遗漏i++可能永远满足条件。迭代就是循环的一轮，不是某个新的Java关键字。

do { ... } while(condition);至少执行一次，while可能一次不执行。读教材投资示例时先看状态怎么变化，不急于套金融背景；double只用于教学计算，不据此推出财务金额都适合浮点数。

2. for把计数规则放在一起

for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

顺序是初始化一次→检查条件→循环体→更新→再检查。这里i的作用域限于for及其循环体。需要恰好n次且从0编号，常用i=0; i<n; i++；需要1到n的值，常用i=1; i<=n; i++，不要不看目的机械替换符号。

3. 初值与空情况

累加从0开始，是因为没有任何数时总和为0。求最大值不能总从0开始：若输入全负数，会得到不存在的0；数组课将处理这一点。n=0时循环可能不进入，程序仍需给出题目规定结果。

嵌套循环像钟表的时针与分针：外层每前进一次，内层完成一整轮。NestedDemo的两行三列共执行6次输出。不要只把两个上限相加；同时也别把一切嵌套循环都不加条件地说成固定平方复杂度。

这一课要解决什么问题

有限的几个选项怎样分派？循环中想提前结束怎么办？整数或小数超出基本类型能力时用什么？

1. switch按一个值选择分支

多重选择是按同一个值匹配若干选项。传统Java8写法中，case标出选项，default处理未匹配情况，break结束当前switch。没有break时可能继续执行后面的语句，叫贯穿；它有时是有意合并分支，但初学要明确标注。

switch (day) {
    case 6:
    case 7:
        System.out.println("weekend");
        break;
    default:
        System.out.println("weekday");
}

示例假定day在1–7内；若任务要求验证范围，必须先处理0、8等非法值。switch适合离散选项，不直接写case score >= 60。新版箭头语法另行补充，首批练习采用教材风格。

2. break和continue

循环里的break结束最内层对应循环；continue跳过本轮剩余部分，转入下一轮。for中的continue会先走更新部分；while里若把更新放在continue之后，可能永远跳过更新导致死循环。

不要说continue“退出循环”；它只退出这一轮。多层嵌套和带标签跳转先会读，本课选做，不要求靠标签重写普通题。

3. BigInteger与BigDecimal

大整数BigInteger用于超出long范围的整数，仍受可用内存与资源限制；不是无限大。new BigInteger("...")从十进制文本建立值。相加写a.add(b)，不能写a+b。

十进制数BigDecimal适合明确控制十进制表示与舍入。需要精确表示0.1时用new BigDecimal("0.1")，避免先把0.1变成近似double再交给构造器。BigDecimal.valueOf(0.1)也是常见选择，但必须分清它与new BigDecimal(0.1)。

这些数值对象的运算返回结果，a.add(b)不改原a，需要保存结果。除法不一定有有限小数，1/3要指定保留位数和舍入规则，如divide(three,2,RoundingMode.HALF_UP)；本课用它观察“保留2位按规则取舍”，不泛称所有金额都采用同一规则。equals还比较scale等表示细节，数值比较用compareTo并检查是否为0。

这一课要解决什么问题

保存一组成绩并统计，而不是为每个人写一个变量。本课结束做一个有明确输入输出的成绩统计器。

1. 数组是编号的一排同类型元素

数组按编号组织一组固定长度元素，像编号从0开始的储物格。int[] scores = new int[3]建立3个int元素，默认各为0；变量scores保存数组引用。合法下标是0、1、2，scores.length是3，数组length不是方法，没有括号。

引用共享：int[] b = scores复制引用，像两张凭证找到同一排格子，改b[0]会影响从scores看到的内容。Arrays.copyOf建立另一份数组。对引用数组做浅拷贝时元素仍可能共享对象；当前先对int数组验证。

for (int i = 0; i < scores.length; i++) {
    scores[i] += 1;
}
for (int score : scores) {
    System.out.println(score);
}

增强for适合依次读取元素；for(int score:scores){score++;}只改本轮局部变量，不会把int数组元素改掉。需要下标更新时用普通for。

2. 不存在的位置不是“随便一个值”

访问length位置会产生越界异常。空数组new int[0]合法，但没有第0项；它与null不同。统计平均值先确认数量大于0；最大值对非空数组可从第一项初始化，避免把全负数误判为0。

3. 排序与查找有前提

Arrays.sort会改变原数组顺序；想保留原始录入顺序先复制。Arrays.binarySearch要求相应区间按同样规则有序；未找到时返回负数编码，不能把所有负结果都解释成固定-1，也不能把返回值直接当成绩。

4. 二维数组是数组的数组

int[][] grid={{1,2},{3,4,5}}两行长度不同。外层grid.length是行数，内层每次读grid[row].length；不能假设每行都等于第0行长度。不规则数组就是这种不等长情况。NestedArrayDemo演示遍历；不要求现在写高维算法。

命令行参数String[] args也属于数组；访问args[0]前检查长度。它与Scanner读键盘是不同的数据入口。

5. 阶段项目的边界

成绩统计器先读数量n，约定0–100；n=0打印no data并结束。n>0再读n个0–100的整数成绩，保留录入顺序，输出总分、两位小数平均分、最大值、最小值、及格人数，再另行打印排序副本。题目规定有效的成绩输入，不把字母恢复或文件保存作为本阶段卡关项。

先写输入/输出样例，再拆步骤：分配数组→读入→统计→复制排序→输出。算法在这里就是为解决任务安排的一系列步骤，不是背某种高深公式。

术语表 · 先懂作用，再记名称

词 一句话解释 为什么需要／类比
编译 将源码检查并转换为另一种可执行表示 像先检查配方并翻译成执行清单；不保证配方符合你的本意
字节码 Java编译器常见的输出指令格式 交给JVM执行；不是本机CPU直接执行的全部机器码
JVM 执行Java字节码的虚拟机 各平台安装合适的执行环境
JDK Java开发工具包 含javac、java等，像开发工具箱
类 一种程序组织与对象描述方式 当前先作为程序外壳；第4章展开
对象 按某个类建立的具体实例 类像说明，具体对象像按说明制作的一份物品
方法 类中有名字、可以被调用的一段操作 避免每次重新描述操作；第4章系统讲定义
main 当前命令行程序的启动入口方法 JVM启动这个类时从它开始
变量 类型、名字和值之间的一种绑定 给运行中的数据起名；不是数学里永不改变的等号
类型 规定值的种类和允许的操作 防止把不合适的东西混用；有些错误能编译前发现
字面量 源码中直接写出的值 如42、3.5、'A'、"hi"、true
表达式 能计算出一个结果的组合 如price*count，用计算结果参与更大任务
引用 用于访问对象的值 类比找到对象的凭证；不是C++可做地址算术的指针
null 引用没有指向对象的特殊值 不等于空字符串或长度为0的数组
索引／下标 指出序列中的第几个位置 从0开始，像一排格子的编号
异常 程序运行过程中报告异常情况的机制 如访问不存在的位置；不等于所有错误
API 库提供给调用者使用的功能约定 像工具说明：名字、参数、返回值和限制
作用域 代码中一个名字可以被使用的范围 不是对象在内存中存活多久
边界测试 专门检查最小、最大、刚好临界的情况 常能发现平常输入隐藏的问题
UTF-8 把文字编码成字节的一种方式 保存、读取双方使用一致规则才能正确显示

public class RaggedSum {
    public static void main(String[] args) {
        int[][] values = {{1, 2}, {3, 4, 5}, {}};
        int sum = 0;
        for (int row = 0; row < values.length; row++) {
            for (int column = 0; column < values[row].length; column++) {
                sum += values[row][column];
            }
        }
        System.out.println("sum=" + sum);
    }
}
ScoreStats.java
import java.util.Arrays;
import java.util.Locale;
import java.util.Scanner;
public class ScoreStats {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        if (n < 0 || n > 100) {
            System.out.println("invalid count");
            return;
        }
        if (n == 0) {
            System.out.println("no data");
            return;
        }
        int[] scores = new int[n];
        for (int i = 0; i < n; i++) {
            scores[i] = in.nextInt();
        }
        int sum = 0;
        int maximum = scores[0];
        int minimum = scores[0];
        int passed = 0;
        for (int score : scores) {
            sum += score;
            if (score > maximum) { maximum = score; }
            if (score < minimum) { minimum = score; }
            if (score >= 60) { passed++; }
        }
        int[] sorted = Arrays.copyOf(scores, scores.length);
        Arrays.sort(sorted);
        System.out.println("original=" + Arrays.toString(scores));
        System.out.println("sum=" + sum);
        System.out.printf(Locale.US, "average=%.2f%n", sum / (double) n);
        System.out.println("max=" + maximum);
        System.out.println("min=" + minimum);
        System.out.println("passed=" + passed);
        System.out.println("sorted=" + Arrays.toString(sorted));
    }
}
