学完要能做什么

能处理输入取消、空文本和有效内容；解释模式对话框返回与无模式回调；选择文件后再验证内容；按组件树与事件路线定位GUI错误，区分模型检查和真实桌面测试。

点取消以后，为什么原来的课程名也被改掉了

输入框里正在编辑的内容与正式业务数据应分开。像填写申请草稿：写在纸上的字不等于已经递交，只有确认并通过规则才提交；类比边界是有些软件选择即时生效，这时需要明确预览/恢复规则，不能把“取消”标签贴上去就以为自动回滚。

JOptionPane提供消息、确认、选项、输入几类标准对话框。消息只报告事实，确认返回选择常量，选项返回索引或关闭值，输入可能返回null。选项类型决定按钮组合，消息类型决定图标风格；警告图标不会替你验证输入，也不会自动保护原数据。

import java.awt.EventQueue;
import javax.swing.*;
public class InputCommitRoute {
    static String accept(String draft) {
        if (draft == null) return "cancel";
        String value = draft.trim(); return value.isEmpty() ? "empty" : value;
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) {
            System.out.println(accept(null)); System.out.println(accept("  ")); System.out.println(accept(" 数组 "));
        } else EventQueue.invokeLater(() -> {
            JFrame f = new JFrame("草稿与提交"); JLabel name = new JLabel("循环"); JButton change = new JButton("改名");
            JPanel p = new JPanel(); p.add(name); p.add(change); f.add(p);
            change.addActionListener(e -> {
                String draft = JOptionPane.showInputDialog(f, "输入课程名", name.getText());
                if (draft == null) return;
                String result = accept(draft);
                if (draft.trim().isEmpty()) JOptionPane.showMessageDialog(f, result); else name.setText(result);
            });
            f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setSize(360, 140); f.setVisible(true);
        });
    }
}

默认打开主窗口，点击改名；取消或右上角关闭保持原名，输入空格报告empty，只有非空名字提交。--check不用弹框，依次把null、空格、数组送给同一个accept函数，输出cancel/empty/数组；这是提交规则检查，不是实际对话框取消按钮的桌面测试。

null、空串和名字分别走哪条路

showInputDialog暂停本次调用的后续语句，待模式对话框关闭后返回；先检查null，再trim，不能对取消结果直接trim导致NullPointerException。oldName是调用前的业务数据，只有accepted才setText。把“读取草稿”与“保存正式值”放在不同语句，出错时就能指出哪一步过早写回。

返回内容 读法 能否提交 原名
null 取消/关闭，没有输入结果 否 保留
" " 有字符串，但规则不接受空名 否 保留
" 数组 " 去边空白后有效 是 变数组

只改一处：把null判断移到trim之后，预测取消时失败阶段，再运行看异常。独立任务：增加最长12字符的规则；先定清这里用String.length计UTF-16单位，不冒称所有语言的12个可见字形。验证12、13和取消，不用PDF补关键步骤。

确认框用choice == JOptionPane.YES_OPTION只允许明确肯定，不写choice != NO_OPTION，后者可能把取消和关闭也算同意。showOptionDialog返回你提供数组中的索引，关闭是CLOSED_OPTION；不要把索引1当成“永远是取消”，要和本次选项对应。不同方法复用某些整数值，含义应由调用的方法与选项组合决定。

“阻塞调用”不等于整个界面线程死掉

模式对话框会阻止受其模态范围影响的窗口输入，本次setVisible(true)要到隐藏/销毁后才返回；Swing仍处理对话框自身事件，否则连确定也按不下。无模式的setVisible立即返回，后续不能当作用户已经填完，应通过确认按钮的回调交出数据。模态范围取决于DOCUMENT/APPLICATION/TOOLKIT等类型，不把教材简化说法“其他所有窗口都锁住”当普遍规则，见Dialog API。

JDialog的owner是所属窗口关系，不是装进主窗口布局的小组件；JFileChooser/JColorChooser是组件，也提供创建/显示对话框的方法，不能因此说它们继承JDialog。隐藏setVisible(false)可复用对象，dispose释放本地窗口资源；重复显示时每次重置本次accepted，避免上一轮确认标记残留。

自定义对话框：本轮草稿先通过，再交回调用者

import java.awt.BorderLayout;
import java.awt.Dialog;
import java.awt.EventQueue;
import javax.swing.*;
public class NameDialogTransaction {
    static class Edit {
        final JPanel panel = new JPanel(new BorderLayout()); final JTextField field = new JTextField(14);
        final JLabel tip = new JLabel("输入非空名字"); final JButton ok = new JButton("确定"), cancel = new JButton("取消");
        boolean accepted; Runnable close = () -> { };
        Edit() {
            JPanel buttons = new JPanel(); buttons.add(ok); buttons.add(cancel);
            panel.add(field, BorderLayout.NORTH); panel.add(tip); panel.add(buttons, BorderLayout.SOUTH);
            ok.addActionListener(e -> { if (field.getText().trim().isEmpty()) { tip.setText("empty"); return; } accepted = true; close.run(); });
            cancel.addActionListener(e -> close.run());
        }
        void reset(String old) { accepted = false; field.setText(old); tip.setText("输入非空名字"); }
        String show(JFrame owner, String old) {
            reset(old); JDialog dialog = new JDialog(owner, "编辑草稿", Dialog.ModalityType.APPLICATION_MODAL);
            close = dialog::dispose; dialog.setDefaultCloseOperation(JDialog.DISPOSE_ON_CLOSE); dialog.add(panel);
            dialog.getRootPane().setDefaultButton(ok); dialog.pack(); dialog.setLocationRelativeTo(owner); dialog.setVisible(true);
            return accepted ? field.getText().trim() : null;
        }
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) EventQueue.invokeAndWait(() -> {
            Edit edit = new Edit(); edit.reset(" "); edit.ok.doClick(0); System.out.println(edit.accepted);
            edit.field.setText(" 数组 "); edit.ok.doClick(0); System.out.println(edit.accepted + ":" + edit.field.getText().trim());
            edit.reset("数组"); edit.cancel.doClick(0); System.out.println(edit.accepted);
        }); else EventQueue.invokeLater(() -> {
            JFrame f = new JFrame("草稿事务"); JLabel name = new JLabel("循环"); JButton button = new JButton("改名"); Edit edit = new Edit();
            button.addActionListener(e -> { String result = edit.show(f, name.getText()); if (result != null) name.setText(result); });
            JPanel p = new JPanel(); p.add(name); p.add(button); f.add(p); f.setSize(360, 150); f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setVisible(true);
        });
    }
}

默认窗口按改名弹出APPLICATION_MODAL对话框。Edit是普通组合对象，panel装字段和按钮；show创建owner明确的JDialog，确定按钮先验证，再accepted=true并dispose。关闭和取消都不走提交。close是Runnable接口引用，当前读法“可无参数调用run的一项动作”；创建面板时默认空动作，装进对话框后替换为dialog::dispose。它不是后台线程。

--check只操作组件：空文本后false，合法名后true:数组，重置后false。真实窗口实验按“确认数组→再打开→输循环→取消”，主标签应仍数组；若把reset中的accepted=false删掉，解释第二轮为何可能拿旧成功状态。独立任务：增加长度上限并保证被拒绝时仍可继续编辑。

文件选择：选择路径与读写文件分两步

File对象表示路径，不是文件内容，new File不会新建磁盘文件。JFileChooser先选择路径，只有返回APPROVE_OPTION才取getSelectedFile；复用选择器时旧selectedFile可能仍存在，因此不能略过本次返回值。过滤器让用户更容易找到文件，不是安全边界或内容解码器。

import java.awt.EventQueue;
import java.io.File;
import javax.swing.*;
import javax.swing.filechooser.FileNameExtensionFilter;
public class FileChoicePolicy {
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            FileNameExtensionFilter filter = new FileNameExtensionFilter("文本 (*.txt)", "txt");
            if (args.length > 0 && args[0].equals("--check")) {
                System.out.println(filter.accept(new File("README.TXT"))); System.out.println(filter.accept(new File("image.png"))); return;
            }
            JFileChooser chooser = new JFileChooser(); chooser.setFileFilter(filter); chooser.setAcceptAllFileFilterUsed(false);
            JFrame f = new JFrame("只选择，不写入"); JLabel path = new JLabel("尚未选择"); JButton choose = new JButton("选择文本");
            choose.addActionListener(e -> {
                if (chooser.showOpenDialog(f) != JFileChooser.APPROVE_OPTION) return;
                File file = chooser.getSelectedFile();
                if (file != null && file.isFile() && filter.accept(file)) path.setText(file.getPath());
                else JOptionPane.showMessageDialog(f, "请选择普通文本文件");
            });
            JPanel p = new JPanel(); p.add(choose); p.add(path); f.add(p); f.setSize(600, 150); f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); f.setVisible(true);
        });
    }
}

默认打开主窗口，选择后只显示路径，不读取也不写入；取消保留原标签。--check在EDT中检查过滤策略，README.TXT=true、image.png=false。FileNameExtensionFilter支持大小写后缀，目录也接受以便浏览；本程序批准后另以isFile确认普通文件。保存对话框只收集目标路径，不会替你写文件、补后缀或完成覆盖确认，见JFileChooser API。

只改过滤扩展txt为md，预测README.TXT不再通过；独立任务：允许txt/md两种。自定义FileView返回null表示采用默认显示；Boolean isTraversable的null是“不指定”而不是false，回忆包装类三种状态。附件用setAccessory安装；监听选择变化用JFileChooser.SELECTED_FILE_CHANGED_PROPERTY.equals(event.getPropertyName())比较内容，不沿用教材p564 / PDF p582的字符串==写法。预览还要检查null、可解码格式及正尺寸，长文件解码不要占住EDT（L53学习后台工作）。

import java.awt.Color;
import java.awt.EventQueue;
import javax.swing.*;
public class ColorCommitRule {
    static Color choose(Color old, Color selected) { return selected == null ? old : selected; }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) {
            System.out.println(choose(Color.WHITE, null).equals(Color.WHITE)); System.out.println(choose(Color.WHITE, Color.BLUE).equals(Color.BLUE));
        } else EventQueue.invokeLater(() -> {
            JPanel panel = new JPanel(); panel.setBackground(Color.WHITE); JButton change = new JButton("背景色"); panel.add(change);
            JFrame f = new JFrame("确认才换色"); change.addActionListener(e -> {

}

先看组件树，再看通知路线，最后检查真实桌面

组件不见了先问是否已加入正确容器、是否visible、布局是否给了正尺寸；按钮没反应先问监听是否注册、是否enabled、事件能否到达、业务是否改变模型；显示没更新再查是否更新正确实例、是否在EDT。按顺序检查比随机加repaint更容易定位。

import java.awt.Component;
import java.awt.Container;
import java.awt.EventQueue;
import javax.swing.*;
public class ComponentTreeWalk {
    static void walk(Component c, String indent) {
        System.out.println(indent + c.getName());
        if (c instanceof Container) for (Component child : ((Container) c).getComponents()) walk(child, indent + "  ");
    }
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            JPanel root = new JPanel(); root.setName("root"); JPanel row = new JPanel(); row.setName("row");
            JLabel label = new JLabel("课程"); label.setName("label"); row.add(label); root.add(row); walk(root, "");
        });
    }
}

输出只含我们给组件设置的name与层次，不依赖观感内部组件数量。for递归读Container子组件，缩进每层两空格；不是把Java类继承树打印出来。只把字段从内层移动到外层，预测树路径变化；独立任务：给自己表单的重要组件setName，找出同一区覆盖添加造成的错误。

教材12.8的反射事件跟踪结合L24/L29，可用Introspector取得事件集合、动态代理转发监听调用。不要直接吞掉所有反射异常后宣称“无事件”：先记录失败的组件和监听类型；代理还要处理Object方法与可能无参数的方法。入门排错先加明确的ActionListener日志，避免调试器比业务更复杂。

Robot面向真实桌面输入：构造Robot，获取目标组件getLocationOnScreen坐标，mouseMove→mousePress→mouseRelease；键盘也必须按下后释放。等待界面空闲用waitForIdle，不能在EDT调用它；控制脚本在非EDT运行、Swing状态读取通过invokeAndWait回EDT。新代码用InputEvent.BUTTON1_DOWN_MASK而非教材旧MASK常量。不应照抄固定屏幕(220,40)就声称点到了本机按钮；多显示器、缩放、遮挡、焦点都可能改变结果。

本课自动检查不发送全局按键/鼠标、不截取其他应用，Robot部分是选读操作原理，未自动化执行。你可在专门测试桌面按书本p576–579 / PDF p594–597实验。模型doClick、合成组件事件、离屏绘制、真实窗口点击各验证不同层次，不能互相冒充。第14章再解释线程等待，届时可完善专用桌面测试。
