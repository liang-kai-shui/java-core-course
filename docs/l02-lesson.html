这一课要解决什么问题

按运行按钮出问题时，你需要知道按钮背后执行了什么。先会手动两步运行，再用便捷脚本。

1. 工具在，但命令可能找不到

PATH是终端找命令时查找的目录列表，像通讯录。没有登记电话号码不等于那个人不存在。本机JDK21已安装，但当前终端直接找不到java和javac；因此课程脚本读取项目配置中的完整路径，不改系统环境。

先在根目录执行.\check-java.ps1，记录实际版本；再执行README的HelloJava命令。PowerShell若限制脚本，使用README给出的单次powershell.exe -ExecutionPolicy Bypass -File ...入口，无需更改全局策略。

2. 编译命令逐项拆开

在某个源码目录中，按环境说明设置$jdk，再执行：

& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 -d .\out .\HelloJava.java
if ($LASTEXITCODE -eq 0) {
    & "$jdk\bin\java.exe" -cp .\out HelloJava
}

&让PowerShell启动引号中的程序；不是Java语法。-d是放编译产物的目录，-cp是运行时查找类的目录。类名在这里是HelloJava，运行时不写扩展名。$LASTEXITCODE记录上个外部程序的退出状态；这里等于0才继续，防止编译失败仍执行旧文件。

当前目录是相对路径的起点。Get-Location看位置，Get-ChildItem看文件。教材命令中的示例路径不能原样当成你电脑的真实地址。

3. 程序的名字要对应

先采用一文件一个public class的约定：HelloJava.java里面是public class HelloJava。大小写也要对应。main必须按当前模板准确写为public static void main(String[] args)；写成Main是不同名字。

命令行参数是在启动类名后给程序的数据，像把待办事项随启动请求一起交进去。ArgsDemo先只显示参数个数，不访问不存在的第一个参数；数组细节L10讲。

4. 读报错不要只看最后一行

编译诊断通常包含文件、位置、说明。先读第一条有意义的错误，再定位原语句；后面许多诊断可能只是前一处错误引发的连锁结果。

error_lab/MissingSemicolon.java和WrongFileName.java预期编译失败；MissingMain.java可以编译，但启动失败；RuntimeCrash.java在运行时报告异常；WrongFormula.java正常结束但面积算错。它们是实验标本，不是待修复的课程样例。复制到my_code再修，保留原标本。

动手实验

  1. 编译HelloJava后在my_code副本中故意写错；确认新编译失败时课程脚本不会输出上次的“你好，Java！”。
  2. 用-ProgramArgs @('red','blue')运行ArgsDemo，再用无参数运行，比较结果。
  3. 按error_lab/README逐个观察失败阶段，记录完整诊断。不要把5个错误标本一起编译。

本课过关

能解释两步命令，自己定位一处文件名问题；能保留原始错误证据、修复自己的副本并重新运行；不把运行旧class当作修复成功。
