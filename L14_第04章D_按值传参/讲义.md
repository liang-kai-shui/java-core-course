## 1. 参数是新的局部格子：先只传一个int

你想让一个方法把计数乘3，方法里明明显示21，返回后却仍是7。先不用“按值”这个词解释一切，把调用的三步展开：求实参表达式的值；用这个值初始化形参；执行方法体。

可以把它想成填写申请表时把数字7抄到柜台的办理单。柜台把自己纸上的7改21，不会隔空改你手中的原表。类比边界：这里只解释两份局部值，不用纸张数量推算JVM具体内存布局，也不把方法返回理解成一张固定物理纸被销毁。

```java
public class ParameterFrames {
    static void triple(int received) {
        System.out.println("inside-before=" + received);
        received = received * 3;
        System.out.println("inside-after=" + received);
    }
    public static void main(String[] args) {
        int original = 7;
        triple(original);
        System.out.println("main-after=" + original);
    }
}
```

先预测三行，再在课程根目录PowerShell输入：

```powershell
.\java.ps1 -Source './L14_第04章D_按值传参/code/ParameterFrames.java'
```

应是inside-before=7、inside-after=21、main-after=7。static void triple(int received)从左往右读：属于类的可直接调用方法、不返回业务结果、名字triple、形参类型int且名字received。triple(original)括号里是实参表达式；这次求值为7，不是把名叫original的变量格子交给方法。

| 时刻 | main.original | triple.received | 下一步 |
|---|---:|---:|---|
| 调用前 | 7 | 还没建立本次形参 | 求实参值7 |
| 进入方法 | 7 | 7 | 两个独立局部格子 |
| 乘3后 | 7 | 21 | 只给received赋值 |
| 方法返回 | 7 | 本次形参不再可用 | main继续打印自己的original |

把received改名为original会不会改变规则？不会，变量归属取决于作用域，不靠名字是否一样。为了易读，本例刻意用两个名字。把方法中的乘3单独改乘4，预测inside-after=28而main仍7；如果你同时把main初值改了，就无法单独观察哪处修改造成差别。

独立小任务：写void setToZero(int number)，在main以9调用并分别在方法内、调用后打印。应是内0、外9。若你想让外部变0，要把结果返回并在main赋值，不能靠给形参改名达到目的。

## 2. 引用也复制：对象可以只有一个

现在把int换成一个可修改的计数对象。Java仍然复制实参的值，只不过这个值是引用。引用让你找到对象，不等于对象本身，也不包含一份字段的自动深复制。

类比你把仓库取货号复印给同事：同事凭副本找到同一批货并增加数量，你再去看当然也见到新数量。边界是Java引用不能任意加减形成地址，也不让你直接读取操作系统内存；这里只借取货号说明多份引用与同一对象。

```java
public class SharedCounterEdit {
    static void addThree(VisitCounter received) { received.add(3); }
    public static void main(String[] args) {
        VisitCounter original = new VisitCounter(5);
        VisitCounter alias = original;
        System.out.println("before=" + original.get());
        addThree(original);
        System.out.println("original=" + original.get());
        System.out.println("alias=" + alias.get());
    }
}
class VisitCounter {
    private int value;
    VisitCounter(int value) { this.value = value; }
    int get() { return value; }
    void add(int amount) { value += amount; }
}
```

输出before=5、original=8、alias=8。VisitCounter是本文件另一个非public业务类，不需要自己的main；公开启动类SharedCounterEdit决定文件名。get返回当前字段值，add修改对象里的字段，private不妨碍类自己的方法维护状态。此小模型只用5加3展示传参，不把它冒称完整业务范围校验。

```text
main.original ─┐
main.alias ────┼──→ 计数对象A：value=5，调用add后为8
形参received ─┘
```

三根箭头是三份引用值，不是三个计数对象。received.add(3)先沿箭头找到A，再由add把A.value加3；不是对received本身赋一个新引用。方法返回后形参不再能直接访问，main两份引用仍找到A。

| 动作 | original指向 | alias指向 | A.value |
|---|---|---|---:|
| new后 | A | 未声明 | 5 |
| alias=original后 | A | A | 5 |
| addThree进入 | A | A | 5 |
| received.add(3)后 | A | A | 8 |
| 方法返回 | A | A | 8 |

只把alias=original改成alias=new VisitCounter(5)。现在alias指向独立对象B，输出最后一行应alias=5。两个对象初值一样不代表身份相同；这是E3的基础。运行命令把前一示例路径末尾换SharedCounterEdit.java，每个程序分别编译，不能把多个public启动类拼成一个文件。

独立小任务：创建两个计数对象，给第一个再起别名，只对别名调用add。画出谁会看到变化，说明这与方法参数是否按值是两个问题。

## 3. 形参换了取货号，调用者手里的那份不跟着换

最容易混淆的是下面这句：received=new RebindCounter(99)。等号左侧是形参引用变量，右侧new产生一个新对象的引用。这里改的是形参格子，根本没有沿原引用去改旧对象字段。

```java
public class ReferenceRebinding {
    static void replace(RebindCounter received) {
        received = new RebindCounter(99);
        System.out.println("inside=" + received.get());
    }
    public static void main(String[] args) {
        RebindCounter original = new RebindCounter(5);
        System.out.println("before=" + original.get());
        replace(original);
        System.out.println("after=" + original.get());
    }
}
class RebindCounter {
    private final int value;
    RebindCounter(int value) { this.value = value; }
    int get() { return value; }
}
```

输出before=5、inside=99、after=5。这不是“参数传递失败了一半”。进入replace时original和received都指A；创建B后只让received指B，original仍指A。RebindCounter.value为final，构造后不改字段，更能看清这是两个对象。

```text
进入时： main.original → A(5) ← received
赋值后： main.original → A(5)    received → B(99)
返回后： main.original → A(5)    本次received不再可用
```

原A没有被B“覆盖”，只是其中一根箭头改了方向。B若没有其他可达引用，后续可能成为可回收对象；这不代表方法返回瞬间一定发生垃圾回收，也不需要在这里调用System.gc验证。

只把new里的99改为0，inside变0，after仍5。若把这一句改成旧可变对象上的setter，那是另一种操作，会改变共享对象状态；必须在图上标字段变化，不能只笼统写“方法里面变了”。本例类型没有setter，故意把两种能力分开。

独立小任务：解释为什么void replace(Scanner in)里重新new Scanner不能让调用者的Scanner变量自动换掉。无需实际多开键盘扫描器，照这个引用图推演即可，避免把资源所有权问题也混进实验。

## 4. 想让调用者获得新对象：返回，再由调用者决定赋给谁

方法里new对象有用，但得把引用交出去。return是把结果交回调用处；调用者的等号才是写入调用者变量的动作。两步缺一，原引用格子都不会自动换目标。

```java
public class ReturnedReference {
    static NextCounter nextCopy(NextCounter received) { return new NextCounter(received.get() + 1); }
    public static void main(String[] args) {
        NextCounter original = new NextCounter(5);
        NextCounter alias = original;
        nextCopy(original);
        System.out.println("ignored=" + original.get());
        original = nextCopy(original);
        System.out.println("new=" + original.get());
        System.out.println("alias=" + alias.get());
    }
}
class NextCounter {
    private final int value;
    NextCounter(int value) { this.value = value; }
    int get() { return value; }
}
```

输出ignored=5、new=6、alias=5。nextCopy(original)第一次也计算并返回了一个值6的新对象，但main没有保存；第二次original=nextCopy(original)才让original指向返回的新对象。旧alias一直指向值5的A。

| 语句 | original | alias | 返回值是否保存 |
|---|---|---|---|
| 声明两个变量 | A(5) | A(5) | 不涉及 |
| 只调用nextCopy | A(5) | A(5) | 丢弃新对象引用 |
| original=nextCopy | 新C(6) | A(5) | 写入original格子 |

NextCounter nextCopy(...)开头的NextCounter是返回类型，不是构造器声明；它有方法名nextCopy。构造器是类内同名且无返回类型的NextCounter(int)，二者不能靠是否出现new这个单词来区分。return new ...先创建/取得引用，再返回；并没有把main的局部变量位置作为额外参数。

只把第二次赋值左侧original改成alias，预测谁会变6。独立写一个返回旧对象引用的identity方法，接住它后用==验证身份不变：有返回值不保证一定新建对象，是否new要看实现与契约。

## 5. “交换失败”不等于“Java交换不了任何数据”

swap(a,b)若只互换两个形参引用，与第3节完全相同：变的是两份副本。数组元素则是数组对象中的状态，通过共享引用可以修改。下面把两个层次放在同一个小实验里，但每段各自打印检查。

```java
import java.util.Arrays;
public class ArraySwapRoutes {
    static void swapVariables(int[] first, int[] second) {
        int[] saved = first;
        first = second;
        second = saved;
    }
    static boolean swapElements(int[] values, int i, int j) {
        if (values == null || i < 0 || j < 0 || i >= values.length || j >= values.length) return false;
        int saved = values[i];
        values[i] = values[j];
        values[j] = saved;
        return true;
    }
    public static void main(String[] args) {
        int[] left = {1, 2};
        int[] right = {8, 9};
        swapVariables(left, right);
        System.out.println(Arrays.toString(left) + "/" + Arrays.toString(right));
        System.out.println(swapElements(left, 0, 1));
        System.out.println(Arrays.toString(left));
        System.out.println(swapElements(left, 1, 1));
        System.out.println(swapElements(left, 0, 2));
        System.out.println(Arrays.toString(left));
    }
}
```

应先输出[1, 2]/[8, 9]，说明两个main数组变量没交换；随后true、[2, 1]、true、false、[2, 1]。成功自交换返回true且内容不变；越界拒绝返回false且内容保持，这些是本例明确约定，不是Java自动选择返回boolean。

swapVariables里的saved是int[]引用，保存一根箭头；swapElements里的saved是int，保存一个元素值。相同变量名不能掩盖不同类型与任务。

| 元素交换步骤 | values[0] | values[1] | saved |
|---|---:|---:|---:|
| 初始 | 1 | 2 | 未建立 |
| saved=values[0] | 1 | 2 | 1 |
| values[0]=values[1] | 2 | 2 | 1 |
| values[1]=saved | 2 | 1 | 1 |

检查条件使用||短路：values为null时已确定拒绝，不再求values.length，避免为了检查而先空指针。合法下标必须小于length；长度2的最后一项下标1，2是越界。所有检查在写元素之前，失败不留下半交换状态。

只把main第一次swapElements的0,1改0,0，内容保持[1,2]但仍成功。再单独用空数组：没有合法第0项，应返回false；null与空数组概念不同，但本接口都拒绝该交换。练习E4要求你独立写接口并保存失败前后的内容，不能只打印false就断言没有修改。

## 6. String看着像“没改到”，根源还有不可变值

String引用也按值复制；除此之外，String对象内容不可变。received=received+"!"先得到新字符串值，再重绑形参，原字符串没变。不要为了背“对象会改、基本值不会改”而漏掉不可变对象。

```java
public class StringReturnRoutes {
    static void appendLocally(String received) {
        received = received + "!";
        System.out.println("inside=" + received);
    }
    static String withMark(String received) { return received + "!"; }
    public static void main(String[] args) {
        String text = "Java";
        appendLocally(text);
        System.out.println("main=" + text);
        String result = withMark(text);
        System.out.println("result=" + result);
        System.out.println("still=" + text);
    }
}
```

输出inside=Java!、main=Java、result=Java!、still=Java。withMark返回新文本结果，result接住它；main.text仍指原文本。把text也赋为withMark(text)才会更新那个变量。LocalDate.plusDays的返回值规律可用同样模型理解。

String received是参数，String withMark(...)最左侧String是返回类型。+在这里按字符串连接，不是对原文本存储区原地插入字符。空字符串""是合法文本值，加后得到"!"；null代表没有字符串对象，不是空文本。本例任务前提非null，不拿Java字符串拼接对null的特定显示行为冒充业务校验。

只把输入Java改空字符串，先写四行完整输出再运行。独立写addSuffix，保留source与alias引用旧文本，接住新结果后证明只有被重新赋值的变量换了目标。练习E5会给完整起步与自测。

## 7. 回到原综合程序：这次逐个调用核对

下面保留原ValuePassing.java与原题语境。它适合做六个小模型学完后的综合检查，不再作为初见对象传参的开场。

```java
public class ValuePassing {
    public static void main(String[] args) {
        int n = 3;
        Box a = new Box(5);
        Box b = new Box(20);
        changeNumber(n);
        changeState(a);
        replace(a);
        System.out.println(n + ":" + a.value);
        swap(a, b);
        System.out.println(a.value + ":" + b.value);
    }
    static void changeNumber(int value) { value = 99; }
    static void changeState(Box box) { box.value += 3; }
    static void replace(Box box) { box = new Box(99); }
    static void swap(Box left, Box right) {
        Box temp = left;
        left = right;
        right = temp;
    }
}
class Box {
    int value;
    Box(int value) { this.value = value; }
}
```

输出3:8、8:20。changeNumber只重绑int形参值；changeState改A.value；replace使局部box转向新C；swap只换left/right。temp保存引用值，main的a、b从未因此互换。

| 刚执行完 | n | a所指对象/字段 | b所指对象/字段 |
|---|---:|---|---|
| 初始化 | 3 | A.value=5 | B.value=20 |
| changeNumber | 3 | A.value=5 | B.value=20 |
| changeState | 3 | A.value=8 | B.value=20 |
| replace | 3 | 仍A.value=8 | 仍B.value=20 |
| swap | 3 | 仍A.value=8 | 仍B.value=20 |

原E1只把replace里的box=new Box(99)改box.value=99，输出变3:99与99:20；这是对已有对象字段的赋值。不要在同一副本里又改swap又改初值，实验就失去单一变量。

## 8. 怎样运行与怎样排错

所有命令都在课程根目录PowerShell输入，不是在Java文件中。每次运行一个public类对应的.java，普通单文件用java.ps1；其他非public类随同一个源码编译，会生成多个class，仍只有本次指定的启动类main被调用。脚本隔离输出并先检查编译结果，失败不执行旧class。

复制到本课my_code后再改，把命令路径code换my_code；源码文件名跟public类名一致。原code留作对照，不把程序输出直接当独立作答。各示例路径已在开头表中，运行其他样本只替换末尾文件名。

| 现象 | 先检查的具体位置 |
|---|---|
| 方法内值变，main没变 | 是对形参赋值，还是对共享字段赋值 |
| 两个变量一起看到新字段 | 它们是否仍指同一对象 |
| new了99但调用后还是5 | 新引用是否只放在局部形参，是否return并接住 |
| swap没有换main变量 | 当前改写的是哪个作用域里的格子 |
| 数组第一项交换越界 | 长度与下标是否混淆，检查是否先于写入 |
| 字符串加后原值没变 | 接口是否返回新值，调用者把它保存到哪里 |
| 同值对象变化不同步 | 是两个独立new，还是两个别名 |

最后用一句完整的话回答本课：Java按值传参，复制的是实参表达式的值；值若是引用，多份引用能访问同一对象，但给局部引用重新赋值不会改写调用者变量。不要把这句话缩成“对象传引用”，也不要从这句话误推“方法永远不能改外部任何状态”。
