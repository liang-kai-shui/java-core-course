## 学完要能做什么

能用extends读取、super接收及捕获助手方法；解释泛型不协变；区分对象运行类与声明上的泛型元信息。

## Integer是一种Number，为什么List<Integer>不是List<Number>

如果允许把整数列表交给List<Number>变量，这个变量就能add一个Double，原调用方再取Integer会出错。所以参数化类型通常**不协变**。需要“能读出Number的一类列表”时，用`List<? extends Number>`表达未知但有上界的元素类型。像只承诺从资料箱拿出“某种数值资料”，不知道它专门装整数还是小数；边界是不能据此往里随便放Number。

`?`表示某个未知类型，不是“每个元素随意换一种T”。extends提供上界，读取至少可当Number；super提供下界，`List<? super Integer>`可接List<Integer>、List<Number>、List<Object>，都能安全放Integer，读出却只保证Object。先按你需要读什么、写什么来选，不先背口诀。

## 一次复制，把来源与目标的职责写进签名

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
public class WildcardCopy {
    static <T> void copyInto(List<? super T> target, List<? extends T> source) {
        for (T value : source) target.add(value);
    }
    public static void main(String[] args) {
        List<Integer> source = Arrays.asList(1, 2);
        List<Number> target = new ArrayList<>();
        copyInto(target, source);
        System.out.println(target);
        List<? super Integer> sink = target;
        sink.add(3);
        System.out.println(target);
    }
}
```

输出[1, 2]与[1, 2, 3]。`<T>`为本次方法命名类型关系；来源`? extends T`提供可当T读的元素，目标`? super T`接收T。对本例推断T为Integer时，来源是Integer列表，目标Number列表符合下界。

| 变量视角 | 可安全读成 | 可安全加入 |
|---|---|---|
| List<? extends Number> | Number | 无任意非null数值保证 |
| List<? super Integer> | Object | Integer及其允许值 |
| List<?> | Object | 无任意非null元素保证 |

循环的T value来自来源get/迭代，再交给目标add，两个方向约束都成立。本例要求来源与目标不共用可变底层结构，不在遍历同一列表时向它追加；这属于遍历/结构修改协议，类型安全不替代该要求。`List<? extends Number>`不是绝对只读：仍可能clear、删除，某些操作依实现还会不支持；它限制的是未知元素类型下的安全写入。null也可写入接受它的列表，所以不能简单说“所有add都禁止”。

只把目标改为List<Object>，复制仍合法；把目标改List<String>则编译拒绝，不应运行旧产物。独立任务：设计只求Number.doubleValue总和的方法，用extends来源即可，不需要为了读数值复制整张列表或强转为List<Number>。

## 数值来源：只要能读Number，就能调用它提供的能力

```java
import java.util.*;
public class NumberReaderWalk {
    static double sum(List<? extends Number> values) { double result = 0.0; for (Number value : values) result += value.doubleValue(); return result; }
    public static void main(String[] args) {
        System.out.println(sum(Arrays.asList(1, 2))); System.out.println(sum(Arrays.asList(0.5, 1.5))); System.out.println(sum(Collections.<Number>emptyList()));
    }
}
```

Number.doubleValue()是不接参数、返回double的实例方法，Integer/Double等数值包装类提供具体实现；for每次读取的Number引用可以调用它，无需把整张List<Integer>强转成List<Number>。输出3.0、2.0、0.0，空表零次迭代保留初值。

| 路线 | sum进入 | 读到的double | sum离开 |
|---|---|---|---|
| Integer第一项 | 0.0 | 1.0 | 1.0 |
| Integer第二项 | 1.0 | 2.0 | 3.0 |
| 空表 | 0.0 | 没有元素 | 0.0 |

只把第二组的1.5改-1.5，先算应为-1.0再运行。独立任务求非空数值列表平均值，明确空列表应拒绝还是另有结果，不把0.0自动当“没有平均值”的唯一约定。本例不接null列表或元素，泛型本身不会替你检查非空；double求和仍有浮点舍入边界，不是金额精确计算承诺。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L35_第08章C_通配符与泛型反射/code/NumberReaderWalk.java'`。改动先复制到my_code，命令相应替换目录。

## 未知类型自己取出又放回：捕获给它取一个临时名字

List<?>的两项来自同一种未知类型，但直接用Object临时量再set不一定能证明安全。后面的capture助手用<T>为这一个未知类型取名字，交换时始终T，不用原始类型。像同一箱资料虽不知道具体类别，但取出的两份确定都属于这箱；边界是不能把另一箱不相关Object塞进去。

## Comparable为什么常写成<? super T>

求最小值只需要候选能与另一个T比较，不要求它的compareTo参数恰好声明T。LocalDate实现的比较接口针对ChronoLocalDate父类型，也能接收LocalDate。`<T extends Comparable<? super T>>`允许这种合法能力，后面日期例子会实际编译验证。不要通过原始Comparable放弃检查来绕开。

## 泛型反射看得到什么，不能看到什么

运行对象getClass通常只得擦除后的原类，不能从任意ArrayList实例读回它创建时的String实参。但字段、方法、父类等**声明**可以保留泛型签名。Field.getGenericType返回Type，可能是Class、ParameterizedType、TypeVariable、WildcardType或GenericArrayType；名字分别描述普通类型、带参数声明、类型变量、通配符、泛型数组声明，并非五种业务对象容器。

不要把反射Types误强转为某个具体实现类。先按接口判断再读取实际类型参数、上下界。教材的通用打印算法可深化阅读；本课独立程序固定查询我们自己声明的字段，不需要写一个万能类型解析器。

## 把未知类型捕获为T，再交换自己的元素

```java
import java.util.Arrays;
import java.util.List;
public class WildcardCaptureSwap {
    static void swap(List<?> values) { capture(values); }
    private static <T> void capture(List<T> values) {
        if (values.size() < 2) throw new IllegalArgumentException("need two");
        T temp = values.get(0);
        values.set(0, values.get(1));
        values.set(1, temp);
    }
    public static void main(String[] args) {
        List<String> values = Arrays.asList("A", "B");
        swap(values);
        System.out.println(values);
    }
}
```

输出[B, A]。公开swap只承诺接收某种列表，内部助手capture声明<T>，在这次调用把未知具体类型命名为T。temp从同列表取，再放回同列表，类型关系保持。少于两项先throw，Arrays.asList虽不能增删却支持set，故本例交换可行。

状态表：初[A,B]→temp=A→第0项=B→第1项=A。只把第二元素改C，预期[C,A]；元素不克隆，仅调换引用位置。独立任务：用Integer列表调用同一入口，说明不需要每种类型写一次swap，也不需要SuppressWarnings或raw List。若列表本身不支持set，则会UnsupportedOperationException，那是修改能力契约，不是捕获失效。

## 比较能力面向父类型，仍然能求子类型最小值

```java
import java.time.LocalDate;
import java.util.Arrays;
import java.util.List;
public class ParentComparableMinimum {
    static <T extends Comparable<? super T>> T min(List<T> values) {
        if (values.isEmpty()) throw new IllegalArgumentException("empty");
        T best = values.get(0);
        for (T value : values) if (value.compareTo(best) < 0) best = value;
        return best;
    }
    public static void main(String[] args) {
        System.out.println(min(Arrays.asList(LocalDate.of(2025, 2, 1), LocalDate.of(2025, 1, 1))));
    }
}
```

输出2025-01-01。T是LocalDate，而Comparable参数允许T的父类型，不要求恰好Comparable<LocalDate>。候选与best都是LocalDate，父类型参数能接住它们，所以compareTo合法。这里extends限定T具有能力，super限定比较器可接收的对象范围；两个方向不能凭“都像继承”互换。

第一次best为02-01，候选01-01较小，更新，最后返回原列表中的日期引用；日期不可变，可以共享。只把1月1日改3月1日，结果应02-01。独立把这个界与L33的简单Comparable<T>逐字比较，解释扩大的是可接受比较能力，不是允许把任何Object送进compareTo。

在课程根目录PowerShell运行`./java.ps1 -Source './L35_第08章C_通配符与泛型反射/code/ParentComparableMinimum.java'`。


## 声明元信息：默认上界不是空数组

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.TypeVariable;
import java.lang.reflect.WildcardType;
import java.util.List;
public class GenericDeclarationInfo {
    public static void main(String[] args) throws ReflectiveOperationException {
        TypeVariable<?> variable = DeclaredTypes.class.getTypeParameters()[0];
        System.out.println(variable.getBounds()[0].getTypeName());
        ParameterizedType words = (ParameterizedType) DeclaredTypes.class.getDeclaredField("words").getGenericType();
        System.out.println(words.getActualTypeArguments()[0].getTypeName());
        ParameterizedType unknown = (ParameterizedType) DeclaredTypes.class.getDeclaredField("unknown").getGenericType();
        WildcardType wildcard = (WildcardType) unknown.getActualTypeArguments()[0];
        System.out.println(wildcard.getUpperBounds()[0].getTypeName());
        System.out.println(wildcard.getLowerBounds().length);
    }
}
class DeclaredTypes<T> { List<String> words; List<?> unknown; }
```

输出java.lang.Object、java.lang.String、java.lang.Object、0。DeclaredTypes<T>的T没显式extends，上界仍Object；words字段声明List<String>，可从ParameterizedType读String；unknown字段List<?>的通配符默认上界Object，无显式下界才返回长度0。

`getDeclaredField`按名字取我们自己字段，getGenericType取声明类型。先验证字段声明确实是List的参数化形式后，样本按已知契约转ParameterizedType；这是固定教学声明，不是对任意未知反射对象盲转的通用算法。最后一个参数转WildcardType，因为我们明确声明?。

教材书本p342 / PDF p360关于无显式限定返回空上界数组的说法不准确：类型变量与通配符的缺省上界均是Object，已按[TypeVariable API](https://docs.oracle.com/javase/8/docs/api/java/lang/reflect/TypeVariable.html)与[WildcardType API](https://docs.oracle.com/javase/8/docs/api/java/lang/reflect/WildcardType.html)核对。书本p337 / PDF p355的Class.cast失败应是ClassCastException，不是BadCastException。

只把words的String改Integer，第二行改变，其他默认界不变。独立解释：程序查看的是字段写下的List<String>声明，而不是取一份任意ArrayList实例后神奇恢复实参。若要扩成通用报告，先分Type接口种类再递归，不依赖JDK内部实现类名。

在课程根目录PowerShell运行`./java.ps1 -Source './L35_第08章C_通配符与泛型反射/code/GenericDeclarationInfo.java'`。
