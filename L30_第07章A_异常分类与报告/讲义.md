## 学完要能做什么

能区分throw与throws、checked与unchecked；为业务失败保留原因；知道在哪层恢复，而不是吞掉失败伪造结果。

## 困惑：输入错了，返回0是不是就算处理好了

你要解析学习分钟。0可能是合法记录，也可能被随手用作“解析失败”代号，调用方分不清发生了什么。**异常**是封装失败信息的对象，让不能正常完成的方法沿另一条路线退出，交给有能力处理的调用层。像柜台给你一份“办理未完成”的说明，而不是递一张看似办好的空证。边界是异常不会自动撤销已经做过的修改，也不会自动重试；要保持安全状态和决定下一步，仍由程序设计负责。

本课规定分钟必须为正，解析失败不产生分钟结果；外层对每条输入报告后继续下一条。这个约定把“有效值”与“这次没有有效值”分开。

```java
public class ExceptionRoutes {
    static int parse(String text) throws InvalidMinutesException {
        int value;
        try { value = Integer.parseInt(text); }
        catch (NumberFormatException ex) { throw new InvalidMinutesException("不是整数", ex); }
        if (value <= 0) throw new InvalidMinutesException("必须为正");
        return value;
    }
    public static void main(String[] args) {
        for (String text : new String[] {"15", "x", "-1"}) {
            try { System.out.println("ok:" + parse(text)); }
            catch (InvalidMinutesException ex) {
                String cause = ex.getCause() == null ? "none" : ex.getCause().getClass().getSimpleName();
                System.out.println("bad:" + ex.getMessage() + " cause=" + cause);
            }
        }
    }
}
class InvalidMinutesException extends Exception {
    private static final long serialVersionUID = 1L;
    InvalidMinutesException(String message) { super(message); }
    InvalidMinutesException(String message, Throwable cause) { super(message, cause); }
}
```

输出`ok:15`、`bad:不是整数 cause=NumberFormatException`、`bad:必须为正 cause=none`。每行输入各有自己的try/catch，因此第二条失败不会阻止第三条被尝试。

`throw new InvalidMinutesException(...)`创建一个失败对象并立即抛出；当前parse中的后续正常语句不再执行。`throws InvalidMinutesException`写在方法声明上，告诉调用者可能有哪些受检查失败要处理；它不是“现在抛一次”，也不是自动处理。两者位置和作用完全不同。

parse里的try仅包住整数解析，NumberFormatException发生时转成更贴业务的InvalidMinutesException，并把原对象作为cause保留。整数解析成功后再检查<=0；负数并不是格式错误，所以它的cause为null。`getMessage()`取业务描述，`getCause()`取原始原因，不能只拼原消息而丢失类型与堆栈。

| 输入 | Integer.parseInt | 正值规则 | 外层路线 |
|---|---|---|---|
| 15 | 得15 | 满足 | ok:15 |
| x | 抛格式异常 | 不再执行 | 包装失败→catch报告 |
| -1 | 得-1 | 不满足，throw | catch报告 |

## 异常家族：名字带Runtime不代表其他失败不在运行时

所有可抛对象来自Throwable。Error分支通常描述JVM/资源等严重问题，不应把普通输入错误设计成Error；Exception分支含应用可讨论的失败。RuntimeException及其子类，与Error及其子类，是unchecked；其余Throwable类属于checked。**检查**说的是编译器是否要求捕获或声明，不是说checked发生在编译阶段。两类异常对象都可以在运行时抛出。

IOException、ClassNotFoundException是常见checked；NumberFormatException、NullPointerException、IndexOutOfBoundsException属于unchecked。不要机械说“unchecked必定是程序员写错、checked必定是用户错”：这是常见设计倾向，决定分类的是继承关系。外部输入解析会产生unchecked格式异常，也仍要在合适边界向用户报告。

调用一个可能抛checked的方法，你可在当前层catch处理，或用throws继续交给上层。自定义InvalidMinutesException extends Exception，因此调用parse必须二选一；main本例catch了它。若删除catch却既不声明也不改调用，会编译失败。声明throws Exception虽省事，却可能丢掉对调用方有用的精确契约，示例优先声明具体类型。

## 自定义异常也是一个类

类名表达这类失败，构造器调用super保存消息和原因；不需要每种错误字符串都造一个新类。`private static final long serialVersionUID=1L`是异常类继承的序列化体系版本标识，避免编译器serial警告；它不是错误编号、不会决定抛出顺序。当前只需按样本保留，卷Ⅰ不要求你实现对象序列化框架。

异常不会返回一个“失败的int”给原赋值语句。例如`int n=parse("x")`失败后n没有获得结果，不能catch后装作这一行成功。捕获后从catch之后继续，不回到失败调用的下一条try内部语句。如果一次操作已改了一半状态，要在提交修改前完成校验，或设计回滚，不能靠catch自动恢复。

覆盖父类方法时，子类不能把受检查失败范围扩得更宽，否则持有父类契约的调用方无从准备；可以更窄或不抛。这一限制不能用“任何方法都能throw任何对象”模糊掉。只能抛Throwable类型对象，不能throw普通字符串。

## 右侧失败了，左侧变量会得到什么

赋值先完整计算右侧，成功才写回。像柜台只有办出新证才替换旧证，失败说明不会自动变成新证；类比边界是异常不会自动回滚此前别处已经发生的修改。

```java
public class FailedAssignmentRoute {
    public static void main(String[] args) {
        int saved = 7;
        try {
            saved = Integer.parseInt("bad");
            System.out.println("after");
        } catch (NumberFormatException ex) {
            System.out.println("caught");
        }
        System.out.println("saved=" + saved);
    }
}
```

saved先有7。parseInt("bad")在右侧抛出，`saved=`尚未写回，try里的after也没执行；catch报告后，在catch之后继续，最后saved仍7。若变量只声明未初始化，在失败后读取就可能被编译器拒绝，不能以“应该有个失败值”代替确定赋值规则。

| 路线 | saved | 是否执行after |
|---|---:|---|
| 非法bad | 保持7 | 否 |
| 改为12 | 写成12 | 是 |

只把bad改12，先预测多哪一行、最终值几；再恢复。独立任务：在自己parsePage外层每条记录单独try，成功才加入页码列表。失败只报告，不把旧saved当这次新结果加入，也不返回0冒充正常页码。
