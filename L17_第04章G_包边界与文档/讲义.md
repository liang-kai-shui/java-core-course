## 学完要能做什么

能区分包命名、import简称、classpath查找和访问权限；生成可阅读的API文档，说明输入单位、返回含义与边界。

## 困惑：已经import了，为什么还是不能用

要成功使用一个类，至少要过三关：名字能解析到哪一个类；编译/运行工具能否找到它；当前代码是否有权访问它。import只帮名字写短，不能安装依赖、把private变public，也不能代替运行时classpath。类比“通讯录简称、仓库地址、通行权限”三张不同的表；边界是Java包不是操作系统文件权限，不能用文件夹可读来推断成员可访问。

包`campus.model`与`campus.model.internal`是两个不同的包；名字看着有上下层，不代表子包自动享有包权限。顶层类通常public或包可见（不写修饰符）；成员在不写访问修饰符时也为包可见，不是private。protected涉及子类，将在L20细讲。

## 先看“给调用者看的说明”

```java
/** Provides a small documented printing-cost example. */
public class DocumentedCost {
    /**
     * Counts sheets for nonnegative inputs; negative inputs count as zero.
     * @param pages pages per copy, with a small enough product for int
     * @param copies number of copies
     * @return total sheets, or zero if an input is negative
     */
    public static int sheets(int pages, int copies) {
        if (pages < 0 || copies < 0) return 0;
        return pages * copies;
    }
    /**
     * Runs the fixed example.
     * @param args unused command-line arguments
     */
    public static void main(String[] args) {
        System.out.println(sheets(4, 3));
    }
}
```

输出12。`/** ... */`是文档注释，放在它描述的声明前。普通`//`注释能帮助读源码，但javadoc不会把它当成方法API说明。第一句概括用途；`@param pages`说明单位是“页”，`@param copies`说明数量；`@return`解释结果，不是把“返回一个int”再说一遍。`{@code ...}`把文字按代码显示，避免文档里的尖括号被误当HTML。

契约还要讲清输入边界。本例负参数按0处理，乘积在int范围内使用；若要支撑极大订单，必须换long并核对溢出，而不是让文档声称任意大整数。文档不会替代码做检查，也不会因为写了“不为负”就自动拦住负数。

## 生成文档，看到注释去了哪里

在课程根目录的PowerShell逐行输入下面一组命令。点加空格先导入课程的JDK查找函数，不改全局PATH；Find-CourseJdk读取本项目配置。输出目录只放本次生成的HTML，不放进源码目录。

```powershell
. .\_课程工具\resolve-jdk.ps1
$docJdk = Find-CourseJdk -Root (Get-Location).Path
& (Join-Path $docJdk 'bin\javadoc.exe') -encoding UTF-8 -charset UTF-8 -d '.\.build\L17-api' '.\L17_第04章G_包边界与文档\code\DocumentedCost.java'
if ($LASTEXITCODE -ne 0) { throw 'Javadoc generation failed' }
Test-Path '.\.build\L17-api\DocumentedCost.html'
```

最后应为True，打开`.build/L17-api/index.html`查看方法摘要、参数和返回说明。javadoc是工具命令，不是写进Java源码的语句；`&`是PowerShell运行路径中命令的调用符。若没有生成页面，先看工具退出码与第一条诊断；注释标签格式或HTML错误也可能让生成失败。

## 真正跨包，再验证公开入口

文末的多文件项目有`campus.model.Counter`、同包的`Inspector`和不同包的`campus.app.Main`。每个文件的package写在import之前；编译后class也按这个包名放置。`Counter.value`为包可见，同包Inspector能读；Main只能调public方法。Main导入Inspector并不能获得其“同包身份”。目录树如下，缩进表示包含，不是继承：

```text
src/
  campus/model/Counter.java
  campus/model/Inspector.java
  campus/app/Main.java
```

| 步骤 | 检查哪件事 | 本例结果 |
|---|---|---|
| 编译Main里的Counter | import→全名 | campus.model.Counter |
| 访问Counter.value | Main是否同包或有权限 | 不同包，不允许 |
| 访问Counter.read() | 类与方法是否public | 允许 |
| 启动campus.app.Main | 从classpath根拼campus/app/Main.class | project.ps1配置正确根 |

运行项目应输出`public=4`、`same-package=4`。复制整个project到my_code/project，用`project.ps1 -Project L17 -SourceRoot './L17_第04章G_包边界与文档/my_code/project' -Mode Run`跑自己的版本。只把Main里的c.read()换成c.value，会在编译期报访问权限错误；先恢复，再把启动查找根设错观察启动失败。这两种失败不能混叫“导包问题”。失败实验不要放回正常样本。

## 文档的其他出口与版本边界

公有常量也可有文档；`@since`写引入版本，`@see 类#方法(类型)`给相关入口，`{@link ...}`可嵌入正文。`@throws`说明失败条件，在L30异常课完整使用。包说明可放`package-info.java`，文档注释在package声明之前；总览可由overview.html提供。`-author/-version`选择显示对应标签，`-link`链接外部API文档，`-linksource`增加源码视图。知道各自用途即可，不要求为这个小程序配置所有选项。

教材关于rt.jar、扩展目录的描述对应旧JDK。JDK 21不能照着往jre/lib/ext塞库；本课程继续用项目内依赖和显式classpath，不改全局CLASSPATH。包密封是JAR来源一致性约束，L46深化，它不等于把Java包变成加密安全边界。

## 单位写在文档里，计算顺序必须写进程序

“分钟转秒”若只说返回long，仍没解释负数、单位和乘法时机。文档像操作说明书，代码是实际接线；边界是说明书不会自动替程序插入检查。

```java
public class MinuteUnitContract {
    /**
     * Converts minutes to seconds; nonpositive inputs count as zero.
     * @param minutes whole minutes
     * @return nonnegative whole seconds
     */
    public static long seconds(int minutes) {
        return minutes <= 0 ? 0 : minutes * 60L;
    }
    public static void main(String[] args) {
        System.out.println(seconds(-1));
        System.out.println(seconds(0));
        System.out.println(seconds(2));
        System.out.println(seconds(Integer.MAX_VALUE));
    }
}
```

最前的/**注释关联seconds声明，@param名字必须对应minutes，@return说明数值含义而不重复“一个long”。`minutes * 60L`使乘法先按long完成；返回类型long不会倒流扩大一个已经溢出的int乘法。

| minutes | 分支 | 预期秒 |
|---:|---|---:|
| -1 | 非正 | 0 |
| 0 | 非正 | 0 |
| 2 | 乘法 | 120 |
| 2147483647 | long乘法 | 128849018820 |

只把60L改60，先预测只有极大输入会暴露错法；小的2无法证明运算宽度正确。恢复后用L17前面的javadoc命令，把源路径换成当前文件、输出目录换成本次独立目录，观察参数与返回说明。独立任务：先用自然语言定义一个“小时转分钟”的契约，再写相应代码与三种边界，不要只替换注释单位却忘记运算。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L17_第04章G_包边界与文档/code/MinuteUnitContract.java'`。改动先复制到my_code，命令相应替换目录。
