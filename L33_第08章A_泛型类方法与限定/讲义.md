# L33 讲义 · 泛型：类型填空，而不是到处强转

> 前置：L22现成泛型容器；L25 Comparable；L30异常
> 教材主线：8.1–8.4；**书本 p309–316 / PDF p327–334**。讲解、类比、案例与练习均为课程原创。

## 学完要能做什么

能声明自己的泛型类与泛型方法；把类型参数和普通参数分开；为需要比较的算法声明能力限定。

## 一个装书名的盒子，为什么还想装分钟数

若盒子字段统一写Object，放入String和Integer都行，取出后却只得到Object视角，需要强转；调用方可能认错内容，直到运行才失败。**泛型**给类型留一个命名的空位，由使用处填上，让编译器沿着存取关系检查。像同款登记表先选“此表登记哪一类资料”，再填写具体记录；类比边界是它不是运行时给每个对象复制一套带不同机器码的方法，L34会看擦除。

`<T>`中的T是类型参数，不是字符串变量、不存放某个对象，也不是Java规定必须叫T。`Parcel<String>`填String后，set和get就按String契约使用。普通参数如value则是这一次调用交来的具体对象引用。类型填空和数值/引用实参属于两层，不能把`new Parcel<"Java">`当合法写法。

## 没有类型空位时，错误会拖到哪一步

```java
public class ObjectBoxNeed {
    static class LooseBox { private Object value; void set(Object value) { this.value = value; } Object get() { return value; } }
    public static void main(String[] args) {
        LooseBox box = new LooseBox(); box.set("Java"); String title = (String) box.get(); System.out.println(title);
        box.set(20);
        try { String wrong = (String) box.get(); System.out.println(wrong); } catch (ClassCastException e) { System.out.println("read-failed"); }
    }
}
```

先写Java，强转String成功；随后同一盒子换整数20，Object接口仍允许写，取String时才输出read-failed。类比空白登记栏让你什么都能填，检查拖到取件时才暴露；边界是Object不是没有类型，它是所有引用类型的公共父类型，具体对象仍是String或Integer，强转不会把整数变文字。

LooseBox只保存一个Object字段，set每次替换该引用；第一次局部title仍指向之前String，不会被后来的set自动改成整数。`(String)`是运行类型检查，不能替你证明以后每次写入都正确。只把20改成另一字符串，第二次读取能成功，read-failed不再出现；独立任务先用String.valueOf把数字转换成文字，再比较“转换内容”与“强转视角”的差别。接下来的Parcel<T>会把错误类型的写入提前到编译时拒绝。

## 先只解决一个字段的存取

```java
public class GenericParcelDemo {
    public static void main(String[] args) {
        Parcel<String> title = new Parcel<>("Java");
        Parcel<Integer> minutes = new Parcel<>(20);
        System.out.println(title.get());
        System.out.println(minutes.get());
    }
}
class Parcel<T> {
    private final T value;
    Parcel(T value) { this.value = value; }
    T get() { return value; }
}
```

输出Java与20，各一行。GenericParcelDemo负责main，Parcel<T>是业务类型，只有启动类public，文件按启动类名保存。`T value`表示字段类型采用这份泛型使用中的T；构造器名字仍是Parcel，不能写成Parcel<T>作为构造器名字。`T get()`把字段值交回，不需要在调用处写(String)强转。

| 使用处 | T填什么 | 构造实参 | get结果的编译类型 |
|---|---|---|---|
| Parcel<String> title | String | "Java" | String |
| Parcel<Integer> minutes | Integer | 自动装箱20 | Integer，赋int时拆箱 |

两次new仍是两个独立对象；通用源码不是共享一个value字段。`<>`让右边从左边和参数推断，不是省略检查。不能写Parcel<int>，泛型类型实参需要引用类型，所以普通整数用Integer。null可作为引用值，本类允许；是否允许由具体业务约定，不是写泛型就自动非null。

## 编译检查究竟挡住什么

在副本把title的构造实参改为整数20，预期编译失败：左边要求Parcel<String>，输入与该约定冲突。正常程序不会先把20塞进去再等get时强转失败。若改为Object盒子，则这种保护消失，强转可能推迟到运行才失败。不要为了让报错消失删除尖括号使用原始类型，那相当于主动放弃部分约束。

## 一处修改与独立写作

先只把Java改为数组，预期第一行变化、第二行不变。再把Integer盒子改为String盒子，必须连变量类型与实参按新契约一起设计，这已是另一实验，不能假装只改一个值。独立小任务：建立两个Parcel<String>，一份允许null，解释get返回null与“没有创建盒子对象”的差别。

接下来的泛型方法不要求外围类也泛型：一次调用自己声明类型空位。需要比较时再给T加上能力限定；不要让调用方替工具猜它是否有compareTo。

## 方法自己的类型空位：先声明，再使用

问题：想取各种非空数组的首项，难道每种元素都重写一遍？泛型方法像可选择资料类别的同一张取件申请；边界是它不会凭空检查数组是否非空，业务边界仍需if。

```java
public class GenericFirstMethod {
    static <T> T first(T[] items) {
        if (items.length == 0) throw new IllegalArgumentException("empty");
        return items[0];
    }
    public static void main(String[] args) {
        System.out.println(first(new String[]{"A", "B"}));
        System.out.println(first(new Integer[]{4, 5}));
    }
}
```

输出A与4。`static <T> T first`按三步读：static归工具类，<T>声明这次方法使用类型参数，T给返回类型。String[]调用推断T为String；Integer[]推断为Integer。工具类本身没有<T>，它的不同方法不自动共用这个T。

| 输入 | 推断 | 访问 | 结果 |
|---|---|---|---|
| {A,B} | String | 第0项 | A |
| {4,5} | Integer | 第0项 | 4 |
| 空数组 | 可推断 | 先throw，不访问 | 无正常返回 |

只把第一个数组改为空，预期运行时明确拒绝；不能把泛型编译通过当作长度检查。独立实现last，先检查空再用length-1。若方法声明忘了<T>，T就不是当前类中已知类型，会在编译时失败，不是运行时没猜出元素。

## 需要比较的算法：限定告诉编译器可以做什么

问题：T可能是任意对象，凭什么直接写candidate.compareTo(best)？限定像申请表要求“这类资料必须提供比较能力”；边界是编译器检查接口契约，不会替你证明比较逻辑满足传递性。

```java
public class BoundedMinimum {
    static <T extends Comparable<T>> T min(T[] values) {
        if (values.length == 0) throw new IllegalArgumentException("empty");
        T best = values[0];
        for (T candidate : values) if (candidate.compareTo(best) < 0) best = candidate;
        return best;
    }
    public static void main(String[] args) {
        System.out.println(min(new String[]{"C", "A", "B"}));
        System.out.println(min(new Integer[]{-2, -5, -1}));
    }
}
```

输出A与-5。`<T extends Comparable<T>>`读成T必须实现与T比较的Comparable能力。这里的extends用于限定，右侧可以是接口，不写implements。首项作为best，循环负返回表示候选更小才更新。空数组先拒绝，本课不接纳null数组或null元素。

| String输入 | best进入 | 比较 | best离开 |
|---|---|---|---|
| 首项C | 尚无 | 初始化 | C |
| C | C | 0 | C |
| A | C | 负 | A |
| B | A | 正 | A |

只把A改Z，应得B；再用全负整数验证没有错误从0起步。独立解释若删限定，编译器无法保证T有compareTo。多个限定写`T extends 类 & 接口1 & 接口2`，若有类必须排第一，只能一个类限定。

这份基础限定刻意简单。有些类型的自然顺序针对父类型，例如LocalDate实现Comparable<ChronoLocalDate>，更灵活的`Comparable<? super T>`会在L35以完整程序深化；当前不要为适配它使用原始Comparable或未经检查强转。教材p318–319残留旧Date/clone写法也不能直接套LocalDate，不可变日期没有那种修改式clone方案。
