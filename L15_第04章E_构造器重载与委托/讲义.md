# L15 讲义 · 构造器：多种入口，同一套有效状态

> 前置：S03；L12封装；L13工厂
> 教材主线：4.6.1–4.6.6；**书本 p123–127 / PDF p141–145**。讲解、类比、案例与练习均为课程原创。

## 学完要能做什么

能区分重载、默认构造器、无参构造器；追踪this(...)委托，避免重复初始化和同名参数漏赋值。

## 困惑：new后面不传参数，为什么有时可以、有时报错

构造器是把新对象带到有效初始状态的入口。同一类可以有不同参数列表的多个入口，叫**重载**。像办卡窗口提供“用默认套餐”和“自选套餐”两种申请表，最后都得生成完整的有效卡。类比边界：构造器不是一个能随时再次调用来重置旧卡的普通方法；`new`创建新对象，构造器没有返回类型，不能给它写void。

“无参”描述参数列表为空；“默认构造器”在严格用语里是你完全没声明构造器时，编译器隐式提供的那个。你一旦声明任意构造器，编译器就不再补默认的无参入口。想允许new LessonPlan()，就自己写无参构造器。

## 三种入口走向一个核心入口

```java
public class PlanConstructors {
    public static void main(String[] args) {
        System.out.println(new LessonPlan().summary());
        System.out.println(new LessonPlan("字符串").summary());
        System.out.println(new LessonPlan("数组", 3).summary());
    }
}
class LessonPlan {
    private final String title;
    private final int hours;
    LessonPlan() { this("未命名", 1); }
    LessonPlan(String title) { this(title, 1); }
    LessonPlan(String title, int hours) {
        this.title = title;
        this.hours = hours > 0 ? hours : 1;
    }
    String summary() { return title + ":" + hours; }
}
```

预期三行：`未命名:1`、`字符串:1`、`数组:3`。本课把非法课时修正为1，这是公开约定，不是Java自动行为。

`LessonPlan()`、`LessonPlan(String)`、`LessonPlan(String,int)`参数列表不同，编译器按调用处参数数量和类型选入口。仅返回类型不同不算重载；参数名字改了也不算。`this("未命名",1)`调用同类另一个构造器，沿用同一个正在构造的对象，不是再new一个对象。在本课程Java 8语法下，this(...)必须是构造器第一条语句；不能先打印再调用，也不能形成互相委托的循环。

`this.title = title`左边是对象字段，右边是当前构造器参数。若误写`title = title`，两边都指参数；本例final字段没有完成赋值，编译器就会拒绝。若普通非final引用字段一直没赋值，它会保留默认null。字段具有默认值：数字0、boolean为false、引用null；局部变量必须明确赋值后才能读取。不能因为字段有默认值就认为它符合业务要求：null标题和0课时未必有效。

| 调用 | 首先选中 | 委托 | 最后保存的字段 |
|---|---|---|---|
| new LessonPlan() | 无参构造器 | 双参入口 | 未命名、1 |
| new LessonPlan("字符串") | 单参构造器 | 双参入口 | 字符串、1 |
| new LessonPlan("数组",3) | 双参构造器 | 无this委托 | 数组、3 |

委托返回后才继续外层构造器剩余语句；本例没有剩余操作。最终字段只需由核心入口检查与赋值一次。若每个入口各复制一份规则，未来将“最少1课时”改为“最少2”时容易漏一个入口。

## 不是所有初始化都该堆进构造器

常用固定初值可写在字段声明处，如`private String note="";`，每次创建实例都会得到该字段初值；不是static共享字段。需要依赖参数的值留在构造器里。final字段若不在声明处初始化，必须在每条正常完成的构造路径中赋值，且不能再重新赋；this委托可以让一个核心入口负责它。

重载选择发生在编译期。`new LessonPlan(null)`在本例选String入口（null可作引用值），并不会自动换成默认标题；设计者仍须决定是否接受null。若另加一个单参数int[]构造器，null同时适用String和int[]，两者互不更具体，调用会歧义。这里用这个边界提醒你：重载应让调用者看得懂，不是入口越多越好。

## 只改一处的实验

把main的第三个课时3改为0，预期`数组:1`；负数同理。然后另开副本，把`this.title = title`改成`title = title`，预期编译失败，因为final字段未完成赋值。若还想观察默认null，再在另一个实验副本去掉title的final，不把它误认为原程序能运行。每次实验分开保存；不要把多个改动混合后猜原因。

## 默认入口的受控实验：字段有初值，不代表构造入口存在

把“房间里已经摆好桌子”和“门上允许哪种申请方式”分开：字段初始化提供状态，构造器参数列表决定可用入口。类比边界是编译器不会真的在文件里替你显示补写的默认构造器。

```java
public class DefaultConstructorDoor {
    public static void main(String[] args) {
        System.out.println(new PlainDoor().title);
        System.out.println(new NamedDoor("数组").title);
    }
}
class PlainDoor {
    String title = "默认";
}
class NamedDoor {
    String title = "默认";
    NamedDoor(String title) { this.title = title; }
}
```

PlainDoor完全没声明构造器，故可以new PlainDoor()；NamedDoor声明了有参入口，所以下面按这个入口传文本。`title="默认"`只是每个实例字段的初始化，不会额外带来NamedDoor()。将第二次new改为`new NamedDoor()`，预计在编译时因无匹配构造器失败，不应谈论之后输出什么。

| 类 | 是否显式声明构造器 | 无参new是否可用 |
|---|---|---|
| PlainDoor | 否 | 有隐式默认入口 |
| NamedDoor | 是，需String | 无无参入口 |

恢复后独立增加`NamedDoor(){ this("默认"); }`，它现在是你显式写的无参构造器，双参或其他入口仍由你设计。再说清this(...)与this.title：前者沿同一对象委托构造，后者选字段。若重复new来“委托”，将创建另一对象并丢弃它，不能初始化当前这份状态。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L15_第04章E_构造器重载与委托/code/DefaultConstructorDoor.java'`。改动先复制到my_code，命令相应替换目录。
