## 学完要能做什么

能区分对象的身份、状态、行为；读懂LocalDate方法的返回值；独立完成跨月日期表，不靠自己硬算月份天数。

## 困惑：明明调用了“加一天”，为什么还是原日期

你要给借书记录计算归还日。若只写`due.plusDays(1);`，屏幕上原日期并没有改变。这不是加法失效，而是先要问：这个方法修改现有对象，还是返回另一个值？对象由**身份**（是不是同一个实例）、**状态**（目前保存什么）与**行为**（允许做什么）三个角度观察。两个日期内容相同，不要求是同一个实例；日期值通常用equals比较。

把不可变日期想成印好的日期卡：想要下一天，另取一张卡，把变量指向新卡。这个类比只帮助理解“原值保持、结果要接住”；Java不保证每次都实际另分配一张卡，不能据此用`==`判断日期内容。LocalDate表示年/月/日，不含时区和一天中的时间；它不是可以唯一定位世界某一瞬间的时间戳。旧Date主要表达时间点，两者职责不同。

## 一个固定的跨年实验

先预测最后一行的3个日期。固定输入比`now()`更适合核对；`now()`会随当前日期和默认时区变化。

```java
import java.time.LocalDate;
public class DateSteps {
    public static void main(String[] args) {
        LocalDate start = LocalDate.of(2024, 12, 31);
        start.plusDays(1);
        LocalDate next = start.plusDays(1);
        System.out.println(start);
        System.out.println(next);
        System.out.println("year=" + next.getYear() + ", month=" + next.getMonthValue() + ", day=" + next.getDayOfMonth());
        LocalDate cursor = start;
        for (int i = 0; i < 3; i++) {
            System.out.print(cursor + (i == 2 ? "\n" : " "));
            cursor = cursor.plusDays(1);
        }
    }
}
```

输出：

```text
2024-12-31
2025-01-01
year=2025, month=1, day=1
2024-12-31 2025-01-01 2025-01-02
```

`import java.time.LocalDate;`只是让编译器认识短类名，不是创建日期。`LocalDate.of(2024,12,31)`读作“请LocalDate按年、月、日给出一个日期值”，这是静态工厂调用，不写new。返回类型仍是LocalDate。`start.plusDays(1)`中的点左边是接收调用的对象引用，括号内1是实参；调用结果必须赋给变量或继续参与表达式才会被利用。

`getYear/getMonthValue/getDayOfMonth`是访问器：返回int而不改日期。方法名里带get是命名习惯，不是编译器强制的“只读”保证，仍要读API契约。`plusDays`虽没有get，也不改变原日期。旧GregorianCalendar的add会改对象，还使用从0开始的月份；不能把那个规则套到LocalDate.of（月份1–12）。

| 时刻 | start指向的值 | next指向的值 | 发生了什么 |
|---|---|---|---|
| of之后 | 2024-12-31 | 尚未声明 | 创建或取得合法日期值 |
| 不接结果的plusDays后 | 2024-12-31 | 尚未声明 | 返回结果没有被保存 |
| 声明next之后 | 2024-12-31 | 2025-01-01 | 两个变量保留各自值 |
| 循环第一次更新后 | 2024-12-31 | 2025-01-01 | 只有cursor改为指向下一天 |

循环里`cursor = cursor.plusDays(1)`先在右侧算出下一天，再将引用写回cursor。这是变量重新赋值，不是改了不可变对象。每次循环开始时i依次为0、1、2，恰好打印3天，循环结束时cursor已是第4天但没有打印。

## API替你守住哪些规则

2024是闰年，2月28日加一天得到29日；2023同样操作得到3月1日。不要把“加一天”写成简单拼接日数，因为31日后月份和年份也可能变化。`LocalDate.of(2024,2,30)`无法构造合法日期，会在运行时抛DateTimeException；这是参数不满足契约，不是源码语法错误。异常的正式处理在L30，这里只做预测，不让非法日期充当正常输入。

教材的月历算法可用一条路线读懂：保存目标月→把游标移到月初→用星期几决定缩进→每打印一天就让游标前进→月份变了就停。星期一的getValue为1、星期日为7。它是日历规则，不是数组下标规则。你可以用`date.withDayOfMonth(1)`取月初；本课先用讲过的`minusDays(day-1)`，避免一次引入太多新方法。

## 只改一处，再独立做一件事

复制程序，把`LocalDate.of(2024,12,31)`换成`LocalDate.of(2024,2,28)`，先写出三天，再运行：应是28日、29日、3月1日。随后单独改年份为2023，观察少了哪一天。每次只动一个输入，才能把结果变化归因到闰年规则。

独立小任务：从2025-01-30开始打印连续5天，每行附`getDayOfWeek().getValue()`。链式调用先求getDayOfWeek返回的星期枚举对象，再在它上面求整数。不要为此先背完枚举语法；这次只使用现成对象的访问器。若一直打印同一天，检查游标更新是否接住返回值；若少一天，列出循环i的取值。教材API表中提到的方法，以真实LocalDate签名为准；返回日期的of/now不是LocalTime。

## 月份变了才停止：不预先硬写本月最后一天

前面的循环按固定次数前进。月历还有另一种需求：只处理当前月，月底自动停止。把游标想成在日历格上移动的标记；类比边界是LocalDate本身不被涂改，每次都要保存返回的新日期值。

```java
import java.time.LocalDate;
public class MonthExitWalk {
    public static void main(String[] args) {
        LocalDate cursor = LocalDate.of(2025, 4, 27);
        int month = cursor.getMonthValue();
        int count = 0;
        while (cursor.getMonthValue() == month) {
            System.out.println(cursor + " " + cursor.getDayOfWeek().getValue());
            count++;
            cursor = cursor.plusDays(1);
        }
        System.out.println("count=" + count + ", next=" + cursor);
    }
}
```

`month`先保存目标月份，不能每轮都跟着cursor重算，否则比较两边总相同。getMonthValue返回整数，while括号里比较的是这次日期是否仍属目标月；getDayOfWeek先返回星期对象，后一个getValue才给1–7。把两个点号逐步读，不是一个含点号的变量名。

| 检查前cursor | 月份相同吗 | 打印与更新 |
|---|---|---|
| 04-27 | 真 | 打印7，前进到28日 |
| 04-28 | 真 | 打印1，前进到29日 |
| 04-29 | 真 | 打印2，前进到30日 |
| 04-30 | 真 | 打印3，前进到05-01 |
| 05-01 | 假 | 不打印此日，离开循环 |

共打印4个日期，退出cursor却已在下月，二者不矛盾。只把起点27改30，预测会打印几天及退出值；再改成2024-02-28并把目标月随起点保存，观察闰日。独立任务：从某月1日遍历到月份改变，统计该月天数，不用if自行编写闰年表。若程序总不停，先查目标月份是否误放进循环内、游标是否接住plusDays结果。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L11_第04章A_对象行为与日期/code/MonthExitWalk.java'`。改动先复制到my_code，命令相应替换目录。
