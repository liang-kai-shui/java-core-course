# L01 参考答案与解析

对应[本课练习](../练习.md)。先自己尝试，再看为什么。题目为课程原创；允许其他正确解法，参考程序也需要接受核对。以下是材料解析，不是对学生作答的批改结论。

## Q1：不是四个并排的名字，而是一条工作链

保存的 Java 源码先交给 javac，编译结果通常是 class 字节码；java 启动工具找到类，交给 JVM 执行。源码供人和编译工具阅读，字节码供 Java 运行系统处理。

类比“写方案→转换工作单→执行”，必须分清转换与执行不是一件事。不能说“JVM 编译源码”概括本课使用的两步流程，也不能把 class 叫作可在任意电脑双击的 exe。

## Q2：通过工具检查，不代表需求正确

编译成功说明通过这轮编译检查，包括语法和有关类型等检查；它不能证明逻辑符合题意。长方形面积误写加法仍可能正常输出。

class 能否运行还依赖兼容运行环境、库及数据等。跨平台表示适配的平台能遵循相应运行规则，不表示不用安装或提供运行能力。

## E1：两行输出的关键检查

先建立两个 println，括号内各是一段带双引号的文本。执行第一条后换行，再执行第二条。自己的昵称可以不同，行数与第二行含义应符合题目。

验证时保存文件、运行自己的 my_code 路径，记录实际命令和正文；不以助手已经运行过示例代替自己的证据。

## E2：输出受运行环境决定

java.version 记录实际 Java 运行版本，os.name 记录实际操作系统名称。两台机器不同是合理结果；不要为匹配讲义示例去伪造版本。这里只要正确解释环境差异，不要求背某个版本号。

## E3：先定位，再恢复验证

缺分号应在本次编译阶段失败，不能产生可供本次启动的正确结果。诊断可能指到下一行，因为编译器在那里确认语句不完整。

补回分号后重新编译运行，看到预期正文才算完成修复。只写“补了分号”或只留下错误文本，尚未提供恢复验证；批改时应说明缺的是哪份证据，不直接推断学生不会。
