# S04 讲义 · 多个文件怎样组成程序：package、import与classpath

> 前置：S01–S03及L01–L10；能区分类定义、对象、引用、实例方法与静态方法。
> 教材对应：**书本 p105–139 / PDF p123–157**（4.3.2；4.7–4.8（中间4.4–4.6已在S03学习））。本课讲解、比喻、程序与题目为课程原创。

## 0. 你看到两个java文件，究竟该运行哪一个

单文件程序把所有代码放在眼前；真实项目往往一边有src文件夹，一边有build或out，IDE还显示package。若只是挨个点击运行，会把工具类当启动类，也可能从错误的目录找class。

本课让一个问候程序跨两个包工作。**先用两份源码解决一次具体协作，再给目录和名字各自定位。** 你不需要为了学习包先装Maven。

## 1. 源文件是容器，类是定义，程序可以由许多类协作

S02的CardBoard.java里写了两个类。现在把它们拆到两个文件，概念上仍可以是相同的程序。将一个非public辅助类拆成同名文件，并不会自动赋予它main；你仍要选择真正的入口类。

本课改用两个小类：Main安排启动和输出，Greeting负责形成问候文本。它们分属`campus.app`与`campus.text`两个包。**包是组织类型的命名与访问单位**，不是把class字节码压缩起来的文件。

像校园部门给设计部件编完整编号：`campus.text.Greeting`即使与别人的Greeting重名，也能靠全名区分。分类全名与存放设计的磁盘文件仍是两种信息；换一个项目根目录不必把包名改成电脑盘符。

## 2. 先看项目目录，然后看两份文件

在本课code/project有原始样本。用编辑器复制整个project目录到本课my_code下，得到my_code/project；若已有自己的副本，继续使用，**不要覆盖**。

```text
project/                         ← 这个小项目的根目录
└─ src/                          ← 源码根目录，名称是本项目约定
   └─ campus/
      ├─ app/
      │  └─ Main.java            ← 包campus.app，类Main，有入口
      └─ text/
         └─ Greeting.java        ← 包campus.text，类Greeting，供调用
```

`Greeting.java`完整内容：

<!-- source: code/project/src/campus/text/Greeting.java -->
```java-source
package campus.text;

public class Greeting {
    public static String forName(String name) {
        return "Hello, " + name;
    }
}
```

`Main.java`完整内容：

<!-- source: code/project/src/campus/app/Main.java -->
```java-source
package campus.app;

import campus.text.Greeting;

public class Main {
    public static void main(String[] args) {
        String name = args.length == 0 ? "Lin" : args[0];
        System.out.println(Greeting.forName(name));
    }
}
```

两个框是**同一项目的两份完整源码**，不能各自拿单文件脚本当两个独立程序运行。Greeting没有main，不需要给它硬加一个。

Main中`args.length == 0 ? "Lin" : args[0]`先问参数是否为空；空时用Lin，否则取第一个参数。条件表达式只计算选中的一边，所以没参数时不会越界访问args[0]。若还不熟，把它改为已学的if/else同样可以。

## 3. package写“我属于哪里”，import写“这个简称代表谁”

```text
package campus.app;          本文件声明的顶层类属于campus.app包
import campus.text.Greeting; 本文件可用短名Greeting指代这个公有类
```

`package`在普通声明之前，`import`在package之后、类定义之前。没有package的早期样本属于未命名包；它是入门简化，不是推荐把所有工程源码永久堆在一层。

**import不会复制源码，不会下载库，不会创建对象，也不会代替classpath。** 像把通讯录里的全名写成一个可识别的短称；有短称不等于已经把人接到了现场。

可以删掉import，并将调用改为`campus.text.Greeting.forName(name)`，行为相同。只删import却保留短名，编译器不能据此猜另一个包的Greeting。

`import campus.*`不会自动导入`campus.text`里的类；父包与子包不共享这种递归导入，也不自动共享包级访问权限。两个全名相同的类在同一个普通编译集合中也不能随意并存。

本例Greeting与forName都用public，才能从另一个包按此方式访问。没有修饰词的顶层类或成员通常是包级可见，不等同于public；private成员则不能由外部Main随便访问。public也不负责“把库加入搜索路径”。

## 5. 手动编译：输入是文件，输出按包建目录

仍在课程根目录的PowerShell，先选中自己的项目与本机JDK：

```powershell
. .\_课程工具\resolve-jdk.ps1
$jdk = Find-CourseJdk -Root (Get-Location).Path
$projectPath = (Resolve-Path '.\S04_结构基础_文件包与类路径\my_code\project').Path
$out = Join-Path $projectPath ('out-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $out | Out-Null
& "$jdk\bin\javac.exe" --release 8 -encoding UTF-8 -d $out "$projectPath\src\campus\text\Greeting.java" "$projectPath\src\campus\app\Main.java"
if ($LASTEXITCODE -ne 0) { throw '编译失败，停止，不启动旧class。' }
Get-ChildItem -LiteralPath $out -Recurse
```

开头点加空格是PowerShell加载课程提供的函数，`$jdk`保存工具包位置；这些不是Java语法。路径带空格时仍保留引号，`&`执行指定工具。长GUID只让每次out文件夹不同，防止旧产物掩盖失败。

`javac`得到两份**源文件路径**；`-d $out`指定**编译输出根目录**。应观察到：

```text
out-本次编号/
└─ campus/
   ├─ app/Main.class
   └─ text/Greeting.class
```

src没有被塞进生成包名，out-编号也不属于包名；真正声明包的是源码的package行。即使你把源码暂放到另一层，`javac -d`仍按声明的包组织输出；为了源码查找、维护和工具协作，我们按包保持src目录一致。

## 6. 启动时：根目录加完整类名，拼出查找位置

上段编译成功后，在同一个PowerShell继续：

```powershell
& "$jdk\bin\java.exe" -cp $out campus.app.Main
```

`-cp`是classpath的短写。**类路径是查找应用类的目录或JAR入口清单**；这里先只有一个目录。它像告诉档案员“从哪个柜子的根开始找”，完整类名再给出柜内分类。

```text
classpath根：out-本次编号
类全名：     campus.app.Main
相对条目：   campus/app/Main.class
查找位置：   out-本次编号/campus/app/Main.class
```

因此`-cp $out\campus\app Main`不对：启动名丢了包，基目录也选深了。`java campus/app/Main.class`同样把文件路径与类名混了。在本课的类启动模式里用点分全名，不带.class。

### 三种“路径”分清职责

| 名称 | 谁使用 | 找什么 |
|---|---|---|
| PATH | 终端/操作系统查命令 | java.exe、javac.exe等工具 |
| classpath / -cp | Java编译与启动工具查应用类型 | 某目录下的包树或某个JAR里的类 |
| 工作目录 | 进程解释普通相对文件路径 | note.txt等数据文件 |

修改PATH不能让缺失的Greeting.class自动出现；加import也不能弥补运行时缺class。JDK标准库按其运行环境机制提供，JDK 21不用照旧书寻找rt.jar或jre/lib/ext；本课的-cp用于自己的应用类和依赖。

## 7. 用一次找错验证理解

| 只做这一改动 | 阶段与原因 | 应回看哪一层 |
|---|---|---|
| Main里删import，不补全名 | 编译阶段短名不能解析 | 命名 |
| 保留import，把Greeting.class从发布副本漏掉 | 执行到调用处可能报告依赖类缺失 | 运行时文件集合 |
| -cp选到out/campus | 找不到入口全名对应的位置 | 查找根 |
| Greeting改为非public，仍跨包使用 | 编译阶段访问受限 | 访问权限 |

不要在正确原件上移动/删除文件。漏文件实验使用新建的发布副本；保留完整产物作对照。程序已经编译成功，运行时仍需要它实际使用的应用类，这与有没有import文字是两回事。
