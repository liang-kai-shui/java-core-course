## 学完要能做什么

能为一个不可变值对象实现equals(Object)、hashCode和toString；解释相等契约与碰撞；不把散列码当地址或唯一编号。

## 困惑：两张内容一样的书签，为什么==却是false

Object是所有类继承链最终的根；即使不写extends Object，也能调用它提供的基础方法。数组也是对象，int等基本类型值不是对象。一个Object变量能引用很多种对象，但它的声明类型只让你直接调用Object上存在的入口。

身份问“是不是同一实例”，内容相等问“按这项业务的规则，是否可视为同一个值”。像两张复印出来的书签：纸张不是同一张，但书号与页数都一样，可以定义为同一个书签位置。边界是程序的相等规则由API明确决定，不能仅凭外观相同就推断。这里把BookmarkKey设为final不可变类，避开子类增加字段后相等语义冲突的问题。

```java
import java.util.Objects;
public class BookmarkEquality {
    public static void main(String[] args) {
        BookmarkKey a = new BookmarkKey("B7", 12);
        BookmarkKey b = new BookmarkKey("B7", 12);
        System.out.println(a == b);
        System.out.println(a.equals(b));
        System.out.println(a.hashCode() == b.hashCode());
        System.out.println(a);
    }
}
final class BookmarkKey {
    private final String book;
    private final int page;
    BookmarkKey(String book, int page) { this.book = book; this.page = page; }
    @Override public boolean equals(Object otherObject) {
        if (this == otherObject) return true;
        if (otherObject == null || getClass() != otherObject.getClass()) return false;
        BookmarkKey other = (BookmarkKey) otherObject;
        return page == other.page && Objects.equals(book, other.book);
    }
    @Override public int hashCode() { return Objects.hash(book, page); }
    @Override public String toString() { return book + "@" + page; }
}
```

预期四行`false`、`true`、`true`、`B7@12`。第一次是引用身份，第二次按字段比较，第三次验证“相等必须有相同散列码”，最后是可读显示。

equals参数必须是Object才能覆盖根类入口。`equals(BookmarkKey other)`只是重载，集合通过Object入口调用时不会采用你以为的相等规则。@Override是检查工具，签名错就让编译器当场报。先判this==other可快速返回；判null/类不同返回false；通过后再强转并逐字段比较。`Objects.equals(book,other.book)`对两个null安全，只有一个null为false，否则调book.equals；page是int用==。

| 比较 | 身份 | 内容 | 结论 |
|---|---|---|---|
| a与a | 同一对象 | 同字段 | 必须相等 |
| a与b | 不同对象 | 同书号同页 | 本类定义相等 |
| a与null | 不适用 | 没有另一个值 | false |
| a与另一页 | 不同对象 | 页不同 | false |

## 相等不是任意一次返回true就算正确

要满足自反、对称、传递、一致和非null对象不等于null。对称指a.equals(b)与b.equals(a)一致；传递指a等于b、b等于c时a也等于c。一致是在比较依据没变时反复比较结果不变，不是禁止一切可变类实现equals。

继承容易破坏对称：父类只看书号页码，子类还看颜色，可能父类认为相等、子类却不同。若各子类允许自己的相等含义，可用getClass严格同类比较；若整个层次必须共用一种身份含义，可在父类统一并限制覆盖。不存在“一律instanceof最好”或“一律getClass最好”的口诀。本课final值类使规则简单明确。

## hashCode是分组线索，不是身份证

散列容器先用散列码缩小查找，再用equals确认。相等对象必须同散列码；同散列码不保证相等，称碰撞。int范围有限，不可能给无限对象值都分配唯一整数。`Objects.hash(book,page)`组合与equals相同的字段；不能只在equals里看书号页码，hashCode却用随机数或每次运行变化的编号。

默认Object.hashCode不保证是内存地址，也不保证不同对象永远不同。教材相关“地址”的表述应理解为历史实现类比，不能当Java契约；[Object API](https://docs.oracle.com/javase/8/docs/api/java/lang/Object.html#hashCode--)只约束一致性和相等对象散列一致。可变键加入散列容器后若改了用于equals/hash的字段，会破坏检索假设，本课用final字段避免这个问题，L38再实测。

toString只负责显示，不参与equals的定义。println对象时会取得其字符串表示；不要依赖默认的类名@十六进制散列作为业务ID，也别把密码等敏感字段一股脑打印。数组直接println不展开元素，使用Arrays.toString；嵌套数组用deepToString，前课已可对照。

## 参数写成自己的类型，为什么Object视角下相等就失效

方法名字一样不意味着覆盖同一入口。像在楼里另设了一个同名窗口，却没接上原总机入口；边界是覆盖由签名等规则判定，不按“作者想比较内容”的意图判断。

```java
public class EqualityEntryTrap {
    public static void main(String[] args) {
        WrongKey a = new WrongKey(3);
        WrongKey b = new WrongKey(3);
        Object oa = a;
        Object ob = b;
        System.out.println(a.equals(b));
        System.out.println(oa.equals(ob));
    }
}
class WrongKey {
    private final int id;
    WrongKey(int id) { this.id = id; }
    public boolean equals(WrongKey other) { return other != null && id == other.id; }
}
```

WrongKey的equals(WrongKey)是新重载。a.equals(b)编译选择它，结果true；oa与ob声明Object，只能选equals(Object)，WrongKey没有覆盖，于是沿用Object身份比较，结果false。不是对象在赋值后变了，a与oa始终指同一对象。

| 表达式 | 选择入口 | 使用规则 |
|---|---|---|
| a.equals(b) | equals(WrongKey) | 本例按id |
| oa.equals(ob) | equals(Object) | 未覆盖，按身份 |

只在错误方法上加@Override，应编译失败而不是修好相等。正确迁移是按前面BookmarkKey完整模式改成equals(Object)，先检查null/类型再转，并同步hashCode。独立任务：用Object变量调用自己的RoomSeat.equals，确认它也按值；只测RoomSeat声明视角可能遗漏签名错误。
