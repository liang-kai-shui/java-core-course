## 窗口宽度写成abc，默认值为什么没有救场

配置把可变化的选择从编译好的程序中拿出来。像菜单写“默认半糖”，用户没填时才用默认；填了“蓝色糖量”是非法值，不能因为有默认就自动变成合法数字。类比边界是配置不是天然可信，读取、解析、范围验证仍要分步做。

Properties主要用字符串键/值描述配置；虽然历史上继承Hashtable<Object,Object>，本课坚持setProperty/getProperty，不向put塞整数对象。`new Properties(defaults)`保存默认表引用，查主表没找到才沿默认表找；它不是把默认项复制进主表。`getProperty(key, fallback)`的fallback处理没找到，不替你捕捉后续parseInt错误。

```java
import java.io.StringReader;
import java.util.Properties;
public class ConfigFallbackSteps {
    static int positive(String text, int fallback) {
        try { int n = Integer.parseInt(text); return n > 0 ? n : fallback; }
        catch (NumberFormatException e) { return fallback; }
    }
    public static void main(String[] args) throws Exception {
        Properties defaults = new Properties(); defaults.setProperty("width", "300"); defaults.setProperty("height", "200");
        Properties settings = new Properties(defaults); settings.load(new StringReader("title=数组\nwidth=abc\n"));
        System.out.println(settings.getProperty("title", "课程"));
        System.out.println(positive(settings.getProperty("width"), 300)); System.out.println(settings.getProperty("height"));
    }
}
```

程序不读取个人配置文件，用StringReader模拟配置正文。load读入title=数组、width=abc；title成功，width解析失败回退300，缺height沿默认表得到200。输出数组、300、200。parsePositive把缺失/非数字/非正数的业务规则集中，catch仅捕获NumberFormatException，不把所有程序错误当“配置错误”。

| 步骤 | 主表width | 默认width | 对应结果 |
|---|---|---|---|
| 构建主表 | 无 | 300 | getProperty得到300 |
| load | abc | 300 | getProperty得到abc |
| parseInt | abc | 不会自动参与 | 抛NumberFormatException |
| 边界函数处理 | 不修改原配置 | 300 | 返回安全整数300 |

只把width=abc改成width=-2，预测不会抛解析异常但仍被业务范围拒绝。独立任务：限制窗口宽200–1600，分别测缺失、abc、199、200、1600、1601；明确默认回退还是向用户报告错误，不能在不同路径偷偷用不同规则。

## 存储在包内还是包外

发行时的默认配置可作为只读资源；个人改过的窗口状态应放包外可写位置。用户主目录可通过System.getProperty("user.home")查询，但本课不自动在你主目录写文件；演示先内存往返，再让你在my_code里明确选择文件。路径、目录创建失败、权限、磁盘错误都属于需要报告的I/O边界，程序不能“保存失败但提示已保存”。

Properties.load(InputStream)传统格式按ISO-8859-1解释字节，非该字符可用Unicode转义；load(Reader)由Reader决定解码，本课明确UTF-8 Reader/Writer。store输出可能包含日期注释、键顺序也不承诺固定，不把整个文件字节等同唯一正确答案。默认链不会自动全部写进主表的store结果；想导出完整有效配置，要明确合并，不误称存了主表就存了所有默认值。见[Properties API](https://docs.oracle.com/javase/8/docs/api/java/util/Properties.html)。

## 先在内存往返：默认表究竟有没有写进去

```java
import java.io.*;
import java.util.Properties;
public class ConfigRoundTrip {
    public static void main(String[] args) throws Exception {
        Properties defaults = new Properties(); defaults.setProperty("width", "300");
        Properties settings = new Properties(defaults); settings.setProperty("title", "数组");
        StringWriter out = new StringWriter(); settings.store(out, "course config");
        Properties copy = new Properties(); copy.load(new StringReader(out.toString()));
        System.out.println(copy.getProperty("title")); System.out.println(copy.getProperty("width"));
        Properties withDefaults = new Properties(defaults); withDefaults.load(new StringReader(out.toString())); System.out.println(withDefaults.getProperty("width"));
    }
}
```

输出数组、null、300。store只写主表title，没有默认width；copy没有默认表所以null，带defaults的新表再load才取得300。StringWriter/Reader只在内存装字符，不涉及磁盘编码；真实文件必须额外选择编码。只把settings.setProperty("width", "500")加在store前，预测第二、三行都变500。独立任务：导出全部有效项，先遍历stringPropertyNames，再逐项getProperty拷入新Properties，说明为何不能只遍历entrySet就覆盖默认链。

## 真实文件：你明确指定一个新文件，才写入

```java
import java.io.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.Properties;
public class ConfigUtf8File {
    public static void main(String[] args) {
        if (args.length == 0) { System.out.println("path-required"); return; }
        try {
            Path root = Paths.get("").toRealPath(), path = Paths.get(args[0]).toAbsolutePath().normalize();
            Path parent = path.getParent(); if (parent == null || !parent.toRealPath().startsWith(root)) throw new IOException("outside course");
            Properties p = new Properties(); p.setProperty("title", "数组");
            try (Writer out = Files.newBufferedWriter(path, StandardCharsets.UTF_8, StandardOpenOption.CREATE_NEW)) { p.store(out, "course config"); }
            Properties read = new Properties(); try (Reader in = Files.newBufferedReader(path, StandardCharsets.UTF_8)) { read.load(in); }
            System.out.println(read.getProperty("title") + ":" + read.getProperty("width", "300"));
        } catch (FileAlreadyExistsException e) { System.out.println("already-exists"); }
        catch (IOException e) { System.out.println("io-error"); }
    }
}
```

默认输出path-required，不操作文件。在课程根目录PowerShell，追加`-ProgramArgs './L47_第13章B_配置首选项与服务加载/my_code/settings.properties'`创建这个新文件，预期数组:300；目录my_code已提供。再次运行同路径输出already-exists，原文件保留。这里只示范新建，不是假装实现自动覆盖的应用保存流程。newBufferedWriter指定UTF-8与CREATE_NEW，异常时不继续读旧文件伪装本轮成功。

程序要求真实父目录在当前课程工作目录内，避免例子把配置写到别处；这只是本课演示边界，不等于完整的防攻击文件系统安全方案。独立任务：写一个只读现有配置的程序，用newBufferedReader读取自己的文件，给缺键默认值并拒绝非法宽度。

## Preferences：树形位置与每个节点里的键值表

Properties是一个平面表，键里写window.main.width只是名字。Preferences则真的有节点树：`/com/example/course/window`是节点位置，该节点里的width是键；userRoot属于当前用户，systemRoot面向系统，不能随便改成后者绕过权限。操作系统后端透明，不保证所有机器都同一存储文件；typed getInt在缺失/不可解析时用默认值，但正数范围仍需自己验证。

下面使用真正的AbstractPreferences协议，**教学后端只存内存**，不调用userRoot、不改Windows注册表，也不模拟“退出再开已持久化”。七个Spi方法是后端要实现的存取钩子，业务仍用标准node/putInt/getInt；本课只要求理解调用边界，不要求新手背写存储后端。

```java
import java.util.*;
import java.util.prefs.AbstractPreferences;
import java.util.prefs.Preferences;
public class MemoryPreferenceTree {
    static class MemoryNode extends AbstractPreferences {
        private final Map<String, String> values = new HashMap<>();
        private final Map<String, MemoryNode> children = new HashMap<>();
        MemoryNode(AbstractPreferences parent, String name) { super(parent, name); }
        protected void putSpi(String key, String value) { values.put(key, value); }
        protected String getSpi(String key) { return values.get(key); }
        protected void removeSpi(String key) { values.remove(key); }
        protected void removeNodeSpi() { values.clear(); }
        protected String[] keysSpi() { return values.keySet().toArray(new String[0]); }
        protected String[] childrenNamesSpi() { return children.keySet().toArray(new String[0]); }
        protected AbstractPreferences childSpi(String name) { return children.computeIfAbsent(name, n -> new MemoryNode(this, n)); }
        protected void syncSpi() { }
        protected void flushSpi() { }
    }
    public static void main(String[] args) {
        Preferences root = new MemoryNode(null, ""); Preferences node = root.node("/com/example/course/window");
        node.putInt("width", 420); System.out.println(node.absolutePath()); System.out.println(node.getInt("width", 300));
        node.put("width", "bad"); System.out.println(node.getInt("width", 300));
    }
}
```

输出/com/example/course/window、420、300：数字写入可读，随后字符串bad覆盖width，getInt回退。节点名不是磁盘路径；getInt不会记住最初的类型，内部存储仍可表现为字符串。只把bad改-2，预测返回-2而不是300，再解释范围校验属于业务。

真实应用可以用Preferences.userNodeForPackage(YourClass.class)，明确它会取得/创建当前用户节点；put不代表已经可靠落盘，flush请求同步并可能抛BackingStoreException。exportNode只导当前节点键值，exportSubtree还包含子树，importPreferences是静态导入且会修改相应树，不能拿不明XML做无影响预览。迁移时要检查节点命名范围、备份、异常；本课不在自动测试中写入或导入你的个人首选项。

在课程根目录PowerShell运行`./java.ps1 -Source './L47_第13章B_配置首选项与服务加载/code/MemoryPreferenceTree.java'`。

package campus.app;
import java.util.ServiceLoader;
import campus.spi.LabelFormatter;
public class PluginMain {
    public static void main(String[] args) {
        LabelFormatter best = null;
        for (LabelFormatter formatter : ServiceLoader.load(LabelFormatter.class)) {
            if (best == null || formatter.rank() > best.rank()) best = formatter;

}

### 插件不是继承了接口就会自己出现

这个项目额外有一份UTF-8文本，路径相对code/project为`resources/META-INF/services/campus.spi.LabelFormatter`，内容如下（不是Java源码）：

```text
campus.impl.PlainFormatter
campus.impl.BracketFormatter
```

构建将它复制为类路径根的`META-INF/services/campus.spi.LabelFormatter`；文件名是接口全名，行里是实现全名。像行业资格协议、提供服务的商家、登记册三部分：implements只满足协议，没有登记册仍发现不到；类比边界是ServiceLoader不会上网搜商家、不隔离恶意插件，注册后执行的仍是普通程序代码。

`load(LabelFormatter.class)`取得加载器，增强for推进时懒加载实现。Java8类路径提供者需public可访问的无参构造器；本课显式写出。选择逻辑遍历全部后比较rank，不依赖出现顺序；相同rank本例保留先遇到者，如果业务需要稳定胜者应另加明确的名字排序规则。

| 步骤 | 看到什么 | 会不会执行format |
|---|---|---|
| load | 服务类型与加载环境 | 不会 |
| 遍历 | 注册的实现，按需加载构造 | 此时只调rank |
| 比较 | 1与2，选Bracket | 不会 |
| 最后调用 | best.format("数组") | 输出[数组] |

只把BracketFormatter.rank返回2改0，预测改选Plain；独立任务先用这个实验确认算法，再新增第三个实现。新增.java必须进项目sources清单，描述文件也要登记；项目清单在_课程工具/projects.json，先备份该L47配置再编辑sources，不改其他项目。只做个人练习可复制整个课程到自己的练习目录，以免修改公共模板。

漏描述文件可能得到空集合，错类名/无可用构造器/类型不匹配可能抛ServiceConfigurationError；这是装配错误，应报告具体提供者，不把所有Error一概吞成“暂无插件”。本课自动项目检查覆盖正常classpath/JAR/搬动，坏注册的桌面操作需另存个人副本，不声称已经逐一执行所有坏插件。



### 新增提供者，不必修改公共项目清单

个人新增UpperFormatter时，先复制code/project到本课my_code/project，在其中添加`src/campus/impl/UpperFormatter.java`（实现LabelFormatter，public无参构造器，rank返回3，format返回text.toUpperCase(java.util.Locale.ROOT)），并在个人服务文件追加`campus.impl.UpperFormatter`。下面命令编译**个人项目内全部.java**，因此不要求改公共_课程工具/projects.json；原项目的project.ps1仍按固定清单工作，二者范围要分清。

在课程根目录PowerShell，复制并编辑好个人目录后运行：

```powershell
. .\_课程工具\resolve-jdk.ps1
$pluginJdk = Find-CourseJdk -Root $PWD.Path
$pluginRoot = Join-Path $PWD.Path 'L47_第13章B_配置首选项与服务加载\my_code\project'
$pluginBuild = Join-Path $PWD.Path ('.build\plugin-' + [guid]::NewGuid().ToString('N'))
$pluginClasses = Join-Path $pluginBuild 'classes'
New-Item -ItemType Directory -Path $pluginClasses -Force | Out-Null
$pluginSources = @(Get-ChildItem -LiteralPath (Join-Path $pluginRoot 'src') -Filter '*.java' -Recurse | ForEach-Object { $_.FullName })
& (Join-Path $pluginJdk 'bin\javac.exe') --release 8 -encoding UTF-8 -Xlint:all,-options -d $pluginClasses @pluginSources
if ($LASTEXITCODE -ne 0) { throw 'Compilation failed; no old output will run.' }
Copy-Item -LiteralPath (Join-Path $pluginRoot 'resources\META-INF') -Destination $pluginClasses -Recurse
$pluginManifest = Join-Path $pluginBuild 'manifest.mf'
@('Manifest-Version: 1.0', 'Main-Class: campus.app.PluginMain', '') | Set-Content -LiteralPath $pluginManifest -Encoding Ascii
$pluginJar = Join-Path $pluginBuild 'app.jar'
& (Join-Path $pluginJdk 'bin\jar.exe') cfm $pluginJar $pluginManifest -C $pluginClasses .
if ($LASTEXITCODE -ne 0) { throw 'Archive failed; do not run an older JAR.' }
& (Join-Path $pluginJdk 'bin\java.exe') '-Dfile.encoding=UTF-8' -jar $pluginJar
if ($LASTEXITCODE -ne 0) { throw 'Plugin launch failed.' }
```

只有原两个实现时输出[数组]；加入rank=3的大写实现后输出数组（中文不改变大小写，但不再有方括号）。要明显看大写，在java命令最后追加Java，得到JAVA。源码与注册表都在个人副本里，公共模板保留。失败先看首次诊断，不在旧classes目录里盲目重跑。
