## 学完要能做什么

## 按钮正在计算，为什么连关闭窗口都不响应

L40的EDT是一条负责处理界面事件的执行路线。若按钮处理器在这条路上连续算几分钟，它后面的点击就排队。**线程**是进程内的一条执行路线；**任务**是想完成的工作；**进程**是运行中的程序及其资源环境。像一个厨房可有几位厨师，各有自己的“做到哪一步”，却可能碰同一只锅；类比边界是线程不是每人私有全部数据，调度也不保证每人轮流一步，单核上可交错，多核上才可能同时执行。

并发表示多项工作在时间上重叠推进，不等于总比顺序快。创建线程、切换、协调都要成本。用新线程保持界面响应也不能授权它随意修改Swing组件；L53用SwingWorker把结果交回EDT。教材弹球案例把线程加入图形程序，本课先用无窗口程序隔离启动规则，再回到界面，避免把绘图与竞争混成一个难题。

```java
public class StartVersusRun {
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> System.out.println(Thread.currentThread().getName().equals("main") ? "run:main" : "start:helper");
        task.run();
        Thread worker = new Thread(task, "helper"); worker.start(); worker.join(); System.out.println("joined");
    }
}
```

输出run:main、start:helper、joined。task.run是普通方法调用，此刻currentThread仍是main；new Thread(task,"helper")只创建Thread对象，start才让新线程执行run；main随后join等helper结束，才打印joined。本例因join而有明确次序，不以start返回先后猜任务已完成。

### 每个名字到底是谁

`Runnable task`是“无参数无返回值工作”的接口引用，Lambda里的语句定义工作，不在赋值时执行。`Thread worker`是运行机制对象，名字helper用于诊断，不是变量名自动成为线程名。Thread.currentThread返回当前真正执行这行的线程，而不是你手里随便某个Thread变量。

| 语句 | 执行这句的线程 | task中的工作是否运行 |
|---|---|---|
| task赋值 | main | 否 |
| task.run() | main | 是，普通调用 |
| new Thread | main | 否 |
| worker.start() | main发起，新路线随后调度 | 由helper执行 |
| worker.join() | main等待 | helper可继续 |

start只能对同一个Thread成功启动一次，结束后也不能再start；需要重复任务可重新创建Thread，或者在执行器章提交多次任务。join不是启动，不是把两个线程合成一个，也不把被等待线程的运行时异常重新抛给等待者。main声明throws InterruptedException表示自己等待时也可能收到取消请求。

只把worker.start()改worker.run()，预测第二行也在main、join很快返回；独立任务：给两个任务各一个Thread名，最后join两者后再打印all-done，不要求两条任务输出先后固定。若把joined挪到join前，解释这个标签为何不再可信。

## 数据共享比“有几条路线”更关键

每次方法调用的局部变量有自己的调用上下文，但局部变量里装的引用可指向共享对象。两个Runnable捕获同一个数组，就可能操作同一数据。像厨师各有便签，却写着同一口锅的编号；类比不能推导“局部变量所以对象也私有”。本课先用不同槽位保存各自结果，join后统一读取，L51再讲共同更新一个状态所需的同步。

sleep暂停的是**调用它的当前线程**，不会启动新线程；`someThread.sleep(...)`即使语法允许也容易误读，应写Thread.sleep。睡一段时间不是其他线程已经完成的证据；观察输出不能代替join/锁等约定。系统调度、输出缓冲、机器负载均会影响肉眼看到的顺序。

## 中断标志：同样像读取，是否清除却不同

```java
public class InterruptFlagReads {
    public static void main(String[] args) {
        Thread current = Thread.currentThread(); current.interrupt();
        System.out.println(current.isInterrupted()); System.out.println(current.isInterrupted());
        System.out.println(Thread.interrupted()); System.out.println(current.isInterrupted());
    }
}
```

此程序只操作main自己的中断标志，不开新线程。输出true、true、true、false：interrupt置位，两次isInterrupted都不清；Thread.interrupted返回清除前的true，最后isInterrupted读false。它是诊断实验，结束前清掉本次自己置的标志，避免影响后续等待。

只把静态interrupted换成current.isInterrupted，预测最后变true，再补Thread.interrupted清理。独立任务：解释为什么`other.interrupted()`容易误导——静态方法仍查当前执行者，推荐用Thread类名调用。书本p635 / PDF p653把isInterrupted释为“是否终止”不准确，它读中断状态，生命周期用isAlive/getState等区分，已核对[Thread API](https://docs.oracle.com/javase/8/docs/api/java/lang/Thread.html)。

在课程根目录PowerShell运行`./java.ps1 -Source './L49_第14章A_线程启动与中断/code/InterruptFlagReads.java'`。


## 不用猜睡多久：让worker明确报告到达入口

CountDownLatch此处先当“一次性门闩”：new(1)表示还等一次countDown，countDown减至0后await才可通过；await本身可中断。ready是worker向main报到，neverOpen始终不开，用于演示取消等待。本例只有两名角色、有限通知，之后L53再系统讨论同步器。它不靠while轮询Thread.State，不把打印速度当同步机制。

```java
import java.util.concurrent.CountDownLatch;
public class InterruptWaitRoute {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch ready = new CountDownLatch(1), neverOpen = new CountDownLatch(1);
        Thread worker = new Thread(() -> {
            try { ready.countDown(); neverOpen.await(); }
            catch (InterruptedException e) {
                System.out.println("catch=" + Thread.currentThread().isInterrupted()); Thread.currentThread().interrupt();
                System.out.println("restored=" + Thread.currentThread().isInterrupted());
            } finally { System.out.println("cleanup"); }
        }, "waiting-worker");
        worker.start(); ready.await(); worker.interrupt(); worker.join(); System.out.println("done");
    }
}
```

路线是main启动→等ready；worker报到→等neverOpen；main收到报到→interrupt；worker捕获/恢复/清理→结束；main join后打印done。ready发生在await之前或main抢先interrupt都可，程序不要求精确调度点。输出catch=false、restored=true、cleanup、done。

只删恢复那一行，预测restored=false，但任务仍因走到run结尾而退出；独立任务：分别解释“任务边界主动退出”和“下层吞异常继续执行”的不同，不机械说catch里任何不恢复都一定错误。若await抛出，本例不再使用旧结果。

在课程根目录PowerShell运行`./java.ps1 -Source './L49_第14章A_线程启动与中断/code/InterruptWaitRoute.java'`。


## 可中断操作向上传：谁决定退出策略

```java
public class InterruptPropagation {
    static void subTask() throws InterruptedException { Thread.currentThread().interrupt(); Thread.sleep(1000); }
    public static void main(String[] args) {
        Runnable task = () -> {
            try { subTask(); }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); System.out.println("cancelled=" + Thread.currentThread().isInterrupted()); }
            finally { System.out.println("released"); }
        };
        task.run(); Thread.interrupted();
    }
}
```

main先在Thread未启动时普通调用task.run：子任务在当前main自置中断，sleep立刻抛异常，边界恢复，输出cancelled=true与released。最后主程序清掉自己实验置的标志。这是异常传播的单线程路线实验，不冒称线程启动实验；你已在前例看过真实worker。subTask明确throws，层层调用可继续传播；Runnable.run不能添加这个受查异常，因此在边界处理。

只把subTask改成catch空块，边界不再收到异常且标志被sleep清除；先预测released仍运行，而cancelled那行消失。独立任务：把subTask放进上一个真实worker，保留ready通知，由main发请求，避免子任务必须自行取消这个教学设定。

在课程根目录PowerShell运行`./java.ps1 -Source './L49_第14章A_线程启动与中断/code/InterruptPropagation.java'`。
