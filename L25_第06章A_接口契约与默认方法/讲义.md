## 困惑：两个没有共同父类的对象，怎么交给同一种工具

工具需要的可能只是一种能力，例如“能提供任务名”，不关心对象原来继承了谁。**接口**用一组方法约定能力；类用implements明确承诺实现。像插座规定接触方式，不要求所有设备都属于同一种家具。边界是方法签名只是契约的一部分，还要遵守含义；一个name()返回完全无关的随机错误文本，编译可能通过却不算履行业务承诺。

接口变量是通用操作入口，实际对象仍由实现类创建。不能new NamedTask()直接实例化接口；`NamedTask task=new BookTask(...)`的右边才是具体实例。一个类只能extends一个父类，却可implements多个接口；不是复制了多个父类的实例字段。

```java
public class TaskContracts {
    public static void main(String[] args) {
        NamedTask task = new BookTask("泛型");
        System.out.println(task.display());
        System.out.println(NamedTask.category());
    }
}
interface NamedTask {
    String name();
    default String display() { return "task:" + name(); }
    static String category() { return "学习"; }
}
class BookTask implements NamedTask {
    private final String title;
    BookTask(String title) { this.title = title; }
    @Override public String name() { return title; }
}
```

输出`task:泛型`、`学习`。NamedTask接口声明name，BookTask提供public实现；接口中的普通抽象方法在Java8下默认public，类实现时不能省public变成包权限。接口没有构造器，也没有每实例字段；接口声明的字段隐含public static final，不该为了省类名而滥用“常量接口”。

`default String display()`有方法体，可调用抽象name()，因此不需要接口保存标题状态。真正标题仍在BookTask对象中。task.display执行接口默认实现，里面再调用当前对象的name。类也可以覆盖display。**默认方法**是接口提供的继承实现，与前课“默认构造器”不是同一个概念。

`static String category()`属于接口本身，用NamedTask.category()调用，不靠某个对象。教材p217残留“接口不能含静态方法”的旧表述，要结合p218–219 Java8新增规则读；本课程样本就是Java8合法静态接口方法。接口的静态方法不会作为实现类的实例方法继承。

| 表达式 | 接收者/归属 | 走到哪里 |
|---|---|---|
| new BookTask("泛型") | 实现类 | 建立带title状态的对象 |
| task.name() | 实际BookTask | 返回title |
| task.display() | 默认实现 | 拼前缀，再调BookTask.name |
| NamedTask.category() | 接口静态方法 | 返回统一分类 |

## 接口和抽象类各解决什么

抽象类适合共享实例状态和构造规则，接口适合约定可横跨类层次的能力。接口能extends其他接口，也可扩展多个接口；实现类必须满足合并后的需求。不要把接口简单说成“完全没有实现的类”，Java8已有default和static实现，但仍不因此允许接口定义普通实例字段。

默认方法有助于接口演化：添加带合理默认行为的入口，可减少旧实现类必须修改的压力；它不保证任何冲突都能自动解决。具体父类已有对应public实例实现时，类实现优先；两个互不更具体的接口提供同签名默认实现时，实现类必须自己覆盖决定，可以在合法的直接超接口上写`NamedTask.super.display()`选它。更具体的子接口覆盖祖接口默认实现时则采用更具体者。别用“后写的接口获胜”猜顺序。

接口不能用default覆盖Object的public equals/toString等方法。默认方法也不是“所有适配器抽象类都该删除”的证明；有些适配器仍维护状态或兼容旧API。L42还会使用事件适配器，届时按具体职责选。

## 自然顺序也是一种契约

后文独立程序实现Comparable<RankedLesson>。尖括号读作“与RankedLesson比较”，compareTo返回负/零/正分别表示排前、同序、排后，不要求恰好-1和1。整数用Integer.compare避免相减溢出；比较应满足符号反对称、传递和等序一致的要求。排序工具自然顺序入口需要这些对象能互相比较；只写一个同名方法、不implements，不算正式提供Comparable能力。

注意compareTo返回0表示排序上同序，不自动等于equals；若两者不同，需要明确说明，尤其后面TreeSet会按比较结果判重。教材p216 API摘要“否则返回负数”是错字，应为正数，正文前面的规则正确。

## 给排序工具一个自然顺序

问题：排序程序知道怎么交换元素，却不知道一门课应排在另一门之前还是之后。这里给课程一个“按优先级从小到大”的自然顺序，标题只用于显示。同优先级不同标题可能同序但不按内容equals，这条差异要明确。

```java
import java.util.Arrays;
public class NaturalLessonOrder {
    public static void main(String[] args) {
        RankedLesson[] lessons = {new RankedLesson("后", 3), new RankedLesson("早", 1)};
        Arrays.sort(lessons);
        for (RankedLesson lesson : lessons) System.out.println(lesson);
    }
}
final class RankedLesson implements Comparable<RankedLesson> {
    private final String title;
    private final int priority;
    RankedLesson(String title, int priority) { this.title = title; this.priority = priority; }
    @Override public int compareTo(RankedLesson other) { return Integer.compare(priority, other.priority); }
    @Override public String toString() { return title + ":" + priority; }
}
```

输出`早:1`、`后:3`。Arrays.sort直接重排传入数组；Comparable<RankedLesson>令compareTo参数就是RankedLesson。比较器的符号不是布尔值，也不是交换指令：排序算法决定怎样移动，compareTo只回答当前二者的相对顺序。只把后课程优先级3改0，输出顺序就翻转。独立把两项优先级换成最小/最大int，验证Integer.compare不依赖可能溢出的减法。

## 两个默认方法同名时，谁负责作决定

两个设备规范都附了默认显示方案，实现类同时承诺它们时不能凭排列顺序决定。像两张都有效但彼此冲突的说明书，装配方必须明确选择；边界是编译器能发现签名冲突，却不能判断你选的业务含义是否合适。

```java
public class DefaultConflictChoice {
    public static void main(String[] args) {
        LeftLabel item = new LabelChoice();
        System.out.println(item.label());
    }
}
interface LeftLabel { default String label() { return "left"; } }
interface RightLabel { default String label() { return "right"; } }
class LabelChoice implements LeftLabel, RightLabel {
    @Override public String label() { return LeftLabel.super.label() + "/" + RightLabel.super.label(); }
}
```

Choice实现两个直接接口，自己覆盖label消解冲突。LeftLabel.super.label语法明确选直接超接口的默认实现，不是对另一个对象new后调用。类返回组合结果，普通接口变量调用依旧走这个公开覆盖入口。

路线：new Choice→以LeftLabel视角调用label→Choice.label→左右默认实现→拼为left/right。只删Choice的label方法，应编译失败；不能因为implements先写LeftLabel就推断它胜出。独立任务：将类覆盖改为只选右方案，保持调用处不变。再用自己的话区别接口默认方法、默认构造器和字段默认值，这三个“默认”不是同一机制。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L25_第06章A_接口契约与默认方法/code/DefaultConflictChoice.java'`。改动先复制到my_code，命令相应替换目录。
