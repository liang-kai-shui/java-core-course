## 学完要能做什么

能预测静态初始化、实例初始化和构造器正文的次序；区分内存回收与外部资源关闭；不依赖finalize收尾。

## 困惑：还没进入构造器，字段为什么已经有值

初始化可以来自字段声明、初始化块、构造器，必须看执行时刻，而不是只找“写在构造器里的赋值”。类比一间工作室：开门前布置一次公共柜台；每接一位学员准备一份个人材料；最后按申请表补全。边界是类初始化不是文件从磁盘读出的同义词，加载与初始化是不同阶段；此处观察第一次主动new触发的初始化，不声称“类一加载就一定运行static块”。

```java
public class InitSequence {
    public static void main(String[] args) {
        new Session();
        new Session("自选");
    }
}
class Session {
    static { System.out.println("static"); }
    private int value = seed();
    { value++; System.out.println("block:" + value); }
    Session() { this("默认"); System.out.println("outer"); }
    Session(String label) { System.out.println("body:" + label); }
    private static int seed() { System.out.println("field"); return 3; }
}
```

预期输出：

```text
static
field
block:4
body:默认
outer
field
block:4
body:自选
```

`static { ... }`是静态初始化块，类初始化时执行一次。本例第一次new触发它，第二次new不重复。`private int value=seed()`是实例字段初始化器：每次new都会调用seed取得3，接着按源代码次序执行实例块，把value加到4并打印。seed本身是静态方法，只是此处被每个实例初始化调用；“方法static”不意味着“只能执行一次”。

`{ value++; ... }`没有static、没有方法名，是实例初始化块。双参/单参等构造入口最后都会经过实例初始化，但this委托链不会对同一个对象重复执行一遍字段初始化。无参入口先this("默认")，核心构造器正文打印body，返回后外层打印outer。继承下父类先初始化的部分将在L19加入；本课的直接父类是Object。

| 次序 | 首次new | 第二次new |
|---|---|---|
| 类初始化 | static块 | 已完成，不再执行 |
| 对象字段默认值 | value先0 | 新对象value先0 |
| 实例字段/块 | seed→3，块→4 | 新对象同样3→4 |
| 构造器正文 | String入口，再无参剩余部分 | 只有String入口 |

不要把“字段写在文件上方”误解为“整个程序启动就创建所有实例字段”；只有对应对象创建时才准备那份状态。实际设计优先用清楚的构造器与字段初值，初始化块适合读懂已有代码，不必为显示高级而到处使用。

## 对象不再用了，文件是不是也自动关了

垃圾回收管理Java对象占用的内存；文件描述符、网络连接等外部资源有自己的寿命。即使对象最终会被回收，也不能承诺“离开作用域立刻关闭文件”。Java没有C++式作用域结束即调用析构器的规则；这里不假设你会C++，只记住局部变量可见范围结束与资源关闭不是同一事件。

教材介绍finalize属于历史机制，并且已经提醒不能靠它回收稀缺资源。本课程在JDK 21上进一步遵循当前说明：finalization自JDK 18起标记为待移除，不用它写正常示例。[Oracle迁移说明](https://docs.oracle.com/en/java/javase/21/migrate/removed-tools-and-components.html)。本课不写“强制垃圾回收后必定打印清理完成”这种不可保证的实验。

实际资源要有明确close时刻。L31会完整拆解try-with-resources；现在先会读这个使用结构：`try (资源类型 r = 创建资源表达式) { 使用r; }`，正常离开或因异常离开，都会尝试调用r.close。它不负责关闭所有随便放在块中的对象；资源必须实现AutoCloseable。本课的初始化样本不持有外部资源，因此不用伪造close或finalize。

## 只改一处的实验与独立追踪

把第二次new删去，预期第一组输出完整保留，后面的field/block/body消失，而static仍只有一次。再在另一副本把字段初值3改成8，block打印9；这证明块读到了字段初始化后的值。

独立任务：做带编号的PackageItem。公共next从10开始，每次对象初始化时id=next++，构造器保存title；依次创建默认标题与指定标题两份，输出各自id和最终next。要求先写事件表再运行，不用sleep、System.gc或finalize猜执行时机。若static重复出现，先确认是否其实启动了两轮JVM；每次重新运行程序都会重新进行该轮类初始化。

## 收尾不靠猜回收时刻：一个可观察的close范围

下面的“小资源”只打印事件，不占用真实文件。它是为了把开始、使用、关闭、继续四步看见；并不声称打印closed就释放了真实系统资源。真实文件应由对应工具的close负责。

```java
public class ExplicitCloseWalk {
    public static void main(String[] args) {
        try (DemoHandle handle = new DemoHandle()) {
            handle.work();
        }
        System.out.println("after");
    }
}
class DemoHandle implements AutoCloseable {
    private boolean closed;
    DemoHandle() { System.out.println("open"); }
    void work() {
        if (closed) throw new IllegalStateException("closed");
        System.out.println("work");
    }
    public void close() { closed = true; System.out.println("closed"); }
}
```

`implements AutoCloseable`读作“这个类承诺提供close操作”，完整接口知识见L25，本次已给出可使用的全部方法。try圆括号声明资源，花括号是使用范围；离开时调用close，之后才打印after。close必须public，因为它实现公共约定。这里close不抛受检异常，main无需额外throws。

状态路线：进入try前open→体内work→离开范围closed→后续after。资源是否可再用由自己的closed标志记录；不是靠局部变量消失、System.gc或等待几秒。只把try体内work调用删去，预测open/closed/after仍存在。独立任务：在close中把closed置true，提供isClosed，说明测试能验证“我们的关闭协议被调用”，却不能据此推断JVM在同一刻回收了对象内存。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L16_第04章F_初始化与资源生存/code/ExplicitCloseWalk.java'`。改动先复制到my_code，命令相应替换目录。
