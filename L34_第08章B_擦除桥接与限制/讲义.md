## 两种类型实参，为什么getClass仍是同一个类

泛型主要为源码编译检查提供约定。Java为兼容旧代码采用**类型擦除**：无界类型参数常擦成Object，有界参数擦为相应首个界，并在需要处插入强转等支持。像同一套表单的资料类别在办理前检查，底层采用统一存储格式；边界是“擦除”不代表所有类型信息全从class消失，声明的泛型签名还可能供反射读取，L35会区分。

```java
import java.util.ArrayList;
public class ErasureIdentity {
    public static void main(String[] args) {
        ErasedBox<String> a = new ErasedBox<>("Java");
        ErasedBox<Integer> b = new ErasedBox<>(2);
        System.out.println(a.getClass() == b.getClass());
        System.out.println(new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass());
    }
}
class ErasedBox<T> {
    private final T value;
    ErasedBox(T value) { this.value = value; }
    T get() { return value; }
}
```

两行都是true。这里两个ErasedBox对象不同，但`getClass()`的类型描述相同；ArrayList<String>与ArrayList<Integer>也不是两个独立运行时类。不应使用`instanceof ArrayList<String>`，不可具体化的类型实参无法按这种方式完整测试；可用instanceof ArrayList<?>确认外层，再逐项按需要检查内容。

`type == ...getClass()`比较Class描述身份，不是比较盒子内容。源码中title.get仍有String契约，编译器会在擦除后的取值处安排所需检查；不要从同Class推出“泛型完全没用”。

| 关注层 | 观察 | 保证范围 |
|---|---|---|
| 编译源码 | ErasedBox<String>只接String | 静态类型安全 |
| 运行外层身份 | 两个getClass相同 | 同一个泛型原类 |
| 数组运行组件 | String[]与Object[]不同 | 数组仍有组件检查 |

只把第二个盒子的Integer改Double并传2.5，Class比较仍true；两个业务对象依旧不是同一个。独立给first盒子提供错误类型实参观察编译失败，解释“类身份相同”和“源码允许混用实参”是两个问题。

## 擦除后的覆盖为什么还需要桥接

后面的StringSlot把泛型父类的T取值具体化为String。为了让擦除后Object返回入口也能进入正确覆盖，编译器可生成**桥接方法**。它是连接旧入口与具体实现的适配，不是作者写了两个只按返回类型区分的合法重载。反射可看isBridge/isSynthetic，但业务不要手动调用合成桥接来替代正常多态。

## 限制不是背禁令：每项都要有可用路线

不能`new T()`，因为擦除后不知道应选哪个具体构造器；接收Supplier<T>工厂，get时由调用者提供创建。不能`new T[n]`来得到想象中的具体数组；接收IntFunction<T[]>数组工厂或使用列表。不能`new List<String>[n]`，因为运行数组组件检查无法完整验证String实参；ArrayList<List<String>>通常更合适。`List<?>[]`可具体化，仍需按通配符规则使用。

static成员不属于某个T版本，不能引用类的T来声明统一静态字段；静态方法可自己声明独立<T>。泛型类不能直接或间接扩展Throwable，也不能catch(T ex)按擦除后不存在的具体T选择处理器；普通异常类配合泛型业务更清楚。重载若擦除后都成同签名也会冲突，例如方法仅以List<String>和List<Integer>区分不可行。

原始类型和可变参数可能产生堆污染，后面独立错误变体明确展示。@SafeVarargs是作者对安全实现的承诺，不会修补不安全数组写入。Java8只允许合适的static/final方法或构造器使用它；不把抑制警告当修复。

## 把桥接变成可观察事实

反射只查看本课程自己的StringSlot声明，不打开JDK私有字段。getDeclaredMethods的返回次序没有保证，所以只统计bridge与非bridge数量；像查看适配器接了几个口，边界是具体合成方法形态属于编译结果，别依赖名字排列。

```java
import java.lang.reflect.Method;
public class BridgeInspection {
    public static void main(String[] args) {
        Slot<String> base = new StringSlot();
        System.out.println(base.get());
        int normal = 0, bridge = 0;
        for (Method method : StringSlot.class.getDeclaredMethods()) {
            if (method.isBridge()) bridge++; else normal++;
        }
        System.out.println("normal=" + normal + " bridge=" + bridge);
    }
}
class Slot<T> { T get() { return null; } }
class StringSlot extends Slot<String> { @Override String get() { return "child"; } }
```

输出child、normal=1 bridge=1。base声明Slot<String>，运行对象StringSlot，覆盖get返回String；擦除父入口返回Object，编译器提供连接。isBridge识别桥接，而不是作者显式写的另一个同签名方法。只把子get返回文字改next，首行变化、计数不变。独立画父入口→桥接→具体get的路线，说明没有新建业务对象，仍同一次接收者调用。

在课程根目录PowerShell运行`./java.ps1 -Source './L34_第08章B_擦除桥接与限制/code/BridgeInspection.java'`。


## 把创建能力当参数交进来

工厂接口让调用者知道真实类型，工具只负责何时请求。Supplier<T>.get不接参数；IntFunction<T[]>.apply接长度。类比让使用者带来合适模具，工具按约定制作；边界是恶意/错误工厂仍可返回null或错误长度，API契约需要写清，这里用标准构造器引用。

```java
import java.util.function.IntFunction;
import java.util.function.Supplier;
public class TypedFactories {
    static <T> T make(Supplier<T> factory) { return factory.get(); }
    static <T> T[] makeArray(int n, IntFunction<T[]> factory) { return factory.apply(n); }
    public static void main(String[] args) {
        StringBuilder draft = make(StringBuilder::new);
        draft.append("ready");
        String[] values = makeArray(2, String[]::new);
        System.out.println(draft);
        System.out.println(values.length);
    }
}
```

先StringBuilder::new提供动作，factory.get才new；数组工厂同理，apply(2)得到String[2]，首项null。只把2改0，长度0仍合法，程序仍正常结束，因为这里没有读取第0项。若另想观察初始null，保持n>0再增加一次values[0]打印；把这两次修改分开记录。独立按E2设计负长度入口检查，不让失败后沿用之前数组。

原始类型污染可在**错误副本**将main正文换成以下片段：List<String> safe=new ArrayList<>(); List raw=safe; raw.add(1); String x=safe.get(0);。需要导入java.util.List/ArrayList；javac会给rawtypes/unchecked警告，写入1绕过了泛型约束，读取String时才ClassCastException。该片段是故意不安全，不放入正常示例。不要用@SuppressWarnings将它冒充类型安全，也不要误以为错误发生在ArrayList容量分配。

在课程根目录PowerShell运行`./java.ps1 -Source './L34_第08章B_擦除桥接与限制/code/TypedFactories.java'`。


## 完整对照：从安全写入到原始类型污染

先运行安全基线。List<String>声明读取应得到String，写入也受该约定约束。类比同一登记本有明确栏目规则；原始类型则绕开栏目的编译检查，边界是警告不意味着运行时自动替你修正。

```java
import java.util.ArrayList;
import java.util.List;
public class RawPollutionCheckpoint {
    public static void main(String[] args) {
        List<String> safe = new ArrayList<>();
        safe.add("Java");
        String value = safe.get(0);
        System.out.println(value);
    }
}
```

正常输出Java。错误副本只把`safe.add("Java");`改成两句：`List raw = safe; raw.add(Integer.valueOf(1));`。raw与safe是同一列表，未经检查写入Integer后，读取并赋String的强转失败。编译应产生rawtypes/unchecked警告，运行应ClassCastException。与new T的编译失败分开记录。独立任务：恢复带类型的写入，解释加SuppressWarnings为什么不会改变那一个Integer元素。

在课程根目录PowerShell运行`./java.ps1 -Source './L34_第08章B_擦除桥接与限制/code/RawPollutionCheckpoint.java'`。
