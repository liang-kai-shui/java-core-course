## 与其人人抢着改账本，能不能只让一个人记账

可以让工作线程交出不可变指令，由一个消费者顺序处理。**队列**像输送带，生产者放、消费者取；有界容量迫使生产者在下游慢时等待，称为背压。类比边界是队列不会自动知道“今天收工”、不会替你处理全部线程失败，也不把放入后还在乱改的对象变成安全副本。

```java
import java.util.concurrent.*;
public class BoundedMessageFlow {
    static class Message { final int number; Message(int number) { this.number = number; } }
    static final Message END = new Message(0);
    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<Message> queue = new ArrayBlockingQueue<>(2); int[] sum = {0}; Thread[] peers = new Thread[2];
        peers[0] = new Thread(() -> {
            try { for (int n = 1; n <= 3; n++) queue.put(new Message(n)); queue.put(END); }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); peers[1].interrupt(); }
        });
        peers[1] = new Thread(() -> {
            try { while (true) { Message m = queue.take(); if (m == END) break; sum[0] += m.number; } }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); peers[0].interrupt(); }
        });
        peers[0].start(); peers[1].start();
        try { peers[0].join(); peers[1].join(); System.out.println("sum=" + sum[0]); }
        finally { peers[0].interrupt(); peers[1].interrupt(); peers[0].join(); peers[1].join(); }
    }
}
```

一个producer放1、2、3、结束消息，consumer依次取并只在自己的sum槽累加，join后输出sum=6。容量2不代表恰好最多两个任务同时工作，而是最多暂存两个未取消息。END是独立对象并由==确认同一标识，不占用某个正常整数含义；队列禁止null，所以不能用put(null)结束。

### 把类型和调用一层层读

`BlockingQueue<Message>`是接口引用，`new ArrayBlockingQueue<>(2)`选择固定容量实现；Message的final字段在构造后不改，生产后不再变更它。`put`可能等待空位，`take`可能等待数据，也可能抛中断。不是先isEmpty再take，因为检查之后状态可以变；直接让take按协议等待。

| 队列状态 | producer | consumer |
|---|---|---|
| 空 | 可put | take等数据 |
| 满 | put等空位 | 可take |
| 取到END | 不再生产 | 退出循环 |

只把容量2改1，预测仍得6，等待模式可能改变但不能靠输出猜每次调度；独立任务增加第二个consumer时，明确每人一个结束消息或另一完整结束协议，不能只放一个END就保证两个都退出。

这份最小例有一个生产者、一个消费者，数据固定且消费体不会业务失败；中断时两线程互相请求退出，main最后也确保两者被中断并等待。实际流水线要传递失败、取消所有相关任务、处理剩余项，不能照教材递归文件搜索忽略listFiles可能null、I/O失败和线程数无限扩张后仍声称可靠。

## 满了或空了，你希望等、返回还是报错

| 操作 | 异常形式 | 立即返回特殊值 | 无限等到可做（可中断） | 有时限等待 |
|---|---|---|---|---|
| 放入 | add，满时报错 | offer，满时false | put | offer(e,time,unit) |
| 取出 | remove，空时报错 | poll，空时null | take | poll(time,unit) |
| 只看不取 | element，空时报错 | peek，空时null | 无 | 无 |

put/take与offer/poll在满/空时**不等价**，教材书本p669 / PDF p687的相关文字按此表校正，依据[BlockingQueue API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/BlockingQueue.html)。超时返回失败不是成功传递，不能扔掉返回值继续当消息已经入队；null在这里是“本次没取到”，不自动表示所有生产者永久结束。

## 失败策略用最小程序直接观察

```java
import java.util.NoSuchElementException;
import java.util.concurrent.*;
public class QueueFailurePolicies {
    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<String> q = new ArrayBlockingQueue<>(1);
        System.out.println(q.offer("A")); System.out.println(q.offer("B")); System.out.println(q.poll()); System.out.println(q.poll());
        try { q.remove(); } catch (NoSuchElementException e) { System.out.println("empty-error"); }
        q.put("C"); System.out.println(q.offer("D", 0, TimeUnit.MILLISECONDS));
    }
}
```

输出true/false/A/null/empty-error，最后计时offer零等待返回false。只看队列peek不取走，第二次offer不能因为“队列线程安全”就保证有位置。只改容量1为2，重新推算每行，别只改预期最后一个值。独立任务补element与peek对空队列的不同路线，异常单独捕获并说明是运行阶段。

## 原子更新：替换整个读算写，而不是只把变量换个类

```java
import java.util.concurrent.atomic.*;
public class AtomicStatistics {
    public static void main(String[] args) throws InterruptedException {
        AtomicLong sequence = new AtomicLong(), maximum = new AtomicLong(Long.MIN_VALUE); LongAdder total = new LongAdder();
        Runnable low = () -> { for (int i = 0; i < 1000; i++) { final int observed = i; sequence.incrementAndGet(); maximum.updateAndGet(old -> Math.max(old, observed)); total.increment(); } };
        Runnable high = () -> { for (int i = 1000; i < 2000; i++) { final int observed = i; sequence.incrementAndGet(); maximum.accumulateAndGet(observed, Math::max); total.increment(); } };
        Thread a = new Thread(low), b = new Thread(high); a.start(); b.start(); a.join(); b.join();
        System.out.println(sequence.get()); System.out.println(maximum.get()); System.out.println(total.sum());
    }
}
```

输出2000、1999、2000。sequence每次原子加一；maximum的updateAndGet把旧值与观察值纯计算合并；total累计后join再sum。第三行不说明并发中随时读sum都具有单一时刻快照语义。

等价CAS读法是：读old→算next→compareAndSet(old,next)，若期间已变导致false，就从读开始重试。不能写maximum.set(Math.max(maximum.get(),observed))，get/set各自原子而组合不是。AtomicLong函数更新可能重试，函数要无副作用，见[AtomicLong API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/atomic/AtomicLong.html)。

只把初始maximum从Long.MIN_VALUE改0，再只上报负数，解释为何错误保留0；独立任务实现该负数边界。LongAccumulator可用满足结合/交换规则的运算与单位元进行分散累加，如max配Long.MIN_VALUE；它也不替代跨字段事务，不承诺所有场景都快于锁。

## 并发映射：单键原子计数与教材错误对照

```java
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.LongAdder;
public class ConcurrentWordUpdates {
    public static void main(String[] args) throws InterruptedException {
        ConcurrentHashMap<String, Long> counts = new ConcurrentHashMap<>(); ConcurrentHashMap<String, LongAdder> adders = new ConcurrentHashMap<>();
        Runnable task = () -> { for (int i = 0; i < 1000; i++) { counts.merge("java", 1L, Long::sum); adders.computeIfAbsent("java", k -> new LongAdder()).increment(); } };
        Thread a = new Thread(task), b = new Thread(task); a.start(); b.start(); a.join(); b.join(); System.out.println(counts.get("java")); System.out.println(adders.get("java").sum());
        ConcurrentHashMap<String, LongAdder> fresh = new ConcurrentHashMap<>(); LongAdder old = fresh.putIfAbsent("java", new LongAdder()); System.out.println(old == null);
        try { old.increment(); } catch (NullPointerException expected) { System.out.println("first-return-is-null"); }
    }
}
```

先输出2000/2000，两种实现分别统计；再true说明首次putIfAbsent返回null，捕获下一行预期NullPointerException输出first-return-is-null。书本p676 / PDF p694把首次返回描述成新值并直接接increment不正确；应使用computeIfAbsent取得可用计数器，或判断putIfAbsent返回值后选旧/新对象，依据[ConcurrentHashMap API](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ConcurrentHashMap.html)。

回调短小，不在compute/merge中修改该映射的其他位置，不用回调调用次数承担业务事件。ConcurrentHashMap不接受null键/值，merge函数返回null是删除现有条目的协议。并发迭代是弱一致，不会因普通并发修改抛CME，但不是冻结整个映射的快照；size/mappingCount并发时也不是业务事务依据。

教材p674 / PDF p692“最多16个并发写者”的旧实现叙述不应作为Java8/21硬限制；concurrencyLevel是实现估算提示，不是线程准入数。不同并发集合的成本不同，不泛化为所有size一定遍历。独立任务：用merge同时统计两个词并在join后验证各自值；如果总数与两个值必须原子一致，另设计同步边界，不声称多个merge自然成为一个事务。

## 弱一致批操作与可添加的键集：先说明有没有并发修改

```java
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;
public class ConcurrentViewsAndReduction {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Long> map = new ConcurrentHashMap<>(); map.put("A", 2L); map.put("B", 3L);
        System.out.println(map.reduceValues(Long.MAX_VALUE, Long::sum)); String found = map.search(Long.MAX_VALUE, (k, v) -> v > 2 ? k : null); System.out.println(found);
        map.clear(); System.out.println(map.reduceValues(Long.MAX_VALUE, Long::sum)); System.out.println(map.reduceValuesToLong(Long.MAX_VALUE, Long::longValue, 0L, Long::sum));
        map.put("old", 5L); Set<String> keys = map.keySet(1L); keys.add("new"); keys.remove("old"); System.out.println(map.get("new") + ":" + map.containsKey("old"));
        Set<String> independent = ConcurrentHashMap.newKeySet(); independent.add("X"); System.out.println(independent.contains("X"));
    }
}
```

这里没有并发修改，所以reduce得5，search仅有B符合而得B；清空后对象归约为null，基本类型归约为0。Long.MAX_VALUE阈值避免并行拆分，阈值1允许更多并行处理但不保证每次有多少线程，也不保证更快；归约函数应能正确结合，不依赖遍历顺序。并发变化时结果按近似观察理解，不能把这次稳定结果承诺成随时精确总账。

newKeySet创建独立可加的并发Set；map.keySet()通常不能add，map.keySet(defaultValue)才有新增键使用的值。删除键集元素会影响原map，添加已有键不改原值。只改默认1L为9L，预测new对应值变9；独立任务先给new预置7再add，解释不会覆盖。不要把Set视图当深复制。

## 同样线程安全，迭代语义可以完全不同

```java
import java.util.*;
import java.util.concurrent.CopyOnWriteArrayList;
public class SnapshotAndSynchronizedWalk {
    public static void main(String[] args) {
        CopyOnWriteArrayList<String> copy = new CopyOnWriteArrayList<>(); copy.add("A"); Iterator<String> old = copy.iterator(); copy.add("B");
        while (old.hasNext()) System.out.println(old.next());
        try { old.remove(); } catch (UnsupportedOperationException expected) { System.out.println("snapshot-remove-rejected"); }
        System.out.println(copy.size()); List<String> safe = Collections.synchronizedList(new ArrayList<String>()); safe.add("A"); safe.add("B");
        synchronized (safe) { int count = 0; for (String name : safe) if (!name.isEmpty()) count++; System.out.println(count); }
    }
}
```

输出A、snapshot-remove-rejected、2、2。copy的旧迭代器在新增B之前取得，所以仍只有A；集合当前size已2。迭代器remove不支持，不能沿用ArrayList过滤习惯。同步包装器整段遍历锁住safe本体，不锁safe.iterator或另一个new对象；包装器保护单操作，循环是多次调用组合。

只把迭代器创建移到add B之后，预测会遍历A和B；独立任务说明旧快照不是“永远实时且不用锁”。CopyOnWrite每次更新可能复制数组，适合读多写少的用途，不能无条件替代频繁更新列表。教材p680 / PDF p698把Vector/Hashtable称为“弃用”应区分不优先推荐与正式@Deprecated；它们在Java8并未因ArrayList/HashMap出现而被正式废弃。

## 并行数组：操作可分组，计算函数就不能依赖碰巧的次序

```java
import java.util.Arrays;
public class ParallelArraySteps {
    public static void main(String[] args) {
        int[] sorted = {3, 1, 2}; Arrays.parallelSort(sorted); System.out.println(Arrays.toString(sorted));
        int[] generated = new int[3]; Arrays.parallelSetAll(generated, i -> i * 2); System.out.println(Arrays.toString(generated));
        int[] prefix = {1, 2, 3}; Arrays.parallelPrefix(prefix, Integer::sum); System.out.println(Arrays.toString(prefix));
    }
}
```

输出排序[1,2,3]、按索引填[0,2,4]、前缀和[1,3,6]。prefix是每个位置此前所有元素的结合结果，不是把所有元素都写成最终总和。加法在此整数小范围内可结合；减法不结合，浮点加法受舍入影响也不应期待与顺序算法逐位相同。

只把parallelPrefix中的sum换为减法，不设唯一“正确顺序累减”预期；独立任务手画分段合并为什么要求结合律。比较器/生成函数保持无外部可变副作用，不能拿i++作为并行生成器。parallelSetAll只有特定类型重载，不是每一种基本类型数组都有，书本p679 / PDF p697的泛称不能代替查API。

## 队列变体：优先、延迟与交接，不能只看名字猜FIFO

```java
import java.util.concurrent.*;
public class SpecializedQueueRoutes {
    static class Due implements Delayed {
        final String name; final long deadline;
        Due(String name, long millis) { this.name = name; deadline = System.nanoTime() + TimeUnit.MILLISECONDS.toNanos(millis); }
        public long getDelay(TimeUnit unit) { return unit.convert(deadline - System.nanoTime(), TimeUnit.NANOSECONDS); }
        public int compareTo(Delayed other) { return Long.compare(deadline, ((Due) other).deadline); }
    }
    public static void main(String[] args) throws InterruptedException {
        PriorityBlockingQueue<Integer> priority = new PriorityBlockingQueue<>(1); priority.put(2); priority.put(1); System.out.println(priority.take() + ":" + priority.take());
        DelayQueue<Due> delays = new DelayQueue<>(); delays.put(new Due("future", 60000)); System.out.println(delays.poll()); delays.put(new Due("ready", -1)); System.out.println(delays.take().name);
        LinkedTransferQueue<Integer> transfer = new LinkedTransferQueue<>(); int[] value = {0}; Thread consumer = new Thread(() -> { try { value[0] = transfer.take(); } catch (InterruptedException e) { Thread.currentThread().interrupt(); } });
        consumer.start(); try { transfer.transfer(5); consumer.join(); System.out.println(value[0]); } finally { consumer.interrupt(); consumer.join(); }
    }
}
```

PriorityBlockingQueue构造参数1是初始容量提示，不是上限，仍能put两个再按1、2取。DelayQueue内future尚未到期时poll=null，加入已到期ready后take取得ready；队列非空不等于头部已经可取。Delayed同时提供getDelay和排序，时间单位用TimeUnit换算；本例安排一分钟后到期的条目与已到期条目，不用睡眠等待到期。

LinkedTransferQueue.transfer把值交给消费者，返回意味着交接已被取走，不等于消费者业务处理已经完成；main随后join消费者才读处理结果5。LinkedBlockingQueue默认容量上限Integer.MAX_VALUE，现实仍受内存限制；ArrayBlockingQueue明确给容量，ConcurrentLinkedQueue是非阻塞操作，不因空队列而等待。双端阻塞队列按First/Last选两头，选错端就改变任务顺序。

只把PriorityBlockingQueue换ArrayBlockingQueue(1)而保留两个连续put且没有消费者，会卡在第二个put，说明不能机械替换。独立任务用offer验证容量差异，避免故意把正常程序挂住。延迟/优先队列的无界不代表没有资源风险，应按实际任务控制输入速度。
