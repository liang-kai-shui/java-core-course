## 困惑：程序没抛异常，结果为什么仍然错

异常机制不能替你证明公式正确。面积写成宽加高可能顺利运行，却不满足需求。调试要先写清**预期**，再找实际执行第一次偏离的地方。把日志想成沿途观察记录、断言想成内部检查点、输入校验想成入口规则；边界是它们都不是自动修复器，也不能仅凭“没有红字”证明业务正确。

对外输入要始终校验，不能只写可能被禁用的assert。内部本应成立的假设可以断言；运行诊断过程可留日志。不要在assert条件里放必需的赋值、计数或保存文件，因为禁用断言后这些副作用也不会发生。

## 日志为什么设置了FINE还看不到

**Logger记录器**决定某级别记录是否进入管线；**Handler处理器**决定送到哪个出口并再次筛选；**Filter过滤器**按内容筛；**Formatter格式化器**决定显示样式。像编辑部先收稿，再分发到不同栏目，各栏目还可以筛选与排版；边界是父子Logger并不是Java包的访问关系，命名虽类似，规则不同。

```java
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.util.logging.Formatter;
import java.util.logging.Level;
import java.util.logging.LogRecord;
import java.util.logging.Logger;
import java.util.logging.StreamHandler;
public class LoggingPipeline {
    public static void main(String[] args) throws IOException {
        Logger logger = Logger.getLogger("course.lesson32");
        logger.setUseParentHandlers(false);
        logger.setLevel(Level.FINE);
        ByteArrayOutputStream buffer = new ByteArrayOutputStream();
        StreamHandler handler = new StreamHandler(buffer, new CompactLog());
        handler.setEncoding("UTF-8");
        handler.setLevel(Level.INFO);
        logger.addHandler(handler);
        try {
            logger.fine("hidden");
            handler.setLevel(Level.FINE);
            logger.fine("step");
            handler.setFilter(record -> !record.getMessage().equals("skip"));
            logger.info("skip");
            logger.log(Level.INFO, "ready {0}", "L32");
            logger.log(Level.WARNING, "read", new IOException("missing"));
            handler.flush();
            System.out.print(new String(buffer.toByteArray(), StandardCharsets.UTF_8));
        } finally { logger.removeHandler(handler); handler.close(); }
    }
}
class CompactLog extends Formatter {
    @Override public String format(LogRecord record) {
        String error = record.getThrown() == null ? "" : "|" + record.getThrown().getClass().getSimpleName();
        return record.getLevel().getName() + ":" + formatMessage(record) + error + "\n";
    }
}
```

预期：

```text
FINE:step
INFO:ready L32
WARNING:read|IOException
```

第一条hidden没有出现，因为Logger已允许FINE，但Handler还只收INFO以上；之后把Handler也设FINE，step才通过。skip的级别足够，却被过滤器拒绝。`setUseParentHandlers(false)`避免同时交父处理器再输出一遍；本例只配置自己的Logger，不改机器或JDK的全局配置。

| 消息 | Logger门槛 | Handler门槛/过滤 | 结果 |
|---|---|---|---|
| hidden FINE | FINE，允许 | INFO，拒绝 | 不输出 |
| step FINE | 允许 | 已改FINE，允许 | 输出 |
| skip INFO | 允许 | filter拒绝 | 不输出 |
| ready INFO | 允许 | 允许 | 输出并替换{0} |
| read WARNING+异常 | 允许 | 允许 | 显示消息与异常类型 |

本例用ByteArrayOutputStream暂存字节，StreamHandler把格式化记录按UTF-8写进去，flush确保缓冲内容送出，再用UTF-8还原打印。它不是文件持久化，仅为稳定观察管线。CompactLog extends Formatter的format接一条LogRecord；formatMessage处理参数替换和资源包本地化，getMessage只取原始文本。getThrown可能为空，所以先判null再读异常类型。

finally里从Logger移除并关闭我们创建的Handler；不关闭System.out。这里buffer关闭不影响控制台。`logger.log(Level.WARNING,"read",异常对象)`保留异常本身，不仅是一段含糊“失败了”。正式日志可用支持堆栈的格式器，这个紧凑示例故意只显示异常类型方便逐行预测，不能说它输出了完整堆栈。

## 级别、配置、文件与本地化再往前一步

SEVERE、WARNING、INFO、CONFIG、FINE、FINER、FINEST从高到低；ALL/OFF用于全开/关闭。门槛收“等于或更高”，不是只收那个单一级别。未显式设级别的Logger可沿命名层次继承有效级别；父处理器也可能接到记录，重复输出先查是否同时装了两条出口。

ConsoleHandler通常输出System.err；stdout重定向不一定包含它。FileHandler可按显式路径、近似大小限制和循环数量轮换，append控制追加；%h为用户目录、%t为临时目录、%g为轮换序号、%u为冲突编号。本课程练习若写日志，选项目内自己建立的目录，先说明覆盖/追加规则，不沿用默认文件位置到处找。SocketHandler把记录送网络端点，本课只解释职责，不需要启动网络服务。

可用启动属性`-Djava.util.logging.config.file=配置路径`指定专用properties配置，或程序调用LogManager读取配置；别把某个Logger的level误写成任意-D系统属性就以为生效。当前JDK的默认配置布局与旧jre/lib不同，本课用程序内显式配置，保持可复现。国际化资源包按键映射不同语言文字，日志传键与{0}参数；S06的资源定位模型仍适用，L47再区分Properties与ResourceBundle的编码规则。entering/exiting/throwing可记录调用轨迹，logp可显式指定来源类和方法。

## 断言：同一份class，启动选项不同

后文RuntimeAssertions用`assert value>=0 : "内部值不应为负:"+value;`表达内部假设，条件失败抛AssertionError。默认应用断言禁用；`-ea`启用，`-da`禁用，还可按类/包选择；系统类另有-esa。开关影响执行检查，不需要修改源码或重新编译，教材“发布时移走”不要误解成你必须删除所有assert。

value在这个诊断样本中模拟上游已应校验的内部结果，负输入专门用于观察断言；它不是可投入使用的用户输入解析器。实际公开方法的非法参数应始终用if/异常维护契约，不能指望用户也开-ea。断言失败应暴露内部bug，不把catch AssertionError后继续办理当常规恢复。

## 调试有顺序，工具才有目标

拿面积例子先写输入2、3→预期6，再追实际取值2、3→执行加法得5。修改乘号后回归0、3与2、3，不要为了让某个输出对上而在println里加1。保存失败输入、最小源码、实际命令、运行JDK和第一处分歧，能让别人复现。

可设置断点在赋值/分支处，观察局部变量、this与调用栈；单步进入看被调方法，单步越过观察调用结果。只检查打印的最终值不如同时检查中间状态。javac的-Xlint诊断可疑但未必非法的代码，不能代替运行验证；本课程编译已启用相应警告。Class加载诊断`-verbose:class`帮助找加载来源，不能修复错误classpath本身。

未捕获异常处理器可按线程记录最后失败信息，它是终止前报告，不是让原失败语句恢复执行；L50会实际使用。jconsole观察内存、线程等进程指标，先识别你要检查的那个JVM进程；堆转储记录对象图供专门工具分析，不能从一张内存曲线立刻判内存泄漏。教材旧jhat已移除，当前迁移文档列出jcmd/jmap与Flight Recorder等方向，[Oracle说明](https://docs.oracle.com/en/java/javase/21/migrate/removed-tools-and-components.html)。本课不要求安装历史工具，不把旧-Xprof当作本机必备命令。

## 一处实验与独立任务

## 实际运行断言开关：先编译一次，再启动两次

这个程序模拟内部结果验证；默认9为合法值，负数是故障注入。`desiredAssertionStatus()`只报告该类的断言状态，不启用断言。Math.sqrt对负数返回NaN，因此关掉断言时程序仍能继续但没有有意义实数结果；不能拿这种表现作为正常用户输入处理。

```java
public class RuntimeAssertions {
    public static void main(String[] args) {
        int value = args.length == 0 ? 9 : Integer.parseInt(args[0]);
        System.out.println("enabled=" + RuntimeAssertions.class.desiredAssertionStatus());
        assert value >= 0 : "内部值不应为负:" + value;
        System.out.println(Math.sqrt(value));
    }
}
```

平常java.ps1命令默认输出`enabled=false`与`3.0`。下面在课程根目录PowerShell逐行执行：创建唯一的编译输出目录，--release8编译一次，失败立即throw，成功后用同一路径启动两次。

```powershell
. .\_课程工具\resolve-jdk.ps1
$assertJdk = Find-CourseJdk -Root (Get-Location).Path
$assertOut = Join-Path '.build' ('L32-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $assertOut -Force | Out-Null
& (Join-Path $assertJdk 'bin\javac.exe') --release 8 -encoding UTF-8 -g -d $assertOut '.\L32_第07章C_断言日志与调试\code\RuntimeAssertions.java'
if ($LASTEXITCODE -ne 0) { throw 'Compilation failed; do not run old class' }
& (Join-Path $assertJdk 'bin\java.exe') -cp $assertOut RuntimeAssertions
& (Join-Path $assertJdk 'bin\java.exe') -ea -cp $assertOut RuntimeAssertions
```

第一次false/3.0，第二次true/3.0。-ea在类名之前是JVM选项；放在类名之后会变成应用参数，不能启用断言。两次命令之间不再javac，说明开关无需重编译。保留这轮PowerShell变量，给两次启动命令末尾各加`-1`再逐条运行：关闭断言时false/NaN；启用时true后AssertionError并指出内部负值，非零退出。这是预期失败，修改实验回到9才属于正常运行。控制台可能乱码时检查PowerShell/Java UTF-8设置，但不要把乱码与断言是否触发混为一个问题。

独立把断言消息改成能说明你内部假设的文字，不在条件里自增变量。实际输入前始终校验的版本用if拒绝负值，与这里的故障演示分开保存。

在课程根目录PowerShell运行`./java.ps1 -Source './L32_第07章C_断言日志与调试/code/RuntimeAssertions.java'`。

## 用中间状态定位公式，别在最后的println补数字

调试像沿配送路线逐站核对包裹：知道正确终点后，找第一处偏离的站点。边界是本例只验证小非负整数，不把它当已解决任意大输入溢出的通用几何库。

```java
public class AreaCheckpoints {
    static int area(int width, int height) { return width * height; }
    static void check(int width, int height, int expected) {
        int actual = area(width, height);
        System.out.println(width + ":" + height + " expected=" + expected + " actual=" + actual + " mismatch=" + (actual != expected));
    }
    public static void main(String[] args) {
        check(2, 3, 6);
        check(0, 3, 0);
    }
}
```

check记录输入、期望、实际，最后用!=给出是否分歧。area独立于显示，便于检查和重用。正常两组均mismatch=false；只把乘号改加号，2/3得到5、0/3得到3，两组都暴露公式错误。再在打印时临时加1只能碰巧修第一组，第二组仍错。

| 检查站 | 2与3 | 0与3 |
|---|---|---|
| 读入值 | 正确2/3 | 正确0/3 |
| 错误加法 | 首次偏离得5 | 首次偏离得3 |
| println | 只显示错误结果 | 同左 |

独立任务：保留错误副本、最小输入、启动命令，再修area中的运算，重复两个用例。若用调试器，把断点放在return前看width/height，单步越过后看actual。日志格式或字号不是导致结果5的原因；解释必须指到第一次错误计算。

运行现成示例：在课程根目录PowerShell输入`./java.ps1 -Source './L32_第07章C_断言日志与调试/code/AreaCheckpoints.java'`。改动先复制到my_code，命令相应替换目录。
