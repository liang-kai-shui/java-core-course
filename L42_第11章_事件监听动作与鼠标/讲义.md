## 1. 点击按钮后发生了什么：源、监听器、事件对象

按钮被点击时，按钮自己并不知道你想做什么。它只负责把“我被点了”这件事包装成一个 `ActionEvent` 对象，然后交给事先注册在它身上的监听器。教材 p439–440 把这套机制叫事件委托模型：事件源负责产生并分发事件，监听器负责响应。

可以把它想成快递柜：柜子（事件源）只管把包裹（事件对象）放进格口，并通知你留过的手机号（监听器）；包裹里写了寄件信息（`getSource`、`getActionCommand`），你拿到后决定怎么处理。类比边界是：监听器不是“柜子的一个部件”，它是独立对象，同一个监听器可以注册到多个事件源上；事件源也不关心监听器内部做什么。

```java
import java.awt.EventQueue;
import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
public class ButtonEventRoute {
    static class StepPanel extends JPanel {
        private static final long serialVersionUID = 1L;
        private int count;
        private final JLabel label = new JLabel("0");
        private final JButton button = new JButton("记录一步");
        StepPanel() {
            add(label); add(button);
            button.addActionListener(event -> { count++; label.setText(Integer.toString(count)); });
        }
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) EventQueue.invokeAndWait(() -> {
            StepPanel panel = new StepPanel(); panel.button.doClick(0); panel.button.doClick(0);
            System.out.println("count=" + panel.count); System.out.println("label=" + panel.label.getText());
        }); else EventQueue.invokeLater(() -> {
            JFrame frame = new JFrame("事件路线"); frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.add(new StepPanel()); frame.pack(); frame.setLocationByPlatform(true); frame.setVisible(true);
        });
    }
}
```

无参数运行后点两次按钮，标签从 0 变到 2；`--check` 用 `doClick(0)` 模拟两次点击，输出 `count=2`、`label=2`。`doClick(0)` 是按钮提供的“程序化点击”，它同步触发 `ActionEvent`，所以检查里不需要真的用鼠标。

| 时刻 | 事件源（按钮） | 监听器 | 面板状态 |
|---|---|---|---|
| 构造时 | 创建按钮 | `addActionListener` 注册 | count=0，标签"0" |
| 第1次点击 | 创建 ActionEvent 并分发 | `actionPerformed` 执行 | count=1，标签"1" |
| 第2次点击 | 再创建并分发 | 再执行一次 | count=2，标签"2" |
| `setText` 后 | 按钮不管 | 监听器结束 | 组件请求重绘，稍后由 EDT 画 |

注意最后一行：`label.setText` 只是改了组件状态并请求重绘，不是立刻把像素画上去；真正重绘仍发生在 EDT 的下一次处理中。这与 L40 的“绘制是回调”是同一条规则。

三个角色各有一个常用方法：`event.getSource()` 返回事件源（这里就是按钮），`event.getActionCommand()` 返回命令字符串（按钮默认是标签文字，可用 `setActionCommand` 改）。教材 p446 提醒：用 `getSource()` 在一堆 `if/else` 里分辨按钮，是可行但不推荐的写法；更好的做法是让每个入口带着自己的上下文（下一节的 `Action`）。

只改一处的实验：把 `count++` 改成 `count += 2`，预测两次点击后的 `count` 与标签；再改回。若你同时改了点击次数，就无法判断变化来自哪一处。

独立小任务：给面板再加一个“清零”按钮，点击后把 `count` 设回 0 并更新标签；要求两个按钮的监听器都能访问同一份状态，说明你把状态放在了哪一层。

## 2. 注册顺序不是承诺：实测先注册的反而后收到

一个按钮可以注册多个监听器，教材 p441 说点击时“按钮会调用所有监听器的 `actionPerformed`”。但“按什么顺序调用”并没有写进 `ActionListener` 的契约。先写一个实验看清楚。

```java
import java.awt.EventQueue;
import java.awt.event.ActionListener;
import java.util.ArrayList;
import java.util.List;
import javax.swing.JButton;

public class ListenerRegistrationOrder {
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            JButton button = new JButton("go");
            List<String> log = new ArrayList<>();
            ActionListener first = event -> log.add("first");
            ActionListener second = event -> log.add("second");
            ActionListener third = event -> log.add("third");
            button.addActionListener(first);
            button.addActionListener(second);
            button.addActionListener(third);
            button.doClick(0);
            System.out.println(String.join(",", log));
            button.removeActionListener(second);
            button.doClick(0);
            System.out.println(String.join(",", log));
        });
    }
}
```

先预测两行输出，再运行。实际是：

```text
third,second,first
third,second,first,third,first
```

第一行是“后注册的先通知”，与大多数人以为的 `first,second,third` 相反。这不是你写错了：Swing 的按钮把监听器放在 `EventListenerList` 里，分发时从数组尾部向前走，所以当前实现表现为逆序。第二行在第一轮之后追加了移除 `second` 后的第二轮：只剩 `third` 和 `first`，日志里就是 `...,third,first`。

| 阶段 | 已注册 | 点击后日志追加 | 完整日志 |
|---|---|---|---|
| 第一次 | first,second,third | third,second,first | third,second,first |
| 移除second | first,third | third,first | third,second,first,third,first |

这个实验最重要的结论不是“记住逆序”，而是：**不要依赖监听器顺序**。规范不保证顺序，换组件、换 JDK 实现、换成别的监听器列表都可能改变。如果两件事有先后依赖，应该让一个监听器按顺序调用两个方法，而不是注册两个监听器赌顺序。

`removeActionListener` 移除的是同一个对象引用；如果你注册的是 Lambda，每次写的 Lambda 都是不同对象，之后用另一个“看起来一样”的 Lambda 是移除不掉的。要移除，就把监听器先存进变量，注册和移除用同一个变量。

只改一处的实验：把 `third` 的注册移到最前，预测新顺序，再运行。你会发现输出仍然是“后注册的先通知”，只是数组里的先后变了。

独立小任务：写两个监听器，一个把计数加一，另一个把计数乘二；用两次点击验证“顺序不同结果不同”，然后改成单个监听器内部按固定顺序调用两个方法，说明为什么后者可控。

## 3. 同一个契约的三种写法：类、匿名类、Lambda

`ActionListener` 只有一个方法 `actionPerformed(ActionEvent)`，所以它可以用三种写法实现：独立的监听器类、匿名内部类、Lambda。教材 p445 的建议是：动作简单、每个监听器只做一件事时用 Lambda；有状态、要复用、要移除时用类。

```java
import java.awt.EventQueue;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;
import javax.swing.JButton;

public class ListenerStyles {
    static class Counter implements ActionListener {
        private int count;
        public void actionPerformed(ActionEvent event) { count++; }
    }

    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            Counter counter = new Counter();
            JButton byClass = new JButton("class");
            JButton byAnonymous = new JButton("anonymous");
            JButton byLambda = new JButton("lambda");
            byClass.addActionListener(counter);
            byAnonymous.addActionListener(new ActionListener() {
                public void actionPerformed(ActionEvent event) { counter.count++; }
            });
            byLambda.addActionListener(event -> counter.count++);
            byClass.doClick(0);
            byAnonymous.doClick(0);
            byLambda.doClick(0);
            System.out.println("count=" + counter.count);
        });
    }
}
```

输出 `count=3`：三个按钮各点一次，三种写法都在改同一份 `counter.count`。语法不同，契约相同——这也是 Lambda 能替代匿名类的前提。

| 写法 | 什么时候用 | 能不能移除 | 典型问题 |
|---|---|---|---|
| 独立类 | 有状态、要复用、要作为字段 | 能，注册与移除同一对象 | 需要把外部状态传进去 |
| 匿名类 | 老代码、需要覆盖多个方法 | 难，没有变量就找不到对象 | 代码冗长；`this` 指向匿名类 |
| Lambda | 一句话动作 | 能，但必须先存变量 | 捕获的局部变量必须 effectively final |

`ListenerStyles` 里的 Lambda 直接访问了 `counter`（一个引用变量），因为 `counter` 从未被重新赋值，满足“有效 final”。如果后面写 `counter = new Counter()`，Lambda 就编译不过。教材 p448 还提到一个历史差异：匿名类里的 `this` 指匿名类自身，Lambda 里的 `this` 指外围对象；这也是新代码偏向 Lambda 的原因之一。

只改一处的实验：把 `byLambda.addActionListener(event -> counter.count++)` 改成 `event -> System.out.println("lambda")`，预测 `count` 变成多少。你会发现“点了按钮”不等于“计数一定增加”，取决于监听器做了什么。

独立小任务：把 `Counter` 改成带初始值的类 `Counter(int start)`，三种写法都让它从 10 开始计数，验证最终是 13；说明状态放在监听器对象里和放在外部面板里各有什么代价。

## 4. 一个命令、多个入口：Action

按钮、菜单项、快捷键往往执行同一件事。如果给每个入口各写一个 Lambda，命令的启用状态、名称、图标就要维护三份。教材 p453–454 给出的办法是 `Action`：把“命令的名称、图标、参数、启用状态、执行体”打包成一个对象，再让多个入口共享它。

`Action` 是接口，它扩展自 `ActionListener`，所以任何需要 `ActionListener` 的地方都能用 `Action`。实际编程中通常继承 `AbstractAction`，它已经实现了除 `actionPerformed` 之外的方法；名称、图标等用 `putValue` 存进一个名/值表。

```java
import java.awt.EventQueue;
import java.awt.event.ActionEvent;
import javax.swing.AbstractAction;
import javax.swing.Action;
import javax.swing.JButton;
import javax.swing.JComponent;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.KeyStroke;
public class SharedActionBinding {
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            JLabel label = new JLabel("A"); JPanel panel = new JPanel();
            Action action = new AbstractAction("Blue") {
                private static final long serialVersionUID = 1L;
                public void actionPerformed(ActionEvent event) { label.setText("B"); }
            };
            JButton first = new JButton(action), second = new JButton(action);
            panel.add(first); panel.add(second); panel.add(label);
            panel.getInputMap(JComponent.WHEN_IN_FOCUSED_WINDOW).put(KeyStroke.getKeyStroke("ctrl B"), "course.blue");
            panel.getActionMap().put("course.blue", action);
            first.doClick(0); System.out.println(label.getText());
            Object key = panel.getInputMap(JComponent.WHEN_IN_FOCUSED_WINDOW).get(KeyStroke.getKeyStroke("ctrl B"));
            System.out.println("bound=" + (panel.getActionMap().get(key) == action));
            action.setEnabled(false); System.out.println("enabled=" + first.isEnabled() + ":" + second.isEnabled());
        });
    }
}
```

输出：

```text
B
bound=true
enabled=false:false
```

第一行：点第一个按钮，共享动作把标签从 A 改成 B。第二行：`ctrl B` 在输入映射里对应动作键 `course.blue`，动作映射里这个键又指回同一个 `action`，所以 `bound=true`——键盘入口与按钮入口确实是同一个对象。第三行：停用动作后，两个由它创建的按钮一起变成不可用；不需要逐个 `setEnabled`。

| 入口 | 绑定方式 | 共享的是什么 |
|---|---|---|
| 按钮 | `new JButton(action)` | 同一个 Action 对象 |
| 菜单项 | `new JMenuItem(action)`（第12章） | 同上 |
| 快捷键 | `InputMap` + `ActionMap` | 同上 |

`new JButton(action)` 会从动作里读 `Action.NAME` 作为按钮文字、读 `SMALL_ICON` 作为图标、把 `SHORT_DESCRIPTION` 设为工具提示，并自动把动作注册成监听器。这就是“一个命令、多个入口”能成立的原因。

只改一处的实验：把 `action.setEnabled(false)` 改成 `first.setEnabled(false)`，预测最后一行输出。前者停的是“命令”，后者只停“一个按钮”，这正是 Action 与组件要分开的理由。

独立小任务：给同一个 Action 再加第三个按钮，并把 `Action.NAME` 改成“变蓝”；运行后说明按钮文字从哪里来，以及停用动作时三个按钮是否一起变灰。

## 5. 键盘也能触发同一个动作：KeyStroke、InputMap、ActionMap

按钮点击之外，用户还可能按 `Ctrl+B`。Swing 的键盘绑定分两层：`InputMap` 把“按键”映射到一个**动作键**（任意对象，习惯用字符串），`ActionMap` 再把动作键映射到 `Action`。教材 p456–457 特意提醒：不要把会显示、会被翻译的动作名当作映射键，最好用一个内部名字，例如 `course.blue`。

```java
import java.awt.EventQueue;
import javax.swing.JComponent;
import javax.swing.JPanel;
import javax.swing.KeyStroke;

public class InputMapConditions {
    public static void main(String[] args) throws Exception {
        EventQueue.invokeAndWait(() -> {
            JPanel panel = new JPanel();
            KeyStroke ctrlB = KeyStroke.getKeyStroke("ctrl B");
            panel.getInputMap(JComponent.WHEN_IN_FOCUSED_WINDOW).put(ctrlB, "course.blue");
            System.out.println("window=" + panel.getInputMap(JComponent.WHEN_IN_FOCUSED_WINDOW).get(ctrlB));
            System.out.println("focused=" + panel.getInputMap(JComponent.WHEN_FOCUSED).get(ctrlB));
            System.out.println("ancestor=" + panel.getInputMap(JComponent.WHEN_ANCESTOR_OF_FOCUSED_COMPONENT).get(ctrlB));
        });
    }
}
```

输出：

```text
window=course.blue
focused=null
ancestor=null
```

同一个按键在三张输入映射里是三个独立的表：只往 `WHEN_IN_FOCUSED_WINDOW` 放，另外两张查出来就是 `null`。这不是“绑定失败”，而是你只注册了一张表。

| 条件 | 什么时候生效 | 适合放什么 |
|---|---|---|
| `WHEN_FOCUSED` | 这个组件自己拥有键盘焦点 | 输入框内的快捷键 |
| `WHEN_ANCESTOR_OF_FOCUSED_COMPONENT` | 这个组件是拥有焦点组件的祖先 | 面板级的命令 |
| `WHEN_IN_FOCUSED_WINDOW` | 这个组件在拥有焦点的窗口里 | 整个窗口都能用的快捷键 |

教材 p456 还讲了查找顺序：先看焦点组件的 `WHEN_FOCUSED`，再沿父链找 `WHEN_ANCESTOR_OF_FOCUSED_COMPONENT`，最后在窗口内所有可视且启用的组件中找 `WHEN_IN_FOCUSED_WINDOW`；找到一个已启用的动作就停止。把 `"none"` 放进映射可以取消一个按键绑定。

只改一处的实验：把 `.put(...)` 的目标从 `WHEN_IN_FOCUSED_WINDOW` 换成 `WHEN_FOCUSED`，预测三行输出分别变成什么。再运行 `SharedActionBinding`，把 `ctrl B` 真的按一次，观察标签是否变化（真实按键需要窗口有焦点）。

独立小任务：给同一个动作再绑 `ctrl Shift B`，并说明 `KeyStroke.getKeyStroke` 的字符串里修饰符、键名的书写规则；写错键名时它返回 `null` 还是抛异常，用一个小程序验证。

## 6. 鼠标：点击、移动、拖动是不同通知

按钮和菜单会自己处理鼠标，你只有在“自己画、自己判断点到了哪里”时才需要直接监听鼠标。教材 p459 把鼠标监听拆成两个接口：`MouseListener` 管按下、释放、点击、进入、离开；`MouseMotionListener` 管移动和拖动。拆开是为了效率——只关心点击的组件不必被高频的移动事件淹没。

```java
import java.awt.Dimension;
import java.awt.EventQueue;
import java.awt.Graphics;
import java.awt.event.InputEvent;
import java.awt.event.MouseAdapter;
import java.awt.event.MouseEvent;
import javax.swing.JFrame;
import javax.swing.JPanel;
public class MouseModelRoute {
    static class PointPanel extends JPanel {
        private static final long serialVersionUID = 1L;
        int x = 20, y = 20;
        PointPanel() {
            MouseAdapter handler = new MouseAdapter() {
                public void mousePressed(MouseEvent e) { moveTo(e); }
                public void mouseDragged(MouseEvent e) { moveTo(e); }
            };
            addMouseListener(handler); addMouseMotionListener(handler);
        }
        void moveTo(MouseEvent e) { x = e.getX(); y = e.getY(); repaint(); }
        @Override public Dimension getPreferredSize() { return new Dimension(300, 180); }
        @Override protected void paintComponent(Graphics g) { super.paintComponent(g); g.fillOval(x - 5, y - 5, 10, 10); }
    }
    public static void main(String[] args) throws Exception {
        if (args.length > 0 && args[0].equals("--check")) EventQueue.invokeAndWait(() -> {
            PointPanel panel = new PointPanel();
            panel.dispatchEvent(new MouseEvent(panel, MouseEvent.MOUSE_PRESSED, 1L, 0, 30, 40, 1, false, MouseEvent.BUTTON1));
            panel.dispatchEvent(new MouseEvent(panel, MouseEvent.MOUSE_DRAGGED, 2L, InputEvent.BUTTON1_DOWN_MASK, 50, 60, 0, false, MouseEvent.NOBUTTON));
            System.out.println(panel.x + ":" + panel.y);
        }); else EventQueue.invokeLater(() -> {
            JFrame frame = new JFrame("鼠标模型"); frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); frame.add(new PointPanel()); frame.pack(); frame.setLocationByPlatform(true); frame.setVisible(true);
        });
    }
}
```

`--check` 往面板里派发两个鼠标事件：先按下 (30,40)，再拖动到 (50,60)，输出 `50:60`。面板的字段 `x/y` 是模型，`paintComponent` 只按模型画圆；每次 `moveTo` 改完模型调用 `repaint()`，而不是自己拿画笔去画。

| 事件 | 触发时机 | 本课用它做什么 |
|---|---|---|
| `mousePressed` | 按下 | 记录起点 |
| `mouseReleased` | 松开 | 通常与 pressed 配对 |
| `mouseClicked` | 按下并在同一组件内松开 | 双击/多击判断（`getClickCount`） |
| `mouseEntered/Exited` | 进入/离开组件 | 悬停效果 |
| `mouseMoved` | 未按键移动 | 光标形状、悬停提示 |
| `mouseDragged` | 按住移动 | 拖动对象 |

几次通知的先后是 `pressed → released → clicked`；拖动的过程中不会产生 `clicked`。`getX()/getY()` 是相对**事件源组件**左上角的坐标，不是屏幕坐标；`getPoint()` 把两者打包成 `Point`。`getClickCount()` 返回连击次数，判断双击通常写 `>= 2`，因为三击时它会是 3。

鼠标按键与修饰键用 `getModifiersEx()` 的位掩码判断，例如右键：

```text
if ((event.getModifiersEx() & InputEvent.BUTTON3_DOWN_MASK) != 0) { ... }
```

教材 p460 提醒：老 API 的 `BUTTON2_MASK` 与 `ALT_MASK` 数值相同，是为了让单键鼠标用修饰键模拟其它键；新代码应该用 `*_DOWN_MASK` 这一组。`getModifiersExText(...)` 可以把掩码转成可读字符串，适合写日志。

`MouseAdapter` 是适配器类的一个例子：它实现了 `MouseListener` 的全部 5 个方法（都是空实现），你只覆盖关心的那几个。窗口监听也是同样的套路：`WindowListener` 有 7 个方法，`WindowAdapter` 全部空实现，只覆盖 `windowClosing` 即可。教材 p452 特别提醒：覆盖时方法名拼错，编译器不会报错（因为你只是新增了一个方法），所以一定要写 `@Override`，让编译器替你检查。

只改一处的实验：把 `mouseDragged` 里的 `moveTo(e)` 删掉，只保留 `mousePressed`，再真实拖动。小圆点不会跟着走——按下时它跳了一次，之后不再更新。这能区分“事件来了”和“模型被更新”。

独立小任务：给面板加一个 `mouseClicked`，双击时把圆点移回 (20,20)；记录单击与双击分别触发了几次 `mousePressed`、`mouseClicked`，说明为什么双击判断通常写在 `clicked` 而不是 `pressed` 里。

## 7. 语义事件与底层事件：一次点击下面还有一层

教材 p466–467 把 AWT 事件分成两类：

- **语义事件**：已经表达了用户意图，例如 `ActionEvent`（按钮点击、菜单选择、回车、定时器到点）、`AdjustmentEvent`（滚动条）、`ItemEvent`（勾选）。
- **底层事件**：构成这些意图的原始动作，例如 `KeyEvent`、`MouseEvent`、`MouseWheelEvent`、`FocusEvent`、`WindowEvent`。

一次“按钮点击”在底层可能是 `mousePressed`、`mouseReleased`、`mouseClicked` 三个 `MouseEvent`，但按钮把它们翻译成了一个 `ActionEvent`。所以监听 `ActionListener` 的代码不需要关心用户是用鼠标点的、用空格键激活的，还是程序调用 `doClick` 触发的——这三种在 `ActionEvent` 层面没有区别。

所有事件对象都继承 `java.util.EventObject`；AWT 事件再继承 `AWTEvent`。`EventObject` 提供 `getSource()`，`AWTEvent` 提供 `getID()` 等通用信息，具体子类再加自己的字段（`ActionEvent.getActionCommand`、`MouseEvent.getX`）。

`Timer` 是“语义事件”的一个好例子：它没有鼠标键盘，时间到了就向监听器发一个 `ActionEvent`，并且这个回调在 EDT 上执行。

```java
import java.awt.EventQueue;
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;
import javax.swing.Timer;
public class SwingTimerTicks {
    static class TickCounter implements ActionListener {
        private int ticks;
        private final Timer timer = new Timer(10, this);
        void start() { timer.start(); }
        public void actionPerformed(ActionEvent event) {
            ticks++;
            if (ticks == 2) { timer.stop(); System.out.println("ticks=" + ticks + " edt=" + EventQueue.isDispatchThread()); }
        }
    }
    public static void main(String[] args) { EventQueue.invokeLater(() -> new TickCounter().start()); }
}
```

输出 `ticks=2 edt=true`：定时器触发两次后自己停下，回调确实跑在 EDT 上。`new Timer(10, this)` 的第一个参数是毫秒间隔，第二个是 `ActionListener`；`timer.stop()` 之后不会再触发。定时器的事件不是“精确到毫秒的闹钟”，间隔只是“至少这么久之后排队”，EDT 忙的时候会顺延——这与 L40 的“不要在 EDT 上做耗时工作”是同一条约束。

| 层次 | 例子 | 监听接口 | 你能拿到什么 |
|---|---|---|---|
| 语义 | 按钮点击、菜单、回车、Timer | `ActionListener` | 命令字符串、修饰键 |
| 底层 | 鼠标、键盘、焦点、窗口 | `MouseListener`、`KeyListener`、`WindowListener` 等 | 坐标、键码、窗口状态 |

只改一处的实验：把 `if (ticks == 2)` 改成 `ticks == 3`，预测输出；再把间隔 10 改成 500，观察它仍然只影响“多久之后排队”，不影响回调在 EDT 上执行这一事实。

独立小任务：用 `Timer` 做一个 5 秒倒计时标签，每 1000 毫秒更新一次，到 0 时停止并显示“完成”；说明为什么更新标签的代码可以直接写在 `actionPerformed` 里，而不需要再 `invokeLater`。

## 8. 运行与排错

所有命令都在课程根目录 PowerShell 输入，单文件用 `java.ps1`；复制到 `my_code/` 后把命令里的 `code` 换成 `my_code`。`--check` 用 `doClick`、`dispatchEvent` 这类程序化方式触发事件，能验证监听器与模型，但不能替代真实鼠标、键盘和焦点检查。

| 现象 | 先查哪里 |
|---|---|
| 点了按钮没反应 | 有没有 `addActionListener`；按钮是否 `setEnabled(false)`；监听器里是否抛了异常被吞掉 |
| 点一次计数加了两 | 同一个监听器注册了两次，或两个监听器都在改同一份状态 |
| 想移除监听器却移除不掉 | 注册和移除是不是同一个对象；每次写的 Lambda 都是新对象 |
| 快捷键没反应 | 绑定在哪个 `InputMap`；窗口是否有焦点；按键字符串是否写对（`ctrl B` 与 `Ctrl+B`） |
| 键盘命令执行了两次 | 同一按键同时绑在两张会生效的映射上，或父子组件都绑了 |
| 鼠标坐标对不上 | `getX/getY` 相对事件源组件；事件源可能不是你监听的面板 |
| 拖动到组件外还在触发 | `mouseDragged` 本来就会继续送到原组件，这是预期行为 |
| 关闭窗口没走自定义逻辑 | 用了 `WindowAdapter` 但方法名拼错；加 `@Override` 让编译器检查 |
| 双击逻辑不触发 | 判断写在 `mousePressed` 而不是 `mouseClicked`；或用了 `== 2` 漏掉三击 |
| 界面在事件里卡住 | 监听器里做了耗时工作，阻塞 EDT |

最后用一句完整的话回答本课：事件委托模型里，事件源产生事件对象并通知注册过的监听器，监听器改模型、再请求重绘；一个动作可以用 `Action` 打包后接到按钮和键盘多个入口；`ActionEvent` 是语义事件，鼠标键盘是底层事件；不要依赖监听器的通知顺序，也不要在监听器里阻塞 EDT。
